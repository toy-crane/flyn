# 라이브러리 수정

## @legendapp/list 3.3.5

`KeyboardAwareLegendList`에서 행이 줄어들 때 질문 뒤 빈 공간을 먼저 계산한다.
스크롤 뷰가 늘어난 하단 인셋을 보고하면 다음 프레임에 목록의 네이티브 높이를 줄인다.
기존 순서에서는 이전 인셋으로 계산한 목록 끝에 스크롤을 맞춰 원문이 아래로 이동했다.
자동 추적과 크기 보정을 모두 꺼도 재현됐다.

고정된 지연 시간이나 사후 스크롤은 추가하지 않는다. 대기 중 내용이 다시 늘어나거나
필요한 인셋이 달라지면 현재 값으로 다시 판단한다. 예약한 프레임은 목록의 기존
`scheduledWork`가 관리하며 화면 종료 때 함께 취소한다. CommonJS와 ESM 배포 파일을
같이 수정한다. 앱의 질문 배치·최신 내용 추적·이전 대화 읽기 설정은 유지한다.

두 플랫폼의 실제 앱에서 교정 펼침·접기 전후 원문 위치와 빠른 반복 누름을 확인했다.
라이브러리를 갱신할 때 [후속 확인](../docs/follow-ups/legend-list-native-inset-shrink.md)의
짧은 대화와 인셋 변경 경로를 검증한 뒤 패치를 제거한다.

## heroui-native 1.0.9

`Menu.Content`의 진입 효과를 감싼 뷰에 `StyleSheet.absoluteFill`을 적용한다.
절대 위치의 자식만 둔 기존 뷰는 높이가 0이다. 메뉴는 보이지만 iOS와 Android의
접근성 목록에서 메뉴 항목이 빠지고, 이름으로 선택할 수도 없었다.
감싼 뷰의 영역을 확보하면 메뉴의 위치·크기·누름·진입 효과를 유지하면서 항목이 노출된다.
기본 진입 효과와 사용자 지정 Keyframe 경로의 소스와 배포 JavaScript에 같은 수정을 둔다.

`bun install --frozen-lockfile`이 고정한 버전과 패치를 함께 설치한다.
HeroUI를 갱신할 때 메뉴 항목을 접근성 이름으로 선택하고 확인창을 취소하는 흐름을
iOS·Android에서 다시 확인한다. 원본이 감싼 뷰의 영역을 확보하면 패치를 제거한다.
