# 모바일 하단 CTA

## 결정

- 스크롤 중에도 계속 접근할 필요가 있는 화면 단위 행동은 하단에 고정한다. 특정 카드나 오류 영역에 속한 행동은 해당 대상 가까이에 둔다.
- 하단 CTA는 주변 배경 없이 떠 있는 형태로 배치한다. 컨테이너에 불투명한 띠, 구분선, 그림자와 블러를 추가하지 않는다.
- 버튼 자체에도 커스텀 그림자와 블러를 기본으로 추가하지 않는다. 버튼은 공통 스타일의 채움색이나 테두리로 배경 콘텐츠와 구분한다. 테두리 버튼이 콘텐츠 위에 겹치면 버튼 내부에는 화면 배경색을 사용해 뒤의 글이 비치지 않게 한다.
- 하단에 있다는 이유로 주요 행동으로 강조하지 않는다. 주요 행동과 보조 행동은 공통 버튼의 스타일로 구분하며, 같은 선택지의 크기를 다르게 만들어 우선순위를 표현하지 않는다.
- 버튼은 프로젝트 공통 `Button`을 사용한다. 크기와 큰 글자 대응은 공통 컴포넌트가 소유하며 화면마다 임의로 키우지 않는다. 너비는 화면의 배치가 정한다.
- 온보딩의 하단 배치를 기본으로 삼는다. 좌우 여백은 24, 위 여백은 12, 아래 여백은 안전 영역과 12 중 큰 값이다. 값은 React Native 논리 단위다.
- 키보드가 올라오면 CTA는 키보드 위로 이동하고 12의 간격을 유지한다. 키보드 회피는 [모바일 키보드 회피](mobile-keyboard-avoidance.md)를 따른다.
- 마지막 콘텐츠를 끝까지 읽고 누를 수 있도록 CTA가 차지하는 공간을 확보한다. 고정 영역이 본문 공간을 이미 차지하면 같은 여백을 중복으로 추가하지 않는다.
- 처리 중 문구와 크기 유지, 진행 표시와 중복 실행 방지는 [모바일 작업 진행 표시](mobile-action-progress.md)를 따른다.

## 경계

- 모든 화면에 하단 CTA를 요구하지 않는다. 하단 고정이 필요한지는 화면의 행동과 사용 맥락으로 판단한다.
- 플로팅은 배치를 뜻한다. 그림자, 반투명 버튼이나 Liquid Glass를 요구하지 않는다.
- 네이티브 시스템 컨트롤의 재질과 효과는 [모바일 UI 렌더러 경계](mobile-ui-renderer-boundaries.md)를 따른다. 채팅 입력창과 네이티브 툴바의 별도 결정을 이 문서로 바꾸지 않는다.
- 이 결정은 온보딩의 기존 배치를 공통 기준으로 정리한 것이다. 기존 화면 전체의 적용 여부는 실제 구현 변경 때 확인한다.

## 이유

온보딩은 별도 배경이나 장식 없이 하단 행동을 찾을 수 있게 한다. 같은 방식을 사용하면 화면마다 하단 영역의 모습이 달라지는 일을 줄인다. 버튼의 강조 수준은 행동의 중요도로 정하고, 배치는 접근 필요성으로 정한다.

Apple과 Google 지침은 모든 CTA에 투명 배경이나 플로팅을 요구하지 않는다. 이 표현은 앱에서 선택한 기본값이다. 공식 지침의 행동 위계와 가독성 원칙을 유지하면서 온보딩과 일관된 표현을 사용한다.

## 재검토 조건

- 복잡한 배경에서 버튼을 구분하기 어렵거나, 큰 글자와 작은 화면에서 본문 접근이 어려울 때
- 여러 행동이나 요약 정보를 하단에 함께 배치해야 할 때

## 계속 제외하는 대안

- 모든 CTA에 그림자나 블러 추가: 보조 행동까지 강조하고 온보딩과 다른 표현을 만든다.
- 모든 행동을 하단에 고정: 행동이 적용되는 카드나 입력 영역과의 관계가 흐려진다.
