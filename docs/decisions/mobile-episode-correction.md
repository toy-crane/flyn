# 모바일 대화 중 교정

## 결정

- 교정할 표현이 있는 사용자 메시지에는 교정이 붙는다. 앞서 같은 실수를
  알려 줬어도 다시 나타난 메시지마다 교정한다. 문장에 문제가 없으면
  그 사실도 사용자에게 알린다. 작업을 마쳤다는 표시만으로 대신하지 않는다.
  교정을 생략한 경우와 문장에 문제가 없는 경우를 구분한다.
  판정은 서버가 하고 앱은 받은 것을 그린다. 판정 규칙은
  [AI 에피소드 프로토콜](ai-episode-protocol.md)이 소유한다.
- 한 메시지에 교정이 있을 때 문제없음 표시를 함께 보여 주지 않는다.
- 한국어로 쓴 메시지에는 같은 뜻의 자연스러운 영어 표현과 짧은 설명을 안내한다.
  한국어 원문을 틀린 영어처럼 표시하거나 문제가 없는 영어 문장으로 판정하지 않는다.
- 한국어 입력의 영어 표현 안내는 기존 교정과 같은 배치와 접기·펼치기 동작을
  쓴다. 접으면 영어 문장만 보이고, 펼치면 원문, 영어 문장과 짧은 설명을 보여 준다.
  별도 표시 방식을 만들지 않고 교정과 다른 색으로 구분한다.
- 확인 중, 문제없음, 실패는 사용자 말풍선 아래 작은 한 줄로 표시한다.
  문제없음은 체크 아이콘과 `자연스러운 표현이에요.`로 알린다.
- 메시지를 보내면 곧바로 `표현을 확인하고 있어요.`와 로딩 표시를 보여 준다.
  교정이 시작됐는지 알 수 없었던 문제를 해결하기 위해, 이 자리는 자동 작업의
  일반적인 1초 대기 규칙을 적용하지 않는다.
- 캐릭터 답변이 끝나면 교정이 진행 중이어도 다음 메시지를 보낼 수 있다.
  늦게 도착한 교정은 판정한 원래 사용자 메시지에 붙는다.
- 교정을 확인하지 못하면 진행 중이나 문제없음과 다른 색으로
  `표현을 확인하지 못했어요.`를 표시한다. 문구 바로 뒤에 작은 새로고침 아이콘
  버튼을 둔다. 접근성 이름은 `표현 다시 확인`이다. 재시도는 그 메시지의 교정에만
  적용하며 사용자 메시지를 다시 보내거나 캐릭터 답변을 새로 만들지 않는다.
- 새로고침 아이콘은 작게 보이되 누를 수 있는 영역을 충분히 확보한다.
  재시도 중에는 그 자리에 로딩 표시를 두고 버튼을 비활성화한다.
- 영어 교정에서 자동으로 보이는 것은 고친 문장 한 줄까지다. 한 줄은 사용자
  말풍선 아래 오른쪽에 매달리고, 교정 표식 아이콘, 모든 수정을 반영한 고친 문장, 펼침
  chevron으로 이루어진다. 바뀐 부분은 교정 채널의 색으로 강조한다.
- 한 줄을 탭하면 그 자리에서 카드로 펼쳐지고, 접기 chevron으로 다시 한 줄이
  된다. 펼치면 한 줄은 사라지고 카드가 그 자리를 대신한다. 붙은 뒤에는 어느
  쪽이든 대화에 남는다.
- 카드 제목은 영어 교정이 `더 자연스러운 영어 표현`, 한국어 입력의 영어 안내가
  `이럴 때 쓰는 영어 표현`이다. 두 제목은 어떤 영어 표현인지 설명하는 같은 형태를
  쓴다. `배울 표현`은 문서에서 두 안내를 함께 부르는 이름이며 카드 제목으로 쓰지 않는다.
  한 메시지에 표현이 여럿이면 기존처럼 제목 뒤에 `N개`를 표시한다.
  본문은 표현별 항목으로 나뉘고 각 항목은 원문의 어긋난 자리, 고친 문장, 이유 한
  줄로 이루어진다. 아래에는 `AI에게 물어보기` 버튼만 둔다.
- 표현이 하나면 항목에 문장을 통째로 놓고 달라진 자리를 짚는다. 여럿이면 문장을
  항목 수만큼 되풀이하는 대신 달라진 조각만 마주 놓는다. 짚는 장치는 두 경우가
  같다.
- 한 메시지에 표현이 여럿이어도 고친 문장은 하나이므로 한 줄은 그대로 한 줄이다.
- 카드에 저장 안내 문구를 두지 않는다. 틀림을 세는 말과 문법·어휘 같은 유형
  라벨도 쓰지 않는다.
- 교정 채널은 전용 보라를 쓴다. 사용자 말풍선과 강조 요소가 쓰는 파랑과
  구분한다. 한 줄과 카드의 배경 띠, 강조한 낱말이 이 색을
  쓴다. 색 토큰의 이름과 등재는
  [모바일 색상 시맨틱](mobile-color-semantics.md)을 따른다.
- 교정 카드에 `다시 보내기`를 두지 않는다. 고친 문장을 본 채팅 입력창에 넣는
  동작과 `고쳐서 다시 보냈어요` 표시도 두지 않는다.
- `AI에게 물어보기`를 탭하면 그 교정을 출처로 시트가 열린다. 시트의 동작은
  [모바일 AI에게 물어보기](mobile-ask-ai.md)를 따른다. 시트를 닫으면 카드는
  그대로 열려 있다.
- 교정은 계정에 남는다. 화면을 나갔다 와도 붙어 있던 배울 표현이 같은 메시지
  곁으로 돌아온다.
- 다시 받기나 수정으로 버려진 메시지의 교정은 그 메시지를 따라 함께 사라진다.
  없던 턴의 배울 표현은 없던 것이다.
- 교정 하나가 도착해도 장면 목록 전체를 다시 그리지 않는다. 말풍선 아래에
  매달리는 자리가 교정 상태를 스스로 읽으므로, 흐르는 장면이 교정 때문에 멈추지
  않는다.
- 접근성 이름은 해당 카드 제목 뒤에 `보기` 또는 `접기`를 붙인다.
  질문 버튼의 접근성 이름은 `AI에게 물어보기`다.

## 경계

- 계정 단위 오늘 배운 표현 보관함 화면과 다음 에피소드에서 다시 쓸 기회를 만들지
  않는다. 그 재료가 되는 행은 이미 쌓인다.
- 교정을 저장되는 대화 기록 안에 넣지 않는다. 교정은 자기 행에 남는다.
- 끝난 화의 읽기 전용 복습에 배울 표현을 표시하지 않는다. 표시 방식은 보관함을
  만드는 단위가 정한다.
- 인물의 대사에 교정을 싣지 않는다. 인물은 내용에 반응하고 영어를 고쳐 주지
  않는다.
- 마무리 화면을 바꾸지 않는다. 오늘 배운 표현의 목록과 지나간 표현의 구분은 다음
  단위가 설계한다.
- 연속 기록, 점수, 틀림 개수 집계를 만들지 않는다.
- 템플릿 채팅(`/chat`)에는 교정을 붙이지 않는다. 이 결정은 에피소드에만
  적용된다.

## 이유

교정이 없으면 내 문장이 맞았는지 확인되지 않고, 확인되지 않으면 실력도 해냈다는
감각도 남지 않는다. 그러나 AI는 지치지 않고 전부 지적할 수 있으므로 자동 노출의
상한을 고친 문장 한 줄로 두고 이유는 탭 뒤로 미룬다. 같은 실수도 메시지마다
일관되게 교정한다. 앞서 알려 줬다는 이유로 교정을 생략하면 사용자는 같은 표현이
어떤 때는 괜찮고 어떤 때는 문제가 있다고 받아들일 수 있다.

문제가 없는 문장에도 결과를 알려 줘야 사용자가 교정이 아직 오지 않은 것인지
걱정하지 않는다. 완료 여부만 알리는 문구는 문장이 괜찮다는 정보를 전하지 못한다.

고친 문장을 다시 보내는 별도 단계는 필요하지 않다고 정했다. 사용자는 교정에서
배울 표현을 확인하고, 이해되지 않는 부분은 AI에게 물어본다. 카드의 동작은 이
도움으로 모은다.

보라는 파랑 사용자 말풍선과 구분되고, 스파클 아이콘과 함께 "AI가 하는 일"의 업계
관습색이다. 청록과 회색 채팅 구조 변형을 비교 렌더로 확인한 뒤 골랐다.

## 재검토 조건

- 반복 교정 때문에 대화보다 교정이 앞서 보이거나 사용자 부담이 커질 때
- 교정이 장면보다 늦게 도착하는 것이 화면에서 어색하다고 관찰될 때
- 계정 단위 보관함이 생겨 쌓인 배울 표현을 화면에 보여 줘야 할 때
- 카드가 길어져 인라인으로 펼치는 것이 대화를 읽기 어렵게 만들 때

## 계속 제외하는 대안

- 판정 결과와 무관하게 같은 표식을 모든 메시지에 두기: 확인 중인지, 문제가
  없는지, 교정할 부분이 있는지 구분할 수 없다. 표시는 결과의 뜻을 전달해야 한다.
- 자동 노출에 이유까지 함께 펼치기: 자동 노출은 업계 조사에서 어디서나 한 줄로
  수렴한다(Speak). 이유까지 자동으로 펼치면 장면보다 교정이 커진다.
- 카드를 시트로 열기: 말풍선과 교정 사이의 거리가 멀어지고, 시트를 닫기 전에는
  대화를 볼 수 없다.
- 교정 카드에 다시 보내기 두기: 고친 문장을 다시 보내는 별도 단계는 현재 요구에서
  제외했다. 그 문장을 실제로 다시 써 보는 별도 학습 흐름이 필요해질 때 재검토한다.
- 교정을 지워서 당장 편하게 만드는 기능: 교정은 사용자를 불편하게 만드는 장치가
  아니라 연습을 성립시키는 조건이다.

## 보존할 근거

- 2026-08 iOS와 Android에서 배울 표현이 붙은 에피소드를 다시 열어 같은 메시지
  곁에 원문 표시, 고친 문장과 이유가 복원되는 것을 확인했다.
- 프로토타입에서 항목이 하나일 때는 문장 전체를, 둘일 때는 조각을 보여 주는 편이
  읽기 좋았다. 서버는 문장과 조각을 모두 주므로 앱이 항목 수로 고른다.
- React Native는 물결 밑줄을 그리지 못한다. 원문의 어긋난 자리는 밑줄로 짚고,
  물결은 승인된 프로토타입의 웹 표현으로만 남긴다.
