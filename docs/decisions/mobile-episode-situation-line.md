# 모바일 에피소드 상황 줄

## 결정

- 에피소드 화면은 헤더 바로 아래에 상황 줄을 둔다. 상황 줄은 이 에피소드의
  사건과 사용자가 하려는 일을 한 줄로 알려 준다.
- 상황 줄은 대화 목록과 함께 스크롤되지 않는다. 첫 장면이 열린 때부터 결말이 난
  뒤까지 같은 자리에 남는다.
- 상황 줄은 에피소드 각본이 정한 장면 이모지와 한국어 문구로 이루어진다. 모델이
  만들지 않는다. 내용의 소유권은 [AI 에피소드 프로토콜](ai-episode-protocol.md)이
  정한 공식 에피소드 데이터에 있다.
- 장면 이모지와 문구는 왼쪽에서 시작한다. 상황 줄을 접거나 닫는 동작을 두지
  않는다.
- 화면과 문서에서는 `GLOSSARY.md`가 정한 이름인 상황 줄을 쓴다. 생김새를 가리키는
  배너를 기능 이름으로 쓰지 않는다.

## 경계

- 홈 카드의 상황 훅을 대신하지 않는다. 홈의 훅은 시작 전에 사건을 소개하고,
  상황 줄은 대화 중에 목표를 다시 알려 준다.
- 지난 전개를 모델이 요약하는 recap을 만들지 않는다.
- 일반 채팅에는 상황 줄을 두지 않는다.

## 이유

짧은 에피소드에서는 마지막 말풍선이 어디까지 진행했는지를 보여 주지만, 사건과
목표는 대화가 쌓일수록 화면에서 사라진다. 헤더 아래의 고정된 한 줄은 모델 호출이나
프로토콜 변경 없이 사용자가 하던 일을 다시 잡게 한다.

헤더 부제목은 제목과 섞여 묻히고, 떠 있는 칩은 대화를 가리며, 입력창 위는 수정
안내와 오류가 쓰는 자리다. 별도 상황 줄은 대화를 가리지 않으면서 헤더와 내용을
구분한다. 시스템 목표 아이콘 대신 각본의 장면 이모지를 쓰면 목표를 억지로 그림으로
번역하지 않고 에피소드마다 자기 표식을 가질 수 있다.

## 재검토 조건

- 작은 화면에서 상황 줄이 대화 공간을 지나치게 줄인다는 문제가 반복될 때
- 에피소드가 길어져 사건과 목표만으로 하던 지점을 되찾기 어려워질 때
- 상황 줄 문구가 사건의 긴장을 미리 풀어 버린다는 문제가 사용자 검증에서 확인될
  때

## 계속 제외하는 대안

- 헤더 부제목: 제목과 같은 축에 놓여 사건과 목표가 묻힌다.
- 떠 있는 칩: 대화 위를 가리고 문구 길이에 맞지 않는다.
- 입력창 위 안내: 수정 안내와 오류가 이미 쓰는 자리다.
- 모델이 만든 전개 요약: 짧은 에피소드에 호출과 새 프로토콜을 더한다. 에피소드가
  길어질 때 재검토한다.
