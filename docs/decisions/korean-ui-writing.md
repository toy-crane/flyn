# 화면 문구 한국어 말투

## 결정

- 화면 문구는 지금 보고 있는 화면과 사용자가 할 일을 바로 이해할 수 있게 쓴다. 기능을
  설명하는 말보다 사용자가 보고 판단하거나 행동하는 데 필요한 말을 먼저 둔다.
- 익숙하고 구체적인 일상어를 쓴다. 기술 용어, 한자어, 줄임말은 정확한 제품 이름이나
  사용자가 이미 아는 표현이 아니면 쉬운 말로 바꾼다.
- 한 문장에는 한 가지 내용만 담는다. 서로 다른 내용을 전해야 하면 문장을 나누고,
  읽지 않아도 다음 행동을 고를 수 있는 설명은 덜어낸다.
- 기본 종결은 해요체다. 자동으로 발송되는 메시지와 사용자가 조심해야 하는 상황만
  합쇼체를 써서 무게를 싣는다.
- 화면의 보조 설명은 기본적으로 추가하지 않는다. 사용자가 요청했거나, 설명 없이는
  다음 행동을 결정하기 어려운 경우에만 추가한다. 버튼, 제목, 화면 전환으로 알 수
  있는 내용을 반복하지 않는다.
- 자주 갈리는 네 가지는 아래대로 판정한다.
  - **버튼과 메뉴**: 기능의 이름이 아니라 목적을 쓴다. "확인", "다음", "계속" 대신
    누르면 무엇이 일어나는지 쓴다. 예외는 온보딩 닉네임 화면의 `다음` 하나다. 규칙만
    보면 목적을 쓴 `아이디 정하기`가 맞지만, 두 화면짜리 흐름에서는 `다음`이 더 자연스럽다.
    이 한 자리에만 두고 다른 화면으로 넓히지 않는다.
  - **오류**: 사과나 오류 이름보다 지금 할 수 있는 해결 방법을 먼저 쓴다. 사용자가
    입력하거나 고른 내용을 유지했다면 함께 알린다. 사용자를 탓하지 않는다.
  - **마침표**: 한 텍스트 덩어리가 평서문이나 명령문 한 문장으로 끝나면 마침표를 붙이지
    않는다. 두 문장 이상을 이어 하나의 글로 보여 줄 때는 마지막 문장을 포함한 각
    평서문과 명령문에 마침표를 붙인다. 물음표와 느낌표는 문장 수와 관계없이 필요할 때
    사용한다. 버튼, 메뉴, 라벨처럼 문장이 아닌 문구에는 문장 부호를 붙이지 않는다.
  - **존칭어**: 최소로 쓴다. "하실 수 있어요"가 아니라 "할 수 있어요"로 쓴다.
- 같은 뜻이면 부정문보다 긍정문을 쓰고, 같은 상태와 행동은 화면마다 같은 말로 부른다.
- 이 계약은 템플릿의 기본 말투다. 템플릿에서 만든 프로젝트는 그대로 물려받는다.
- 채팅 답변, 문서, 결정 계약, 작업 기록의 말투는 `AGENTS.md`가 정한다. 이 계약은
  앱 화면에 보이는 문구만 다룬다.

## 경계

- 색상, 타이포그래피, 간격, 아이콘, 컴포넌트의 모양은 이 계약이 정하지 않는다.
  [모바일 색상 시맨틱](mobile-color-semantics.md),
  [모바일 타이포그래피](mobile-typography.md), [모바일 UI 렌더러 경계](mobile-ui-renderer-boundaries.md)가 소유한다.
- 사용자가 쓴 글과 서버가 소유하는 스토리 콘텐츠는 앱이 말투와 문장 부호를 고치지 않는다.
- 제공자가 문구를 정해 둔 자리에는 이 계약보다 제공자 규칙이 앞선다.
  Google과 Apple 로그인 버튼이 여기에 해당한다.
- 법률 문구와 알림은 문맥과 위험도에 맞춰 따로 판단한다.

## 이유

출시된 문구만 보고 말투를 되짚으면 의도와 우연을 구분할 수 없고 세션마다 말투가
달라진다. 버튼, 오류, 마침표처럼 반복해서 갈리는 지점을 이 계약에 직접 적으면 Flyn의
화면과 사용자를 기준으로 판단할 수 있다.

짧은 화면 문구는 글보다 화면 요소에 가깝다. 한 문장에도 마침표를 붙이면 작은 상태나
빈 화면 안내가 필요 이상으로 무겁게 보인다. 두 문장 이상은 문장 사이의 경계가 필요하고
마지막 문장만 마침표를 빼면 글이 덜 끝난 것처럼 보이므로 모든 문장을 마침표로 닫는다.

이 저장소는 템플릿이라 여기서 정한 말투가 파생 프로젝트의 시작점이 된다. 그래서 고유
브랜드 보이스가 생기면 교체할 수 있게 재검토 조건을 함께 둔다.

## 재검토 조건

- 프로젝트의 고유 브랜드 보이스가 정의될 때
- 실제 화면에서 짧은 문구와 이어지는 글의 구분이 읽기를 방해할 때
- 한국어가 아닌 언어를 제품 범위에 추가할 때

## 계속 제외하는 대안

- 외부 디자인 시스템의 글쓰기 기준을 그대로 따르기: Flyn의 화면과 말투보다 다른
  제품의 구조와 세계관을 판단 기준으로 삼게 된다.
- 출시된 문구만 보고 말투를 귀납하기: 의도와 우연을 구분하지 못한다.
- 외부 글쓰기 가이드를 저장소에 복사하기: Flyn이 선택한 기준과 외부 기준의 경계가
  흐려지고, 사본이 바뀌지 않아도 계속 맞는 기준처럼 남는다.
