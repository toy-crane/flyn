# 모바일 뒤로 가기 표시

## 결정

- 뒤로 가기 버튼은 쉐브론(‹)만 쓴다. 이전 화면 제목이나 "뒤로" 라벨을
  붙이지 않는다.
- iOS가 공식 제공하는 표시 옵션 중 쉐브론만 쓰는 모드(minimal)를 쓴다.
  버튼 자체는 네이티브 셸이 소유하며 커스텀 컴포넌트로 대체하지 않는다.
- 접근성 이름은 "뒤로 가기"를 유지한다. 화면에 보이는 라벨이 없어도 보조
  기술에는 이름이 읽혀야 한다.
- 화면 가장자리 스와이프로 돌아가는 시스템 제스처는 그대로 둔다.

## 경계

- 이 결정은 뒤로 가기 버튼의 표시만 정한다. 헤더의 소유권과 렌더러는
  [모바일 UI 렌더러 경계](mobile-ui-renderer-boundaries.md)가 소유한다.
- 모달과 폼 시트의 닫기 버튼은 이 결정의 범위가 아니다.

## 이유

iOS 기본값은 이전 화면 제목을 라벨로 쓰지만, 이 앱의 화면은 제목이 본문에
크게 있어 라벨이 중복 정보가 된다. 사진, App Store처럼 콘텐츠 중심 Apple
앱들도 같은 이유로 쉐브론만 쓴다. 스토리 선택 화면 검토에서 사용자가
확정했다.

## 재검토 조건

- 라벨 없는 뒤로 가기가 어디로 돌아가는지 헷갈린다는 사용성 문제가 실제
  사용에서 관찰될 때
- 시스템 기본 동작이 바뀌어 minimal 모드의 표시가 달라질 때

## 계속 제외하는 대안

- 이전 화면 제목 라벨(기본값): 큰 제목과 중복되고, 제목이 길면 시스템이
  "뒤로"로 바꿔 표시가 일정하지 않다.
- 커스텀 뒤로 가기 버튼: 네이티브 셸 소유 결정과 어긋나고 스와이프 제스처
  일관성을 해칠 수 있다.
