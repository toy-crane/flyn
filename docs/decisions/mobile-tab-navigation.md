# 모바일 탭과 상세 화면 배치

## 결정

- 화면을 보는 동안에도 하단 탭으로 다른 영역을 오가야 하면 해당 탭의 Stack 안에 둔다.
  목록이나 상세라는 이름보다 그 화면에서 탭 이동이 필요한지를 기준으로 판단한다.
- 탭 없이 보는 일반 화면은 탭 바깥의 상위 Native Stack에서 연다. 화면이 탭 전체를
  덮고, 뒤로 가면 실제로 그 화면을 열었던 화면과 탭으로 돌아간다.
- 스토리 상세, 대화 기록과 에피소드 대화는 탭 바깥에서 연다. 홈, 탐색 목록,
  스토리 목록과 표현 노트는 NativeTabs 안에 둔다. 상세와 기록에서 탭을 숨기려고 전역 경로나
  화면 포커스에 따라 `NativeTabs.hidden`을 바꾸지 않는다.
- 스토리 상세에서 대화 기록을 열면 뒤로 가기는 상세로 돌아간다. 스토리 목록에서
  기록을 열면 스토리 목록으로 돌아간다. 같은 내용을 보여 준다는 이유로 다른 탭의
  화면으로 이동시키거나 복귀 경로를 고정하지 않는다.
- 대화에서 뒤로 가면 대화를 열었던 상세 또는 대화 기록으로 돌아간다. 다음 화를
  진행해도 이 복귀 경로를 유지한다.
- 탭이 없는 화면끼리 이동할 때 탭 바가 잠깐 나타나지 않는다. 탭 목록과 상세 사이의
  전환은 Native Stack이 소유하며, 뒤로 가기 제스처 도중 드러나는 원래 목록과 탭도
  시스템 전환에 맡긴다.

## 경계

- 화면 배치와 돌아가는 기준을 정한다. 스토리별 행동과 데이터는
  [모바일 스토리 탐색](mobile-story-browsing.md)이 정한다.
- 모든 상세 화면에 탭을 없애라는 규칙이 아니다. 상세를 보면서도 다른 탭으로
  이동해야 한다면 탭 하위에 둘 수 있다.
- 독립 시트와 모달의 표시 방식, 설정 계층과 네이티브 헤더는
  [모바일 UI 렌더러 경계](mobile-ui-renderer-boundaries.md)를 따른다.
  `AI에게 물어보기`를 여는 기존 시트는 일반 상세 화면으로 바꾸지 않는다.
- 공개 링크로 앱 밖에서 처음 진입했을 때의 복귀 정책을 새로 정하지 않는다.

## 이유

탭은 현재 화면에서도 다른 영역으로 이동할 수 있다는 뜻이다. 탭이 필요한 화면은
탭 안에 두고, 한 흐름에 집중하는 화면은 그 위에서 열면 화면 배치가 이 뜻을 그대로
표현한다. 어느 탭에서 열었는지만으로 화면의 소속을 정하지 않는다.

상세와 기록을 탭 안에 둔 채 전역 주소로 탭을 숨기면, 그 위에서 대화를 열 때도
뒤에 남은 탭의 표시 상태가 바뀐다. 탭이 없는 화면을 상위 Stack에서 열면 탭 표시를
별도로 맞출 필요가 없고, 들어온 화면으로 돌아가는 이력도 같은 흐름에 남는다.

## 재검토 조건

- 스토리 상세나 대화 기록에서도 다른 탭으로 바로 이동해야 하는 요구가 확인될 때
- Expo Router가 화면별 탭 숨김과 뒤로 가기 제스처를 함께 처리하는 공식 기능을
  제공하고, 탭 하위에 화면을 유지해야 할 제품 요구도 생길 때
- 공개 링크로 처음 진입한 상세 화면의 복귀 경로를 제품에서 정해야 할 때

## 계속 제외하는 대안

- 상세와 기록을 탭 안에 두고 경로나 포커스로 `NativeTabs.hidden`을 바꾸기:
  대화 진입과 복귀 때 뒤에 있는 탭 상태까지 따로 맞춰야 한다.
- 숨김 경로 목록에 에피소드를 추가하는 데서 끝내기: 현재 경로의 누락은 줄이지만,
  새 화면을 열 때마다 탭 상태를 다시 관리해야 하는 구조가 남는다.
- 돌아갈 탭을 탐색이나 스토리 중 하나로 고정하기: 실제 진입 경로가 다른 사용자를
  열지 않았던 화면으로 보낸다.

## 보존할 근거

- [Expo 공식 문서의 상세 화면 복귀 패턴](https://docs.expo.dev/router/basics/common-navigation-patterns/#going-back-to-the-tab-you-came-from)은
  상세를 탭 밖의 상위 Stack에서 열면 들어온 탭으로 돌아간다고 설명한다.
  [탭 안의 Stack](https://docs.expo.dev/router/basics/common-navigation-patterns/#stacks-inside-tabs-nested-navigators)은
  하위 화면에서도 탭을 유지하는 패턴이다. 2026-09-09 원문을 확인했다.
- [NativeTabs의 탭 바 숨김](https://docs.expo.dev/router/advanced/native-tabs/#hiding-the-tab-bar)은
  부모의 `hidden`과 Context를 사용하는 공식 기능이다. 이 기능이 없어서 다른
  방식을 택한 것이 아니라, 탭이 필요 없는 화면의 배치와 복귀를 함께 맞추려고
  상위 Stack을 선택했다.
- 기준 checkout의 `bun.lock`은 `expo-router 57.0.18`과 `react-native-screens 4.26.2`를
  지정한다. Expo Router 57.0.18의 소스에서 `usePathname()`이 전역 경로를 읽고,
  iOS와 Android의 NativeTabs가 `hidden`을 네이티브 `tabBarHidden`에 전달함을 확인했다.
- 같은 버전의 `usePathname()`과 앱의 탭 숨김 함수를 작업 폴더 밖에 복사해 경로를
  주입했다. `/records/… → /episode → /records/…`에서 숨김 값은
  `true → false → true`였다. 이는 상태 변화의 근거이며, 실제 기기의 전환 장면이나
  수정 후 동작을 검증한 결과는 아니다.
