# AI 프롬프트 평가

## 결정

- 실제 모델을 부르는 프롬프트 평가는 해당 패키지의 별도 명령으로 둔다.
  `bun run test`와 CI에는 넣지 않고, 프롬프트나 모델을 바꿀 때 사람이 돌린다.
- 평가는 고정 질문 묶음, 기계 검사, 출력 전문 기록으로 이루어진다. 기계 검사가
  관문이고, 출력이 매번 달라서 질문마다 여러 번 돌려 전부 통과해야 한다.
- 검사는 고치기 전 프롬프트의 답을 떨어뜨리는지로 판별력을 확인한다. 이전 답을
  통과시키는 검사는 규칙을 지키는지 재지 못한다.
- 모델 채점은 항목별 참·거짓으로 두지 않는다. 넣는다면 이전 답과 새 답을 짝지어
  고르는 비교 채점으로 넣는다.
- 평가에 쓰는 모델은 서버가 쓰는 같은 모델 설정을 읽는다. 별도 모델을 고르지 않는다.
- 새 평가 도구나 호스팅 서비스를 들이지 않는다.

## 경계

- 가짜 모델로 도는 자동 테스트의 범위는 [AI 채팅 프로토콜](ai-chat-protocol.md)이
  그대로 소유한다. 이 결정은 그 테스트를 대신하지 않는다.
- 어떤 검사 항목과 질문을 두는지는 프롬프트마다 그 규칙을 소유한 계약이 정한다.
  물어보기 답은 [AI에게 물어보기 답변](ask-ai-answers.md)이 정한다.
- 운영 트래픽의 추적, 점수 수집, 대시보드는 이 결정의 범위가 아니다.

## 이유

프롬프트를 고칠 때 그 답이 규칙을 지키는지 확인할 길이 없으면 같은 문제가 되풀이된다.
실제 모델 호출은 비용과 외부 상태에 매이므로 CI 밖에 두되, 저장소 안에 두면 프롬프트와
같은 PR에서 결과를 남길 수 있다. promptfoo, Braintrust, Langfuse는 모두 고정 질문
묶음, 기계 검사, 모델 채점, 통과 기준을 두고 프롬프트가 바뀔 때 돌리는 같은 모양이라,
첫 조각은 도구 없이 그 모양만 만든다.

항목별 참·거짓 모델 채점을 시험했더니 고치기 전 답과 딱딱한 답까지 전부
통과시켰다. 판별력 없는 채점은 안심만 주므로 관문에서 뺀다. 짝 비교는 항목 채점보다
판별력이 높다고 알려져 있어 필요할 때 그 형태로 넣는다.

## 재검토 조건

- 평가할 프롬프트가 여럿이 되어 추이를 한 곳에서 봐야 할 때
- 기계 검사만으로 말맛 회귀를 놓치는 일이 반복될 때
- 실제 모델 호출 비용이나 시간이 프롬프트 수정 흐름을 막을 때

## 계속 제외하는 대안

- Langfuse 데이터셋·실험·평가자: 추적 SDK, 키, 호스팅 서비스를 API 서버에 더한다.
  프롬프트가 여럿이 되고 추이가 필요할 때 재검토한다.
- promptfoo 같은 평가 CLI: 새 의존성과 설정 형식을 들인다. 검사 종류가 늘어 직접
  짠 검사가 무거워질 때 재검토한다.
- CI에 실제 모델 평가 넣기: 비용과 외부 서비스 상태에 매이고 결과가 매번 달라 PR을
  막는다. 결과가 충분히 안정되고 비용이 문제가 아닐 때 재검토한다.
- 항목별 참·거짓 모델 채점: 시험에서 판별력이 없었다. 비교 채점으로만 재검토한다.

## 보존할 근거

- 2026-09-10 물어보기 프롬프트 평가에서 기계 검사(말투, 마크다운 기호, 문단, 예문
  줄, 되묻기 어구, 길이, 돌아갈 영어 문장)는 고치기 전 답 6개를 모두 떨어뜨리고
  후보의 답 16개(영어 교정 12개, 한국어 입력 안내 4개)를 모두 통과시켰다. 같은 답에 항목별 참·거짓 모델 채점을 돌리면
  전부 통과했다.
