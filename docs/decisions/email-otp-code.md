# 이메일은 세 번째 로그인 수단이고, 매직링크가 아니라 6자리 코드다

**이 결정은 앞선 "이메일은 채택하지 않음"을 뒤집은 것이다**(03a에서 회귀).
이유 두 가지가 겹친다.

1. 소셜 계정이 없는 사용자에게 경로를 열어준다.
2. **소셜 로그인은 자동 검증이 원천 불가**하다. 이메일이 없으면 로그인 이후
   경로 전체를 사람 손 없이는 한 줄도 확인할 수 없다. 근거는
   [docs/auth-verification.md](../auth-verification.md), 제약의 출처는
   [native-social-login](native-social-login.md).

즉 이메일은 사용자 편의 항목이기 전에 **이 저장소의 유일한 자동 검증 경로**다.
이 경로를 막거나 우회하는 변경은 검증 능력을 함께 잃는다.

## 매직링크는 기각한다 — 링크는 모바일에서 깨진다

링크 방식은 딥링크 핸들러와 AASA 호스팅을 요구하는데, 그 위에서 실패한다:

- 메일 보안 장비가 링크를 **미리 열어 일회용 토큰을 소모**한다.
- 같은 장비가 URL을 자기 도메인으로 재작성해 **AASA 매칭 자체를 깨뜨린다.**

우리만 겪는 문제가 아니다. 같은 이유로 Magic·WorkOS·Clerk(Expo)·Auth0·Cognito가
모바일 매직링크를 지원하지 않거나 폐기했다.

**6자리 코드는 이 실패 모드가 전부 없고 앱을 떠나지도 않는다.** 로컬에서는
`[auth.email.template.*]`가 `supabase/templates/`의 `{{ .Token }}` 템플릿을
쓴다.
