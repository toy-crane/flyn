# 모바일 이미지 로딩

## 결정

- 모바일 React Native UI에서 스토리 표지처럼 사용자가 콘텐츠를 고르는 데 쓰는 원격 이미지를 새로 만들거나 로딩 방식을 바꿀 때는 `expo-image`를 사용한다.
- 이미지별 BlurHash를 `placeholder`로 전달한다. 원본이 준비되면 짧은 cross-dissolve 전환으로 보여 준다. 원본과 미리보기의 영역, 잘림 기준과 모서리 모양을 일치시킨다.
- BlurHash는 이미지를 등록하거나 교체할 때 미리 생성한다. 이미지 주소와 해당 이미지의 해시를 함께 제공한다. 화면을 열 때 원본을 내려받아 해시를 생성하지 않는다.
- 이미지 교체 시 주소와 해시는 같은 원본을 가리켜야 한다. 다른 이미지의 해시를 공통 미리보기로 재사용하지 않는다.
- 이미지 로딩 상태를 이모지로 표시하지 않는다. 스토리 표지의 기존 이모지도 없앤다.
- 이미지 로딩 때문에 주변 내용이나 행동을 기다리게 하지 않는다. 이미지 영역 크기는 로딩 전후에 유지한다.

## 경계

- 프로필 사진은 이 표준의 대상이 아니다. 기존 HeroUI `Avatar.Image`의 로딩 완료 전환과 사진이 없을 때의 이름 첫 글자·사람 아이콘을 유지한다. 작은 식별 이미지에 BlurHash 생성과 저장을 추가할 필요가 확인되지 않았다.

- 정적 앱 에셋, 시스템 아이콘, 웹 이미지와 네이티브 UI가 직접 소유하는 이미지는 이 계약의 대상이 아니다.
- 기존 이미지 전체를 한 번에 교체하도록 요구하지 않는다. 실제 적용 범위는 각 명세가 정한다.
- 이미지가 없거나 로딩에 실패한 경우의 대체 표시는 해당 기능이 정한다. 로딩 미리보기를 진행 표시나 오류 안내의 공통 대체물로 사용하지 않는다.
- 에피소드의 상황 줄처럼 이미지 로딩과 관계없는 이모지를 제거하는 근거로 쓰지 않는다.

## 이유

사용자는 원본과 색이 이어지는 미리보기와 짧은 전환을 모바일 이미지 로딩 표준으로 선택했다. 이미지 표시와 전환은 Expo가 제공하는 API에 맡긴다. 해시를 미리 제공하면 원본 다운로드가 끝나기 전에도 앱이 미리보기를 표시할 수 있다.

BlurHash와 ThumbHash는 모두 Expo가 지원한다. 이번 표준은 공식 기본 예제와 서버 생성 안내가 있는 BlurHash로 통일한다. 두 형식을 함께 관리할 제품 요구는 없다.

## 재검토 조건

- 투명 이미지의 미리보기 품질이나 해시 크기에 실제 문제가 확인되어 ThumbHash 등 다른 방식이 필요할 때
- Expo 업그레이드 후 미리보기와 전환의 플랫폼별 동작이 달라질 때
- 이미지 등록 경로에서 원본과 해시를 함께 제공할 수 없는 새 제약이 생길 때

## 계속 제외하는 대안

- 화면에서 원본 다운로드 후 해시 생성: 첫 로딩을 가리는 데 쓸 수 없다.
- 모든 이미지에 같은 BlurHash 사용: 원본과 관계없는 색을 보여 준다.
- 스토리 표지에 이모지를 남기기: 사용자가 이모지 제거를 명시했다.

## 보존할 근거

- 2026-09-09 [Expo Image 공식 문서](https://docs.expo.dev/versions/latest/sdk/image/)의 `placeholder`, `placeholderContentFit`, `transition`과 서버 BlurHash 생성 안내를 확인했다. `placeholderContentFit` 기본값은 `scale-down`이므로 원본의 `contentFit`과 맞춰 크기 차이에 따른 깜빡임을 피한다.
- 작업 폴더 밖에서 npm 배포본을 읽었다. 프로젝트의 `expo 57.0.19`는 `bundledNativeModules.json`에서 `expo-image ~57.0.4`를 지정한다. `expo-image 57.0.4`의 타입과 소스에도 위 API가 있다. `expo-image 57.0.4`를 앱에 설치했다. iOS Simulator와 Android Emulator에서 지연 요청, 실패와 미리보기에서 원본으로 이어지는 전환을 확인했다. 검증 범위는 [스토리 표지 명세](../specs/story-cover-image-loading/spec.md)에 기록한다.
- Expo 공식 `expo/skills` 저장소와 프로젝트에 있는 `expo-native-ui` 안내를 확인했다. 공식 문서는 작업할 때 원문을 다시 읽고 설치 버전과 맞춘다. 문서 사본은 저장하지 않는다.
