# 모바일 이미지 로딩

## 결정

- 모바일 React Native UI에서 스토리 표지처럼 사용자가 콘텐츠를 고르는 데 쓰는 원격 이미지를 새로 만들거나 로딩 방식을 바꿀 때는 `expo-image`를 사용한다.
- 이미지별 BlurHash를 `placeholder`로 전달한다. 원본이 준비되면 짧은 cross-dissolve 전환으로 보여 준다. 원본과 미리보기의 영역, 잘림 기준과 모서리 모양을 일치시킨다. `placeholderContentFit`은 원본의 `contentFit`과 같은 값을 쓴다.
- BlurHash는 이미지를 등록하거나 교체할 때 미리 생성한다. 이미지 주소와 해당 이미지의 해시를 함께 제공한다. 화면을 열 때 원본을 내려받아 해시를 생성하지 않는다.
- 이미지 교체 시 주소와 해시는 같은 원본을 가리켜야 한다. 다른 이미지의 해시를 공통 미리보기로 재사용하지 않는다.
- 이미지 로딩 상태를 이모지로 표시하지 않는다. 스토리 표지의 기존 이모지도 없앤다.
- 이미지 로딩 때문에 주변 내용이나 행동을 기다리게 하지 않는다. 이미지 영역 크기는 로딩 전후에 유지한다.

### 스토리 표지

- 탐색 목록, 스토리 목록, 스토리 상세와 대화 기록 등 스토리 표지를 보여 주는 모든 곳이 공통 `StoryCover`로 같은 기준을 따른다. 전환 시간은 200ms이며 기기 확인에 따라 조정할 수 있다.
- 해시가 없거나 유효하지 않으면 표지 배경색을 유지한 채 원본을 계속 받는다. 표지가 없으면 배경색만 보여 준다. 원본을 받지 못하면 유효한 미리보기를 유지하고, 없으면 배경색만 보여 준다. 회전 진행 표시나 이미지 전용 다시 시도 버튼은 두지 않는다.
- 해시가 없다는 이유로 스토리를 열지 못하게 하지 않는다. 표지 실패를 스토리 정보 전체의 조회 실패로 취급하지 않는다.
- 빠르게 스크롤하거나 다른 스토리를 열어도 이전 스토리의 원본이나 해시를 잠깐 보여 주지 않는다. 표지를 교체한 뒤 캐시 때문에 교체 전 표지를 계속 보여 주지 않는다.
- 표지는 장식 이미지로 취급한다. 화면 읽기에 로딩 상태나 미리보기를 따로 읽히지 않는다.

## 경계

- 프로필 사진은 이 표준의 대상이 아니다. 기존 HeroUI `Avatar.Image`의 로딩 완료 전환과 사진이 없을 때의 이름 첫 글자·사람 아이콘을 유지한다. 작은 식별 이미지에 BlurHash 생성과 저장을 추가할 필요가 확인되지 않았다.
- 정적 앱 에셋, 시스템 아이콘, 웹 이미지와 네이티브 UI가 직접 소유하는 이미지는 이 계약의 대상이 아니다.
- 기존 이미지 전체를 한 번에 교체하도록 요구하지 않는다. 실제 적용 범위는 각 명세가 정한다.
- 스토리 표지 밖의 이미지가 없거나 로딩에 실패한 경우의 대체 표시는 해당 기능이 정한다. 로딩 미리보기를 진행 표시나 오류 안내의 공통 대체물로 사용하지 않는다.
- 에피소드의 상황 줄처럼 이미지 로딩과 관계없는 이모지를 제거하는 근거로 쓰지 않는다. 표지 이모지를 화면에서 없앤다는 규칙은 `stories.cover_emoji` 열을 지우라는 뜻도 아니다.

## 이유

사용자는 원본과 색이 이어지는 미리보기와 짧은 전환을 모바일 이미지 로딩 표준으로 선택했다. 이미지 표시와 전환은 Expo가 제공하는 API에 맡긴다. 해시를 미리 제공하면 원본 다운로드가 끝나기 전에도 앱이 미리보기를 표시할 수 있다.

BlurHash와 ThumbHash는 모두 Expo가 지원한다. 공식 기본 예제와 서버 생성 안내가 있는 BlurHash로 통일한다. 두 형식을 함께 관리할 제품 요구는 없다.

`placeholderContentFit`의 기본값은 `scale-down`이다. 원본의 `contentFit`과 맞추지 않으면 미리보기와 원본의 크기가 달라 전환 때 깜빡인다.

## 재검토 조건

- 투명 이미지의 미리보기 품질이나 해시 크기에 실제 문제가 확인되어 ThumbHash 등 다른 방식이 필요할 때
- Expo 업그레이드 후 미리보기와 전환의 플랫폼별 동작이 달라질 때
- 이미지 등록 경로에서 원본과 해시를 함께 제공할 수 없는 새 제약이 생길 때

## 계속 제외하는 대안

- 화면에서 원본 다운로드 후 해시 생성: 첫 로딩을 가리는 데 쓸 수 없다.
- 모든 이미지에 같은 BlurHash 사용: 원본과 관계없는 색을 보여 준다.
- 스토리 표지에 이모지를 남기기: 사용자가 이모지 제거를 명시했다.

## 보존할 근거

- 로컬 스택에서는 표지 원본이 너무 빨리 와서 미리보기가 보이지 않는다. 캐시되지 않은 새 주소를 원본 응답을 보류하는 임시 프록시로 연결해야 iOS와 Android에서 미리보기, 원본 전환, 원본 404, 잘못된 해시를 재현할 수 있었다.
