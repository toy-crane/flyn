# 에피소드 종료와 표현 돌아보기

## 결정

### 대화의 종료

- 마지막 인물 대사는 표현 확인을 기다리지 않고 보여 준다. 표현 확인은 사용자
  메시지의 영어 교정이나 한국어 입력 안내를 만드는 작업이며, `자연스러운 표현이에요`로
  끝난 메시지도 완료로 센다. 사용자가 안내를 읽거나 펼치기를 기다린다는 뜻이 아니다.
- 진행 중인 대화에 결말이 처음 도착하면 입력창 자리에 축하, 실제 결말 카드와 `표현 돌아보기` 버튼을 바로
  보여 준다. 표현 확인이 끝나기를 기다려 카드를 미루지 않는다.
- 그 화의 사용자 메시지 가운데 확인 중인 것이 남아 있으면 `표현 돌아보기` 버튼만
  진행 상태로 둔다. 문구와 크기를 유지한 채 앞에 작은 진행 표시를 두고, 누를 수 없으며
  화면 읽기에 진행 중과 비활성을 함께 알린다. 마지막 메시지만 늦는다고 가정하지 않는다.
  기다리는 동안에도 준비된 표현 안내는 읽을 수 있다. 입력창 자리에
  `표현을 확인하고 있어요` 같은 별도 문구를 두지 않는다. 확인 중임은
  [모바일 대화 중 교정](mobile-episode-correction.md)이 정한 대로 그 메시지 곁의 표시가
  알린다.
- 확인이 성공이든 실패든 모두 끝나면 버튼이 열린다. 재시도로 확인이 다시 시작되면 끝날
  때까지 버튼은 다시 진행 상태다. 일부나 모든 확인이 실패해도 종료하고 다음 화와 홈으로
  갈 수 있다. 실패한 메시지를 완료나 자연스러운 표현으로 처리하지 않는다. 실패 안내와
  재시도는 대화 화면의 그 메시지 곁에 남는다.
- 사용자가 버튼을 눌러 이동한다. 마지막 대화를 읽는 도중 자동으로 넘기지 않는다.
  상황 줄은 종료 뒤에도 남는다.
- 사용자가 대화를 저장하는 단계, 저장 버튼, 저장 중 표시, 완료 저장 실패 화면을
  두지 않는다. 앱과 서버가 기록한다.

### 끝난 대화 다시 읽기

- 끝난 대화를 다시 열거나 표현 돌아보기에서 대화로 돌아오면, 하단에는
  `표현 돌아보기` CTA만 둔다. 대화 목록과 별개인 하단에 고정하되 안전 영역을
  지키고 마지막 대사를 가리지 않는다.
- 축하 카드, 완료 마크, `대화가 끝났어요` 안내와 결과 요약은 다시 보여 주지 않는다.
  종료 안내나 결과 요약을 대화 맨 끝에 별도로 추가하지도 않는다. 대화 전문과 상황 줄은 유지한다.
- CTA의 표현 확인 대기, 비활성과 실패 처리는 위 대화의 종료 규칙을 그대로 따른다.
  읽기 전용이어도 준비된 대사 뜻과 배울 표현을 열고 AI에게 물어볼 수 있다.

### 결말 축하

- 모든 결말에 짧은 축하를 보여 준다. 파란 원의 마크가 튀어나오고 체크가 그려지며
  고리가 한 번 퍼지고, 파랑·보라·청록 조각이 터진다. 카드, 마크, 체크, 고리, 조각,
  `해냈어요!`, 결과 문장이 순서대로 나타나고, 마크가 튀는 박자에 햅틱을 한 번 준다.
- 목표를 그대로 이루지 못한 결말은 `해냈어요!`와 고리 없이 마크와 결과 문장만
  조용히 나타나고 조각은 절반이다. 실제 결과를 `해냈어요!`나 `한 장면을 마쳤어요!`로
  대신하지 않는다.
- 축하는 카드가 나오는 순간에 재생한다. `표현 돌아보기` 버튼이 진행 상태에서 열리는
  순간에는 아무것도 재생하지 않는다. 확인할 것이 없으면 버튼은 축하가 시작될 때부터
  누를 수 있다.
- 축하는 종료 때 한 번만 재생한다. 뒤로 돌아오거나, 기록에서 다시 열거나, 재시도와
  재진입으로 결과가 바뀌어도 반복하지 않는다. 다시 읽기의 표시는 위 규칙을 따른다.
  종료 직후 동작 줄이기에서는 마크의 마지막 프레임을 정지 상태로 보여 준다.
- 조각은 카드 위와 양옆으로 퍼질 수 있어야 한다. 카드의 모서리와 내용 영역이
  조각을 잘라내지 않도록 축하 장식과 카드 내용을 분리한다. 화면 경계 밖까지
  그릴 필요는 없으며, 장식은 대화 스크롤과 버튼 누름, 화면 읽기를 방해하지 않는다.
- 성공 결말의 고리는 마크 주위에서 온전히 보이고, 조각은 마크에서 터져 카드 안과
  바깥으로 이어지는 움직임을 보여 준다. 불투명한 카드 뒤에 가려 출발점이나 고리가
  사라지지 않는다. 장식이 결과 문장과 CTA를 계속 가리지 않게 한다.
- 마크와 조각은 사용자가 알아볼 수 있도록 천천히 나타나고 잦아든다. 효과가 끝나도
  종료 직후의 결과 카드와 CTA는 사용자가 이동할 때까지 남는다. 화면을 떠나면
  진행 중인 효과를 끝내고 다른 화면으로 넘기지 않는다.
- 이모지와 앱의 시스템 아이콘을 축하 그래픽으로 쓰지 않는다. 마크와 조각은 저장소가
  소유하는 Lottie 파일이며, 파일의 자리는 [모바일 아이콘 렌더링](mobile-icon-rendering.md)이
  정한다. 밝은 화면과 어두운 화면에서 그 화면의 강조색과 채널 색을 따른다.

### 표현 돌아보기

- 화면 제목은 `표현 돌아보기`다. 위쪽에 스토리와 해당 화를 표시하고, 그 회차의 그
  화에 준비된 배울 표현만 보여 준다. 다른 회차나 다른 화의 표현을 섞지 않는다.
- 영어 교정과 한국어 입력 안내를 한 목록 `기억해 둘 표현`에 모은다. 목록 제목은 카드가
  있을 때만 보이고 옆에 개수를 두지 않는다. 읽었는지에 따른 구분이나 `안 본 표현`
  표시를 두지 않는다.
- 확인에 실패했거나 아직 준비되지 않은 항목은 목록에서 뺀다. 실패한 원문, 오류 안내,
  개별 재시도와 `다시 확인할 문장` 영역은 이 화면에 두지 않는다. 빼도 원래 메시지의
  실패 상태와 재진입 때의 재확인 대상은 그대로다.
- 카드는 [표현 노트](expression-note.md)와 같은 카드다. 첫 줄은 출처 대신 쓰는
  상황이며 채널 색과 반짝임 아이콘을 쓴다. 아래는 영어 문장과 한국어 뜻이다. 카드는
  접힌 채 열리고, 누르면 `내가 쓴 문장`과 `이렇게 쓰는 이유` 두 섹션이 펼쳐진다. 카드
  아래 오른쪽에는 책갈피와 복사가 이 순서로 선다. 원문 오류 표시와 제안문 강조도
  표현 노트의 규칙을 따라, 올바른 원문을 오류로 표시하지 않는다.
- 사용자 메시지 하나를 카드 하나로 묶고 대화 순서로 놓는다. 한 문장 안의 수정은 같은
  카드에 모으고, 다른 메시지에서 반복된 표현도 그 문맥과 함께 둔다.
- 왼쪽 뒤로 가기는 이 화면을 열었던 대화로 돌아간다. 오른쪽 홈 아이콘(접근성 이름
  `홈으로 이동`)은 홈으로 간다. `대화 다시 보기`와 `오늘은 여기까지` 버튼을 두지 않는다.
- 목록을 처음 읽는 동안에는 본문에 진행 표시를 두고 목록 제목과 빈 상태 안내를 아직
  보여 주지 않는다. 그 화에 확인할 사용자 메시지가 하나 이상 있고, 모두 자연스러운
  표현이라는 결과로 끝났으며 준비된 카드가 없으면
  `이번 대화, 완벽했어요!`를 본문 가운데 보여 준다. 칭찬을 카드로 감싸거나 목록 제목,
  아이콘, 색 면, 그림과 빈 그림 자리를 함께 두지 않는다.
- 일부 확인이 실패했거나 뜻을 파악하기 어렵다는 결과가 있으면 카드가 없어도 완벽하다고
  말하지 않는다. 확인할 사용자 메시지가 없는 경우도 칭찬하지 않는다. 이때는
  `이번 대화에는 안내한 표현이 없어요`를 임시로 유지한다. 안내 문구를 다시 정하기
  전까지 카드가 없다는 사실만으로 모든 문장이 자연스럽다고 판정하지 않는다.
- 목록을 불러오지 못하면 헤더와 이동 수단을 유지하고 기존 목록 조회 오류와
  `다시 시도하기`를 보여 준다. 다시 읽는 동안에는 오류 안내를 유지한 채 버튼에만
  진행 표시를 두고 중복 누름을 막는다. 조회 중에도 이동할 수 있고, 늦게 온 결과가
  이동한 다른 화면이나 화의 내용을 바꾸지 않는다.
- 다음 이야기 예고는 `다음 이야기`, 다음 화 번호, 제목과 짧은 예고를 별도의 `surface`
  카드에 담아 하단에 고정한다. Primary 버튼은 카드 밖 아래에 둔다. 하단 전체에 새로운
  불투명 띠, 구분선, 그림자나 블러를 더하지 않고 [모바일 하단 CTA](mobile-bottom-cta.md)를 따른다.
  다음 화가 이미 끝났으면 버튼을 `N화 다시 보기`로 표시하고 기존 결말이 있는 대화를
  연다. 마지막 화에서는 같은 카드 자리에 스토리 이름과 `마지막 이야기까지 함께했어요`를
  보여 주고 아래에 `대화 기록 보기`를 둔다. 없는 다음 화의 버튼은 두지 않는다.
  카드 목록, 칭찬, 빈 상태와 조회 실패 사이에도 하단 배치를 유지한다. 작은 화면과
  큰 시스템 글자에서도 본문을 읽고 버튼을 누를 수 있어야 한다.

### 카드 내용의 생성과 저장

- 대화 중 표현을 확인할 때 카드에 필요한 내용을 함께 만들어 그 사용자 메시지의 결과에
  저장한다. 원문, 고친 영어 문장과 설명에 더해 쓰는 상황 한 줄, 전체 영어 문장의 한국어
  뜻 한 줄, 다른 예문 하나와 그 뜻이다. 예문과 그 뜻은 서버가 만들어 저장하지만 화면에는
  보여 주지 않는다.
- 표현 돌아보기는 저장된 내용을 읽기만 한다. 열 때마다 새로 만들지 않고, 기록에서 다시
  열어도 저장된 내용을 쓴다.
- 사용자 메시지마다 확인의 완료 여부와 결과를 함께 남긴다. 문제없음도 완료다. 카드가
  없다는 이유로 미완료로 보지 않고, 완료로 표시했는데 필요한 내용이 없는 상태를 만들지
  않는다. 겹친 요청이 같은 메시지의 결과를 중복 생성하거나 서로 덮어쓰지 않는다.
- 뜻을 파악하기 어렵다는 판정은 `표현의 뜻을 파악하기 어려워요`로 확인된 결과에
  남긴다. 통신 실패와 구분하며, 카드나 자동 재확인을 만들지 않는다.

### 나갔다 돌아오기

- 화면을 떠난 뒤에는 표현 확인을 계속하지 않는다. 기다리는 동안 화면을 나갈 수 있고,
  앱을 닫은 동안 확인이 끝난다고 약속하지 않는다.
- 같은 화에 돌아오면 서버에 남은 결과를 먼저 읽고, 완료 결과가 없는 메시지(실패 포함)만
  자동으로 처음부터 다시 확인한다. 재개 버튼은 없다. 사용자 메시지를 다시 보내거나
  인물의 대사를 다시 만들거나 대화를 처음부터 시작하지 않는다.
- 이미 끝난 화에 돌아오면 위 끝난 대화 다시 읽기 규칙으로 표시한다. 미완료 메시지를
  다시 확인하는 동안 하단 `표현 돌아보기` CTA만 진행 상태로 둔다. 표현 확인의 수명에서
  대화와 표현 돌아보기 사이를 오가는 것은 같은 흐름이고,
  홈, 기록 목록, 다른 에피소드로 나갔다 오는 경우를 재진입으로 본다. 다시 확인해도
  실패하면 대화 화면에 실패와 재시도를 남기고 종료를 허용하며, 같은 화면에서 무한히
  자동 재시도하지 않는다.

### 기록에서 다시 보기

- 대화 기록에서 끝난 화를 열면 같은 대화 화면에서 위 끝난 대화 다시 읽기 규칙을
  따른다. 상황 줄, 대화와 표현 안내를 유지하고 하단에는 `표현 돌아보기` CTA만 둔다.
  입력창, 별도의 `끝` 표시나 기록용 화면은 두지 않는다.
- 뒤로 가면 방금 보던 끝난 화의 대화로, 다시 뒤로 가면 대화 기록으로 돌아간다.
- 열어 보기만 해서 새 회차가 생기거나 대화가 다시 시작되거나 결말이 바뀌지 않는다.

## 경계

- 대화 중 배울 표현 카드와 확인 실패 줄, 재시도는
  [모바일 대화 중 교정](mobile-episode-correction.md)이 소유한다.
- 결말 낱말과 결과 한 줄의 화면 표기는
  [스토리 진행·결말 화면 표기](story-progress-and-ending-display.md)가 소유한다.
- 사용자가 손으로 담은 표현은 [표현 노트](expression-note.md)가 소유한다. 표현
  돌아보기의 책갈피는 그 항목을 만든다.
- 점수와 틀림 개수는 만들지 않는다. 홈 구성과 연속 기록은 이 계약의 범위가 아니며
  [홈의 연속 기록과 이번 주 카드](../specs/home-streak/spec.md)가 정한다.

## 이유

축하 조각이 카드 경계에서 잘리면 작은 상자 안에 갇힌 것처럼 보인다. 조각을 카드 밖으로
펼치되 조작을 가로막지 않도록 분리한다. 다시 읽을 때는 이미 종료를 아는 사용자에게
큰 완료 카드와 결과 요약을 반복하지 않고 대화 공간을 돌려준다.

결말은 "몇 개 틀렸다"가 아니라 실제로 얻어 낸 결과로 보여 준다. 사용자는 대화가
어떻게 끝났는지 이해하고, 영어로 대화를 이어 간 성취를 느껴야 한다.

결말은 마지막 대사와 같은 스트림 끝에 이미 확정되어 저장된 사실이라 기다릴 이유가
없다. 기다리는 것은 표현 돌아보기에 실을 카드뿐이므로, 그 화면을 여는 버튼만 기다리게
하면 돌아보기를 열 때 카드가 다 있어야 한다는 목적을 지키면서 빈 시간을 없앤다.
확인 중임을 입력창 자리에 다시 쓰지 않는 것은 같은 문구가 그 메시지 곁에 이미 붙고,
자동 작업의 진행 상태는 처리하는 대상이 소유한다는
[모바일 작업 진행 표시](mobile-action-progress.md)를 따르기 때문이다. 2026-09-11
dogfooding에서 아래쪽 문구가 무엇을 기다리는지와 떨어져 어색하다는 피드백으로
바꿨다. 실패해도 종료를 허용해야 확인 한 번의 오류가 결말을 막지 않는다.

카드 내용을 확인할 때 함께 만들어 두면 표현 돌아보기를 열 때 기다림이 없고, 기록에서
다시 열어도 같은 내용이 나온다. 표현 돌아보기의 카드를 표현 노트와 같게 둔 것은 같은
문장을 몇 분 간격으로 두 화면에서 다시 보기 때문이다. 예문을 화면에서 뺀 것은 예문이
설명 화면의 장치이지 다시 읽기의 장치가 아니기 때문이다. Duolingo와 Speak의 저장
목록에도 예문이 없다.

카드가 0장인 까닭은 표현이 모두 자연스럽기 때문일 수도, 확인에 실패했기 때문일 수도
있다. 칭찬은 전자에만 쓰고 후자에는 중립 안내를 남겨 결과를 잘못 말하지 않는다.
칭찬은 가운데 문구만 두어 표현 목록과 구분한다. 다음 이야기만 카드로 감싸면
예고와 Primary 버튼을 각각 알아보기 쉽다.

축하를 Lottie로 만드는 것은 한 번 틀고 끝나며 입력에 반응하지 않는 연출이기 때문이다.
반짝임 아이콘은 앱 전체에서 배울 표현의 표식이라 축하에 겹쳐 쓰지 않는다. 요소가
순서대로 나타나는 연출은 Duolingo의 lesson complete 방식을 따른다.

## 재검토 조건

- 몇 화 써 보고 표현 돌아보기의 예문이 그리워지지 않을 때. 서버의 예문 생성을 끊어
  확인 한 번의 비용을 줄인다.
- 화면을 떠나거나 앱을 닫은 동안에도 확인을 끝내야 한다는 요구가 확인될 때
- 스토리를 마친 뒤 첫 화와 마지막 화에서 쓴 문장을 나란히 보여 줄 때
- 여러 표현이 모인 카드가 읽기 어렵다는 관찰이 반복될 때
- 칭찬 위에 이미지나 Lottie를 추가하기로 결정할 때. 그전에는 그림 자리를 비워 두지 않는다.
- 사용자 메시지가 없거나 확인 실패·뜻 파악 어려움으로 카드가 없는 경우의 새 안내를 정할 때
- 타협하거나 실패한 결말과 같은 칭찬이 충돌한다는 반응이 있을 때. 그전에는 이야기의
  결말과 별개로 표현 확인 결과만으로 칭찬을 결정한다.

## 계속 제외하는 대안

- 화면을 떠난 뒤에도 확인을 이어 가는 지속 실행: 앱 안에서 이어 가려 해도 작업과 요청을
  화면보다 오래 붙들고 여러 에피소드와 연결해야 하고, 앱을 닫은 뒤까지 이어 가려면
  요청과 별개인 서버 실행, 상태 보관, 재조회와 중복 방지가 필요하다. 사용자는 이것이
  쉽게 구현되지 않으면 원하지 않는다고 했고, 돌아왔을 때 미완료 메시지만 다시 확인하는
  쪽을 골랐다. Vercel의 `waitUntil`은 함수 실행 제한에 묶이고 상태 보관과 재조회를
  해결하지 않는다.
- 확인이 끝났다고 푸시로 알리기: 매 메시지의 짧은 확인에는 과하다.
- 확인이 끝날 때까지 카드를 미루고 입력창 자리에 확인 중 문구 두기: 같은 문구가 메시지
  곁에도 있어 두 번 보이고, 이미 확정된 결말을 늦춘다. 2026-09-11까지의 방식이다.
- 확인이 끝날 때까지 입력창 자리를 비워 두기: 확인이 길어질 때 화면이 빈 이유를 말해
  주지 않는다.
- 카드 자리에 진행 표시만 두기: 진행 표시가 메시지 곁과 카드 자리 두 곳이 된다.
- 표현 돌아보기에 실패 항목과 개별 재시도 두기: 재시도는 대화 화면이 맡고, 돌아보기는
  준비된 카드만 보여 준다.
- 축하에 Rive, 마스코트, 소리 쓰기: Rive는 상태 기계로 반응하는 그래픽에 맞고 편집기를
  다룰 사람이 필요하다.
