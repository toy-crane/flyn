# 모바일 업데이트 경험

## Decisions

- 일반 EAS Update는 사용자에게 알리지 않고 적용한다. 업데이트 발견이나 다운로드 완료를 이유로 배너, 팝업 또는 다시 시작 요청을 보여 주지 않는다.
- 우선 백그라운드로 다운로드하고 다음 완전한 앱 실행에 적용하는 기본 방식을 사용한다.
- 강제 업데이트는 최소 지원 앱 버전 하나로 관리한다. 그보다 낮은 버전은 업데이트 화면을 보여 주고, 값이 없으면 강제 업데이트를 해제한다. 특정 빌드 차단은 만들지 않는다.
- 최소 지원 버전은 Supabase에 저장하고 운영자가 Dashboard의 Table Editor에서 조절한다. 새 앱 배포가 이 값을 자동으로 올리거나 덮어쓰지 않는다.
- 앱은 로그인 전후에 정책을 읽을 수 있고 일반 사용자는 정책을 바꿀 수 없다.

### 최소 지원 버전 확인

- `public.app_version_policies`는 iOS·Android와 내부·공개 배포의 조합마다 한 행을 둔다. 최소 지원 버전은 `숫자.숫자.숫자` 형식이며 숫자로 비교한다. 설치 주소는 HTTPS여야 하고, 주소 없이 차단을 켤 수 없다. 초기에는 최소 버전과 주소를 모두 비운다.
- 앱은 Supabase Data API로 정책을 읽는다. 운영자가 값을 바꾸면 앱·API 배포 없이 다음 조회에 반영한다. 일반 사용자는 로그인 여부와 관계없이 읽기만 가능하고 쓰기·삭제는 할 수 없다.
- 실제 설치된 사용자용 버전을 비교한다. 최소 버전보다 낮으면 새 작업을 막고, 지원 버전이나 `NULL` 정책을 받으면 차단 화면을 해제한다. OTA 번들의 설정과 빌드 번호를 비교하거나 설치 화면을 열었다는 이유로 업데이트 완료로 판단하지 않는다.
- 앱 시작과 다른 앱에서 돌아올 때 확인한다. 설치 화면에서 돌아오거나 앱을 완전히 다시 열면 일반 확인 간격과 관계없이 확인한다.
- 업데이트 화면은 설치 경로를 여는 `업데이트하기` 버튼 하나를 둔다. 로고와 꾸밈 아이콘, 별도 관리자 화면을 추가하지 않는다.

### 변경 가능한 기본값

다음은 명세에서 구현 기본안으로 정한 값이다. 사용자가 별도로 고정한 값으로 취급하지 않는다.

- 일반 복귀의 확인 간격은 5분, 조회 제한 시간은 5초다. 앱이 열린 동안 주기적으로 반복 조회하지 않는다.
- 조회 실패나 누락된 설정으로 새로 차단하지 않는다. 같은 실행에서 확인한 차단은 재조회 실패만으로 풀지 않고, 인터넷 연결을 확인하고 앱을 다시 열도록 안내한다. 차단을 다음 실행까지 영구 저장하지 않는다.
- 진행 중인 응답·저장은 완료나 실패 처리를 마친 뒤 업데이트 화면으로 전환한다. 설치 경로 열기 실패나 잘못된 응답을 업데이트 완료로 처리하지 않는다.
- 빌드에 새긴 EAS Update 채널로 배포 대상을 구분한다. `internal`과 개발 빌드는 내부 정책을 읽고, 알 수 없는 채널로는 차단하지 않는다. 공개 채널은 공개 빌드를 준비할 때 정한다.
- 기본 문구는 `업데이트가 필요해요`, `플린을 계속 사용하려면 최신 버전으로 업데이트해 주세요`다.

## Boundaries

- 앱 복귀 시 자동으로 다시 시작하는 방식은 아직 선택하지 않았다. 실제 적용 지연이 문제가 될 때 작성 중인 내용과 대화 위치를 보존할 수 있는지 함께 검토한다.
- Table Editor의 필드와 차단 설정·해제 절차는 [최소 지원 버전 운영](../minimum-app-version-operations.md)을 따른다.
- 이 기능이 없는 기존 앱에는 차단 화면을 표시할 수 없다. 먼저 정책을 읽는 앱이 필요하다. 앱 화면 차단은 서버 권한 검사나 구버전 요청 거절을 대신하지 않는다.
- 조회 실패 시 새로 차단하지 않고 계속 열린 앱은 다음 확인까지 기다리므로 항상 즉시 차단되는 정책은 아니다.
- 공개 배포 채널과 실제 스토어 주소는 공개 출시 때 준비한다. 주소가 열리기 전에 임의로 채우지 않는다.
- 운영자가 Dashboard에서 최소 지원 버전 값을 조절하는 것은 승인된 운영 설정 변경이다. 스키마와 앱 코드의 배포 승인은 기존 배포 계약을 따른다.
- 배포 승인과 순서는 [검증과 내부 테스트 배포](continuous-delivery.md)를 따른다.

## Why

배포할 때마다 업데이트를 알리면 사용자는 영어 대화와 관계없는 안내를 반복해서 닫아야 한다. 일반 수정은 사용 흐름을 방해하지 않는 것을 우선한다.

강제 업데이트는 최소 지원 버전만 두어 운영 방법을 단순하게 한다. Supabase에서 값을 직접 바꾸면 운영자가 코드 배포 없이 강제 업데이트를 켜고 해제할 수 있다.

## Reconsider when

- 업데이트 적용 지연이 실제 사용이나 운영에 문제를 일으킬 때
- 작성 중인 내용과 대화 위치를 보존하면서 앱 복귀 시 업데이트를 적용할 필요가 생길 때
