# 모바일 업데이트 경험

## 결정

- 일반 EAS Update는 사용자에게 알리지 않고 적용한다. 업데이트 발견이나 다운로드 완료를 이유로 배너, 팝업 또는 다시 시작 요청을 보여 주지 않는다.
- 우선 백그라운드로 다운로드하고 다음 완전한 앱 실행에 적용하는 기본 방식을 사용한다.

## 경계

- 앱 복귀 시 자동으로 다시 시작하는 방식은 아직 선택하지 않았다. 실제 적용 지연이 문제가 될 때 작성 중인 내용과 대화 위치를 보존할 수 있는지 함께 검토한다.
- 특정 앱 버전의 강제 업데이트 대상, 운영 절차와 화면은 별도 논의 중이다. 일반 업데이트의 무알림 원칙만으로 강제 업데이트 동작을 정하지 않는다.
- 배포 승인과 순서는 [검증과 내부 테스트 배포](continuous-delivery.md)를 따른다.

## 이유

배포할 때마다 업데이트를 알리면 사용자는 영어 대화와 관계없는 안내를 반복해서 닫아야 한다. 일반 수정은 사용 흐름을 방해하지 않는 것을 우선한다.

## 재검토 조건

- 업데이트 적용 지연이 실제 사용이나 운영에 문제를 일으킬 때
- 작성 중인 내용과 대화 위치를 보존하면서 앱 복귀 시 업데이트를 적용할 필요가 생길 때
