# 모바일 업데이트 경험

## 결정

- 일반 EAS Update는 사용자에게 알리지 않고 적용한다. 업데이트 발견이나 다운로드 완료를 이유로 배너, 팝업 또는 다시 시작 요청을 보여 주지 않는다.
- 우선 백그라운드로 다운로드하고 다음 완전한 앱 실행에 적용하는 기본 방식을 사용한다.
- 강제 업데이트는 최소 지원 앱 버전 하나로 관리한다. 그보다 낮은 버전은 업데이트 화면을 보여 주고, 값이 없으면 강제 업데이트를 해제한다. 특정 빌드 차단은 만들지 않는다.
- 최소 지원 버전은 Supabase에 저장하고 운영자가 Dashboard의 Table Editor에서 조절한다. 새 앱 배포가 이 값을 자동으로 올리거나 덮어쓰지 않는다.
- 앱은 로그인 전후에 정책을 읽을 수 있고 일반 사용자는 정책을 바꿀 수 없다.

## 경계

- 앱 복귀 시 자동으로 다시 시작하는 방식은 아직 선택하지 않았다. 실제 적용 지연이 문제가 될 때 작성 중인 내용과 대화 위치를 보존할 수 있는지 함께 검토한다.
- 강제 업데이트의 확인 시점과 화면, 운영 절차는 [최소 지원 앱 버전 명세](../specs/minimum-app-version/spec.md)를 따른다.
- 운영자가 Dashboard에서 최소 지원 버전 값을 조절하는 것은 승인된 운영 설정 변경이다. 스키마와 앱 코드의 배포 승인은 기존 배포 계약을 따른다.
- 배포 승인과 순서는 [검증과 내부 테스트 배포](continuous-delivery.md)를 따른다.

## 이유

배포할 때마다 업데이트를 알리면 사용자는 영어 대화와 관계없는 안내를 반복해서 닫아야 한다. 일반 수정은 사용 흐름을 방해하지 않는 것을 우선한다.

강제 업데이트는 최소 지원 버전만 두어 운영 방법을 단순하게 한다. Supabase에서 값을 직접 바꾸면 운영자가 코드 배포 없이 강제 업데이트를 켜고 해제할 수 있다.

## 재검토 조건

- 업데이트 적용 지연이 실제 사용이나 운영에 문제를 일으킬 때
- 작성 중인 내용과 대화 위치를 보존하면서 앱 복귀 시 업데이트를 적용할 필요가 생길 때
