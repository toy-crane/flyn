# 채팅 메시지 쓰기는 Hono 스트리밍 경계가 소유한다

채팅방 CRUD와 메시지 조회는 기존 하이브리드 데이터 접근 결정대로 앱이
Supabase RLS 안에서 직접 한다. 다만 사용자·AI 메시지 쓰기는 인증된 Hono
스트리밍 요청 하나가 맡고, 모바일에는 메시지 쓰기 권한을 주지 않는다.

사용자 메시지를 앱이 먼저 저장하는 안은 왕복 하나가 줄지만, 스트리밍 요청과
DB 기록이 서로 다른 성공 상태를 만들고 클라이언트가 AI 역할 메시지를 위조하지
못하게 하는 권한도 별도로 복잡해진다. Hono가 방 소유권 확인, 사용자 메시지의
멱등 저장, DB 기록 기반 모델 입력, AI 응답 저장을 한 경계에서 처리하면 모바일이
보낸 과거 대화를 신뢰하지 않아도 되고 저장된 기록과 모델이 본 기록이 일치한다.

대가는 일반 메시지 작성도 API 가용성에 의존한다는 점이다. 이 기능 자체가 모델
호출 없이는 완료되지 않으므로, 오프라인 작성 큐가 제품 요구가 되기 전까지 이
결합을 받아들인다.
