# 모바일 채팅 스크롤

## 결정

- 에피소드와 `AI에게 물어보기`는 같은 스크롤 규칙을 쓴다. 메시지는 `KeyboardAwareLegendList`에 시간 순서대로 넣고 목록을 뒤집지 않는다. 화면보다 짧은 대화도 아래쪽에 배치한다.
- 대화를 처음 열거나 다시 열면 메시지가 준비된 뒤 마지막 내용을 보여 준다. 마지막 내용은 입력창 위에서 온전히 읽을 수 있어야 하며, 입력창이 없으면 하단 안전 영역과 마무리 표시 위에 둔다.
- 질문을 보내면 입력창을 비우고 키보드를 먼저 닫는다. 키보드가 닫히고 입력창이 제자리에 놓인 다음 목록 끝으로 한 번 이동한다. 키보드가 이미 닫혀 있으면 바로 이동한다. 질문을 화면 위쪽에 맞추거나 그 배치를 위해 뒤에 큰 빈 영역을 만들지 않는다.
- 목록 이동에 말풍선 자체의 진입 애니메이션을 겹치지 않는다. 배치 중 답변이 와도 이동을 반복하지 않으며, 목록 끝에 도착한 뒤 자동 추적을 켠다.
- 사용자가 최신 내용을 보고 있으면 스트리밍 답변과 교정 등 새 내용의 끝을 계속 따라간다. 이전 메시지를 읽으려고 위로 스크롤하면 자동 추적을 끄고 읽던 위치를 유지한다.
- 질문을 새로 보내거나 최신 메시지 이동 버튼을 누르면 목록 끝으로 이동한다. 자동 추적은 이동을 마친 뒤에 켠다. 사용자가 직접 목록 끝에 도달해도 다시 켠다.
- 최신 메시지가 보이지 않으면 입력창 위 가로 중앙에 아래쪽 화살표 버튼을 표시한다. 접근성 이름은 `최신 메시지로 이동`이다.
- 최신 메시지 버튼은 누르는 순간이 아니라 목록 끝에 도착한 뒤 사라진다. 끝까지 거리가 한 화면보다 멀면 마지막 한 화면만 부드럽게 이동하고, 가까우면 남은 거리만 이동한다. 중간에 사용자가 스크롤을 멈추거나 이전 메시지를 읽으면 그 위치를 유지한다.
- 최신 메시지 버튼은 입력창 뒤에서 올라와 멈추고 같은 길로 내려가 사라진다. 크기를 움직이거나 Glass 표면의 투명도를 바꾸지 않는다. 중앙 44px 크기와 입력창 위 배치를 유지한다. 숨은 버튼은 누르거나 화면 읽기 기능으로 선택할 수 없다.
- 시스템의 동작 줄이기 설정에서는 목록 이동과 버튼의 나타남·사라짐에 이동 애니메이션을 쓰지 않는다.
- 음수 스크롤 위치, 키보드와 입력창의 움직임, 메시지 크기 변화와 코드가 시작한 스크롤은 사용자가 자동 추적을 끈 것으로 보지 않는다.
- 지난 메시지의 크기가 바뀌거나 사용자가 지난 배울 표현을 펼치면 그 내용을 읽을 수 있도록 위치를 보정한다. 새 답변이나 교정이 도착해도 읽는 중인 사용자를 맨 아래로 돌려보내지 않는다.
- 키보드와 여러 줄 입력창의 높이는 목록 공간에 한 번만 반영한다. 최신 내용을 보던 사용자는 하단을 유지하고, 이전 대화를 읽던 사용자는 읽던 위치를 유지한다.

## 경계

- 이 결정은 준비된 대화를 어디서 보여 줄지만 정한다. 대화 저장·복원 여부와 수명은 [AI 에피소드 프로토콜](ai-episode-protocol.md)과 [모바일 AI에게 물어보기](mobile-ask-ai.md) 등 각 기능의 계약을 따른다.
- 메시지 본문 형식, 서버 경로, 인증, 모델 라우팅과 스트리밍 프로토콜은 이 결정에서 정하지 않는다.
- 읽던 스크롤 위치의 장기 저장이나 이전 메시지를 추가로 불러오는 기능을 새로 만들지 않는다.
- 입력창 뒤와 아래의 배경은 [모바일 AI 채팅 표현](mobile-ai-chat-rendering.md)을 따른다. 배경 효과를 위해 마지막 메시지를 가리거나 목록 공간을 중복 계산하지 않는다.

## 이유

사용자가 대화를 열거나 말을 보냈을 때 최신 내용이 입력창 가까이에 있으면 다음 말을 이어가기 쉽다. 짧은 대화도 같은 기준을 쓰고 질문 상단 배치를 위한 빈 공간을 없애면 대화 길이에 따라 다음 답변을 찾는 위치가 달라지지 않는다.

지난 대사와 교정을 읽는 동안에는 사용자가 고른 위치가 우선한다. 자동 추적을 최신 내용을 보겠다는 상태로 관리하면 답변이 계속 늘어나도 복습을 방해하지 않는다. 사용자가 끝으로 돌아오거나 새 메시지를 보내면 그때 최신 내용을 다시 따라간다.

키보드 닫기와 목록 이동을 순서대로 진행하면 입력창이 움직이는 동안 말풍선이 그 뒤로
들어가는 일을 막을 수 있다. 버튼을 누르는 순간 자동 추적까지 켜면 이동 도중 답변이
늘어날 때 목록이 다시 끝으로 당겨질 수 있다. 도착 후 추적을 켜고 버튼을 숨기면
각 움직임의 시작과 끝이 분명해진다. 먼 거리는 마지막 한 화면만 보여 주어 긴 대화를
빠르게 훑는 움직임을 줄인다.

## 재검토 조건

- 대화를 다시 열 때 마지막 내용보다 지난번 읽던 위치가 필요하다는 요구가 생길 때
- `KeyboardAwareLegendList`의 끝 도달이나 위치 보정 신호가 현재 동작을 안정적으로 표현하지 못할 때
- 질문 전송 뒤에도 키보드를 유지해야 할 때
- 매우 긴 단일 메시지의 렌더링 비용이 실제 문제로 확인될 때
- 키보드 닫기를 기다리는 시간이 전송 반응을 늦춘다는 사용자 검증 결과가 있을 때
- 마지막 한 화면으로 이동하는 경계에서 실측되지 않은 메시지 때문에 위치가 튈 때

## 계속 제외하는 대안

- 위로 스크롤해도 무조건 맨 아래로 이동: 지난 대사와 교정을 읽을 수 없게 된다.
- 새 질문을 위쪽에 맞추고 뒤에 빈 공간을 만들기: 최신 내용을 입력창 가까이에서 이어 읽는 흐름과 맞지 않는다.
- 말풍선 진입과 목록 스크롤을 함께 실행하기: 같은 질문을 서로 다른 속도로 움직인다. 목록 이동만으로 전송 위치를 알기 어렵다는 결과가 있을 때 다시 검토한다.
- 긴 대화 전체를 한 번에 애니메이션으로 지나가기: 이동 거리가 길수록 글이 너무 빠르게 지나간다. 이동 중 지난 문맥을 보여 줄 필요가 생길 때 다시 검토한다.
