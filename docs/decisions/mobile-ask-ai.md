# 모바일 AI에게 물어보기

## 결정

- 화면 문구와 접근성 이름은 모두 `AI에게 물어보기`를 쓴다. `Side chat`은 화면에
  쓰지 않는다. 코드의 식별자와 파일 이름에 남은 `side chat`은 템플릿 채팅이
  쓰는 장치의 이름이고, 사용자에게 보이지 않는다.
- 진입하는 자리는 둘이다. 템플릿 채팅에서는 완료된 부모 AI 답변의 구절을
  선택해 시스템 텍스트 선택 메뉴로 열고, 에피소드에서는 배울 표현 카드의
  버튼으로 연다. 에피소드에는 텍스트 선택 진입을 붙이지 않는다.
- 완료된 부모 AI 답변에서 구절을 선택하면 시스템 텍스트 선택 메뉴에
  `AI에게 물어보기`를 표시한다. 복사, 찾기와 번역 같은 시스템 항목은 유지한다.
  답변을 기다리거나 받는 동안에는 새 대화를 시작하지 않는다.
- 템플릿 채팅에서는 선택한 구절마다 새 대화를 만든다. 같은 답변에서 다시
  시작해도 기존 대화와 합치지 않는다. 첫 질문을 보내기 전에 닫으면 임시 대화와
  초안을 버리고 수에 포함하지 않는다.
- 물어보기 대화는 만든 순간의 부모 대화 처음부터 출처 AI 답변 전체까지를 읽기
  전용 스냅샷으로 이어받는다. 출처만 화면에 읽기 전용으로 보여 주고, 부모
  스냅샷은 메시지 목록에 표시하지 않는다. AI 요청에는 고정한 부모 스냅샷과
  물어보기 대화의 메시지를 함께 보내며 부모 대화와 스냅샷을 바꾸지 않는다.
- 두 진입 모두 [모바일 UI 렌더러 경계](mobile-ui-renderer-boundaries.md)에 따라 Expo
  Router Stack의 `pageSheet`로 열고 같은 시트 옵션을 공유한다. 제목은
  `AI에게 물어보기`이고 원래 대화로 돌아갈 때는 뒤로 가기가 아니라 닫기를
  사용한다. 화면이 열린 뒤 입력창에 포커스를 주는 시점은
  [모바일 진입 키보드](mobile-keyboard-entry-focus.md)를 따른다. 첫 질문 전에는
  출처와 입력창만 보여 준다.
- 에피소드에서는 배울 표현 하나에 대화 하나다. 같은 카드의 버튼을 다시 눌러도 새
  대화를 만들지 않고, 나눈 말과 쓰다 만 초안이 그대로 있는 그 대화를 다시 연다.
  출처는 선택한 구절이 아니라 그 교정이고, 배울 표현 라벨과 함께 내가 쓴 원문과
  고친 문장을 읽기 전용으로 보여 준다.
- 에피소드의 대화는
  [AI 에피소드 프로토콜](ai-episode-protocol.md)의 `POST /ai/episode/ask`를
  쓰고, 에피소드 대화 스냅샷과 그 교정을 문맥으로 보낸다. 템플릿 채팅의 대화는
  기존 `POST /ai/chat`을 그대로 쓴다.
- 에피소드의 대화에는 입력창 위의 수 표시와 다시 열기 목록을 두지 않는다.
  돌아갈 길은 대화에 남아 있는 그 카드다.
- 물어보기 대화의 새 메시지는 부모 채팅과 같은 표현, 스크롤, 키보드, 스트리밍과
  메시지 동작을 사용한다. 구체적인 동작은
  [모바일 AI 채팅 표현](mobile-ai-chat-rendering.md),
  [모바일 채팅 스크롤](mobile-chat-scrolling.md),
  [모바일 채팅 메시지 동작](mobile-chat-message-actions.md)을 따른다. 여기의 AI
  답변도 선택할 수 있지만 그 선택 메뉴에는 `AI에게 물어보기`를 넣지 않는다.
- 첫 질문을 보낸 대화는 그것을 연 화면이 살아 있는 동안 메모리에 보관한다.
  시트를 닫아도 메시지, 초안, 전송 상태와 수정 상태를 유지하고 진행 중인 답변도 계속
  받는다. 각 대화는 이 상태를 따로 가진다.
- 템플릿 채팅에서는 첫 질문을 보낸 대화가 있으면 입력창 위에 그 수를
  `AI에게 물어보기 N개`로 표시한다. 하나면 바로 다시 열고, 여러 개면 최근에 만든
  순서의 목록에서 고른다. 목록은 선택한 구절과 마지막으로 오간 말을 각각 한 줄
  평문으로 보여 준다.
- 부모 화면을 나가거나 로그아웃하거나 앱 프로세스가 끝나면 그 화면의 모든 물어보기
  대화를 지운다. 템플릿 채팅에서 부모 메시지 수정이나 답변 다시 받기로 출처 답변이
  사라지면 해당 대화의 진행 중인 답변을 먼저 멈추고 함께 지운다.
- 수 표시는 접근성 역할을 버튼으로 알린다. 하나일 때는
  `AI에게 물어보기 1개 다시 열기`, 여러 개일 때는 `AI에게 물어보기 N개 고르기`를
  접근성 이름으로 쓴다. 목록 항목은 선택한 구절과 `AI에게 물어보기 열기`를 함께
  알리고, 시트 닫기 버튼은 `AI에게 물어보기 닫기`로 알린다.

## 경계

- 물어보기 대화는 그것을 연 화면의 메모리 수명만 따른다. DB, Supabase 테이블, 기기
  저장소, 지난 대화 조회 API, 앱 재시작 뒤 복구와 기기 간 동기화를 추가하지 않는다.
- 물어보기 대화 안에서 또 다른 물어보기를 만들거나, 부모 대화와 합치거나, 답변을
  부모 대화로 보내지 않는다. 에피소드에서 고친 문장을 본 채팅으로 가져오는 일은 이
  시트가 아니라 교정 카드의 다시 보내기가 맡는다. 부모 스냅샷에는 수정, 다시 받기와
  메시지 동작을 붙이지 않는다.
- 첨부, 이미지, 음성 입력과 모델 고르기를 추가하지 않는다.
- [AI 채팅 프로토콜](ai-chat-protocol.md)의 기존 `POST /ai/chat`, 인증, 모델 라우팅과
  UI message 스트리밍 프로토콜을 그대로 사용한다. Expo Web은 지원하지 않는다.
- 네이티브 Stack이 시트 배경, 모서리, 전환과 닫기 제스처를 소유한다. `push`,
  `formSheet`, BottomSheet와 커스텀 시트 모양으로 바꾸지 않는다.

## 이유

물어보기는 선택 메뉴에서 끝나는 짧은 작업이 아니라 키보드, 긴 메시지와 계속되는
대화를 가진 독립 흐름이다. `pageSheet`는 이 대화 공간과 라우트 수명을 제공하고,
네이티브 Stack의 닫기와 전환 동작도 유지한다.

부모 대화 전체를 메시지 목록에 보여 주면 읽기 전용 문맥과 수정 가능한 메시지가
섞인다. 부모 대화는 고정한 AI 문맥으로만 보내고 출처만 화면에 보여 주면 원래 대화를
바꾸지 않으면서 질문의 출발점을 확인할 수 있다.

물어보기 대화를 출처마다 분리하고 그것을 연 화면의 수명에 묶으면 서로 다른 질문의
상태가 섞이지 않는다. 템플릿 채팅의 입력창 위 수 표시는 부모 답변을 다시 찾지 않아도
같은 자리에서 돌아갈 길을 제공한다. 에피소드에서는 그 자리를 교정 카드가 이미
가지고 있어 수 표시가 필요하지 않다.

## 재검토 조건

- 앱을 다시 시작하거나 다른 기기에서 지난 물어보기를 이어야 할 때
- 부모 스냅샷과 물어보기 메시지를 함께 보내는 요청이 모델 문맥 한도, 비용 또는
  전송 크기 문제를 반복해서 만들 때
- 한 부모 대화에 물어보기가 많이 생겨 현재 수 표시와 목록으로 찾기 어려울 때
- 물어보기를 중첩하거나 부모 대화와 합쳐야 한다는 제품 요구가 생길 때
- 에피소드에서 카드만으로 지난 물어보기를 다시 찾기 어렵다고 관찰될 때
- 네이티브 `pageSheet`가 필요한 대화 공간이나 플랫폼 동작을 안정적으로 제공하지 못할 때

## 계속 제외하는 대안

- BottomSheet 또는 `formSheet`: 부분 높이와 높이 전환에 맞지만 긴 대화 공간과 독립
  라우트 수명이 부족하다.
- 부모 대화 전체를 물어보기 목록에 표시: 읽기 전용 문맥과 수정 가능한 메시지가
  섞이고 같은 대화를 화면에 반복한다.
- 같은 부모 답변의 물어보기를 하나로 합치기: 서로 다른 구절과 질문의 상태가 한
  대화에 섞인다.
- 출처 답변 아래에 다시 열기 표시 두기: 템플릿 채팅에서는 대화 어디에서나
  돌아가려면 출처 답변을 다시 찾아야 한다. 에피소드의 교정 카드는 사정이 달라서, 그
  카드가 곧 대화에 남아 있는 진입점이다.
- 첫 버전부터 물어보기 저장: 지금의 화면 수명보다 긴 수명과 동기화 규칙을 새로
  만든다.
- 에피소드의 시트에 본 채팅으로 보내는 장치 두기: 반영의 루프는 카드의 다시
  보내기로 이미 닫혀 있어 카드의 일을 복제한다.

## 보존할 근거

- `react-native-enriched-markdown@1.0.1`은 렌더링한 평문을 밖으로 내주지 않는다.
  다시 열기 목록은 마지막 말을 한 줄 평문으로 보여 주기 위해 짝이 맞는 Markdown
  표시만 제거하고, `owner_id`나 `a => b`처럼 짝이 아닌 낱개 문자는 보존한다.
  렌더러가 평문을 제공하게 되면 이 변환을 렌더러 출력으로 바꾼다.
