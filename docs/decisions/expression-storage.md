# 표현 저장 구조

## 결정

- 번역한 인물 대사, 영어 교정, 한국어 입력의 영어 안내는 `expressions`에서 문장과 뜻을 한 번만 보관한다. 대화, 표현 돌아보기, 표현 노트는 같은 표현을 읽는다.
- `expressions.kind`는 영어 문장의 출처를 구분한다. `dialogue`는 인물 대사, `correction`은 사용자의 영어를 고친 문장, `translation`은 사용자의 한국어를 영어로 옮긴 문장이다. 한국어 뜻의 유무를 구분하는 값이 아니다.
- 검사 판정은 사용자 메시지의 `expression_status`에 둔다. 완료된 판정 없음은 `NULL`, 교정 또는 안내 표현 제공은 `provided`, 문제없음은 `natural`, 뜻을 알 수 없음은 `unclear`다. AI 메시지는 검사 대상이 아니므로 `NULL`이다. 처리 중과 통신 실패는 완료 판정으로 저장하지 않는다.
- `episode_expression_results`는 제거한다. 표현 제공 판정과 표현 내용은 함께 확정하며, 메시지에는 표현의 종류를 중복 저장하지 않는다. 판정 갱신은 본문 수정이나 대화 순서 변경이 아니다.
- 표현 노트에 담았는지는 같은 표현의 `saved_at`으로 구분한다. `NULL`이면 담지 않은 표현이고, 값이 있으면 마지막으로 담은 시각이다. 별도의 노트 복사본이나 책갈피 테이블은 두지 않는다.
- 이미 담긴 표현을 다시 저장해도 내용과 저장 시각을 바꾸지 않는다. 취소한 뒤 다시 담으면 새 저장 시각을 기록한다.
- 원본이 남아 있는 표현을 노트에서 빼면 `saved_at`만 비운다. 대화의 번역과 교정 결과는 유지한다.
- 원본 메시지를 지우면 담지 않은 표현은 함께 지운다. 담긴 표현은 원본 연결만 끊고 문장, 뜻, 설명과 스토리·에피소드 출처를 보존한다. 원본이 없는 표현을 노트에서 빼면 그 표현도 지운다.
- 표현은 계정에 속한다. 같은 원본의 같은 대사 또는 배울 표현은 하나만 존재한다. 서로 다른 메시지나 회차의 문장이 같아도 합치지 않는다.
- AI 응답은 기존처럼 여러 화자의 대사를 포함한 메시지 하나로 저장한다. 인물 대사는 `message_id`와 0부터 시작하는 `dialogue_index`로 구분한다. 사용자 메시지 전체의 배울 표현에는 대사 위치가 없다.
- 문제없음과 뜻을 알 수 없음은 완료된 검사 결과이며 노트에 담을 표현이 아니다. 검사 완료와 필요한 표현 내용은 함께 확정되어야 한다. 실패를 문제없음으로 처리하지 않는다.

## 경계

- 화면, 번역 생성 조건과 모델 호출의 수명은 [인물 대사 번역](mobile-utterance-translation.md), [표현 노트](expression-note.md), [AI 에피소드 프로토콜](ai-episode-protocol.md)이 정한다.
- 계정 삭제 뒤에도 표현을 보존하는 결정이 아니다. 계정 삭제의 기존 범위를 따른다.
- 회차가 없는 첫 장면의 뜻은 기존처럼 화면에만 있다가 회차가 생길 때 보관한다.

## 이유

번역과 노트 저장은 행동이 다르지만 같은 문장과 뜻을 복사할 필요는 없다. 같은 표현에 저장 시각을 두면 별도 연결 테이블 없이 두 행동을 구분하고, 중복 저장과 두 복사본을 맞추는 처리를 없앨 수 있다. 대신 삭제 시 저장 여부와 원본 유무를 함께 판단한다.

## 재검토 조건

- 사용자가 노트에서 원본과 다른 문장이나 뜻을 직접 편집해야 할 때.
- 하나의 표현을 여러 사람이 공유하거나 여러 노트에 담아야 할 때.
- 대사 하나만 수정하거나 다시 생성하는 기능이 필요해 메시지 저장 단위가 바뀔 때.
