# 모바일 스토리 탐색

## 결정

- 기본 탭은 `홈 / 탐색 / 스토리`다. 홈은 영어 학습 공간으로 남기고 구체적인 내용은
  추후 설계한다. 탐색은 플레이할 스토리를 찾는 곳, 스토리는 내가 대화한 스토리로
  돌아가는 곳이다.
- 탐색은 전체 스토리의 표지, 제목과 소개를 보여 주고 상세로 연결한다. 특정 플레이의
  진행 바를 전체 스토리의 상태처럼 표시하지 않는다.
- 스토리 탭은 대화 기록이 있는 스토리를 하나씩 보여 준다. 목록에서 해당 스토리의
  대화 기록으로 이동하고, 거기서 개별 플레이를 고르거나 이어간다. 첫 장면만 열고
  사용자 메시지를 보내지 않은 플레이는 이 목록에 새 항목을 만들지 않는다.
- 향후 사용자가 스토리를 제작하고 공개하는 커뮤니티로 확장한다. 현재 공식 콘텐츠만
  있다는 이유로 탐색을 공식 콘텐츠 전용으로 정의하지 않는다. 제작·게시·신고·검토와
  추천·정렬 정책은 별도로 설계한다.
- 스토리 상세는 표지, 제목, 소개와 고정된 에피소드 목록을 보여 준다. 모든 화의
  제목과 결말을 드러내지 않는 상황 설명을 공개한다. 회차별 진행 바, 잠금 표시와
  결과 문구는 이 목록에 넣지 않고, 목록에서 특정 화를 바로 플레이하지 않는다.
- 끝내지 않은 회차가 있으면 `이어서 하기`와 `새로 시작하기`를 함께 보여 준다.
  두 버튼에 화 번호나 회차 번호를 덧붙이지 않는다. 새로 시작하기는 1화로 바로
  이동하며, 기존 기록 보존을 설명하는 별도 문구나 확인 단계를 추가하지 않는다.
- 상세 우측 상단의 History 아이콘은 `대화 기록`을 연다. 기존 네이티브 헤더 버튼
  규격을 사용하고, 접근성 이름도 `대화 기록`으로 둔다.
- 대화 기록은 상단에 스토리 표지, 제목과 소개를 보여 주고 아래에 회차별 카드를
  둔다. 카드는 시작 날짜와 시간을 제목으로 쓰고, 분절 진행 바와 대화 위치 또는 결과를 보여 준다.
  여러 회차를 이어갈 수 있으므로 특정 회차에 `현재 플레이` 표시를 붙이지 않는다.
- 끝낸 화의 대화는 대화 기록에서 읽기 전용으로 연다. 끝내지 않은 회차는 그 카드에서
  이어간다. 기록을 열어 보는 것만으로 다른 회차의 진행이나 기억을 바꾸지 않는다.
- 여러 미완료 회차 중 상세의 이어하기 대상을 고르는 기준은
  [스토리 다시 플레이 스펙](../specs/story-replay/spec.md)의 미확정 항목에서 다룬다.
- iOS 스토리 상세는 투명한 네이티브 헤더와 상단의 부드러운 스크롤 경계 효과를
  사용한다. 헤더 배경과 구분선을 직접 그리지 않고 본문이 헤더 뒤로 이어지게 한다.
- 진행과 결말의 화면 표기는
  [스토리 진행·결말 화면 표기](story-progress-and-ending-display.md)를 따른다.
  대화 저장과 읽기 전용 범위는 [AI 에피소드 프로토콜](ai-episode-protocol.md)이
  소유한다.

- 홈의 `새 대화` 버튼과 독립된 일반 채팅은 제공하지 않는다. 에피소드는 홈 카드에서
  시작하거나 이어 가며, 교정 카드의 `AI에게 물어보기`는 유지한다.

## 경계

- 스토리 제작, 공유, 탐색 피드와 추천을 만들지 않는다. 이 기능은 제품 정의를
  먼저 거친다.
- 공식 스토리가 한 자릿수인 동안 검색과 분류를 두지 않는다.
- 카드의 정확한 크기, 간격과 표지 그림 스타일은 이 계약이 정하지 않는다.

## 이유

홈과 스토리 탭에 같은 이어 하기 카드를 놓으면 두 화면의 역할이 겹친다. 홈은 다음
행동 하나를 강하게 보여 주고, 스토리 탭은 전체 목록과 기록을 보여 주는 편이
사용자가 이어 갈 때와 새로 고를 때를 각각 짧게 만든다.

제품이 첫 동선을 정하면 레벨 테스트 없이 통제한 장면에서 시작할 수 있다. 그렇다고
다른 스토리를 막을 필요는 없다. 기본 경로와 선택 가능성을 나누면 첫 장면의 의도와
사용자의 선택을 함께 지킨다.

상세에서 회차별 진행과 콘텐츠 소개를 함께 보여 주면 사용자가 어느 회차의 상태인지
먼저 해석해야 한다. 상세는 스토리 자체를 소개하고, 회차별 대화와 결과는 기록에서
보여 준다. 상황 설명은 남겨 무엇을 플레이할지 판단할 수 있게 한다.

## 재검토 조건

- 공식 스토리가 늘어 순서 목록만으로 원하는 스토리를 찾기 어려워질 때
- 진행 중인 스토리가 많아 홈의 보조 목록이 다음 행동을 흐릴 때
- 고정된 에피소드 상황 설명이 실제 사용자에게 스포일러로 받아들여질 때

## 계속 제외하는 대안

- 스토리 탭에 이어 하기 카드를 다시 두기: 홈과 같은 내용을 되풀이해 두 화면의
  역할이 겹친다.
- Activity와 Saved 탭을 유지하기: 현재 제품에서 각각 맡을 독립된 사용자 행동이
  없다.
- 상세를 최근 생성한 회차의 진행 화면으로 쓰기: 다른 회차를 이어갈 때 목록의
  기준이 모호해진다.
- 특정 회차를 현재 플레이로 강조하기: 여러 미완료 회차를 독립적으로 이어갈 수 있다.
