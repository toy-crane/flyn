# 모바일 스토리 탐색

## 결정

- 기본 탭은 `홈 / 탐색 / 스토리 / 노트`다. 홈은 영어 학습 공간으로 남기고 구체적인
  내용은 추후 설계한다. 탐색은 플레이할 스토리를 찾는 곳, 스토리는 내가 대화한
  스토리로 돌아가는 곳, 노트는 대화에서 손으로 담아 둔 표현이 스토리와 상관없이
  모이는 곳이다.
- 탐색은 스토리의 표지, 제목과 소개를 보여 주고 상세로 연결한다. 목록 위에는 필터 칩
  `전체`와 `내 스토리`를 두며, 구역 제목은 두지 않는다. `전체`는 내가 만든 스토리를
  위에, 공식 스토리를 아래에 이어서 보여 주고, 공식 스토리에는 화면에서 이름을 붙이지
  않는다. `전체`의 만든 스토리는 만든 순서의 역순이다. 칩은 HeroUI `TagGroup` 기본
  패턴을 쓰고, 만든 스토리가 없어도 늘 보이며, 탐색을 다시 열면 `전체`로 돌아간다.
  `내 스토리`가 비었으면 목록 자리 중앙에 `아직 내 스토리가 없어요.`와 Primary
  `스토리 만들기` 버튼을 보여 준다. 특정 플레이의 진행 바를 전체 스토리의 상태처럼
  표시하지 않는다.
- 스토리 표지는 [모바일 이미지 로딩](mobile-image-loading.md)을 따른다. 원본 로딩 중에는 해당 이미지의 BlurHash 미리보기를 보여 주고 짧은 전환으로 원본을 표시한다. 표지 이모지는 표시하지 않는다.
- 스토리 탭은 대화 기록이 있는 스토리를 하나씩 보여 준다. 목록에서 해당 스토리의
  대화 기록으로 이동하고, 거기서 개별 플레이를 고르거나 이어간다. 첫 장면만 열고
  사용자 메시지를 보내지 않은 플레이는 이 목록에 새 항목을 만들지 않는다.
- 사용자는 탐색에서 자기 스토리를 만든다. 탐색 헤더 오른쪽의 + 아이콘
  `Stack.Toolbar.Button`(접근성 이름 `스토리 만들기`)이 `스토리 만들기` 화면을 탭
  바깥에서 연다. 만든 스토리는 만든 사람에게만 보인다. 제작 대화와 각본 생성은
  [스토리 만들기](story-creation.md)가 정한다. 게시·신고·검토와
  추천·정렬 정책은 별도로 설계하되, 현재 공식 콘텐츠와 만든 사람만 보는 스토리뿐이라는
  이유로 탐색을 그 둘 전용으로 정의하지 않는다.
- 스토리 상세는 표지, 제목, 소개와 고정된 에피소드 목록을 보여 준다. 모든 화의
  제목과 결말을 드러내지 않는 상황 설명을 공개한다. 회차별 진행 바, 잠금 표시와
  결과 문구는 이 목록에 넣지 않고, 목록에서 특정 화를 바로 플레이하지 않는다.
- 스토리 상세는 기록 유무나 완료 상태와 관계없이 하단에 Primary `대화 시작하기` 하나를 둔다.
  [모바일 하단 CTA](mobile-bottom-cta.md)를 따른다. 상세는
  [모바일 탭과 상세 화면 배치](mobile-tab-navigation.md)에 따라 탭 바깥에서 열어
  탭 바를 표시하지 않는다. 버튼은 새 플레이의 1화를 바로 연다.
  상세에는 `이어서 하기`를 두지 않는다. 이어갈 회차는 대화 기록의 개별 카드에서 고른다.
  기존 기록 보존을 설명하는 별도 문구나 확인 단계를 추가하지 않는다.
- 상세 우측 상단의 History 아이콘은 `대화 기록`을 연다. 기존 네이티브 헤더 버튼
  규격을 사용하고, 접근성 이름도 `대화 기록`으로 둔다.
- 스토리 탭은 `최근 대화`라는 목록 제목을 사용하고, 스토리별 마지막 사용자 메시지
  시각으로 정렬한다. 기록을 열어보기만 하거나 빈 플레이를 시작해도 순서는 바뀌지 않는다.
- 스토리 탭에 기록이 없으면 본문 중앙에 대화 아이콘과 `아직 대화한 스토리가 없어요.`를
  보조색의 보통 굵기로 보여 준다. 아래에는 탐색 탭을 여는 Primary `스토리 둘러보기` 버튼을 둔다.
- 대화 기록은 진입 경로와 관계없이 네이티브 헤더 오른쪽에 `새 대화` 텍스트 버튼을 둔다.
  별도 강조색이나 커스텀 테두리를 추가하지 않고 시스템 표현을 따른다. iOS 26의 시스템 캡슐 배경을 숨기지 않는다. 하단 CTA는 두지 않는다.
  새 플레이의 1화를 열며, 입력 없이 뒤로 가면 기존 기록으로 돌아간다.
- 대화 기록도 탭 바깥의 상세 계층으로 연다. 대화 기록에는 하단 CTA가 없지만,
  스토리 상세와 같은 상세 흐름에서 개별 플레이를 고르고 이어 가므로 상위 탭을 함께 표시하지 않는다.
  상세에서 열었으면 상세로, 스토리 목록에서 열었으면 해당 목록으로 돌아간다.
  기록에서 대화로 들어갔다 돌아오는 동안에도 탭 바를 표시하지 않는다.
- iOS의 헤더 텍스트 액션은 `Stack.Toolbar.Button`을 사용한다. Android에서 이 컴포넌트가
  텍스트를 지원하지 않으면 `Stack.Toolbar.View` 안에 플랫폼에 맞는 텍스트 컨트롤을 둔다.
- 대화 기록은 상단에 스토리 표지, 제목과 소개를 보여 주고 아래에 회차별 카드를
  둔다. 소개와 카드 사이에는 얇은 구분선과 보조색·중간 굵기의 작은 `최근 대화` 소제목을 둔다.
  기록이 없으면 소제목 아래 남은 본문 중앙에 대화 아이콘과 `아직 나눈 대화가 없어요.`를
  보조색의 보통 굵기로 보여 준다. 이 빈 상태에는 버튼을 두지 않는다. 헤더의 `새 대화`가
  새 플레이를 시작한다. 소개와 카드는 한 화면에서 함께 스크롤한다.
  카드는 만든 순서의 역순으로 정렬하고 시작 날짜와 시간을 제목으로 쓴다.
  이어 가도 시작 시각과 카드 순서는 바꾸지 않는다. 분절 진행 바와 대화 위치 또는
  결과를 보여 주며, 여러 회차를 이어갈 수 있으므로 특정 회차에 `현재 플레이`
  표시를 붙이지 않는다.
- 끝낸 화의 대화는 대화 기록에서 읽기 전용으로 연다. 끝내지 않은 회차는 그 카드에서
  이어간다. 카드를 펼치면 해당 회차에서 끝낸 화의 대화를 볼 수 있다. 기록을 열어
  보는 것만으로 다른 회차의 진행이나 기억을 바꾸지 않는다.
- 이어갈 회차는 사용자가 대화 기록의 카드에서 고른다. 상세나 기록 조회가 기본 대상을 자동으로 고르지 않는다.
- 목록, 상세, 대화 기록과 개별 대화를 불러오지 못하면 헤더는 유지하고 본문에서
  실패와 `다시 시도`를 보여 준다. 조회는 성공했지만 기록이 없으면 빈 상태를 보여
  주고 재시도는 두지 않는다.
- 시작 실패는 시작을 시도한 화면 위에서 알린다. 닫으면 그 화면에 머물고 재시도는
  같은 시작 동작을 다시 실행한다. 실패하거나 알림을 닫는 것만으로 회차를 만들지
  않는다. 다음 화로 넘어가도 최초의 상세 또는 대화 기록 복귀 경로를 유지한다.
- iOS 스토리 상세는 투명한 네이티브 헤더와 상단의 부드러운 스크롤 경계 효과를
  사용한다. 헤더 배경과 구분선을 직접 그리지 않고 본문이 헤더 뒤로 이어지게 한다.
- 진행과 결말의 화면 표기는
  [스토리 진행·결말 화면 표기](story-progress-and-ending-display.md)를 따른다.
  대화 저장과 읽기 전용 범위는 [AI 에피소드 프로토콜](ai-episode-protocol.md)이
  소유한다.
- 홈의 `새 대화` 버튼과 독립된 일반 채팅은 제공하지 않는다. 에피소드는 스토리 상세에서
  시작하거나 대화 기록에서 새로 시작하고 이어 간다. 교정 카드의 `AI에게 물어보기`는 유지한다.

## 경계

- 공유, 게시, 탐색 피드와 추천을 만들지 않는다. 이 기능은 제품 정의를 먼저 거친다.
- 공식 스토리가 한 자릿수인 동안 검색과 분류를 두지 않는다.
- 카드의 정확한 크기, 간격과 표지 그림 스타일은 이 계약이 정하지 않는다.

## 이유

탐색은 전체 스토리를 살펴보는 곳이고, 스토리는 사용자가 대화한 스토리로 돌아가는 곳이다.
둘을 나누면 콘텐츠 소개와 개별 대화 진행의 기준이 섞이지 않는다. 홈은 별도의 영어 학습
공간으로 남겨 둔다.

상세에서 회차별 진행과 콘텐츠 소개를 함께 보여 주면 사용자가 어느 회차의 상태인지
먼저 해석해야 한다. 상세는 스토리 자체를 소개하고, 회차별 대화와 결과는 기록에서
보여 준다. 상황 설명은 남겨 무엇을 플레이할지 판단할 수 있게 한다.

구역 제목 대신 필터 칩을 쓰는 것은 공식 스토리에 붙일 자연스러운 이름이 없어서다.
`플린이 만든`은 플린을 작가로 만들고, `모든 스토리`는 내 것 아래에서 뜻이 겹치며,
`추천`과 `기본`은 없는 뜻을 만든다. 화면을 나누는 일이 아니라 같은 목록을 거르는
일이라 세그먼트나 상단 탭이 아니라 칩을 쓴다.

빈 안내에 굵은 제목을 쓰지 않는 것은 사용자가 과한 굵기와 어색한 배치를 지적하고
본문 중앙의 보통 굵기 안내를 고른 결과다.

## 재검토 조건

- 공식 스토리가 늘어 순서 목록만으로 원하는 스토리를 찾기 어려워질 때
- 대화한 스토리가 많아 최근순 목록만으로 찾기 어려워질 때
- 고정된 에피소드 상황 설명이 실제 사용자에게 스포일러로 받아들여질 때

## 계속 제외하는 대안

- 스토리 탭에서 특정 회차를 대표 이어하기 대상으로 고르기: 여러 미완료 회차 중
  어느 대화를 여는지 모호해진다. 스토리별 기록에서 사용자가 직접 고른다.
- 활동 탭 두기: 현재 제품에서 맡을 독립된 사용자 행동이 없다. `노트` 탭은 대화에서
  손으로 담은 문장을 다시 보는 일이 스토리 진행과 별개의 행동이라 따로 둔다.
- 상세를 최근 생성한 회차의 진행 화면으로 쓰기: 다른 회차를 이어갈 때 목록의
  기준이 모호해진다.
- 특정 회차를 현재 플레이로 강조하기: 여러 미완료 회차를 독립적으로 이어갈 수 있다.
