# 시뮬레이터 검증은 agent-device로 한다 — 좌표로 찍지 않는다

Claude Code에는 iOS 시뮬레이터를 조작하는 내장 도구가 딸려 있다. 설치가 필요
없어 손에 먼저 잡히지만, **그 도구는 스크린샷을 보고 좌표를 찍는 방식이다.**
이것이 명시적 결정인 이유는 그 편의성 때문이다 — 아무 규칙이 없으면 세션은
당연히 이미 붙어 있는 쪽을 쓴다.

이 저장소의 화면은 [expo-ui-by-default](expo-ui-by-default.md)에 따라 진짜
SwiftUI다. 좌표 방식이 가장 안 맞는 대상이다. 키보드가 올라오며 레이아웃이
밀리고, 시트·메뉴는 프로세스 밖에 뜨고, 한 번 얻은 좌표는 다음 프레임에
무효가 된다. `agent-device`는 XCTest 접근성 트리를 읽어 `@e7 [text-field]`
같은 ref나 셀렉터로 요소를 지목하므로 이 셋 다 해당이 없다.

- **MCP와 CLI를 둘 다 열어 뒀다.** MCP는 `.mcp.json`에 project 스코프로 붙였다.
  둘은 같은 데몬으로 들어가므로 **능력 차이가 없다** — MCP 쪽 이득은 셸 따옴표를
  거치지 않는 인자 전달과 별도 권한 표면뿐이다. 그러니 어느 쪽을 쓰든 맞고,
  섞어 써도 된다.
- **명령어를 지침에 옮겨 적지 않는다.** `.agents/skills/agent-device` 스킬이
  버전에 맞는 `agent-device help` 토픽으로 보내주므로, 여기 베껴 두면 CLI가
  올라갈 때 어긋나기만 한다.
- **앱 빌드는 여전히 Expo 몫이다.** `agent-device`는 이미 빌드된 앱을 설치·실행·
  조작하고 증거(스크린샷·로그·네트워크·perf)를 남길 뿐, 빌드하지 않는다.
- **소셜 로그인 벽은 그대로다.** Google은 JWKS 서명 검증, Apple은 2FA 채널
  부재가 원인이라 화면을 더 정확히 눌러서 뚫리는 것이 아니다. 자동 검증은
  계속 이메일 OTP 경로로 한다 — [auth-verification](../auth-verification.md).

전환 비용은 전역 npm 패키지 하나다. 맞지 않으면 지우면 되고, 내장 도구는
그대로 남아 있다.
