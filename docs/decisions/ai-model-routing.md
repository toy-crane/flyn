# AI 모델 라우팅

## 결정

- 서버의 모델 호출은 Vercel AI Gateway를 거친다.
- `apps/api`는 AI SDK에서 Gateway가 지원하는 `provider/model` 형식의 모델 식별자를 사용한다.
- 모델 식별자는 서버 설정으로 관리한다. 모바일 앱은 모델을 고르거나 요청에 모델 식별자를 넣지 않는다.
- 채팅, 에피소드 장면, 표현 교정과 표현 질문은 모두 GPT 5.6 Luna(`openai/gpt-5.6-luna`)를 사용한다. 로컬 개발과 배포 환경의 `AI_GATEWAY_MODEL`을 같은 값으로 설정한다.
- 모델 ID는 소스 코드에 고정하지 않는다. 서버 설정과 설정 예시에서 관리한다.

## 경계

- 첫 구현에서 모델 제공자의 SDK를 직접 호출하지 않는다.
- 이 결정은 fallback 순서, BYOK 사용 여부, 예산과 사용량 제한을 정하지 않는다.
- 배포 환경의 Gateway 인증과 로컬 개발용 자격 증명은 Vercel의 권장 설정을 따른다. 인증 방식 자체는 앱의 공개 계약으로 만들지 않는다.

## 이유

AI Gateway를 사용하면 모바일 프로토콜과 서버 코드를 크게 바꾸지 않고 모델이나 제공자를 바꿀 수 있다. Gateway가 제공하는 제공자 장애 시 재시도와 사용량 확인도 별도 연동 없이 사용할 수 있다. Vercel은 Gateway를 통한 토큰 사용에 별도 인상분을 붙이지 않는다.

에피소드는 사용자가 말을 보낼 때마다 장면과 표현 교정을 각각 호출한다. 반복 호출 비용을 고려해 모든 AI 기능에서 Luna를 사용한다.

## 재검토 조건

- 필요한 모델 기능을 AI Gateway에서 제공하지 않을 때
- 자체 호스팅 모델을 사용하게 될 때
- 배포 환경이 Vercel에서 벗어날 때
- Gateway의 안정성이나 비용이 제품 요구에 맞지 않을 때

## 계속 제외하는 대안

- 모델 제공자 SDK 직접 사용: 제공자별 패키지와 키 관리가 서버 코드에 묶인다. Gateway에서 제공하지 않는 기능이 꼭 필요할 때만 재검토한다.
