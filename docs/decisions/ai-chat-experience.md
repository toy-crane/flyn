# 스트리밍 대화 화면의 상호작용

이 계약은 AI 응답이 스트리밍되는 모든 대화 표면에 적용된다. 현재는 롤플레잉
에피소드의 대화와 문장 질문이 여기 해당한다.

## Decisions

- 사용자 메시지는 즉시 오른쪽 중립 말풍선에 보이고, AI 응답은 전체 폭
  Markdown으로 스트리밍한다. composer는 텍스트만 받으며 최대 4,000자다.
- 대화 화면은 가상 목록, streaming store, keyboard controller와 composer가 한
  scroll 경계를 공유하는 RN surface다.

생성 상태는 다음처럼 표현한다.

| 상태 | 대화 영역 | composer action |
| --- | --- | --- |
| 입력 없는 `ready` | 추가 표시 없음 | 비활성 전송 |
| 입력 있는 `ready` | 추가 표시 없음 | 전송 |
| `submitted` | AI 응답 위치의 system spinner | 탭 가능한 중단 spinner |
| `streaming` | 실제 text 전까지 spinner, 이후 응답만 표시 | 중단 symbol |
| `error` | spinner 제거, 오류와 재시도 표시 | 입력 상태에 따른 전송 |

- `Thinking`, 정적 말줄임표, stream cursor와 최소 spinner 노출 시간을 만들지 않는다.
- 첫 내용 전에 중단하면 빈 AI 메시지를 남기지 않는다. 일부 내용 뒤 사용자가
  중단하면 받은 내용을 `stopped`로 보존하고 오류로 표시하지 않는다.
- 맨 아래 또는 72pt 이내에서는 새 tail을 즉시 따라가되 content 변화마다 smooth
  animation을 다시 시작하지 않는다. 위를 읽는 중에는 viewport를 유지한다.
- 맨 아래에서 벗어나면 composer 위 중앙에 `맨 아래로` action을 표시하고, 사용자가
  누를 때만 한 번 부드럽게 이동한다.
- 키보드는 `whenAtEnd` 정책으로 맨 아래의 composer와 tail을 함께 올린다. 과거를
  읽는 중에는 위치를 유지하고, 실제 composer 높이를 목록 inset에 반영한다.
- pull-to-refresh spinner는 사용자가 직접 당긴 요청만 나타낸다. background fetch,
  query invalidation과 화면 밖 refetch를 `refreshing`에 연결하지 않는다.
- 메시지에 곁들이는 표시는 말풍선 본문이 아니라 **고정 폭 열**에 둔다. 서버가
  늦게 보내는 값이 붙어도 layout이 흔들리지 않아야 한다.

롤플레잉 에피소드의 대화에는 다음이 함께 얹힌다. 각 요소는 하나씩만 말하고 같은
정보를 두 곳에서 반복하지 않는다.

| 요소 | 담당 |
| --- | --- |
| 네이티브 헤더 | 시나리오 제목과 역할 |
| 상황 카드 | 상황 설명. 접힘/펼침 |
| 목표 바 | 지금 할 목표와 전체 목록 |
| 대화 흐름 | 목표 달성 기록 |

- 상황 카드는 대화 목록의 첫 요소이며 **제자리에서 펼쳐진다.** 접힌 상태의
  라벨은 `상황 자세히 보기`다.
- 목표 바는 **composer 바로 위**에 상주한다. 접히면 지금 할 목표 한 줄, 펼치면
  같은 자리에서 턴 진행과 목표 3개 전체가 나온다. 완료는 채운 success 체크,
  현재는 accent 링, 남은 것은 중립 빈 원으로 구분한다. 헤더에 `목표` 버튼은 두지
  않는다 — 목표는 탭 없이 항상 보인다.
- 턴은 목표 바를 펼쳤을 때만 보인다. 다만 **남은 턴이 5개 이하가 되면** 접힌 바
  오른쪽에 `n턴 남음`이 나타난다. 나타난다는 사실 자체가 신호이므로 경고색을
  쓰지 않고 보조 텍스트로 둔다.
- 목표를 달성하면 대화 흐름에 완료 한 줄이 영구히 남아, 스크롤만으로 언제
  달성했는지 되짚을 수 있다. 그 줄의 자리는 달성 시각이 아니라 목표를 달성한
  메시지가 정한다 — 시각만으로는 흐름의 어디에 끼울지 알 수 없다.
- 말풍선에는 **실제로 상대에게 전달된 문장**이 남는다. 한글로 쓰면 번역된 영어가
  전달되고, 영어로 쓰면 원문 그대로 전달된다. 교정본을 대신 보내지 않는다.
- 한글 입력은 막힐 때 쓰는 **비상구**다. 기능은 온전히 두되 UI에서 앞세우지
  않으며 composer 문구는 `영어로 써 보세요`다.
- 말풍선 곁의 표시는 셋이고, 둘은 누를 수 있고 하나는 상태다.

| 표시 | 뜻 | 탭 |
| --- | --- | --- |
| 번역 표시 | 한글로 썼다 | 시트 열림 |
| info 표시 | 더 자연스럽게 쓸 여지가 있다 | 시트 열림 |
| 체크 | 그대로 잘 통했다 | 없음 |

- 누를 수 있는 둘은 원형 버튼으로, 상태인 체크는 배경 없는 플랫 아이콘으로 그려
  무엇이 눌리는지 모양이 먼저 말하게 한다. 둘은 같은 하단 시트 하나를 열고
  내용만 다르다.
- 말풍선 본문에는 밑줄을 넣지 않는다. 밑줄은 시트의 개선 문장에만 붙는다.
- 이 표시에 커스텀 글리프나 `ellipsis`를 쓰지 않는다. `ellipsis`는 명령 메뉴를
  뜻한다.
- **표시를 채우는 곁가지 호출이 실패해도 대화 중에는 실패를 드러내지 않는다.**
  오류 배너도 재시도 버튼도 표시 자리의 실패 상태도 만들지 않고, 빈 자리는 다음
  호출이 지난 문장까지 함께 판정해 조용히 메운다 — 실패가 대화 화면에 쌓이면
  시끄럽고 대개 다음 턴에 저절로 채워진다. 끝까지 못 채운 문장만 대화가 끝난 뒤
  결과 화면의 문장 목록에서 `다시 확인`으로 드러난다.

## Why

AI 요청 상태, streaming 높이, keyboard frame과 수동 scroll이 같은 offset을 따로
제어하면 점프·반복 animation·읽던 위치 탈취가 생긴다. 사용자 의도에 따라 목록
하나가 scroll을 소유하고, system loader와 native keyboard 경계를 쓰면 현재
상태를 보이면서 layout을 유지할 수 있다.

말풍선에 전달된 문장을 그대로 남기는 이유는 이 앱이 파는 것이 "내 영어가 실제로
통하는가"이기 때문이다. 교정본을 대신 보내면 사용자는 언제나 완벽한 영어를 하는
사람이 되어 롤플레잉이 실력을 비추지 못한다. 원문을 보내야 대화 자체가 검증이
되고, 그때 체크와 info 표시가 각각 "그대로 통했다"와 "통했지만 더 나은 표현이
있다"는 뜻을 가질 수 있다.

턴을 접힌 바에서 감추는 이유는 턴 상한이 목표가 아니라 안전망이기 때문이다.
목표 3개에 각 2턴, 인사와 마무리에 2턴이면 8턴이라 상한은 옆길로 새지 않는 한
부딪히지 않는다. 옆길로 새는 것이 롤플레잉의 연습 가치이므로 남은 턴을 상시
노출하면 없는 압박을 만든다.

## Boundaries

- header, back gesture와 toolbar는 native stack이 소유한다.
- icon-only action은 최소 44pt hit target과 한국어 accessibility label을 가진다.
- AI Markdown은 문단·제목·강조·목록·링크·code·표를 지원하지만 이미지와 syntax
  highlighting은 지원하지 않는다.
- 이 계약은 대화 표면의 공통 상호작용과, 그 위에 얹히는 목표 바·상황 카드·
  말풍선 곁 표시의 뜻과 자리를 함께 소유한다. 표시에 쓰는 글리프와 색은
  [셸·브랜드 층 계약](apple-hig-with-app-theme.md)이, 표시를 채우는 판정·번역
  호출의 경계는 [모델 호출 계약](ai-gateway-for-model-calls.md)이 소유한다.
- 대화 표면 밖 — 에피소드 생성 흐름, 홈 목록, 종료와 결과 화면 — 은 이 계약이
  정하지 않는다. 예외는 대화 중 침묵의 대가로 남는 `다시 확인` 하나뿐이다.
- 메시지 persistence와 server 권한은 [데이터 접근 계약](hybrid-data-access.md),
  실패 재시도와 운영 한도는 [안정성 계약](ai-chat-reliability.md)이 소유한다.

## Reconsider when

첨부·offline queue·background generation·대화 pagination 또는 사용자 선택 scroll
정책이 제품 요구가 되면 해당 상호작용을 별도 결정한다.

다음 둘은 롤플레잉 대화에서 열어 둔 채 출하했다. 제품 요구가 되면 그때 정한다.

- **표현 저장.** 첨삭받은 문장을 모아 두는 자리를 만들지 정하지 않았다. 만들면
  복습 화면이 새로 필요하다.
- **한글 입력 비율.** 비상구로 위치를 낮췄지만, 계속 한글로만 쓰는 사용자를
  어떻게 다룰지는 정하지 않았다.

## Still-rejected alternatives

- streaming chunk마다 animated `scrollToEnd`를 다시 시작하기.
- keyboard event마다 별도 강제 scroll이나 수동 frame animation 만들기.
- 과거를 읽는 중 새 메시지나 keyboard가 자동으로 tail로 이동시키기.
- query의 `isFetching`을 iOS `RefreshControl.refreshing`에 직접 연결하기.
- AI SDK 상태 이름만 보고 실제 text가 없는데 spinner를 제거하기.
- 늦게 도착하는 표시를 위해 말풍선 안 공간을 그때 늘리기.
- 곁가지 판정이 실패했을 때 대화 화면에 오류·재시도 상태를 드러내기.

## Evidence worth preserving

- content-size callback의 반복 smooth scroll과 visible-content 보정을 함께 켰을 때
  streaming 중 같은 offset을 두 로직이 제어해 점프가 생겼다.
- keyboard spike에서 `whenAtEnd`는 맨 아래 tail과 과거 viewport를 모두 보존했지만
  `always`는 과거의 첫 visible item을 바꿨다.
- 화면 밖 background refetch가 native `RefreshControl`을 켜면 뒤로 돌아왔을 때
  spinner만 고착됐다. 데이터 동기화와 수동 제스처 상태를 분리하면 사라졌다.

표시와 아이콘 어휘를 정한 HIG 근거는 다음과 같다.

- 애플 HIG는 [컨텍스트 메뉴가 기본적으로 숨겨져 있어 존재를 모를 수 있으니 항상
  메인 인터페이스에도 같은 항목을 두라](https://developer.apple.com/design/human-interface-guidelines/context-menus)고
  명시한다. 롱프레스 단독은 주 경로가 될 수 없다.
- HIG는 [info 버튼을 "행의 내용에 대한 더 많은 정보를 드러낼 때만"
  쓰라](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)고
  규정한다. 첨삭 시트가 정확히 이 용도다.
- 애플 메시지는 말풍선을 탭해도 아무 일도 일어나지 않는다. 표시 없는 탭은
  발견되지 않는다 — 그래서 곁의 표시가 유일한 진입점이다.
- Apple Writing Tools의 인라인 밑줄은 **이미 적용된 변경**을 뜻한다. 교정 전
  문장에 밑줄을 그으면 의미가 반대가 된다.
- 원형 화살표는 iOS에서 새로고침을 뜻한다. 재시작 액션에 쓰면 예상과 다른 일이
  벌어진다.
- 실제 앱들의 지속 목표 표시는 헤더 아래 또는 composer 위로 수렴하고, 밀도는
  예외 없이 "현재 것 하나만 한 줄"이다. 전체 목록을 기본 노출하는 사례는 없었다.
