# 스토리 표지 불변 경로 명세

## 목표

- 공식 스토리 표지를 새 그림으로 교체하면, 옛 표지를 이미 받아 둔 앱도
  재설치나 재시작 없이 새 그림을 보게 한다.
- 표지 파일 이름, 시드의 경로 값, slug 사이에 같은 이름이 반복되며 손으로
  맞추던 연결을 규칙 하나로 만든다.
- 앞으로 사용자가 스토리를 직접 만들 때 쓸 소유자 폴더 구조와 충돌하지 않는
  공식 표지 자리를 정해 둔다.

## 확정 범위

- `story-covers` 버킷의 공식 표지 객체 이름은
  `<slug>-<내용 해시 앞 8자>.<확장자>`다. 예: `mia-cafe-3f9a1c2b.png`.
- 해시는 파일 내용에서 계산한다. 내용이 같으면 이름이 같고, 내용이 바뀌면
  이름이 바뀐다.
- 표지 객체는 불변이다. 표지를 교체할 때는 같은 경로를 덮지 않고 새 이름의
  파일을 만들어 스토리의 `cover_image_path`를 그 경로로 바꾼다.
- 저장소 `supabase/story-covers/`의 파일 이름과 시드가 넣는
  `cover_image_path` 값은 항상 같은 규칙의 같은 값이다. 표지를 바꾸는 변경은
  파일과 시드를 같은 커밋에서 함께 바꾼다.
- 공식 표지는 버킷 루트에 둔다. 루트 객체는 첫 폴더 조각이 없어서, 소유자
  폴더의 첫 조각을 검사하는 사용자 쓰기 정책이 나중에 생겨도 서로 닿지
  않는다.
- 읽는 쪽은 경로의 생김새에 의미를 두지 않는다. `cover_image_path`를 URL로
  바꿔 그리는 API와 앱의 동작은 바뀌지 않는다.

## 확정 제약과 이유

- 같은 경로를 덮는 교체는 이미 실제 증상을 냈다. React Native의 `Image`가
  URL을 키로 캐시해서, 파일 내용만 바뀌면 앱은 옛 그림을 계속 보여 준다.
  Supabase 문서도 자주 바뀌는 자산은 새 경로에 올리라고 권장한다. Smart CDN이
  엣지 캐시는 지워도 기기에 이미 내려간 캐시는 지우지 못한다.
- 판 번호 대신 내용 해시를 쓴다. 해시는 표지를 만드는 쪽이 파일에서
  계산하므로 이름 올리기를 잊을 수 없고, 내용이 같으면 이름도 같아 불필요한
  캐시 무효화가 없다.
- 이름에 slug를 남긴다. 공식 표지는 사용자 입력이 아니라 저장소가 소유한
  콘텐츠 제작 산출물이라 난수 이름이 막아 줄 충돌이나 조작 위험이 없고,
  저장소에서 사람이 파일을 찾을 때 slug가 쓰인다.
- 공식 표지와 사용자 표지의 경로 규칙을 하나로 합치지 않는다. 합치는 길은 셋
  다 실제 비용을 낸다. 시스템 계정은 `auth.users`에 로그인하지 않는 가짜
  계정을 만들고, 스토리 ID 폴더로 통일하면 쓰기 정책에 join과 생성 순서
  문제가 생기고, 공식 표지까지 난수로 지으면 저장소 가독성만 잃는다. 읽는
  쪽이 분기하지 않는 한, 쓰는 쪽 규칙이 갈리는 것은 혼란이 아니다.

## 수용 기준

- 로컬 스택을 새로 세우면 스토리 탭과 스토리 상세에 다섯 스토리의 표지가
  보인다.
- 다섯 스토리 행의 `cover_image_path`가 버킷의 실제 객체와 하나씩 일치하고,
  이름이 `<slug>-<해시 8자>.<확장자>` 규칙을 따른다.
- 표지 한 장을 새 그림으로 교체하는 절차를 밟으면, 그 표지를 이미 표시했던
  앱이 재시작 없이 다음 조회에서 새 그림을 보여 준다. 시뮬레이터에서
  확인한다.
- 저장소의 기존 자동 검사가 통과한다.

## 가정

아래는 에이전트가 정한 값이라 더 나은 값이 확인되면 바꿀 수 있다.

- 해시는 파일 내용의 SHA-256 앞 8자 16진수로 한다.
- 확장자는 현재 표지들이 쓰는 png를 유지한다.

## 제외

- 사용자 스토리 제작·공유 기능과 그 표지 업로드 구조. 소유자 폴더
  (`{userId}/...`), 쓰기 정책, 경로 소유 제약은 그 기능의 제품 정의를 먼저
  거친다는 기존 경계를 따른다. 이 명세는 그 구조와 겹치지 않게 공식 표지의
  자리만 정한다.
- 사용자 표지의 공개 범위와 버킷 분리 여부. 공유 기능의 제품 정의에서
  정한다.
- 버킷 접근 제어 변경. 공개 읽기와 쓰기 정책 없음을 그대로 둔다.
- 표지 그림 자체의 교체나 스타일 변경.

## 남은 위험

- 호스티드 환경에 표지를 올리는 배포 절차가 아직 없다. 절차가 생길 때 이
  규칙을 그대로 적용하고, 교체 뒤 옛 객체를 지우는 일도 그 절차가 맡는다.
- `objects_path` 시드가 하위 폴더를 재귀 업로드하는지는 확인하지 않았다.
  루트를 유지하므로 이 명세에는 영향이 없고, 공식 표지를 폴더로 옮기는 안이
  다시 나오면 그때 확인한다.
