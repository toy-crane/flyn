# 메시지 전송 뒤 입력창 비우기

## 상태

2026-09-11 dogfooding에서 정한 입력창 비우기가 남은 구현 대상이다. 함께 다뤘던
종료 카드 즉시 표시와 CTA만 기다리는 동작은 구현됐다. 그 동작은
[에피소드 종료와 표현 돌아보기](../../decisions/episode-ending-and-review.md)가 소유하고,
축하·재진입·대기 상태의 남은 검증은 [누락 보완 명세](../conversation-ui-completion/spec.md)에서 확인한다.

## 사용자가 얻는 것

메시지를 보내면 입력창이 비고, 마지막 글자가 빠지거나 같은 말이 두 번 전송되지 않는다.
곧바로 다음 글을 써도 앞의 말이 섞이지 않는다. 에피소드 대화의 기존 전송 전 표기 보정은 유지한다.

## 범위

- 보내기가 실행되면 입력창은 빈 상태가 된다. 마지막 글자를 치고 곧바로 눌러도, 한글
  조합이 끝나지 않은 채 눌러도, 시스템 자동 수정이 막 글자를 바꾼 뒤 눌러도 같다.
- 보낸 메시지는 누르는 순간 입력창에 있던 글에서 앞뒤 공백을 정리한 내용이다.
  에피소드 대화에는 [AI 에피소드 프로토콜](../../decisions/ai-episode-protocol.md)의
  전송 전 표기 보정을 적용한다. 그 외에는 글자를 빼거나 더하지 않는다. 조합 중이던
  글자가 빠지거나 입력창에 남지 않는다.
- 한 번 누름으로 같은 말이 두 번 나가지 않는다.
- 눌리는 보내기 버튼이 아무 일도 하지 않는 경우는 없다. 보낼 수 없는 조건이면 버튼이
  눌리지 않고, 눌리면 반드시 보내거나 기존 오류 안내를 보인다.
- 입력창에 남은 글 뒤에 새 글을 이어 쳐서 앞의 말이 다시 섞여 나가는 일이 없다.
- 이 규칙은 같은 입력창을 쓰는 모든 채팅에 적용한다. 에피소드 대화, `AI에게 물어보기`,
  스토리 만들기가 해당한다. iOS와 Android 모두에서 확인한다.

## 확인 기준

- 마지막 글자 입력 직후 보내기, 한글 조합 중 보내기, 자동 수정 직후 보내기의 세 경우
  모두 입력창이 빈다. 보낸 말에는 기존 앞뒤 공백 정리와 에피소드의 전송 전 표기 보정만
  적용되고, 마지막 글자나 조합 중이던 글자가 빠지지 않는다. iOS와 Android에서 각각
  확인한다.
- 보낸 뒤 바로 다음 글을 치면 앞의 말이 입력창에 섞여 있지 않다.
- 답이 오는 중이거나 보낼 수 없는 조건에서 보내기 버튼은 눌리지 않는다. 눌리는 상태에서
  누르면 메시지가 나가거나 오류 안내가 보인다.

## 제약과 이유

- 화면에 전송된 메시지와 입력창 비우기를 따로 확인한다. 사용자가 겪은 문제는 메시지가
  대화에 올라왔는데도 입력창에 글이 남는 경우였다. 입력창만 지워 놓고 마지막 글자를
  잃거나, 전송하지 않은 채 성공한 것처럼 보이는 수정은 허용하지 않는다.
- HeroUI 이전으로 바뀐 공용 `Button`과 `IconButton`, `Typography` 역할을 유지한다.
  입력창 비우기를 위해 원시 버튼이나 개별 글자 스타일로 되돌리지 않는다.
- 입력창의 모양, 키보드 회피, 보낸 뒤 목록을 옮기는 규칙은 바꾸지 않는다. 목록 이동은
  [모바일 채팅 스크롤](../../decisions/mobile-chat-scrolling.md)을 따른다.
- 결말 판정, 종료 카드의 내용·위치와 표현 돌아보기는 이 작업에서 바꾸지 않는다.
  끝난 대화를 다시 열면 큰 카드 없이 CTA만 표시한다는 종료 계약을 유지한다.

## 원인 가정과 확인할 경로

- iOS 입력창이 보낸 변경 횟수와 앱이 확인한 횟수가 다르면 앱의 비우기 값을 무시하는
  경로를 우선 확인한다. 마지막 글자 직후 누름, 한글 조합, 자동 수정이 이 조건을 만들 수
  있다. 사용자는 전송된 뒤에도 글이 남았다고 확인했지만, 셋 중 어떤 조건인지는 모른다.
  변경 횟수 불일치가 실제 원인인지는 재현으로 확인한다.
- Android에는 조합 중인 글자를 따로 지우는 처리가 있다. iOS와 같은 원인이라고
  가정하지 않고 두 플랫폼에서 같은 사용자 결과를 확인한다.
- 별도로, 버튼은 눌리는데 인증 토큰이 잠깐 없거나 직전 요청이 정리 중이라 전송도
  비우기도 하지 않는 경로를 확인한다. 사용자가 겪었다고 확인한 경로는 아니지만 같은
  입력창에서 보내기가 조용히 무시되는 결함이므로 위 확인 기준에 포함한다.
- 에이전트 가정(사용자가 바꿀 수 있음): 같은 입력창을 쓰는 세 채팅의 전송 경계를
  재사용한다. 실제 원인을 확인한 뒤 수정 방법을 고르며, 앱 전체 입력창을 새로 설계하지 않는다.

## 검증과 남은 위험

- iOS·Android 각각 에피소드, `AI에게 물어보기`, 스토리 만들기의 입력·전송 결과를 확인한다.
  저장소 루트의 개발 명령과 worktree 전용 기기를 쓰고 인증은
  [모바일 인증](../../decisions/mobile-authentication.md)을 따른다.
- 이 문제는 사람의 타이밍에 달린 경합이라 자동화 도구의 글자 입력만으로 재현되지
  않을 수 있다. 시뮬레이터의 하드웨어 키보드와 한글 자판, 실제 기기에서 마지막 글자
  직후·조합 중·자동 수정 직후를 손으로 재현한다. 각 조건의 전송된 본문과 빈 입력창을
  함께 기록하고, 자동화 테스트 통과만으로 네이티브 입력 경합을 해결했다고 하지 않는다.
- 종료 카드를 대화 목록 안으로 옮기고 하단에 버튼만 남기는 선택은 여전히 범위 밖이다.
  종료 직후 카드는 입력창 자리에 두며, 다시 읽기는 CTA만 표시한다.
