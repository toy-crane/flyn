# 에피소드 종료 카드 대기와 입력창 비우기

상태: 2026-09-11 dogfooding 피드백으로 결정을 마쳤다. 구현 전이다.

에피소드 대화에서 두 가지를 고친다. 결말이 난 뒤 표현 확인을 기다리는 동안 입력창
자리를 어떻게 채울지, 그리고 메시지를 보낸 뒤 입력창에 글이 남는 현상을 없애는 것이다.

[에피소드 종료 시안](../episode-expression-review/prototype.html)의 `에피소드 대화`
화면에 이번 결정을 반영했다. 상태 메뉴의 `표현 확인 지연`이 기다리는 순간이고,
`에피소드 종료`가 확인이 끝난 뒤다.

## 사용자가 얻는 것

- 마지막 대사를 읽자마자 결말과 축하를 본다. 표현 확인이 끝나기를 기다리며 빈 자리나
  같은 안내 문구를 두 번 보지 않는다.
- 무엇을 기다리는지는 확인 중인 메시지 곁의 표시와 `표현 돌아보기` 버튼의 진행 상태가
  말해 준다. 버튼이 열리면 그 화의 표현 카드가 다 준비된 것이다.
- 메시지를 보내면 입력창이 반드시 비고, 보낸 말은 입력창에 있던 글과 같다.

## 범위

### 결말 카드는 바로, 버튼만 기다린다

- 결말이 도착하면 입력창은 사라지고 그 자리에 결말 카드가 바로 나온다. 확인 중인
  메시지가 남아 있어도 카드를 미루지 않는다. 카드의 내용과 결말 낱말을 숨기는 규칙은
  [스토리 진행·결말 화면 표기](../../decisions/story-progress-and-ending-display.md)를
  그대로 따른다.
- 축하 연출은 카드가 처음 나오는 순간에 한 번 재생한다. 버튼이 열리는 순간에는
  아무것도 재생하지 않는다. 뒤로 돌아오거나 기록을 다시 볼 때 반복하지 않는 규칙,
  동작 줄이기에서 정지된 완료 표시로 대신하는 규칙은 기존과 같다.
- 확인 중인 메시지가 하나라도 있으면 카드의 `표현 돌아보기` 버튼은 진행 상태다. 문구와
  크기를 유지하고 문구 앞에 작은 회전 표시를 두며, 누를 수 없고 화면 읽기에 진행 중과
  비활성 상태를 함께 알린다. 모양과 접근성은
  [모바일 작업 진행 표시](../../decisions/mobile-action-progress.md)의 버튼 규칙을
  따른다.
- 모든 확인이 성공 또는 실패로 끝나면 버튼이 열린다. 실패한 메시지는 지금처럼 그 메시지
  곁에 실패 안내와 재시도를 남기고, 실패 때문에 버튼을 막지 않는다. 사용자가 재시도를
  누르면 그 확인이 끝날 때까지 버튼은 다시 진행 상태가 된다.
- 입력창 자리에 `표현을 확인하고 있어요.` 문구를 두지 않는다. 확인 중임은 그 메시지
  곁의 표시가 이미 알리고, 자동 작업의 진행 상태는 처리하는 대상이 소유한다는 계약을
  따른다.
- 끝난 화에 다시 들어와 미완료 확인을 자동으로 다시 수행할 때도 같다. 카드는 바로
  보이고 버튼만 기다린다. 대화 기록에서 끝난 화를 열 때 확인할 것이 없으면 버튼은 처음부터
  열려 있다.
- 버튼이 진행 상태에서 열리는 사이 카드가 다시 그려지거나 축하가 다시 재생되지 않는다.

### 보낸 뒤 입력창은 빈다

- 보내기가 실행되면 입력창은 빈 상태가 된다. 마지막 글자를 치고 곧바로 눌러도, 한글
  조합이 끝나지 않은 채 눌러도, 시스템 자동 수정이 막 글자를 바꾼 뒤 눌러도 같다.
- 보낸 메시지의 내용은 누르는 순간 입력창에 있던 글 전체와 같다. 조합 중이던 글자가
  빠지거나 남지 않는다.
- 한 번 누름으로 같은 말이 두 번 나가지 않는다.
- 눌리는 보내기 버튼이 아무 일도 하지 않는 경우는 없다. 보낼 수 없는 조건이면 버튼이
  눌리지 않고, 눌리면 반드시 보내거나 기존 오류 안내를 보인다.
- 입력창에 남은 글 뒤에 새 글을 이어 쳐서 앞의 말이 다시 섞여 나가는 일이 없다.
- 이 규칙은 같은 입력창을 쓰는 모든 채팅에 적용한다. 에피소드 대화, `AI에게 물어보기`,
  스토리 만들기가 해당한다. iOS와 Android 모두에서 확인한다.

## 확인 기준

- 결말이 도착한 직후 확인 중인 메시지가 남아 있으면, 결말 카드와 축하가 보이고 그 안의
  `표현 돌아보기`는 회전 표시가 붙은 채 눌리지 않는다. 화면 읽기는 버튼을 진행 중이자
  비활성으로 읽는다.
- 마지막 확인이 끝나면 버튼이 열리고, 카드의 나머지는 바뀌지 않으며 축하가 다시 재생되지
  않는다.
- 확인이 하나 실패하고 나머지가 끝나면 버튼이 열리고, 실패한 메시지 곁에는 실패 안내와
  재시도가 남는다. 재시도를 누르면 버튼이 다시 진행 상태가 되었다가 결과가 오면 열린다.
- 결말이 도착한 뒤 `표현을 확인하고 있어요.` 문구는 입력창 자리와 카드 안팎 어디에도
  나오지 않는다. 확인 중인 메시지 곁에 그 메시지마다 하나씩만 보인다.
- 대화 기록에서 끝난 화를 열면 카드가 바로 보이고, 남은 확인이 없으면 버튼이 열려 있다.
- 마지막 글자 입력 직후 보내기, 한글 조합 중 보내기, 자동 수정 직후 보내기의 세 경우
  모두 입력창이 비고 보낸 말이 입력창에 있던 글 전체와 같다. iOS와 Android에서 각각
  확인한다.
- 보낸 뒤 바로 다음 글을 치면 앞의 말이 입력창에 섞여 있지 않다.
- 답이 오는 중이거나 보낼 수 없는 조건에서 보내기 버튼은 눌리지 않는다. 눌리는 상태에서
  누르면 메시지가 나가거나 오류 안내가 보인다.

## 정한 제약과 이유

- **결말 카드를 미루지 않는다.** 결말은 마지막 대사와 같은 스트림 끝에 이미 확정되어
  저장된 사실이다. 기다리는 것은 표현 돌아보기에 실을 카드뿐이므로, 그 화면을 여는
  버튼만 기다리게 하면 "표현 돌아보기를 열었을 때 카드가 다 있어야 한다"는 애초의 목적을
  그대로 지키면서 빈 시간을 없앤다. 2026-09-09에 정한 "확인이 끝난 뒤 카드와 버튼을
  띄운다"는 순서를 이 결정이 대신한다.
- **입력창 자리의 안내 문구를 없앤다.** 같은 문구가 확인 중인 메시지 곁에 이미 붙는다.
  두 번째 문구는 무엇을 기다리는지와 떨어져 있어 어색하게 읽혔고, 자동 작업의 진행
  표시를 관계없는 새 줄에 두지 않는다는 계약과도 어긋났다.
- **축하는 카드가 나오는 순간에 한 번.** 축하할 사건은 결말이 난 순간이다. 버튼이 열리는
  것은 뒤에서 하던 확인이 끝난 것일 뿐이라 축하와 묶지 않는다.
- **비교한 대안.** 아래를 비워 두는 안은 확인이 길어질 때 화면이 빈 이유를 말해 주지
  않아 제외했다. 카드 자리에 진행 표시만 두는 안은 진행 표시가 두 곳이 되어 계약이
  피하라는 모양으로 돌아가 제외했다. 업계 기준선으로 확인한 Speak, Duolingo 역할극,
  Babbel은 결과 표시를 대화 흐름 안에 두고 하단에는 버튼만 남긴다. 카드 자체를 대화 목록
  안으로 옮기는 안은 이번에 다루지 않았다.

## 가정

- 입력창에 글이 남는 원인은 iOS 입력창이 앱의 "비우기" 값을 버리는 조건이다. iOS
  입력창은 자기가 낸 변경 횟수와 앱이 확인한 횟수가 다르면 앱이 보낸 값을 무시한다.
  마지막 글자 직후의 빠른 누름, 한글 조합, 자동 수정이 그 조건을 만든다. 2026-09-11
  사용자가 글이 남았을 때 메시지는 대화에 올라가 있었다고 확인했으므로, 전송은 정상이고
  비우기만 실패한 이 경로가 실제로 겪은 것이다. Android 입력창은 조합 중인 글자를 따로
  지우는 처리가 있어 iOS에서 먼저 나는 문제로 본다.
- 같은 증상을 낼 수 있는 두 번째 경로는 보내기가 조용히 아무 일도 하지 않는 경우다.
  버튼은 눌리지만 인증 토큰이 잠깐 없거나 직전 요청이 정리 중이면 전송도 비우기도 하지
  않는다. 사용자가 겪은 것은 아니지만 같은 자리의 결함이므로 확인 기준에 함께 넣었다.
- 버튼의 회전 표시는 카드가 나오는 순간부터 바로 보인다. 자동 작업의 1초 규칙을 여기에
  적용하지 않는다. 버튼은 어차피 그동안 눌리지 않아야 하고, 이유 없이 눌리지 않는 버튼은
  고장으로 읽히기 때문이다.
- 버튼의 진행 상태는 확인 요청의 기존 제한 시간을 따른다. 제한 시간에 걸린 확인은 실패로
  끝나 버튼을 열고 메시지 곁에 재시도를 남긴다. 별도의 대기 상한을 두지 않는다.

## 손대지 않는 것

- 결말을 판정하는 방식. 모델이 각본의 기준을 보고 같은 출력의 마지막 줄에 결말을 쓰고,
  서버가 그 줄을 결말로 바꿔 저장한다. 이 흐름은
  [AI 에피소드 프로토콜](../../decisions/ai-episode-protocol.md)이 소유한다.
- 결말 카드의 위치. 입력창 자리에 고정하는 지금 배치를 유지한다. 대화 목록 안으로
  옮기는 것은 별도 결정이다.
- 결말 카드의 내용, 결말 낱말을 숨기는 규칙, 표현 돌아보기 화면.
- 확인 중인 메시지 곁의 표시, 실패 안내와 재시도의 모양.
- 입력창의 모양, 키보드 회피, 보낸 뒤 목록을 옮기는 규칙. 마지막 것은
  [모바일 채팅 스크롤](../../decisions/mobile-chat-scrolling.md)이 소유한다.

## 미룬 결정

- 결말 카드를 대화 목록의 마지막 항목으로 옮기고 하단에는 버튼만 남길지. 업계
  기준선은 그쪽이지만 이번 피드백은 대기 문구에 관한 것이라 다루지 않았다. 그때까지
  카드는 입력창 자리에 둔다.

## 남은 위험

- 축하 연출이 재생되는 동안 위쪽 메시지 곁의 회전 표시가 함께 돈다. 시선이 갈릴 수
  있는데, 실제 기기에서 dogfooding으로 확인한다.
- 확인이 오래 걸리는 기기에서는 버튼의 진행 상태가 길게 느껴질 수 있다. 그때는 대기
  상한이나 안내 문구를 다시 본다.
- 입력창 문제는 사람의 타이밍에 달린 경합이라 `agent-device`의 글자 입력만으로는
  재현되지 않을 수 있다. 시뮬레이터의 하드웨어 키보드와 한글 자판, 실제 기기에서 확인
  기준의 세 경우를 손으로 재현한다.
- 사용자가 겪은 것은 첫 번째 경로로 확인했지만, 어느 조건(빠른 누름, 한글 조합, 자동
  수정)이었는지는 모른다. 세 조건을 모두 재현해 확인한다.
