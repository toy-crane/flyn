# 스토리 만들기 다듬기

상태: 승인. 사용자가 2026-09-11에 첫 dogfooding에서 본 여섯 가지를 하나씩 채팅으로
정했다. 2026-09-12에는 에피소드별로 원하는 상황을 플레이 전에 함께 정하고, 실제
결말은 플레이에서 정하며, 화 사이에 제작 인터뷰를 넣지 않는 흐름을 승인했다.
2026-09-13에는 카드의 `에피소드 추가하기`로 추가 의사를 받고 상황은 인터뷰로
정하는 방식과, 카드의 빈 이미지 자리를 없애는 것을 승인했다. 첫마디와 카드 뒤 안내
문구도 확정했다. 이번 범위는 구현을 시작할 수 있으며, 아래 가정과 후속 결정은 구분한다.
같은 날 실제 리뷰에서 설명과 질문이 한 문단으로 붙어 읽기 어렵다는 피드백을 받았다.
사용자는 세부 형식 제한 대신 사용자의 판단을 돕는 방향을 모델에 제시하기로 했다.
아래 대화와 평가 기준은 이 결정을 반영한다. 사용자의 적용 요청에 따라 API 프롬프트와
기계 검사에도 반영했다. 리뷰 중인 기기는 조작하지 않았으며 실제 화면 확인은 별도로 남는다.
새 지침의 3회 57개 응답은 기계 검사를 통과했지만, 출력 검토에서 추가 장면의 결말 가정과
여러 화를 함께 묻는 사례가 남았다. 대화 품질 검증은 완료가 아니다. 출력 전문과 검토는
[평가 기록](../../../apps/api/eval/results/story-evaluation-review-2026-09-13.md)에 남겼다.
기존 54개 응답의 통과 기록은 이전 기준의 결과이며 새 대화 품질의 통과 근거가 아니다.
표지 풍은 실제 이미지 모델로 만든 시안 세 벌을 보고 골랐고, 시안은 결정 뒤 버렸다.
이 스펙은 출시한 [스토리 만들기](../../decisions/story-creation.md) 계약을
고치는 두 번째 조각이다. 이 글에서 "앞 스펙"은 그 계약으로 옮겨진 첫 스펙을 말하며,
계약이 정한 것 중 여기서 말하지 않는 것은 그대로다. 화별 상황 합의와 실제 결과의
연결 규칙은 결정 계약에도 반영했으며, 앱 구현은 아직 남아 있다. 이 스펙은 기존 앱의
다음 동작을 바꾼다. 카드를 내는 기준(사건 하나와 상대 하나 → 화별로 합의한 상황), 화 수
(기본 3화 → 사용자가 원하는 상황 수, 한 화도 허용), 카드 버튼
이름(`대화 시작하기` → `스토리 만들기`), 만든 뒤 여는 화면(1화 → 상세), 표지가
늦을 때의 동작(1화를 먼저 연다 → 상세 전에 기다린다), 표지 문구에서 스토리마다
바뀌는 것(인물 설명과 장소 → 표지용 한 줄).

[승인한 카드 시안](prototype.html)은 스토리 만들기 화면 안의 카드와 추가 인터뷰
진입을 보여 준다. 입력과 답은 가상 예시이며 AI 생성, 저장, 상세와 플레이는 연결하지
않았다. 시안의 생성 안내와 뒤로 가기 확인창은 검토용이며 새 제품 요구가 아니다.
생성 이후의 흐름은 아래 명세를 따른다.

## 사용자가 얻는 것

사용자가 경험하고 싶은 사건을 화별로 함께 정한다. 사건 하나를 말했을 때 플린이
비슷한 사건을 여러 화로 늘리지 않는다. 원하는 상황은 알고 시작하되 상대의 반응과
결말은 플레이하면서 알게 되고, 지난 선택은 다음 화에서 받을 도움과 대화 방법에도
영향을 준다. 화 사이에는 제작 인터뷰가 없다.

플린은 사용자가 장면을 이해하고 자기 뜻과 맞는지 판단할 수 있게 한국어로 대화한다. 만드는 동안 무엇이 되고 있는지 한 줄씩
알 수 있고, 다 되면 방금 생긴 표지와
소개, 에피소드 목록을 상세에서 먼저 본 뒤 대화를 시작한다. 만든 스토리의 표지는
공식 표지와 같은 결로 보이면서 스토리마다 다른 사람과 다른 앵글로 나온다.

## 범위와 동작

### 인터뷰

- 고정 첫마디는 `어떤 상황에서 영어로 대화해 보고 싶으세요?`다. 앱이 보여 주고
  모델은 반복하지 않는다. `싶으세요`는 이 첫마디에 적용하며 다른 문구까지 일괄 바꾸지 않는다.
- 플린은 한국어 해요체로 말한다. "~해요", "~예요"로 끝내고 "~합니다"와 반말을 섞지
  않는다. 사용자를 `사용자`나 `당신`으로 부르지 않고 주어를 뺀다.
- 사용자가 제안하는 장면을 충분히 이해하고 자기 뜻과 맞는지 판단할 수 있게 설명한다.
  설명의 길이와 형식은 내용에 맞게 고르되 휴대폰 채팅에서 읽기 편하고 무엇에 답하면
  되는지 분명해야 한다. 문장·문단·물음표 수, 공감 문장의 위치나 Markdown 사용 여부로
  대화 형식을 고정하지 않는다. 필요한 설명을 줄이거나 문단을 반드시 나누도록 요구하지 않는다.
- 상황을 떠올리기 어려워하면 구체적인 장면이나 인물을 제안해 판단을 돕는다. 이미
  원하는 상황을 충분히 말했다면 제안부터 하는 순서를 반복하지 않는다. 뜻이 불분명하면
  필요한 뜻을 확인하고, 제안과 다른 답이나 사용자가 덧붙이는 뉘앙스를 따른다.
- 사용자가 말한 큰 틀에서 각 화에 넣을 상황을 하나씩 함께 정한다. 사용자가 특정
  사건을 말하면 그 사건부터 다룬다. 장소나 인물만 바꾼 비슷한 사건으로 화 수를 채우지
  않는다. 사용자가 여러 상황을 이미 말했다면 말한 것만 차례로 확인한다.
- 각 화에서 어디서, 누구와, 무슨 일이 생겨서, 사용자가 무엇을 하려는지 확인한다.
  상대의 사정, 안 풀렸을 때 잃는 것, 사용자가 가진 자료나 아는 사실도 그 상황에
  필요하면 묻는다. 친해지고 싶은 대화에 적대적인 상대나 큰 손해를 억지로 넣지 않는다.
- 한 번에 한 화의 빈 부분만 묻는다. 사용자가 이미 말한 것은 다시 묻지 않는다.
  사용자의 목표와 중요한 조건을 바꾸는 제안은 동의를 받은 뒤 넣는다. 시간과 주변
  소음 같은 배경은 합의한 상황을 바꾸지 않는 범위에서 플린이 정한다.
- 화 수는 함께 정한 상황 수다. 한 화로도 스토리를 만들 수 있고 상한 5화는 유지한다.
  추가 화는 사용자가 원할 때만 제안하고 확인한다. 기본 3화를 채우지 않는다.
- 요청한 모든 화의 상황이 정해지면 스토리 카드를 낸다. 사용자가 처음부터 구체적인 상황을
  충분히 말했으면 다시 확인하느라 카드를 늦추지 않는다. 카드에서 `스토리 만들기`를
  누르는 것이 플레이 전 최종 확정이다.
- "그냥 만들어 줘"면 그때까지 정한 상황으로 바로 카드를 낸다. 아직 정하지 않은
  세부는 플린에게 맡긴 것으로 보되, 원하지 않은 화를 더하지 않는다. 카드 뒤에 글을
  쓰지 않고, 고칠 것을 말하면 나머지는 유지한 새 카드를 내는 규칙은 그대로다.
- 1번 인물은 이야기의 중심 상대다. 인물 수는 [에피소드 콘텐츠 제작](../../decisions/episode-authoring.md)을
  따른다. 화마다 사건의 크기를 키우거나 상대를 바꾸는 것을 의무로 두지 않는다.
  인물 목록과 각 화의 cast에는 AI가 연기할 상대만 넣는다. 사용자를 이름과 역할이 있는
  별도 인물로 만들지 않는다. 상대 운전자 한 명과 사고 정보를 교환하는 상황이면 상대
  한 명만 만든다. 사용자 역할을 복제한 카드는 평가에서 실패해야 한다.
- 프롬프트 예시 셋은 한 사건만 만드는 대화, 서로 다른 두 상황을 화별로 고르는 대화,
  결말을 가정하지 않고 같은 인물을 다시 만나는 두 화를 고르는 대화로 둔다.
  예시의 인물 설명에는 무엇에 어떻게 반응하는지 한 문장이 들어간다.
  [prompt.md](prompt.md)가 구현에 쓰는 인터뷰 프롬프트 전문이다.
- 카드에는 앞 스펙의 `setting` 외에 표지용 한 줄이 더 실린다. 1번 인물의 성별,
  나이대, 머리, 옷, 표정과 앵글을 영어로 적은 것이고, 화면에는 그리지 않는다. 앵글은
  제품이 정한 목록에서 고른다. 실제 사람이나 회사 이름은 넣지 않는다.

### 카드와 에피소드 추가

- 카드에는 제목, 한 줄 소개, 인물과 화별 상황을 글로 보여 준다. 아직 표지를 만들기
  전이므로 이미지나 빈 이미지 자리를 두지 않는다. 제목과 소개는 카드 너비를 쓴다.
- 가장 최근 카드의 에피소드 목록 아래에 `에피소드 추가하기`와 `스토리 만들기`를
  둔다. 추가 버튼은 덜 강조하고, 지금까지 정한 화들로 확정하는 만들기 버튼을 더
  강조한다. 한 화만 있어도 확정할 수 있다. 지난 카드에는 두 버튼 모두 두지 않는다.
- 추가 버튼은 같은 스토리에 한 화를 더 넣고 싶다는 의사만 받는다. 누른 즉시 화를
  채우거나 각본을 만들지 않고, 같은 채팅에서 다음 상황을 정하는 인터뷰를 시작한다.
  추가 버튼과 말로 하는 추가 요청은 같은 인터뷰 규칙을 따른다.
- 아직 사용자가 요청한 상황을 다 정하지 못한 인터뷰에서는 필요한 것을 묻는다.
  모두 정하고 카드를 낸 뒤에는 매번 더 만들지 묻지 않는다. 카드 뒤의 고정 문구
  `바꾸고 싶은 부분이 있으면 말해 주세요.`를 쓰고, 추가 가능성은 버튼으로 보여 준다.
  이 안내는 대화 안의 문장이므로 한 문장짜리 고정 UI 문구와 달리 마침표를 유지한다.
- 추가할 상황을 합의하면 새 카드를 낸다. 앞서 정한 화의 사건, 목표와 세부 조건은
  유지한다. 사용자가 말로 충분한 상황을 주었다면 다시 묻지 않고 카드에 반영한다.
- 상한 5화는 버튼과 말로 하는 요청에 똑같이 적용한다. 상한을 넘기려고 기존 화를
  사용자 몰래 빼거나 바꾸지 않는다.

### 합의한 상황과 플레이 결과

- 인터뷰에서는 각 화의 시작 상황과 사용자가 하려는 일을 정한다. 상대가 이해해
  준다거나 원하는 것을 얻는다는 결과는 정하지 않는다. 성공·타협·실패의 판정 기준과
  실제로 어떤 결말이 나는지는 다르다. 실제 결말은 그 화의 플레이로 정한다.
- 인터뷰에서 합의한 세부는 각본에도 남는다. 카드의 한 줄 설명에서 생략된 자료,
  상대의 사정, 피하고 싶은 상황과 사용자 목표가 각본 생성에서 빠지면 안 된다.
- 각본은 사용자가 확정한 상황을 지킨다. 예를 들어 한숨을 쉬는 승객을 요청했다면
  처음부터 고함치는 승객으로 바꾸지 않는다. 각본과 플레이에서 사용자의 반응에 따라
  일어나는 변화는 처음 상황과 구분한다.
- 다음 화의 사건은 앞 화의 실제 결말을 몰라도 성립하도록 합의한다. 같은 승객과
  다시 만나는 것은 정할 수 있지만, 친해진 승객과 만난다고 미리 확정하지 않는다.
  다음 화의 제목, 예고와 첫 장면도 아직 일어나지 않은 화해나 성공을 단정하지 않는다.
- 각본은 [에피소드 콘텐츠 제작](../../decisions/episode-authoring.md)과
  [AI 에피소드 프로토콜](../../decisions/ai-episode-protocol.md)의 첫 장면 규칙을 따른다.
  첫 장면은 어떤 결말 뒤에도 성립하는 상황에서 시작하고, 이후 인물의 반응과 구체적인
  전개는 같은 회차의 실제 이야기 기억을 따른다. 이 작업이 첫 장면의 즉석 생성을
  요구하는 것은 아니다.
- 지난 결과는 인사말이나 지난 일의 언급만 바꾸는 데 그치지 않는다. 합의한 상황에
  맞춰 상대에게 부탁할 수 있는 것, 받을 수 있는 도움, 필요한 설명이나 대화를 풀
  방법에도 차이를 만든다. 그 차이 때문에 사용자가 다음에 하는 말이 달라질 수 있어야
  한다. 다음 화의 성공이나 실패까지 자동으로 정하지 않는다.
- 플레이가 시작되면 화 사이에 다음 상황을 정하는 인터뷰를 끼우지 않는다. 사용자는
  기존 흐름대로 표현 돌아보기를 보고 다음 화를 시작한다. 다시 플레이할 때도 합의한
  상황은 같고, 연결에 쓰는 기억은 그 회차의 실제 결과만 따른다.

### 만드는 동안

- 카드의 버튼 이름은 `스토리 만들기`다. 상세에 있는 `대화 시작하기`와 같은 이름을
  쓰지 않는다.
- 버튼은 진행 표시를 붙이고 같은 요청을 다시 시작하지 못한다.
  [모바일 작업 진행 표시](../../decisions/mobile-action-progress.md)의 문구 유지 규칙에서
  제외하며, 만드는 동안 카드 아래 안내는 숨긴다.
- 버튼 안의 문구는 실제로 일이 넘어갈 때마다 다음 문구로 바뀐다. 시간으로 바꾸지 않는다. 문구는
  [UX 라이팅 원칙](../../decisions/ux-writing.md)을 따른다. 아래 승인 당시 문구의
  마침표는 [UX 라이팅 적용 명세](../flyn-ui-writing/spec.md)에서 한 문장 기준으로 바꾼다.
  1. 누르면 `각본을 쓰고 있어요.`
  2. 각본이 다 써졌는데 표지가 아직이면 `표지를 그리고 있어요.`
  3. 각본과 표지가 다 되어 저장하고 여는 동안 `거의 다 됐어요.`
- 단계가 넘어갔다는 사실은 서버가 알린다. 앱이 시간을 재어 바꾸지 않는다. 알리는
  형식은 [AI 채팅 프로토콜](../../decisions/ai-chat-protocol.md)이 정한 스트리밍
  규칙 안에서 구현이 고른다.
- 표지가 각본보다 먼저 끝나 있으면 둘째 단계는 건너뛴다. 표지 생성이 실패하면 표지
  없이 셋째 단계로 넘어간다.
- 만들기에 실패하면 앞 스펙과 같은 알림(`닫기`, `다시 시도`)을 띄운다.
  버튼은 `스토리 만들기`로 돌아가고 카드 아래 안내를 다시 보여 준다.

### 만든 뒤

- 저장이 끝나면 `스토리 만들기` 화면 자리에 방금 만든 스토리의 상세가 선다. 상세에서
  뒤로 가면 탐색이고 `스토리 만들기` 화면은 남지 않는다. 이 흐름이 들어가면
  만든 1화에서 뒤로 갔을 때 만들기 화면이 남던 후속 기록은 일어날 자리가 없어지므로 지운다.
  2026-09-13 iOS와 Android에서 생성한 상세의 뒤로 가기가 탐색으로 이동하는 것을 확인하고
  해당 후속 기록을 지웠다. 만들기 화면은 남지 않았다.
- 1화는 상세의 `대화 시작하기`로 연다. 상세의 구성과 그 버튼의 동작은
  [모바일 스토리 탐색](../../decisions/mobile-story-browsing.md)이 정한 그대로다.
- 상세가 열릴 때 표지가 보인다. 표지가 실패한 스토리는 앞 스펙대로 빈 색 상자다.

### 표지

- 풍은 공식 표지와 같은 애니메이션풍 셀 셰이딩이고, 단색 배경이며, 인물 한 명이
  화면의 3분의 2쯤을 채운다. 글자, 로고, 명찰, 배경 풍경은 없다.
- 배경색은 제품이 정한 여섯 색(짙은 남색, 테라코타, 청록, 겨자색, 자주, 짙은
  초록) 중 하나다.
- 인물은 언제나 한 명, 1번 인물이다. 두 명 이상은 그리지 않는다.
- 스토리마다 바뀌는 것은 카드의 표지용 한 줄뿐이다. 이 줄이 인물의 생김새, 그
  상황에서 짓는 표정과 자세, 앵글, 배경색을 정하므로 같은 직업이라도 스토리마다 다른
  사람과 다른 분위기가 나온다. 상황의 느낌은 이 표정과 자세와 배경색으로만 전한다.
  스타일 문구에 표정을 고정하지 않는다. 앵글 목록은 어깨 너머로 돌아보기, 아래에서
  올려다보기, 기울인 클로즈업, 위에서 내려다보기, 몸을 튼 4분의 3 정면이다.
- 인물은 손에 아무것도 들지 않는다. 물건 구절이 명찰과 깨진 글자를 불렀다.
- 모델은 `openai/gpt-image-1-mini`, 품질 low, 1024×1024 한 장이다. 앞 스펙과 같다.
- 스토리당 한 장, 카드를 고칠 때는 만들지 않는 것, 저장 방식은 앞 스펙 그대로다.

## 완료 기준

- 첫마디는 `어떤 상황에서 영어로 대화해 보고 싶으세요?`이고, 카드 뒤에는
  `바꾸고 싶은 부분이 있으면 말해 주세요.`가 보인다. 모델이 두 문구를 중복해서 쓰지 않는다.
- 추가 확인이 필요한 상황을 보내면 사용자가 제안된 장면과 아직 정할 부분을 이해할 수
  있고 무엇에 답하면 되는지 분명하다. 충분한 설명과 휴대폰에서의 가독성을 함께 확인한다.
  문장 수나 줄바꿈 유무만으로 통과시키거나 떨어뜨리지 않는다.
- 비행기에서 아기가 울음을 멈추지 않는 사건 하나를 요청하면 그 상황을 확인하고
  한 화의 카드를 낸다. 사용자가 요청하지 않은 비슷한 사건을 추가하지 않는다.
- 카드에 빈 이미지 자리가 없고, 가장 최근 카드에만 두 버튼이 보인다. 한 화 카드에서
  추가 질문에 답하지 않고 `스토리 만들기`로 확정할 수 있다.
- `에피소드 추가하기`를 누르면 같은 채팅에서 다음 상황을 묻고, 답하기 전에는 화 수가
  늘지 않는다. 상황을 합의한 뒤 새 카드에는 원래 화와 추가한 화가 함께 보이고,
  원래 화의 조건은 유지된다. 말로 추가를 요청해도 같은 흐름을 따른다.
- 카드가 나온 뒤 플린이 추가를 권하는 질문을 붙이지 않는다. 아직 요청한 여러 상황을
  확인 중일 때는 필요한 질문을 계속한다. 두 경우를 구분해 확인한다.
- 5화까지 정하면 추가 버튼으로 더 늘릴 수 없다. 말로 6화를 요청해도 기존 화를
  임의로 바꾸지 않는다. 한 화를 빼면 다시 추가할 수 있다.
- 사용자가 서로 다른 두 상황을 요청하면 두 화를 각각 확인한다. 한 화를 고쳐도
  다른 화에서 정한 상황은 유지한다. 카드는 합의한 두 화만 담는다.
- 상황이 충분한 첫 말에는 바로 카드가 나오고, 무엇을 하려는지 불분명하면 그 부분을
  묻는다. "그냥 만들어 줘" 다음에는 요청하지 않은 화를 더하지 않고 바로 카드가 나온다.
- 카드에서 생략된 세부 조건도 플레이의 첫 상황과 상대의 사정에 남는다. 한숨을 쉬는
  승객과 대화하려고 만든 화가 고함치는 승객과의 다툼으로 시작하지 않는다.
- 같은 승객을 다시 만나는 두 화를 만들면 카드, 예고, 각본의 첫 장면에 아직 일어나지
  않은 화해나 도움을 사실로 쓰지 않는다. 같은 첫 화가 다른 결과로 끝난 두 회차에서
  두 번째 화를 확인하고, 상대의 반응과 도움이나 대화 방법이 실제 기억에 따라 다른지
  기록한다. 지난 사건을 한 번 언급하는 것만으로 통과하지 않는다.
- 1화 종료부터 2화 시작까지 제작 인터뷰가 없고, 중간에 나갔다 돌아와도 실제 결과와
  합의한 다음 상황이 유지된다. 한 화짜리 스토리는 1화 뒤 완주하며 없는 다음 화를
  만들거나 예고하지 않는다.
  2026-09-13 Android에서 만든 한 화짜리 `새 커피 머신의 누수`를 끝냈다. 영수증과 누수
  영상이 첫 장면에 남았고, 교환 대화 뒤 표현 돌아보기와 `마지막 이야기까지 함께했어요`가
  나왔다. 두 화 사이의 실제 플레이 연결과 사용자 재미 확인은 아직 남아 있다.
- 카드의 버튼이 `스토리 만들기`이고, 누르면 단계 문구와 진행 표시가 나오고 두 번
  눌리지 않는다. 실패하면 원래 버튼 문구와 카드 아래 안내가 돌아온다.
- 버튼 안에 `각본을 쓰고 있어요`가 보이고, 각본이 끝나면 `표지를 그리고 있어요` 또는
  `거의 다 됐어요`로 바뀐 뒤 상세가 열린다. 문구는 실제 단계가 넘어갈 때 바뀌며
  카드 아래에는 중복해서 표시하지 않는다.
- 열린 상세에 표지, 소개, 에피소드 목록이 있고 `대화 시작하기`를 누르면 1화가
  첫 장면부터 열린다. 상세에서 뒤로 가면 탐색이고 만들기 화면은 없다.
- 표지 생성만 실패시키면 `표지를 그리고 있어요`가 뜨지 않거나 곧 넘어가고, 상세는
  빈 색 상자로 열린다.
- 만든 표지에 글자나 명찰이 없고, 배경은 여섯 색 중 하나이며, 다른 직업의 스토리 두
  개를 만들면 인물의 생김새나 앵글이 다르다.
- 인터뷰 프롬프트 평가 명령이 있고, 고치기 전 프롬프트는 떨어지며 새 프롬프트는
  세 번 돌려 전부 통과한다. 출력 전문 기록이 저장소에 남는다.

### 프롬프트 평가

인터뷰 프롬프트의 평가는 이 조각의 필수 산출물이다. 사용자가 2026-09-11에 반드시
있어야 한다고 정했다. 평가 없이 프롬프트만 바꾼 상태는 완료가 아니다.
[AI 프롬프트 평가](../../decisions/ai-prompt-evaluation.md)를 따라 `AI에게 물어보기`의
`eval:ask`와 같은 모양으로 고정 대화 묶음, 기계 검사, 출력 전문 기록을 두고 사람이
돌린다. 검사는 고치기 전 프롬프트의 답을 떨어뜨려야 하고, 새 프롬프트는 여러 번
돌려 전부 통과해야 한다. 그 결과 기록이 구현 PR에 함께 남는다.

- 고정 대화 묶음: 예시와 다른 상황에서 한 사건만 요청하기, 구체적인 상황 두 개를
  각각 확인하기, 한 화의 조건만 고치기, 충분한 첫 말과 모호한 첫 말, 둘째 턴에
  "그냥 만들어 줘"를 보내기를 포함한다. 카드 뒤 추가 버튼으로 의사만 보내기,
  구체적인 상황을 말로 추가하기, 상한에서 추가 요청하기도 포함한다.
  별도로 사용자 피드백의 비행기 사건을
  회귀 사례로 두고 한 사건을 비슷한 여러 화로 늘리는지 확인한다.
- 기계 검사: 충분한 첫 말에는 첫 턴에 카드가 나오고, 모호한 첫 말에는 첫 턴에 카드가 나오지
  않는다. "그냥 만들어 줘" 다음 턴에는 카드가 나온다. 한 사건 요청은 한 화,
  두 상황 합의는 두 화인지 확인한다. 카드의 인물 이름이
  영어이고, 표지용 한 줄에 앵글 목록의 문구가 하나 들어 있다.
- 상황의 의미를 바꾸지 않았는지, 한 화를 고칠 때 다른 화의 합의가 유지되는지,
  결과를 미리 확정하지 않았는지는 출력 전문 기록을 사람이 읽어 확인한다.
- 대화 품질은 장면을 이해하고 자기 뜻과 맞는지 판단할 수 있는지, 답할 지점이 분명한지,
  필요한 설명을 유지하면서 휴대폰에서 읽기 편한지로 확인한다. 친근하고 정중한 한국어
  해요체인지도 함께 읽는다. 짧은 답만 우대하거나 문장·문단·물음표 수와 서식 유무를
  합격 기준으로 쓰지 않는다. 기존 한 문단 답과 새 답을 같은 입력으로 비교해 근거를 남긴다.
  모델 비교 채점을 쓰면 기존 평가 계약의 짝 비교 방식을 따른다.
- 각본 생성과 화 사이의 반응을 고칠 때도 같은 평가 계약을 따른다. 합의한 세부가
  카드에서 각본까지 이어지는지, 서로 다른 실제 결과에 따라 다음 화의 반응과 도움이나
  대화 방법이 달라지는지를 검사한다. 인터뷰 평가 통과만으로 이 기준을 대신하지 않는다.

### 사용자와 확인할 재미

- 첫 확인은 같은 사용자와 두 화짜리 스토리 하나로 한다. 플레이 전에 원하는 두
  상황을 함께 정하고, 화 사이 인터뷰 없이 끝까지 플레이한다.
- 원하는 상황이 나왔는지, 상황을 알고 시작해도 전개가 궁금했는지, 앞에서 한 말이
  다음 화에 영향을 줬다고 느꼈는지를 묻고 답을 남긴다. 사용자의 답은 실제로 확인한
  뒤 기록한다. 에이전트가 대신 답하거나 기계 검사 통과로 재미까지 검증했다고 쓰지 않는다.

## 결정 이유

- **화별로 원하는 상황을 확인한다.** 사용자는 큰 틀만 맞고 구체적인 사건이 다르면
  자기 스토리로 느끼지 못했다. 비행기에서 아기가 울던 사건 하나를 요청했을 때 AI가
  비슷한 사건 네 개를 채운 피드백이 있었다. 더 많은 화보다 원한 사건을 지키는 것이
  먼저다.
- **상황은 함께, 결과는 플레이에서 정한다.** 사용자가 경험할 상황을 고르면 자기
  선택이라는 느낌을 지킨다. 상대의 반응과 결말을 남겨 두면 상황을 알아도 전개가
  궁금하다. 다음 화의 큰 사건이 달라지는 자유는 줄지만, 실제 결과에 따라 관계와
  대화 방법이 달라지는 재미는 지킨다.
- **플레이 중에 제작 인터뷰를 하지 않는다.** 화마다 다음 사건을 정하게 하면 영어로
  대화하던 사용자가 다시 이야기를 만드는 역할로 돌아가야 한다. 처음에 원하는 상황을
  함께 정하고, 이후의 연결은 플레이에서 생긴 사실에 따른다.
- **예시는 대화까지.** 카드 예시만 늘리면 카드 모양은 좋아지고 인터뷰는 그대로다.
  대화와 카드를 한 묶음으로 세 개 두어, 한 사건을 지키고 여러 상황을 각각 확인하며
  실제 결과를 미리 정하지 않는 방식을 보여 준다.
- **추가할지는 버튼, 무엇을 추가할지는 질문.** 수정 안내만으로는 추가할 수 있다는
  것을 알기 어렵다. 반대로 카드마다 더 만들지 물으면 한 화로 끝내려는 사용자도
  답해야 한다고 느낄 수 있다. 추가 행동은 계속 보이게 두고, 사용자가 원할 때만
  다음 상황을 함께 정한다.
- **표지가 없을 때는 자리도 비우지 않는다.** 개요를 고르는 카드에서 빈 상자는
  판단할 정보를 주지 않는다. 이미지는 확정 뒤 만들고 상세에서 보여 준다.
- **진행 단계는 실제 이벤트에만.** 실제로 시간이 드는 일은 각본과 표지 둘뿐이고 나란히
  실행한다. 순서 있는 단계를 꾸미면 실제와 어긋난다. 단계 문구는 각본 완료, 표지 완료, 저장
  시작이라는 실제 전환에 붙는다. 실제 생성은 약 20초가 걸리므로 작은 진행 표시만으로는
  무엇을 기다리는지 알기 어렵다. 문구는 사용자가 셋 중 골랐다.
- **생성 단계는 버튼 안에 보여 준다.** 2026-09-13 사용자 리뷰에서 단계별 문구를
  카드 아래가 아닌 버튼 안에 표시하기로 바꿨다. 기존 프로토타입의 문구 유지보다
  이 결정을 우선한다. 다른 버튼의 진행 표시 규칙은 바꾸지 않는다.
- **상세로 간다.** 스토리에 화가 여럿이라 만든 결과를 한눈에 보는 자리가 상세다.
  20초를 기다린 끝에 새로 생긴 표지, 소개, 목록을 1화로 바로 가면 못 본다. 상세에는
  이미 `대화 시작하기`가 있어 한 번만 더 누르면 1화다. GPT Builder는 미리보기부터,
  Character.AI는 채팅부터 보여 주는데 여러 화짜리 묶음은 전자가 맞다.
- **애니메이션풍 유지.** 탐색 목록이 공식과 만든 스토리를 한 줄로 섞어 보여 주므로
  만든 것끼리의 일관성보다 공식과의 일관성이 먼저다. 플랫 풍은 두 장이 서로 가장
  닮았지만 공식 표지 옆에서 다른 앱의 그림처럼 보였다.
- **생김새와 앵글을 카드가 정한다.** 인물 줄이 성격과 직업뿐이면 모델이 매번 같은
  기본값(남자, 짙은 정장, 정면)으로 간다. 시안 네 장 모두 그랬다. 표지용 한 줄에
  생김새와 앵글을 영어로 적어 넘기자 네 장이 성별, 나이대, 앵글 모두 갈렸다.
- **low 품질.** 같은 프롬프트로 low와 medium을 그려 72px과 원본에서 비교했다.
  72px에서는 구분이 안 되고 원본에서도 선이 조금 매끈한 정도였다. 값은 열 배다.
- **물건 구절 삭제.** "작은 물건 하나"가 호텔 직원과 회사원에서 명찰과 핸드폰을
  불렀고 그 위에 깨진 글자가 생겼다. 빼자 글자가 사라졌다. 유니폼에 붙는 글자 없는
  명찰 판은 남을 수 있고 72px에서는 거슬리지 않아 그대로 둔다.

## 가정

바꿀 수 있는 기본값이다. 사용자가 다른 뜻을 밝히면 그쪽을 따른다.

- 상세를 열기 전에 표지를 기다린다. 앞 스펙은 표지 때문에 기다림을 늘리지 않고
  표지가 늦으면 1화를 먼저 열기로 했는데, 목적지가 상세로 바뀌어 표지가 첫 화면에
  크게 보이므로 이 조각에서 뒤집는다. 표지가 보통 각본보다 먼저 끝나므로 기다림이
  거의 늘지 않고, 상세가 빈 상자로 열렸다가 그림이 튀어 들어오는 것보다 낫다. 표지가
  실패하면 기다리지 않는다. 사용자가 앞 스펙의 동작을 원하면 그쪽으로 돌린다.
- 생성 단계는 확정 버튼 안에 놓고, 만드는 동안 카드 아래 안내는 숨긴다.
- 추가 버튼은 시안처럼 더하기 표시와 테두리를 쓰고 확정 버튼 바로 위에 둔다.
  5화에서는 버튼을 비활성화하고 상한을 짧게 알린다. 추가 상황을 확인 중일 때도
  기존 카드의 두 버튼을 비활성화한다. 세부 배치와 비활성 표시 방식은 바꿀 수 있다.
- 시안의 앱 배경, 본문과 카드 색은 프로젝트 값을 쓴다. 의존 패키지가 제공하는
  강조색과 경계색은 근삿값이므로, 구현은 실제 앱의 토큰과 컴포넌트를 따른다.
- 질문 횟수를 목표로 두지 않는다. 중요한 조건이 비었으면 확인하고 충분히 정했으면
  카드를 낸다. 같은 것을 되묻거나 필요 없는 세부 때문에 확정을 미루지 않는다.
- 앵글 목록 다섯은 공식 표지 다섯 장의 구도에서 뽑았다.
- 팔레트 여섯 색은 공식 표지의 배경색 계열이다. 실제 색값은 구현이 정한다.
- 표지용 한 줄은 카드를 만드는 모델이 쓴다. 각본 단계에서 쓰면 표지가 각본을
  기다려야 한다.

## 제외

- 기본 화 수를 채우려고 에피소드를 자동으로 더하기. 한 화도 완성된 스토리다.
- 카드마다 더 만들지 묻기, 추가 버튼만으로 AI가 다음 화를 바로 채우기.
- 개요 카드에 아직 없는 표지의 빈 자리 남기기.
- 매 화 뒤에 다음 사건을 고르는 제작 인터뷰. 플레이 흐름을 끊는다.
- 앞 화의 결말에 따라 사용자가 고른 다음 화의 사건 자체를 다른 사건으로 바꾸기.
  이번에는 원하는 상황을 지키며 그 안의 관계와 전개에 결과를 반영한다.
- 만든 스토리에 플레이 도중 새 에피소드를 추가하기. 상황과 화 수는 시작 전에 확정한다.
- 카드에 표지 그리기. 카드마다 한 장이 되어 스토리당 한 장 원칙을 깬다.
- 각본을 화별로 스트리밍해 `1화 각본이 나왔어요`처럼 보여 주기. 서버 저장 경로를
  다시 짜야 해서 이번 조각을 넘는다. dogfooding 뒤에도 길게 느껴지면 본다.
- 공식 표지 다시 그리기. 만든 표지가 공식에 맞추는 쪽이지 그 반대가 아니다.
- 플랫 풍. 공식 표지와 결이 다르다.
- 두 명 이상의 인물과 장소 배경. mini low로 그려 보니 세 명은 얼굴이 뭉개지고, 장소
  배경은 공식 표지와 결이 갈린다. 상황의 느낌은 인물 한 명의 표정과 자세로 전한다.
- 대기 중 취소.
- 앞 스펙이 미룬 수정과 삭제, 공유, 표지 다시 만들기.

## 미결

- 이번 구현을 시작하기 위해 사용자가 더 정할 사항은 없다. 위의 가정은 바꿀 수 있는
  기본값으로 두고, 아래의 더 넓은 품질 개선은 실제 플레이 확인 뒤에 정한다.
- **더 넓은 각본 품질.** 이번에는 합의한 세부의 보존, 결과를 단정하지 않는 각본,
  실제 기억에 따른 다음 화의 반응까지 다룬다. 그 밖의 각본 재미 개선은 두 화짜리
  사용자 확인 뒤에 정한다.

## 남은 위험

- **프롬프트는 모델 출력이다.** 원하지 않은 화를 더하거나 조건을 바꾸고 결말을
  미리 확정할 수 있다. 예시와 평가가 필요하다.
- **화 수만 맞을 수 있다.** 한 화를 만들었어도 세부가 다르면 같은 실패다. 개요와
  각본, 실제 플레이까지 요청한 상황을 대조한다.
- **인터뷰가 길어질 수 있다.** 모든 상황을 시작 전에 정하므로 화가 많을수록 첫
  플레이가 늦어진다. 이미 말한 것을 되묻지 않고 한 화로 끝낼 수 있게 한다.
- **버튼만으로 상황을 떠올리기 어려울 수 있다.** 추가 가능성을 아는 것과 원하는
  장면을 떠올리는 것은 다르다. 사용자가 추가를 원하면 구체안을 함께 정하는 질문이
  도움이 되는지 확인한다.
- **기억이 언급에 그칠 수 있다.** 실제 결과가 다음 화의 대화 방법에도 영향을 주는지
  서로 다른 기록으로 확인한다. 상황이 유지되는 만큼 큰 줄거리 분기는 제한된다.
- **표지용 한 줄도 모델이 쓴다.** 앵글 목록 밖의 말을 쓰거나 생김새를 빠뜨릴 수
  있다. 그러면 이미지 모델이 기본값으로 간다.
- **상세 전 표지 대기.** 이미지 모델이 느린 날에는 대기가 각본 시간을 넘길 수 있다.
  측정에서 low는 8–10초였다.
- **명찰 판.** 유니폼 직업에서는 글자 없는 명찰 판이 남을 수 있다.

## 근거

- 2026-09-13 대화 방향 승인. 사용자는 설명 자체를 줄이기보다 장면을 충분히 이해하고
  판단할 수 있기를 원했다. 문장 수와 줄바꿈 같은 세부 지시 대신 목적을 모델에 전달하고,
  스토리 만들기의 다른 대화 지침도 같은 기준으로 정리하기로 했다. 화 수, 상황 보존,
  결말과 카드 동작의 계약은 유지한다.
- 2026-09-13 문구 승인. 사용자는 첫 질문의 `싶으세요`와 카드 뒤의
  `바꾸고 싶은 부분이 있으면 말해 주세요.`를 선택했다. 화면 흐름과 문구의 결정은
  마쳤으며, 앱 구현과 실제 모델 평가, 사용자 플레이 확인은 아직 남아 있다.
- 2026-09-13 카드 시안 검토와 승인. 사용자는 수정 안내만으로 에피소드 추가가
  가능한지 알 수 없고, 아직 이미지가 없는 카드의 빈 이미지 자리가 불필요하다고
  짚었다. 추가 의사는 버튼이나 말로 받고 내용은 인터뷰에서 정하는 방식을 선택했다.
- 카드 시안에서 한 화부터 추가 인터뷰, 추가 합의 뒤 새 카드, 5화 상한과 삭제 뒤
  재추가 가능 여부를 확인했다. 생성과 저장은 연결하지 않은 화면 확인이며, 실제
  모델 평가나 사용자 재미 검증을 대신하지 않는다.
- 2026-09-12 사용자 피드백과 승인. 큰 틀은 맞지만 원한 사건이 빠졌고, 비행기에서
  아기가 울던 한 사건이 비슷한 여러 화로 늘어났다. 사용자는 매 화 뒤 제작 인터뷰가
  플레이를 끊는 문제도 짚었다. 상황은 시작 전에 함께 정하고 결과는 플레이에서 정하며,
  한 화도 허용하고 처음에는 두 화로 재미를 확인하는 방향을 승인했다.
- 2026-09-12 현재 구현 확인. 각본 생성에는 인터뷰 전체가 아니라 제목, 인물 설명과
  화별 한 줄 설명만 전달된다. 합의한 세부를 그 경계에서 잃지 않는 기준을 추가했다.
- 2026-09-11 코드 확인. 버튼 문구가 `만드는 중`으로 바뀌는 구현, 만들기 프롬프트에
  말투 규칙이 없는 것, 표지 프롬프트의 구성을 읽었다.
- 2026-09-11 표지 시안 세 번. 같은 두 스토리(호텔 직원, 거래처 담당자)를 지금 풍,
  플랫, 고정 팔레트로 그려 공식 표지와 나란히 놓았고, 고친 프롬프트로 low와
  medium을, 표지용 한 줄로 앵글 넷을 그렸다. 두 명, 세 명, 장소 배경도 그려 세 명은
  얼굴이 뭉개지는 것을 보았다. 마지막으로 최종 규칙대로 다섯 상황(호텔 직원, 담당자,
  동료, 집주인, 의사)을 그려 표정과 자세와 배경색이 상황마다 갈리고 글자와 명찰이
  없는 것을 확인했다. 모두 작업 폴더 밖에서 이 프로젝트의 게이트웨이와
  `gpt-image-1-mini`로 만들었고 결정 뒤 버렸다.
- 앞 스펙의 측정: 각본 3화 13–18초, 표지 low 10초 안팎, 장당 $0.0024.
