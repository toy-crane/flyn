# 최소 지원 버전 운영

Supabase Dashboard의 **Table Editor → `public.app_version_policies`**에서 값을 바꾼다. `platform`은 `ios` 또는 `android`, `distribution`은 `internal` 또는 `public`이다. 두 열은 행의 이름이므로 바꾸지 않는다.

각 행에서 운영자가 바꾸는 값은 두 가지다.

| 열 | 넣을 값 |
| --- | --- |
| `install_url` | 해당 사용자가 실제로 설치할 수 있는 HTTPS 주소. iOS 내부는 TestFlight 초대 주소, 공개 iOS는 App Store, 공개 Android는 Play Store 주소를 쓴다. |
| `minimum_version` | `1.2.0`처럼 숫자 세 자리를 점으로 구분한 설치 버전. `NULL`이면 차단을 끈다. |

새 앱에 이 확인 기능이 들어간 뒤, 대상 사용자가 새 버전을 **실제로 설치할 수 있는지** 먼저 확인한다. 내부 iOS라면 TestFlight 그룹과 초대 주소를 확인한다. 공개 iOS의 App Store 페이지는 아직 열리지 않으므로 공개 행은 비워 둔다. 설치 주소를 넣고, 그다음 같은 행의 `minimum_version`을 올린다. 예를 들어 `1.2.0`이면 설치 버전 `1.1.9`는 막히고 `1.2.0`은 계속 쓸 수 있다. 주소가 비어 있으면 DB가 최소 지원 버전 저장을 거절한다.

차단을 풀려면 해당 행의 `minimum_version`을 `NULL`로 바꾼다. `install_url`은 그대로 두어도 된다. 차단 화면의 **다시 확인**을 누르면 바로 새 값을 읽고 화면이 닫힌다. 앱 시작에도 확인하며, 다른 앱에서 돌아올 때는 직전 확인으로부터 5분이 지났으면 확인한다. 설치 화면에서 돌아오면 5분을 기다리지 않는다. 조회가 실패하면 새로 차단하지 않고, 이미 차단된 화면은 다시 확인할 수 있게 유지한다.

앱을 새로 배포해도 이 값은 자동으로 바뀌지 않는다. 이 기능이 들어가기 전에 설치된 앱은 정책을 읽지 못하므로 먼저 확인 기능이 담긴 앱을 배포해야 한다. 내부 빌드는 EAS Update 채널 `internal`의 행을 읽는다. 공개 빌드를 만들 때는 공개 채널과 실제 스토어 주소를 먼저 준비한다.
