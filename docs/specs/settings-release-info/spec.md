# 설정에서 설치된 앱 버전과 실행 중인 업데이트 확인

## 배경

설정의 `버전` 행은 현재 앱 설정에 적힌 버전 값을 보여 준다. 이 값만으로는 기기에
설치된 앱의 버전과 지금 실행 중인 EAS Update를 각각 확인할 수 없다. 내부 테스트
중 문제가 생기면 두 값을 구분해 확인할 수 있어야 한다.

## 사용자에게 보이는 결과

- `앱 정보`의 `버전` 행은 기기에 설치된 앱의 사용자용 버전을 보여 준다. EAS Update가
  적용되어도 설치된 앱이 바뀌지 않았다면 이 값은 그대로다.
- `버전` 아래에 `업데이트` 행을 둔다. 내려받은 업데이트를 실행 중이면 해당
  업데이트 ID의 앞 8글자를 보여 준다. 행을 누르면 전체 ID를 복사하고
  `업데이트 ID를 복사했어요`를 보여 준다.
- 빌드에 포함된 코드를 실행 중이면 `업데이트` 값은 `기본 버전`, 개발 중인 코드를
  실행 중이면 `개발 중`으로 보여 준다. 이 두 상태의 행은 눌러도 복사하지 않는다.
- 설치된 앱의 버전을 읽을 수 없으면 `버전 정보 없음`을 보여 준다. 업데이트 기능이
  꺼졌거나 업데이트 ID를 읽지 못했으며 개발 중도 아니라면 `업데이트 정보 없음`을
  보여 준다. 이 경우에도 ID를 복사하지 않는다.

## 범위

- 설정 첫 화면의 `앱 정보` 두 행만 다룬다. 업데이트를 확인하거나 내려받거나
  적용하는 동작은 추가하지 않는다.
- iOS와 Android는 같은 정보 순서와 값을 보여 주되 각 플랫폼의 기존 설정 표현을
  따른다.

## 완료 기준

- 설치된 앱의 사용자용 버전이 앱 설정에 적힌 버전과 다르더라도 `버전` 행에는
  설치된 앱의 값이 나타난다.
- 내려받은 업데이트 A를 실행하면 A의 ID 앞 8글자가 보이고 전체 ID를 복사할 수
  있다. 다른 업데이트 B를 실행하면 값과 복사 결과가 B의 ID로 바뀐다.
- 빌드에 포함된 코드를 실행할 때와 개발 중일 때는 각각 정해진 문구가 나타나며
  복사 동작은 없다. 업데이트 정보를 읽지 못할 때도 빈칸이나 잘못된 ID가 나타나지
  않는다.
- 화면 읽기는 두 행의 이름과 현재 값을 함께 전달한다. 짧게 보여 준 ID와 복사한
  전체 ID가 같은 업데이트를 가리킨다.

## 제약과 근거

- [모바일 설정 구조](../../decisions/mobile-settings-structure.md)는 `앱 정보`의 행
  순서와 값 행의 표현을 정한다.
- [UX 라이팅 원칙](../../decisions/ux-writing.md)은 상태와 복사 안내의 문구를 정한다.
- [검증과 내부 테스트 배포](../../decisions/continuous-delivery.md)는 빌드와 EAS
  Update가 각각 배포되는 범위를 정한다. 설정의 값은 배포 성공이나 최신 상태를
  판정하지 않고, 이 기기에서 지금 실행 중인 것을 보여 준다.
- [Expo SDK 57의 Updates 문서](https://docs.expo.dev/versions/v57.0.0/sdk/updates/)는
  실행 중인 업데이트 ID, 빌드에 포함된 코드의 여부, 개발 환경의 ID 부재를
  설명한다. [Expo의 앱 버전 안내](https://docs.expo.dev/build-reference/app-versions/)는
  설치된 앱의 사용자용 버전을 읽는 방법을 권한다.
- 현재 잠금 파일의 `expo-updates`는 57.0.21이다. SDK 57의 앱 버전 모듈
  57.0.2와 이 버전의 패키지에서 해당 값을 내보내는 것을 작업 폴더 밖에서
  확인했다. 실제 기기의 표시 값은 구현 뒤 배포용 빌드에서 확인해야 한다.

## 가정

- 에이전트 가정: 업데이트 ID의 앞 8글자는 목록에서 서로 구별하기에 충분하다.
  전체 ID를 복사할 수 있으므로 정확한 확인에는 복사한 값을 쓴다. 같은 앞 8글자의
  업데이트가 생기면 표시 길이를 다시 검토한다.
- 에이전트 가정: 문제를 확인하는 내부 테스터에게만 이 값이 중요하므로, 별도
  상세 화면을 만들지 않고 설정의 한 행에서 확인과 복사를 끝낸다.

## 손대지 않는 것

- 앱의 사용자용 버전을 올리는 시점, 빌드 번호의 자동 증가, 업데이트 채널과
  runtimeVersion 정책. 현재 배포 결정이 맡는다.
- 새 업데이트를 수동으로 찾거나 바로 적용하는 기능. 이번 요청은 현재 실행 중인
  것을 확인하는 데 한정된다.

## 미룬 결정

- 공개 출시 뒤 일반 사용자에게도 업데이트 ID를 계속 보여 줄지는 출시 범위를
  정할 때 다시 판단한다. 그전에는 내부 테스트용으로 표시한다.

## 남은 위험

- 짧은 ID만 적어 전달하면 다른 업데이트와 혼동할 수 있다. 정확한 조사에는 행에서
  복사한 전체 ID를 사용해야 한다.
- 실제 배포용 빌드에서 설치된 앱 버전과 업데이트 ID가 의도한 값인지 확인해야 한다.
  개발 빌드의 값만으로 배포 동작을 증명할 수 없다.
- 설치된 앱의 버전을 읽는 모듈은 현재 앱에 없으므로, 이 기능을 배포하려면
  새 빌드가 필요하다. Expo가 기존 모듈만으로 같은 값을 안정적으로 제공하게 되면
  이 선택을 다시 검토한다.
