# 스토리 다시 플레이

## 상태와 목적

2026-09-09까지 검토한 화면 구성을 확정한다. 기존 기록을 보존하면서 같은 스토리를
여러 번 진행할 수 있게 한다. 프로토타입과 명세를 정리한 단계이며 실제 앱과 저장
구조는 아직 구현하지 않았다. 스토리 상세에서는 새 대화를 시작하고, 이어갈 대화는
대화 기록의 개별 카드에서 사용자가 고른다. 기본 이어하기 대상을 자동으로 고르지 않는다.

[검토용 프로토타입](prototype.html)은 선택한 화면 한 벌을 보존한다. 실제 데이터와
네이티브 런타임을 연결하지 않은 HTML이다. 정확한 네이티브 재질, 접근성, 키보드와
스트리밍 동작은 구현 단계에서 기존 컴포넌트를 사용해 확인한다.

## 사용자에게 보이는 결과

- 같은 스토리를 1화부터 새 회차로 시작할 수 있다.
- 기존 회차의 대화, 교정과 결말이 남고, 여러 미완료 회차를 각각 이어갈 수 있다.
- 상세는 스토리 자체를 소개하고, 회차별 진행과 결과는 대화 기록에서 보여 준다.
- 점수나 성공·실패 배지 대신 이야기의 진행과 선택의 결과를 보여 준다.

## 확정 범위

### 탭과 콘텐츠 탐색

- 하단 탭은 `홈 / 탐색 / 스토리`로 구성한다.
- 홈은 향후 영어 학습 내용을 보여 줄 공간이다. 구체적인 학습 화면은 이번 범위에서
  확정하지 않는다. 프로토타입은 홈의 제목과 탭만 남긴다.
- 탐색은 전체 스토리를 표지·제목·소개로 보여 주고 상세로 연결한다. 목록에서
  특정 플레이를 대표하는 진행 바를 표시하지 않는다.
- 스토리는 대화 기록이 있는 스토리를 하나씩 묶어 보여 주고 해당 대화 기록으로
  연결한다. 기록에서 개별 플레이를 이어간다. 기록이 없으면 탐색으로 연결한다.
- 스토리 상세와 대화 기록의 뒤로 가기는 진입한 화면으로 돌아간다.
- 향후 사용자 제작 스토리를 공개하는 커뮤니티로 운영한다. 이번에는 탭의 역할을
  반영하며, 제작·게시·공개 범위·신고·콘텐츠 검토·검색·추천 정책은 별도로 정한다.

### 스토리 상세

- 표지, 제목, 소개와 전체 에피소드 목록을 보여 준다. 각 화에는 제목과 고정된
  상황 설명을 두고, 사용자가 만든 결말이나 회차별 진행 상태를 넣지 않는다.
- 모든 화의 상황 설명을 공개하되 결말을 드러내지 않는다. 목록은 콘텐츠 소개이며
  특정 화를 플레이하거나 지난 대화를 여는 버튼이 아니다.
- 기록 유무나 완료 상태와 관계없이 하단에 Primary `대화 시작하기` 하나를 고정한다.
  [모바일 하단 CTA](../../decisions/mobile-bottom-cta.md)를 따른다.
  상세의 `이어서 하기`는 제거한다. 이어갈 회차는 대화 기록의 개별 카드에서 고른다.
- 우측 상단은 History 아이콘 버튼이다. 접근성 이름은 `대화 기록`이고 기존
  네이티브 헤더 버튼 규격을 재사용한다.
- `대화 시작하기`는 새 플레이의 첫 화를 바로 연다. 기존 기록을 보존한다는 안내나 확인창은 두지 않는다.

### 최근 대화와 새 대화

- 스토리 탭의 목록 제목은 `최근 대화`다. 스토리별 마지막 사용자 메시지 시각을
  기준으로 최근순 정렬한다. 기록 조회나 빈 플레이 시작은 순서를 바꾸지 않는다.
- 대화 기록의 헤더 오른쪽에 `새 대화` 텍스트 버튼을 둔다. 별도 강조색이나 커스텀
  테두리를 추가하지 않고 시스템 표현을 따른다. iOS 26의 시스템 캡슐 배경을 숨기지 않는다. 하단 CTA는 두지 않는다.
- 탐색의 상세에서 들어오거나 스토리 탭에서 들어와도 같은 버튼을 제공한다. 기존 기록을
  유지하고 같은 스토리의 1화를 시작한다. 입력 없이 돌아오면 새 기록을 만들지 않는다.
- 대화 기록에서 새 대화나 이어하기로 들어가면 뒤로 가기로 해당 기록 화면에 돌아간다.
  상세에서 시작했으면 상세로 돌아간다. 같은 회차의 다음 화로 넘어가도 이 복귀 경로를 유지한다.

### 대화 기록

- 화면 제목은 `대화 기록`이다. 상단에 해당 스토리의 표지, 제목과 소개를 둔다.
- 카드 제목은 시작 날짜와 시간으로 표시한다. 예: `9월 8일 오후 3:42`. 회차 번호와
  중복된 날짜 줄은 표시하지 않는다. 분절 진행 바와 대화 위치 또는 결과는 유지한다.
- 진행 바는 화 수만큼 나눈다. 끝낸 화만 채우고, 화 수를 다시 설명하는 문장이나
  완료·진행 중 배지를 붙이지 않는다. `현재 플레이`처럼 하나를 대표로 표시하지 않는다.
- 카드를 펼치면 그 회차에서 끝낸 화의 대화를 볼 수 있다. 미완료 회차에는
  `이어서 하기`가 있고, 해당 회차의 중단한 화 또는 다음 화로 이동한다.
- 기록 조회만으로 최근 대화 정렬이나 다른 회차의 데이터를 바꾸지 않는다.
- 첫 화를 끝내지 않았어도 사용자 메시지가 있으면 기록을 보여 준다. 이때 진행 바는
  비어 있으며, 아직 끝낸 화가 없으므로 카드에는 지난 화 목록 없이 `이어서 하기`를 둔다.
- 기록이 없으면 빈 화면을 보여 준다. 불러오기 실패는 빈 기록과 구분하고 다시
  시도할 수 있어야 한다.

### 오류와 빈 상태

- 스토리 목록·상세, 대화 기록 목록과 대화의 조회 실패는 해당 본문에 공통 상태
  화면을 표시한다. 제목과 아이콘, `다시 시도` 버튼을 사용하고 헤더를 유지한다.
- 조회가 성공했지만 기록이 없으면 빈 상태를 표시한다. 재시도 버튼을 붙이지 않고
  필요한 돌아가기 경로를 제공한다. 버튼을 다시 설명하는 문구는 넣지 않는다.
- 대화 시작 실패는 시작을 시도한 상세 또는 대화 기록 화면 위 알림창에서 알린다.
  `닫기`는 그 화면에 머물고 `다시 시도`는 실패한 시작 동작을 다시 실행한다.
  실패하거나 알림창을 닫는 동작만으로 새 회차를 만들지 않는다.
- 진행 중 대화의 조회 실패와 읽기 전용 기록의 조회 실패는 같은 표현을 사용한다.
  재시도 뒤에는 각각 대화 입력이 가능한 화면과 읽기 전용 기록으로 복구한다.
- 프로토타입은 Apple의 ContentUnavailableView와 Alert 개념을 HTML로 표현한다.
  실제 네이티브 컴포넌트의 외형과 접근성 동작을 검증한 결과는 아니다.

### 회차와 기록 보존

- 다시 플레이하는 단위는 스토리 전체다. 특정 화만 새로 플레이하거나 기존 회차의
  앞선 결말을 바꾸고 뒤의 기록과 섞는 기능은 제공하지 않는다.
- 여러 회차를 진행해도 메시지, 교정, 결말과 이야기 기억은 회차별로 분리한다.
  다음 화는 같은 회차의 이야기 기억만 읽는다. 계정의 언어 수준은 기존 범위를 유지한다.
- 사용자가 한 번도 말하지 않고 첫 장면에서 나오면 새 회차를 기록이나 회차 수에
  넣지 않는다. 기존 회차를 지우거나 덮어쓰지 않는다.
- 끝난 화는 읽기 전용이다. 끝내지 않은 화는 저장된 대화부터 이어간다.
- 기존 기록을 새 구조로 옮길 때 대화, 결말, 교정과 이야기 기억을 보존해야 한다.
  구체적인 이전 방식과 요청 식별자는 구현 설계에서 확인한다.

### 대화 화면에서 유지할 기존 기준

직전 동기화한 `origin/main`의 `e034adf`(#38)와 관련 결정 계약을 기준으로 한다.
이번 점검은 원격 브랜치를 다시 동기화한 결과가 아니다.

- 일반 채팅과 홈의 새 대화 버튼을 되살리지 않는다. 배울 표현의 `AI에게 물어보기`는 유지한다.
- 짧은 대화는 위에서 시작한다. 긴 대화와 긴 기록을 다시 열면 최신 내용을 보여 준다.
  사용자가 위로 스크롤해 읽기 시작하면 자동 이동으로 읽던 위치를 바꾸지 않는다.
- 전송은 키보드를 닫고 보낸 질문을 위쪽에 놓는 기존 규칙을 유지한다. 재진입 규칙을
  전송 동작에 적용하지 않는다.
- 네이티브 헤더 아래 상황 줄은 자신의 공간을 차지하며 고정된다. 긴 문구는 모두
  줄바꿈해 보여 주고 첫 지문을 가리지 않는다.
- 완료 기록의 `끝`과 결과는 하단에 고정한다. 마지막 메시지가 가려지지 않게 한다.
- iOS 입력창과 완료 안내 뒤의 흐림 효과, Android의 일반 배경, 교정의 표시·재시도와
  AI 답변 중지는 새 기능에서도 기존 계약을 따른다.

## 구현에서 확정한 항목

- **이전 기록:** 기본안대로 (사람, 스토리)마다 회차 하나를 만들어 기존 플레이를 통째로
  옮긴다. 회차가 없던 구조에서는 한 사람이 한 화를 한 번만 플레이할 수 있었으므로 한
  스토리의 기록은 언제나 한 흐름이다. 2026-09-09 로컬 데이터에서 중복 플레이 0건,
  결말만 남고 대화가 없는 플레이 0건, 대화가 없는 미완료 플레이 0건을 확인했다.
  원격 데이터는 확인하지 않았다. 없는 대화를 만들어 채우지 않는다.
- **동시 시작:** 구분한다. 회차 행은 `대화 시작하기`를 누를 때가 아니라 1화에서 첫
  사용자 메시지가 도착할 때 만든다. 빈 회차가 생기지 않으므로 숨기는 규칙 없이도
  기록에 빈 줄이 늘지 않고, 두 기기가 각각 처음 말하면 회차도 둘로 갈린다. 서로 다른
  대화를 한 회차로 합치면 그 회차의 이야기 기억이 두 흐름을 섞어 읽는다.
  회차 안의 2화부터는 플레이를 미리 열어도 된다. 기록의 단위는 회차이므로 빈 플레이가
  기록에 줄을 만들지 않는다.
- **대화 시작 실패:** 시작은 그 스토리의 1화 정보를 확보하는 일이다. 상세에서는 이미
  읽어 둔 것을 쓰고 대화 기록에서는 그때 읽는데, 읽지 못하면 그 화면에 머문 채
  알림창으로 알린다. 회차는 아직 만들어지지 않았으므로 실패도 알림창 닫기도 새 회차를
  만들지 않는다.

## 바꿀 수 있는 기본안

- 회차 카드는 생성 순서의 역순으로 정렬한다. 카드 제목의 시작 시각은 이어하기로 바뀌지 않는다.
- 카드 날짜는 시작 날짜와 시간을 사용한다. 보조 설명은 사용자가 요청했거나 다음 행동을
  결정하는 데 필요한 경우에만 추가한다.

## 수락 기준

1. 스토리 상세에 표지, 소개와 모든 화의 제목·상황 설명이 보인다. 회차를 바꿔도 목록은 같다.
2. 스토리 상세는 기록 유무나 완료 상태와 관계없이 하단 Primary `대화 시작하기` 하나를 보여 준다.
3. 상세의 `대화 시작하기`와 기록의 `새 대화`는 안내나 확인 단계 없이 새 플레이의 1화를 연다. 기존 대화와 결말은 보존된다.
4. 첫 장면만 보고 나오기를 반복해도 빈 기록과 새 회차 번호가 늘지 않는다.
5. 두 회차에서 다른 선택을 해도 대화, 교정, 결말과 다음 화의 기억이 서로 섞이지 않는다.
6. 대화 기록에 표지·제목·소개와 회차별 카드가 보인다. 진행 막대와 상태 문장을 중복하지 않는다.
7. 미완료 회차가 여럿이어도 현재 플레이 배지가 없고, 각각의 카드에서 해당 회차를 이어갈 수 있다.
8. 끝낸 화는 입력창 없이 읽기 전용으로 열린다. 조회만 해서는 다른 회차의 진행이 바뀌지 않는다.
9. 기록 조회와 입력 없는 진입은 스토리 탭의 최근 대화 순서를 바꾸지 않는다.
   어느 회차에서든 사용자 메시지를 보내면 해당 스토리의 최근 대화 시각이 갱신된다.
10. 짧은 기록은 위에서 시작하고 긴 기록은 최신 내용을 보여 준다. 상황 줄과 하단 결과가
    대화를 가리지 않고, 이전 대화를 읽는 중에는 위치가 유지된다.
11. 스토리별 첫 방문, 미완료, 모두 완료, 기록 없음과 실패·재시도에서 올바른 동작을 제공한다.
12. iOS·Android, 큰 글자와 화면 읽기 기능에서 헤더 아이콘과 카드 동작을 구분할 수 있다.

## 제외 범위와 남은 위험

- 에피소드 단독 재시작, 회차 삭제·이름 변경, 결말 수집, 공유와 새 일반 채팅은 추가하지 않는다.
- 모델, 요금과 프롬프트 품질을 이번 화면 변경과 함께 바꾸지 않는다.
- 프로토타입은 더미 대화와 브라우저 표시만 검증한다. 서버 저장, 회차 소유권, 기억 분리,
  동시 요청과 네이티브 키보드·스크롤은 구현 단계에서 별도로 검증해야 한다.

## 프로토타입 상태 목록

상단 `state`는 검토용 더미 데이터와 실패 상태를 고르는 도구다. 제품 화면에는 표시하지
않는다. 화면이나 상태 선택기를 직접 바꾸면 해당 더미 데이터를 다시 준비한다. 제품
안의 버튼으로 이동할 때는 대화와 진입 경로를 유지하고 실제 상태에 맞춰 선택기를 갱신한다.

| 화면 | 검토 상태 |
| --- | --- |
| 홈 | Default. 학습 화면은 추후 설계한다. |
| 탐색 | Default, 불러오기 실패 |
| 스토리 | Default, 기록 없음, 불러오기 실패 |
| 스토리 상세 | Default, 시작 실패, 불러오기 실패 |
| 대화 기록 | Default, 여러 대화 진행 중, 모든 대화 완료, 기록 없음, 기록이 많을 때, 시작 실패, 불러오기 실패 |
| 에피소드 대화 | Default, 대화 진행 중, 에피소드 마무리, 스토리 마무리, 지난 대화, 긴 대화 기록, 대화 기록 없음, 불러오기 실패, 기록 불러오기 실패 |

- 상세의 `처음 시작`과 `스토리 완주` 상태는 제거했다. 기록 유무와 관계없이 같은 상세를
  사용하며, 각 데이터 조건은 대화 기록 상태에서 상세로 돌아가 확인한다.
- 대화 기록의 Default는 미완료 대화 하나와 완료 대화 하나다. `여러 대화 진행 중`에는
  첫 메시지만 보낸 대화를 포함한다. `모든 대화 완료`에서도 헤더의 `새 대화`는 유지한다.
- 에피소드의 Default는 첫 장면이며, 메시지를 보내면 `대화 진행 중`으로 바뀐다.
  프로토타입은 사용자 메시지 두 개 뒤에 해당 화를 끝낸다. 이 횟수는 검토용 모의 동작이다.
- 에피소드의 `불러오기 실패`는 진행 중 대화, `기록 불러오기 실패`는 읽기 전용 기록이다.
  `긴 대화 기록`은 최신 내용 진입과 마지막 메시지·고정 결과 영역의 겹침을 확인한다.

## 이번 문서·프로토타입 검증

- 2026-09-09에 현재 화면 구성과 상태 목록, 시작·이어하기·복귀·실패 복구 경로를 대조했다.
- 25개 화면·상태를 390, 768과 전체 너비에서 확인했다. 화면 표시, 상태 선택기 동기화와
  가로 넘침을 포함한 75개 검사와 주요 전환 23개 검사, 총 98개가 통과했고 JavaScript 오류는 없었다.
- 새 대화의 입력 없는 복귀, 첫 메시지 뒤 기록 추가, 서로 다른 회차 이어가기, 조회만 할 때
  정렬 유지, 메시지 전송 뒤 최근순 갱신, 새 스토리의 1화부터 5화까지 완료를 확인했다.
- 상세와 기록 각각의 시작 실패에서 닫기·재시도, 다음 화 뒤 원래 화면으로 복귀,
  진행 중 대화와 읽기 전용 기록의 오류 복구를 확인했다.
- 긴 기록이 최신 내용으로 열리고 마지막 메시지가 고정 결과에 가리지 않는지 확인했다.
  상세의 마지막 에피소드가 하단 CTA 위로 완전히 드러나는지도 확인했다.
- 위 검사는 임시 Playwright 검증이며 실제 앱의 자동 테스트를 통과했다는 뜻은 아니다.
- 프로토타입은 HTML 표시와 더미 데이터의 전환을 확인한다. 실제 스트리밍·교정 결과,
  회차 소유권과 서버 저장, 이야기 기억 분리, 네이티브 키보드·스크롤·접근성은 검증하지 않았다.
