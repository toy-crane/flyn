# 일반 채팅 제거와 대화 화면 개선

## 상태와 목적

홈 상단의 `새 대화` 버튼과 일반 채팅 전용 기능을 삭제한다. 에피소드의
`AI에게 물어보기`와 두 대화가 함께 쓰는 기능은 유지한다. 대화방에 들어올 때의
스크롤 위치와 입력창 아래 배경을 개선한다. 최신 내용을 따라가되 사용자가 이전 대화를
읽을 때는 읽던 위치를 유지한다.
채팅의 중지는 입력창 한곳에서 제공하고, 앱 진입이 늦어지면 화면에 로딩을 표시한다.
상황 줄이 대화를 가리는 첫 배치를 바로잡고, 긴 문구도 자연스럽게 줄바꿈해 전체를
보여 준다. 진행 표시의 크기를 문구와 컨트롤에 맞추고, 문구와 표시 사이의 간격을
정리한다. 2026-09-08 사용자 확인에서 짧은 대화의 아래 정렬과 전송 동작 변경이
의도와 다름을 확인했다. 해당 변경을 먼저 되돌리며 재진입 동작은 다시 구현한다.
나머지 완료 결과와 당시 검증 기록은 보존한다.

## 사용자에게 보이는 결과

- 홈 상단에 `새 대화` 버튼과 더하기 아이콘이 보이지 않는다.
- 일반 채팅 화면과 그 안에서만 쓰던 구절별 물어보기는 더 이상 열리지 않는다.
- 사용자는 기존 홈 카드에서 에피소드를 시작하거나 이어 간다.
- 에피소드의 배울 표현 카드에서 `AI에게 물어보기`를 열고 대화를 이어 갈 수 있다.
- 오른쪽 상단의 프로필 버튼으로 설정을 여는 동작은 유지한다.
- 짧은 대화는 상황 줄 아래부터 위에서 시작한다. 대화방에 다시 들어오면 긴
  대화의 최신 내용이 입력창에 가려지지 않고 보인다. 전송 시 질문 배치는 기존대로 유지한다.
- iOS에서는 입력창 뒤와 그 아래 공간으로 지나가는 대화가 아래로 갈수록 흐려진다.
  입력창 아래 안전 영역까지 효과가 이어지고, 위쪽에 가로 경계선이 생기지 않는다.
- 새 질문, 다시 받기와 재시도로 시작한 AI 답변은 입력창의 중지 버튼으로 멈춘다.
- 앱 시작 시 로그인 상태와 프로필을 확인하는 시간이 길어지면 화면 중앙에 로딩을 표시한다.
- 상황 줄은 네이티브 헤더 아래에서 자신의 공간을 차지하며 대화 내용을 가리지 않는다.
- 상황 줄이 길거나 시스템 글자가 커져도 문구 전체를 자연스럽게 줄바꿈해 보여 준다.
- 작은 보조 문구 옆의 스피너가 문구보다 과하게 강조되지 않는다. 표현 확인 실패의
  문구와 재시도 아이콘, 재시도 중 스피너가 가까운 한 묶음으로 보인다.

## 확정 범위

### 홈의 새 대화 버튼

- iOS와 Android의 홈에서 `새 대화` 버튼을 삭제한다. 비활성 버튼, 누를 수 있는
  빈자리, 대체 버튼이나 안내 문구를 남기지 않는다.
- 화면 읽기 기능과 키보드 탐색에도 해당 버튼을 남기지 않는다.
- 첫 방문, 진행 중인 스토리가 있는 상태, 모든 스토리를 끝낸 상태, 불러오는 중,
  불러오기 실패와 다시 시도 중인 상태에 모두 적용한다.
- 홈의 제목, 프로필 버튼, 스토리 카드, 스토리 탭 이동과 다시 시도는 유지한다.

### 일반 채팅 전용 기능 제거와 AI에게 물어보기 유지

- 버튼만 숨기는 데 그치지 않고 독립된 일반 채팅 기능을 제거한다. `/chat`과
  `/chat/side`는 앱 안의 이동과 직접 링크 모두에서 일반 채팅을 열지 않는다.
  삭제한 기능을 위한 대체 화면이나 다른 진입 버튼을 만들지 않는다.
- 일반 채팅에서 구절을 선택해 시작하던 물어보기, 그 대화의 수 표시와 다시 열기
  목록도 제거한다. 이 흐름에만 쓰이는 화면, 상태, 요청 처리, 문구, 아이콘과 테스트를
  남기지 않는다. 공통 화면에 남는 전용 옵션과 사용되지 않는 분기도 정리한다.
- 일반 채팅 전용 `POST /ai/chat`과 해당 세계관·프롬프트를 제거한다. 서버는 이
  경로에서 더 이상 모델을 호출하거나 대화를 생성하지 않는다.
- 에피소드의 배울 표현 카드에서 여는 `AI에게 물어보기`는 유지한다.
  `POST /ai/episode/ask`, 교정과 에피소드 대화 스냅샷을 이어받는 문맥, 카드별 대화와
  초안, 시트를 닫았다 다시 여는 동작은 바꾸지 않는다.
- 에피소드와 `AI에게 물어보기`가 함께 쓰는 메시지 표시, 입력창, 대화 상태,
  스트리밍, 인증과 모델 연결은 유지한다. `AI에게 물어보기`의 전송, 중지, 복사,
  수정, 다시 받기와 실패 뒤 재시도도 유지한다. 같은 폴더나 이름을 쓴다는 이유로
  공통 코드를 함께 삭제하지 않는다.
- 테스트와 패키지는 일반 채팅에만 쓰이는 경우에 제거한다. 남는 기능의 동작과
  인증·스트리밍을 검증하던 테스트는 남는 기능의 공개 동작을 기준으로 유지한다.
- 현재 기능을 설명하는 문서도 제거 범위에 맞춘다. 완료된 과거 명세와 검증 기록은
  당시 결과로 보존한다.

### 대화방 진입 위치와 대화 배치

- 에피소드와 `AI에게 물어보기`에 같은 기준을 적용한다.
- 대화 내용은 항상 위에서 시작한다. 짧은 대화를 입력창 위에 붙이려고 메시지
  위에 빈 공간을 만들지 않는다.
- 대화방을 처음 열거나 나갔다 다시 들어오면 준비된 메시지를 기준으로 위치를 정한다.
  대화가 상황 줄 아래부터 입력창 위까지의 공간에 모두 들어가면 위에서 보여 준다.
  내용이 그 공간을 넘으면 목록 끝으로 이동해 최신 내용을 보여 준다.
- 입력창이 없는 기록도 위에서 시작한다. 긴 기록을 열 때는 마지막 내용이 하단 안전
  영역과 마무리 표시에 가리지 않게 한다.
- 메시지 전송은 기존 동작을 유지한다. 키보드를 닫은 뒤 보낸 질문을 목록 위쪽에
  놓고 답변과 뒤쪽 빈 영역이 그 아래로 이어지게 한다. 재진입 규칙을 전송에 적용하지 않는다.
- 최신 내용을 보던 사용자는 새 답변과 교정을 따라간다. 사용자가 위로 스크롤하면
  자동 이동을 멈추고 읽던 위치를 유지한다. 키보드나 입력창 높이, 지난 배울 표현의
  펼침만으로 읽던 위치를 목록 끝으로 옮기지 않는다.
- 사용자가 직접 끝으로 돌아오거나 `최신 메시지로 이동`을 누르면 도착한 뒤 자동
  추적을 다시 켠다. 전송 후 추적은 기존 질문 배치가 끝난 뒤의 위치를 따른다.

### 스크롤 동작

2026-09-08 사용자 정정을 반영해 진입과 전송을 나눈다.

| 상황 | 동작 |
| --- | --- |
| 짧은 대화방을 처음 열거나 다시 들어옴 | 첫 메시지를 위에서 보여 준다. 빈 공간은 아래에 남는다. |
| 긴 대화방을 처음 열거나 다시 들어옴 | 목록 끝으로 이동해 최신 내용을 보여 준다. |
| 새 메시지를 보냄 | 키보드를 닫고 보낸 질문을 위쪽에 놓는 기존 동작을 유지한다. |
| 최신 내용을 보는 동안 답변이 늘어남 | 기존 추적 기준에 따라 마지막 내용을 따라간다. |
| 사용자가 이전 대화를 읽으려고 위로 스크롤함 | 자동 이동을 멈추고 읽던 위치를 유지한다. |
| 직접 맨 아래로 돌아오거나 `최신 메시지로 이동`을 누름 | 맨 아래에 도착한 뒤 자동 추적을 다시 켠다. |

앞서 아래 정렬과 전송 뒤 목록 끝 이동까지 포함한 해석은 폐기한다. 다음 참조는
이전 내용을 읽는 동안 자동 추적을 멈추는 근거이며 메시지 아래 정렬의 근거가 아니다.

- [Vercel AI Elements](https://elements.ai-sdk.dev/components/conversation)는 하단 자동 이동과
  최신 위치로 돌아가는 버튼을 제공한다. 기반 도구인
  [use-stick-to-bottom](https://github.com/stackblitz-labs/use-stick-to-bottom)은 사용자가 위로
  스크롤하면 자동 추적을 취소할 수 있다고 명시한다.
- [Open WebUI의 채팅 소스](https://github.com/open-webui/open-webui/blob/main/src/lib/components/chat/Chat.svelte)도
  목록 끝에 있는지에 따라 자동 이동을 켜고 끈다. 2026-09-08에 확인한 공개 구현의
  예시이며, 모든 상용 AI 앱이 같은 방식이라고 단정하는 근거로 쓰지 않는다.

### 상황 줄과 대화의 배치

- 에피소드의 네이티브 헤더를 유지하고, 그 아래에 상황 줄과 대화 목록을 차례로 둔다.
  상황 줄을 제목이나 부제목에 합치거나 헤더 전체를 직접 구성하지 않는다.
- 상황 줄은 대화 목록과 함께 스크롤되지 않는다. 자신의 실제 높이만큼 공간을
  차지하며, 첫 화면부터 대화가 상황 줄 뒤에 가려지지 않는다.
- 문구는 화면 너비와 시스템 글자 크기에 맞춰 자연스럽게 줄바꿈한다. 줄 수를
  제한하거나 말줄임하지 않으며, 한 줄에 맞추려고 글자를 줄이지 않는다.
- 상황 줄 높이가 달라져도 대화 목록은 남은 공간을 사용한다. 화면 너비나 시스템
  글자 크기가 달라져도 두 영역이 겹치지 않으며, 네이티브 헤더 높이를 중복 반영하지 않는다.
- 처음 열 때는 확보된 대화 영역을 기준으로 최신 내용을 보여 준다. 대화를 맨 위로
  스크롤하면 첫 지문을 온전히 읽을 수 있다. 배치 중의 높이 변화를 사용자의 스크롤로 보지 않는다.
- 대화를 읽는 중에 상황 줄 높이가 바뀌어도 최신 내용을 보던 사용자는 하단을 유지하고,
  이전 대화를 읽던 사용자는 읽던 내용을 계속 볼 수 있다.
- 상황 줄의 문구, 이모지, 표시 수명과 내용 소유권은
  [모바일 에피소드 상황 줄](../../decisions/mobile-episode-situation-line.md)을 따른다.

### 입력창 하단의 흐림 효과

- iOS에서는 Dearly의 현재 채팅 화면처럼 입력창 뒤와 아래의 배경을 흐리게 한다.
  입력창만 유리 재질로 바꾸는 것으로 이 요구를 충족하지 않는다.
- 대화는 입력창 뒤로 이어진다. 배경 효과는 입력창 위쪽에서 자연스럽게 시작해
  아래로 갈수록 짙어지고, 입력창 아래 여백과 홈 인디케이터가 있는 화면 끝까지
  빈틈없이 이어진다. 단색 띠나 경계가 선명한 흐림 사각형을 남기지 않는다.
- 입력창 안의 글자, 보내기·중지 버튼과 입력창 위의 안내는 선명하게 보인다.
  배경 효과가 터치, 대화 스크롤이나 화면 읽기 기능을 가로채지 않는다.
- 키보드를 열고 닫을 때 효과도 입력창과 함께 움직인다. 키보드를 연 동안에는
  입력창과 키보드 사이에 흐림 처리가 끊긴 틈이나 키보드 높이만큼의 빈 공간이 없다.
- 여러 줄 입력, 수정 안내와 오류 안내로 입력 영역 높이가 바뀌면 효과 범위도 함께
  바뀐다. 마지막 대화 내용은 입력창과 안내 위에서 온전히 읽을 수 있다.
- 라이트·다크와 투명도 줄이기 설정에서도 입력 내용과 버튼을 구분할 수 있다.
- 입력창 자체의 Liquid Glass와 그 아래 배경 효과는 역할을 나눈다. 지원되지 않는
  환경의 입력창은 기존 일반 표면을 유지한다. Android는 Dearly와 현재 플랫폼
  계약에 따라 iOS의 흐림 효과를 복제하지 않는다.
- 입력창이 없는 완료된 에피소드의 대화 기록에는 빈 입력창이나 이 효과만 남기지 않는다.

### 중단할 수 있는 채팅 작업

- AI 답변을 기다리거나 받는 동안 입력창의 전송 버튼을 중지 버튼으로 바꾼다.
  스피너로 버튼을 막아 중지할 수 없게 만들지 않는다.
- 답변을 `다시 받기`나 오류의 `다시 시도하기`로 시작해도 같은 입력창 버튼으로
  중지한다. 메시지마다 중지 버튼을 추가하거나 요청을 시작한 버튼마다 따로 두지 않는다.
- 중지하면 받은 내용은 유지한다. 메시지와 오류 영역의 기존 표시 규칙은
  [모바일 채팅 메시지 동작](../../decisions/mobile-chat-message-actions.md)을 따른다.
- 이 규칙은 현재 중단할 수 있는 AI 답변 요청에 적용한다. 저장, 로그인과 계정 삭제에
  새 취소 기능을 만들지 않는다.

### 진행 표시의 크기와 간격

- 시스템 스피너를 유지하며 보조 문구, 컨트롤과 화면 중앙의 역할에 맞는 공통
  크기와 정렬을 사용한다. 모든 자리에 같은 크기를 강제하거나 화면마다 임의로 정하지 않는다.
- 보조 문구 옆의 스피너는 문구보다 강조되지 않는다. 큰 글자를 지원하고 문구가
  여러 줄이면 첫 줄의 세로 중앙에 표시를 맞춘다. 스피너 때문에 문구를 축소하지 않는다.
- 컨트롤 안에서는 원래 아이콘 자리와 문구 위치, 컨트롤 크기를 유지한다.
  화면 중앙에서는 스피너와 상태 문구를 하나의 묶음으로 배치한다.
- 문구와 스피너 또는 재시도 아이콘에는 역할별로 정한 표시 영역 크기와 간격 값을
  적용한다. 간격은 문구 영역 끝에서 표시 영역 시작까지 재며, 터치 영역은 계산에서
  제외한다. 같은 역할의 화면마다 눈대중으로 다른 간격을 적용하지 않는다.
- 표현 확인 실패 문구 뒤의 재시도 아이콘에는 보조 문구용 공통 간격을 적용한다.
  재시도 중에는 스피너가 같은 크기의 표시 영역과 간격을 유지한다. 상태 문구의 내용 변화와 별개로
  아이콘 교체 자체가 추가적인 위치 이동을 만들지 않는다.
- 간격을 줄여도 기존 재시도 버튼의 44×44 터치 영역을 줄이지 않는다. 실제 터치가
  닿는 영역을 확인하고, 이웃한 컨트롤이나 메시지의 입력을 가로채지 않게 한다.
- 색상, 진행 상태의 의미, 화면 읽기 이름과 중복 실행 방지는 기존 계약을 유지한다.
  확인과 재시도는 해당 메시지의 교정에만 적용하며 새 취소 기능을 추가하지 않는다.
- [모바일 작업 진행 표시](../../decisions/mobile-action-progress.md)와
  [모바일 대화 중 교정](../../decisions/mobile-episode-correction.md)을 함께 따른다.

### 앱 진입 대기의 로딩 표시

- 앱 시작 시 저장된 로그인 상태와 필수 프로필을 확인하는 동안 사용할 수 있는
  화면이 없으면 화면 로딩으로 알린다. 특정 버튼 안의 진행 표시로 대신하지 않는다.
- [모바일 작업 진행 표시](../../decisions/mobile-action-progress.md)의 자동 작업 기준을
  따른다. 진입 대기가 1초 안에 끝나면 시각적인 로딩을 생략하고, 1초를 넘기면
  화면 중앙에 기본 스피너와 현재 확인 중인 작업을 알리는 문구를 표시한다.
- 로그인 상태 확인에서 프로필 확인으로 단계가 넘어가도 같은 진입 대기라면 시간을
  다시 세지 않는다. 로딩은 결과를 알 때까지 유지하고 다른 화면을 미리 보여 주지 않는다.
- 확인이 끝나면 실제 상태에 맞는 로그인, 프로필 설정 또는 홈 화면으로 이동한다.
  실패하면 기존 오류 화면과 다시 시도 경로를 사용한다. 로딩 화면에 머물러 오류를 숨기지 않는다.
- 이미 사용 중인 화면의 백그라운드 갱신에는 화면 전체 로딩을 씌우지 않는다.
- 라이트·다크의 앱 배경을 유지하고 화면 읽기 기능에도 진행 중임을 알린다.

## 수락 기준

1. iOS와 Android에서 홈을 열면 상단에 `새 대화` 버튼이나 더하기 아이콘이 없다.
   스크롤하거나 다른 화면에서 홈으로 돌아와도 다시 나타나지 않는다.
2. VoiceOver, TalkBack과 키보드 탐색으로 홈 상단을 이동해도 `새 대화` 버튼이나
   동작 없는 빈 컨트롤에 초점이 가지 않는다.
3. 오른쪽 상단의 프로필 버튼을 누르면 설정이 열리고, 뒤로 가면 홈으로 돌아온다.
4. 홈 카드에서 에피소드를 시작하거나 이어 갈 수 있다. 모든 스토리를 끝낸 홈에서는
   기존 안내로 스토리 탭을 열 수 있다.
5. 홈 내용을 불러오는 중이거나 불러오기에 실패해도 `새 대화` 버튼은 없다.
   불러오기 실패 뒤 다시 시도할 수 있다.
6. 짧은 대화는 처음 열거나 다시 들어와도 첫 메시지가 상황 줄 아래에 있다. 빈 공간은
   대화 아래에 남는다. 긴 대화는 다시 들어오면 최신 내용이 입력창이나 마무리 표시에
   가리지 않고 보인다. 전송하면 보낸 질문을 위쪽에 놓는 기존 동작을 유지한다.
7. iOS에서 대화를 입력창 뒤로 스크롤하면 뒤의 글자와 배경이 점차 흐려진다.
   입력창 아래 여백과 화면 끝에 효과가 빠진 줄이나 선명한 가로 경계가 없다.
8. 키보드를 열고 닫거나 입력창을 여러 줄로 늘여도 입력창과 배경 효과가 함께
   움직인다. 수정·오류 안내가 나타나도 마지막 메시지를 가리지 않는다.
9. 라이트·다크, 큰 글자와 투명도 줄이기 설정에서 입력 내용과 버튼을 읽고 누를 수
   있다. 배경 효과 자체는 터치 대상이나 화면 읽기 기능의 선택 대상이 아니다.
10. Android는 기존 입력창 표면을 유지하고, iOS에서 입력창이 사라진 대화 기록에는
    빈 입력 영역이나 흐림 효과만 남지 않는다.
11. 각 대화에서 이전 메시지로 스크롤하면 답변이 계속 늘어나거나 교정이 도착해도
    읽던 위치를 유지한다. 지난 배울 표현을 펼쳐 읽을 수 있고 키보드 변화만으로
    맨 아래로 돌아가지 않는다.
12. `최신 메시지로 이동`이나 직접 스크롤로 끝에 도착하면 자동 추적이 다시 켜지고
    이동 버튼이 사라진다. 새 메시지를 보내면 기존 질문 배치와 추적 재개 기준을 유지한다.
13. 대화를 처음 열거나 `AI에게 물어보기`를 닫았다 다시 열면, 메시지가 준비된 뒤
    짧은 대화는 위에서, 긴 대화는 마지막 내용이 보이는 위치에서 시작한다. 입력창
    포커스와 키보드가 뒤늦게 적용돼도 최신 내용을 가리지 않는다.
14. 새 질문, 다시 받기와 재시도로 답변을 시작한 각각의 경우에 입력창의 중지 버튼으로
    답변을 멈출 수 있다. 받은 내용이 유지되고 메시지별 중지 버튼은 추가되지 않는다.
15. 앱 진입 확인을 1초 이상 지연하면 화면 중앙에 로딩과 상태 문구가 보인다.
    로그인 확인에서 프로필 확인으로 넘어가도 표시가 사라졌다 다시 나타나지 않는다.
16. 앱 진입 확인이 1초 안에 끝나면 로딩이 깜빡이지 않는다. 확인 성공 시 알맞은 화면으로
    이동하고, 프로필 확인 실패 시 기존 오류 화면과 다시 시도를 사용할 수 있다.
17. 사용 중인 화면에서 프로필을 백그라운드로 갱신해도 화면 전체 로딩으로 바뀌지 않는다.
    앱 진입 로딩은 라이트·다크와 화면 읽기 기능에서 진행 상태를 전달한다.
18. iOS와 Android에서 에피소드를 처음 열거나 다시 열면 상황 줄과 대화가 겹치지 않는다.
    대화를 맨 위로 스크롤하면 첫 지문을 온전히 읽을 수 있고, 스크롤해도 상황 줄은 고정된다.
19. 좁은 화면, 지원하는 화면 방향과 큰 글자 설정에서 상황 줄과 대화의 경계가 맞는다.
    상황 줄 높이가 바뀌어도 최신 내용의 하단 표시와 지난 내용을 읽는 위치를 유지한다.
20. 한 줄에 들어가는 짧은 문구와 두 줄 이상으로 줄바꿈되는 긴 문구를 각각 확인한다.
    큰 글자 설정에서 세 줄 이상이 되어도 문구 전체가 보이고, 말줄임이나 글자 축소가 없다.
    첫 진입과 화면 크기 변경 뒤에도 상황 줄 높이와 대화 영역이 함께 맞춰진다.
21. iOS와 Android에서 표현 확인 중의 작은 문구와 스피너에 같은 역할별 크기 기준을
    적용한다. 큰 글자는 공통 확대 기준을 따르고 여러 줄일 때 첫 줄과 정렬된다.
22. 표현 확인 실패의 문구 영역 끝에서 재시도 표시 영역 시작까지의 거리가 보조 문구용
    공통 간격 값과 일치한다. 스피너로 바뀌어도 같은 크기의 표시 영역과 간격을 유지하며,
    터치 영역의 안쪽 여백을 더하지 않는다.
23. 재시도 아이콘 주변의 기존 44×44 영역에서 누를 수 있고, 이웃한 컨트롤은 별도로
    누를 수 있다. 재시도 중 중복 실행을 막으며 화면 읽기 이름과 진행 상태가 유지된다.
24. 컨트롤의 아이콘을 스피너로 바꾸어도 문구 위치와 컨트롤 크기가 유지된다.
    화면 중앙의 로딩은 상태 문구와 한 묶음으로 보인다. 각 역할의 크기와 간격을
    라이트·다크와 큰 글자 설정에서 실제 화면으로 확인한다.
25. `/chat`과 `/chat/side`의 직접 링크로 일반 채팅을 열 수 없다. `POST /ai/chat`은
    존재하지 않는 경로로 응답하며 모델을 호출하지 않는다. 일반 채팅에만 쓰이는
    코드, 옵션, 문구, 아이콘, 테스트와 패키지 참조가 남아 있지 않다.
26. 에피소드의 배울 표현 카드에서 `AI에게 물어보기`를 열면 해당 교정이 출처로 보인다.
    질문에 스트리밍 답변을 받고, 시트를 닫았다 같은 카드에서 다시 열면 기존 대화와
    쓰던 초안이 유지된다. 에피소드의 대화와 진행은 바뀌지 않는다.
27. `AI에게 물어보기`에서 전송, 중지, 복사, 수정, 다시 받기와 오류 재시도를 사용할 수
    있다. 요청은 `/ai/episode/ask`로 보내며, 로그인하지 않은 요청을 거부하고 교정과
    에피소드 문맥을 이어받는 기존 서버 동작도 유지된다.

## 제약과 이유

- 사용자가 홈의 대화 추가 기능이 필요 없다고 밝히고 삭제를 요청했다. 삭제 여부를
  다시 묻거나 시안을 비교할 필요가 없어 추가 화면 검토를 생략한다.
- [제품 정의](../../../PRODUCT.md)의 에피소드 중심 경험과
  [모바일 스토리 탐색](../../decisions/mobile-story-browsing.md)의 홈 역할을 따른다.
  기존 에피소드 시작과 이어 하기는 바꾸지 않는다.
- 사용자가 일반 채팅의 관련 코드 전체 삭제를 추가로 요청하고,
  `AI에게 물어보기`는 유지하도록 명시했다. 삭제 범위는 일반 채팅 전용 기능이며,
  에피소드와 교정 카드의 물어보기가 함께 쓰는 코드는 유지한다.
- 기존 결정 계약에 남은 일반 채팅 진입, 구절 선택 기반 물어보기와 `/ai/chat`의
  유지 규칙은 이번 명세의 제거 범위로 대체한다. 에피소드의 물어보기 문맥과 수명은
  [모바일 AI에게 물어보기](../../decisions/mobile-ask-ai.md), 서버 경로는
  [AI 에피소드 프로토콜](../../decisions/ai-episode-protocol.md)의 해당 규칙을 유지한다.
- 사용자가 채팅의 중지 위치와 앱 진입 로딩 표시에 동의했다. 중지를 입력창 한곳에
  두면 요청을 시작한 위치가 달라도 같은 곳에서 멈출 수 있다. 앱 진입 확인이 늦어질
  때 로딩을 표시하면 빈 화면과 기다리는 상태를 구분할 수 있다.
- 사용자가 네이티브 헤더 아래에 상황 줄과 대화 목록을 차례로 두는 방식에 동의했다.
  상황 줄의 공간을 먼저 확보하면 첫 배치에서 대화가 가려지는 일을 막을 수 있다.
  승인한 배치 관계를 반영하므로 별도 시안 비교는 생략하며 실제 화면 검증은 구현 때 수행한다.
- 사용자가 상황 줄의 자연 줄바꿈과 전체 표시에 동의했다. 작은 화면이나 큰 글자
  설정에서도 사건과 목표를 읽을 수 있도록 기존 한 줄 말줄임을 없앤다.
- 사용자가 진행 표시의 크기를 역할에 맞추는 기준에 동의했고, 표현 확인 실패
  문구와 재시도 표시의 간격 문제를 추가로 지적했다. 기존 `small` 고정 규칙을
  역할별 기준으로 바꾸고, 보이는 간격과 터치 영역을 구분한다. 에이전트가 같은 오류를
  반복하지 않도록 하는 작성과 검토 기준은
  [모바일 UI 일관성 검토](../../decisions/mobile-ui-consistency-review.md)를 따른다.
  새로운 로딩 모양이나 동작은 정하지 않는다.
- [모바일 채팅 스크롤](../../decisions/mobile-chat-scrolling.md)의 위에서 시작하는 배치와
  전송 시 질문 배치를 복원한다. 재진입 시 최신 내용을 보여 주는 규칙은 별도로 적용한다.
  잘못 해석한 변경을 먼저 되돌려 커밋한 뒤 새 작업을 진행한다.
- 입력창 배경의 기준은
  [모바일 AI 채팅 표현](../../decisions/mobile-ai-chat-rendering.md)과
  [모바일 UI 렌더러 경계](../../decisions/mobile-ui-renderer-boundaries.md)에 함께 반영한다.

  별도 시안 비교는 생략한다. 실제 Flyn 화면의 시각 검증은 구현 때 수행한다.

## Dearly 참조 근거

2026-09-08에 수정 사항이 없는 `toy-crane/dearly@2e5d12735c65a2e459cf80a97d622f01a06573dd`의

- [채팅 화면](https://github.com/toy-crane/dearly/blob/2e5d12735c65a2e459cf80a97d622f01a06573dd/apps/mobile/src/screens/chat/components/chat-panel.tsx)은

  72px 높다.
- [iOS 배경 효과](https://github.com/toy-crane/dearly/blob/2e5d12735c65a2e459cf80a97d622f01a06573dd/apps/mobile/src/shared/components/ui/blur-ramp.ios.tsx)는

## 가정

- 사용자는 오른쪽 상단이라고 표현했지만 현재 코드와 테스트는 `새 대화`를 왼쪽,
  프로필을 오른쪽에 둔다. 삭제 대상은 위치가 아니라 `새 대화` 동작으로 해석한다.
  이는 별도 확인을 받지 않은 가정이며, 프로필 버튼은 삭제하지 않는다.
- 배경 효과의 위쪽 시작 높이와 흐림 정도는 Dearly의 표현을 기준으로 Flyn에서
  조정할 수 있다.

## 제외

- 에피소드와 교정 카드의 `AI에게 물어보기` 삭제: 사용자가 유지하도록 명시했다.
- 에피소드 진행, 교정 내용과 `AI에게 물어보기`의 대화 문맥 변경: 이 대화들에는
  스크롤과 배경 표현, 상황 줄의 배치, 진행 표시의 크기와 간격을 적용하며 기능과 내용은 유지한다.
- 프로필 저장 버튼의 접근성 이름 변경: 현재 이름이 바뀌는 위치를 설명한 단계이며
  이름을 바꾸는 동작을 이번 작업에서 변경하지 않는다.
- 대화 기록, 플레이 기록과 계정 데이터 삭제: 일반 채팅 전용 코드를 제거하는 데
  필요하지 않다. 에피소드와 계정의 데이터 구조도 바꾸지 않는다.
- 다른 화면에 일반 채팅 진입 버튼 추가: 삭제한 동작을 옮겨 달라는 요청이 없다.
- 홈 재배치와 탭 구성 변경: 버튼 삭제 외의 화면 개편은 요청 범위가 아니다.

## 유보와 남은 위험

- 대화 배치와 전송의 잘못된 변경을 되돌린 뒤 재진입 동작을 구현하고 검증해야 한다.
- 앱 실행 중 글자 크기를 바꾸면 네이티브 텍스트가 이전 높이를 유지하는 현상은
  텍스트 뷰를 다시 만드는 방법으로 처리했다. 근본 원인은
  [글자 크기 변경 뒤 대화 배치](../../follow-ups/chat-text-layout-after-font-size-change.md)에
  남겼다. 사용자 말풍선, 지문, 인물 이름과 상황 줄에도 이 처리를 적용했다.
- 루트 빌드는 기존 환경 변수 로딩 문제 때문에 위 명령으로 실행했다. 자세한 내용은
  [루트 빌드의 환경 변수 로딩](../../follow-ups/root-build-fails-because-expo-export-skips-env-local.md)을
  따른다.
- 저장소 전체 변경을 대상으로 Codex 기본 리뷰를 요청했지만, 자동 승인 검토가
  `codex review` 실행 전에 거절했다. 변경 코드를 외부 서비스로 보낼 수 있으며 별도
  공개 승인이 없다는 이유다. 자동 리뷰 결과는 없고, 우회 실행하지 않았다.
  테스트와 기기 검증 결과를 코드 리뷰 결과로 대신 표시하지 않는다.
