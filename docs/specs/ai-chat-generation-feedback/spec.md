# AI 채팅 생성 상태 피드백

## 상태

- 이 문서는 확정된 구현 스펙이다.
- 구현은 한 작업 세션에서 끝낸다.
- 부모 스펙은 [AI 채팅](../ai-chat/spec.md)이고, 오류와 재시도의 동작은
  [AI 채팅 운영 안정화](../ai-chat-reliability/spec.md)를 따른다.
- 생성 상태의 시각 표현이 부모 스펙과 충돌하면 이 문서가 우선한다. 메시지 저장,
  중단, 재시도와 모델 호출 경계는 바꾸지 않는다.

## 목적

메시지를 보낸 직후부터 첫 응답이 보일 때까지 앱이 멈춘 것처럼 보이지 않게 한다.
응답을 기다리는 상태와 실제 텍스트가 출력되는 상태를 구분하되, Flyn이 제공하지
않는 추론 과정을 `Thinking` 같은 문구로 암시하지 않는다.

이 스펙은 Vercel AI SDK의 `ChatStatus`와 AI Elements의 전송 버튼 상태 구성을
기준으로 삼는다.

- [`PromptInputSubmit` 상태 구성](https://github.com/vercel/ai-elements/blob/main/packages/elements/src/prompt-input.tsx#L1211-L1235)
- [React Native `ActivityIndicator`](https://reactnative.dev/docs/activityindicator)

## 생성 상태

| 상태 | 의미 | 대화 영역 | 전송 버튼 |
| --- | --- | --- | --- |
| `ready`, 입력 없음 | 보낼 메시지가 없음 | 추가 표시 없음 | 회색 전송 화살표, 비활성 |
| `ready`, 입력 있음 | 메시지를 보낼 수 있음 | 추가 표시 없음 | 기본 전송 화살표, 탭하면 전송 |
| `submitted` | 요청을 보냈고 첫 응답 내용을 기다림 | 소형 회색 스피너 | 버튼 전경색의 스피너, 탭하면 중단 |
| `streaming` | 응답 스트림이 시작됨 | 실제 텍스트가 없으면 스피너, 있으면 응답 | 중단 사각형, 탭하면 중단 |
| `error` | 응답 생성에 실패함 | 대기 스피너 제거 | 입력 유무에 따른 `ready` 표현 |

`streaming`은 메타데이터만 도착해도 시작될 수 있다. 따라서 대화 영역의 스피너는
상태 이름만 보지 않고, 사용자에게 보여 줄 실제 AI 텍스트가 생길 때까지 유지한다.
반면 버튼은 중단 가능한 요청 상태를 표현하므로 `streaming`이 되는 즉시 중단
사각형으로 바뀐다.

상태 변화는 즉시 표시한다. 짧은 응답에서 스피너가 잠깐 보일 수 있지만, 최소 노출
시간이나 인위적인 지연은 두지 않는다.

## 대화 영역 스피너

- 마지막 AI 응답이 아직 비어 있고 생성이 진행 중일 때 AI 메시지가 시작될 왼쪽
  위치에 스피너 하나를 표시한다.
- React Native의 iOS 네이티브 `ActivityIndicator`를 `small` 크기로 사용한다.
- 색상은 앱의 `muted foreground` 의미 색상을 따른다.
- 말풍선, 배경, `Thinking`, 경과 시간, 설명 문구를 붙이지 않는다.
- 현재의 정적인 `…` placeholder와 block cursor `▌`는 표시하지 않는다.
- 첫 실제 텍스트가 보이는 순간 스피너를 응답 내용으로 교체한다. 텍스트와 스피너를
  동시에 표시하지 않는다.
- 텍스트가 스트리밍되는 동안 별도의 cursor나 대화 영역 로더를 덧붙이지 않는다.
  진행 중이라는 사실과 중단 동작은 composer 버튼이 계속 표현한다.

## Composer 버튼

- 버튼의 위치, 원형 배경, 44pt 이상 hit target은 모든 상태에서 유지한다.
- 상태 변경은 내부 아이콘만 바꾸며 composer 레이아웃을 움직이지 않는다.
- `submitted`의 스피너는 대화 영역과 같은 네이티브 `ActivityIndicator`를 쓰되
  버튼의 `primary foreground` 의미 색상을 따른다.
- `submitted` 스피너는 단순 표시가 아니라 중단 버튼이다. 탭하면 첫 내용이 오기
  전이라도 현재 요청을 중단한다.
- `streaming`에서는 중단 사각형을 표시하고 같은 중단 동작을 제공한다.
- `error` 전용 아이콘은 추가하지 않는다. 오류 설명과 `다시 시도`는 기존 오류
  카드 한 곳에서 담당한다.

## 중단, 오류와 재시도

- 첫 내용 전에 중단하면 대화 영역과 버튼의 스피너가 사라지고 빈 AI 메시지를
  남기지 않는다.
- 일부 텍스트를 받은 뒤 중단하면 받은 내용과 `중단됨` 표시는 기존 동작대로
  보존한다.
- 첫 내용 전에 실패하면 사용자 메시지를 남기고 대화 영역 스피너를 제거한 뒤 기존
  오류 카드를 표시한다.
- 일부 텍스트 뒤 실패한 경우의 보존과 제거 시점은 AI 채팅 운영 안정화 스펙을
  따른다.
- `다시 시도`를 누르면 새 요청의 `submitted` 상태부터 같은 피드백을 다시
  시작한다.

## 접근성과 테마

- 대화 영역의 대기 상태는 VoiceOver에 `응답 생성 중`으로 한 번 전달하며,
  애니메이션 회전마다 반복해 알리지 않는다.
- `submitted`와 `streaming`의 composer 버튼은 모두 `응답 중단`이라는 한국어
  accessibility label과 button role을 가진다.
- 비활성 전송 버튼은 비활성 상태를 보조 기술에도 전달한다.
- 스피너와 버튼은 앱의 의미 색상을 사용해 light/dark 양쪽에서 대비를 유지한다.
- 커스텀 회전 애니메이션이나 제3자 로더 패키지를 추가하지 않고 시스템 로더를
  사용한다.

## 유지할 경계

- AI SDK `useChat`, `expo/fetch`, abort 전달과 서버 스트리밍 형식은 유지한다.
- 사용자 메시지, 완료·중단 AI 메시지의 저장 규칙은 유지한다.
- 오류 카드와 재시도, timeout, 출력 상한, 운영 로그는 AI 채팅 운영 안정화
  스펙을 유지한다.
- 메시지 목록 가상화, 자동 스크롤, keyboard dismissal, Markdown과 composer
  표면은 유지한다.
- 채팅 상세는 계속 RN 화면이며 SwiftUI Host를 중간에 재진입시키지 않는다.

## 제외 범위

- reasoning 또는 thinking 내용·시간·단계 표시
- 도구 호출과 웹 검색 진행 상태
- background generation, 알림과 앱 밖 진행 상태
- resumable stream과 generation 실행 이력
- 모델, Gateway, API, DB schema와 메시지 저장 형식 변경
- AI SDK 패키지 업데이트
- 오류 카드, 메시지 말풍선, Markdown과 composer 레이아웃 재설계
- 새로운 로더 패키지 또는 커스텀 애니메이션 도입

## 완료 조건

- `ready → submitted → streaming → ready` 전환에서 표의 대화 영역과 버튼 표현이
  일치하며 레이아웃이 움직이지 않는다.
- 첫 응답이 늦을 때 대화 영역과 버튼의 스피너가 즉시 회전하고, 첫 실제 텍스트가
  오면 대화 영역 스피너만 사라진다.
- 메타데이터 때문에 `streaming`이 텍스트보다 먼저 시작되어도 대화 영역이 빈
  메시지나 cursor로 바뀌지 않고 스피너를 유지한다.
- `submitted`와 `streaming` 양쪽에서 composer 버튼으로 요청을 중단할 수 있다.
- 첫 내용 전 중단, 일부 내용 뒤 중단, 첫 내용 전 오류, 일부 내용 뒤 오류와
  재시도 흐름이 기존 저장 규칙을 지킨다.
- `Thinking`, 정적 `…`, block cursor `▌`와 중복 로더가 보이지 않는다.
- light/dark와 VoiceOver label을 실제 iOS 시뮬레이터에서 확인한다.
- 상태 전환과 버튼 동작을 자동 테스트로 재현하고 `bun run check`가 통과한다.

## 가정과 남은 위험

- 매우 빠른 응답에서는 `submitted` 스피너가 짧게 보일 수 있다. 즉각적인 요청
  접수 피드백을 우선해 debounce나 최소 표시 시간을 두지 않는다.
- `ActivityIndicator`의 세부 모양은 iOS 버전에 따라 달라질 수 있다. 앱은 고유
  loader 모양보다 시스템 일관성을 우선한다.
- 화면과 버튼에 동시에 스피너가 보이는 짧은 구간이 있다. 사용자의 시선 위치와
  무관하게 요청 접수를 알리고 버튼의 중단 가능 상태를 유지하기 위한 의도된
  중복이다.
