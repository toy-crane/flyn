# 에피소드 롤플레이 MVP

flyn의 제품 방향을 확정한 스펙. flyn은 **재미 중심 스토리 롤플레이로 영어
라이팅을 연습하는 iOS 앱**이다 — 한국어 화자가 재밌는 상황극 안에서 영어로
쓰고, 버블마다 첨삭을 받고, 궁금하면 해설 챗으로 파고든다. 관심 분야가 킥이다:
대화는 유틸리티 시나리오가 아니라 사람들이 재밌어할 소재에서 나온다.

용어는 [GLOSSARY.md](../../../GLOSSARY.md)를 따른다 — 에피소드·스토리·관심
분야·목표·첨삭·해설 챗·총평이 이 스펙과 함께 정의됐다.

## 확정 결정

### 온보딩

**순서: 관심 분야 → 레벨 → 로그인 → 표시 이름 → 아이디.**

로그인이 가운데 있는 이유는 취향이 아니라 기계적이다. **두 프리필이 모두 로그인
뒤에야 생긴다** — 표시 이름은 Apple·Google이 주고, 아이디는 이메일에서 뽑는다.
둘 중 하나라도 로그인 앞에 두면 그 필드는 빈칸으로 시작해 사용자가 직접 친다.
반대로 관심 분야와 레벨은 서버가 필요 없는 순수 탭이라 앞에 둬도 타이핑이 0으로
유지되고, 로그인 요구가 사용자가 이미 두 번 답한 뒤에 온다.

- 앞 두 걸음의 답은 로그인 전까지 기기에 들고 있다가 마지막에 함께 저장한다.
- **이미 프로필이 있는 사람이 로그인하면 서버 값을 지키고 방금 고른 값은 버린다.**
- 전부 탭으로 고른다 — 자유 입력(서술형) 없음.
- 단계 라벨 대신 진행 바를 쓴다. 버튼은 "다음", 마지막만 "시작하기".
- 관심 분야와 레벨에 건너뛰기를 두지 않는다. 관심 분야는 이 제품의 킥이라,
  건너뛴 사용자에게는 우리가 팔려는 경험이 없다.
- 관심 분야는 **최소 1개, 최대 3개**. 아무것도 고르지 않으면 다음이 잠긴다.
- 레벨은 3단계 자가 선택이고, 에피소드 난이도와 첨삭 말투에 반영된다.

**온보딩 완료 판정은 학습 설정 행의 존재다.** `display_name is null`은 더 이상
쓸 수 없다 — 이름이 프리필되므로 온보딩을 거치지 않아도 null이 아니다. 이는
[private-auth-profiles](../../decisions/private-auth-profiles.md)가 정한 위치를
뒤집으므로, 구현 전에 새 결정 기록을 쓴다.

**쓰는 순서가 규칙의 일부다** — 계정 값(표시 이름·아이디)을 먼저 쓰고 학습 설정을
마지막에 쓴다. 중간에 실패하면 학습 설정 행이 없어 사용자는 온보딩에 그대로 남고,
다시 밟으면 된다. 반대로 쓰면 아이디 없이 "완료"가 된다.

**단계마다 라우트를 둔다.** 온보딩 화면은 네이티브 header를 쓰므로 뒤로가기는
iOS가 그린다 — 한 라우트 안에서 상태로 넘기면 그 뒤로가기를 우리가 만들어야 하고,
네이티브 우선 기조와 어긋난다. 진행 바는 header 옆이 아니라 **header 아래, 우리가
소유하는 화면의 첫 요소**로 둔다.

### 표시 이름과 아이디

**두 필드를 나눈다.** 성격이 정반대라 한 필드로 겸할 수 없다.

- **표시 이름** — 사람이 읽는 이름이고 **비공개**다. **한글을 허용하고 중복도
  허용한다.** 동명이인이 서로를 밀어내면 그건 이미 이름이 아니라 식별자다.
  Apple·Google이 준 후보로 미리 채운다.
- **아이디** — 남이 나를 찾아 입력하는 키이고, 스코어보드가 생기면 **공개되는
  값**이다. **영문 소문자·숫자·하이픈, 3–20자.** 앞뒤 하이픈과 연속 하이픈을
  막고, `admin`·`flyn` 같은 예약어를 막는다. 유니크 제약은 **소문자 정규화
  기준**으로 건다 — `ToyCrane`과 `toycrane`이 다른 사람이 되면 사칭이 쉬워진다.

두 값을 각각 다른 화면에서 받는다. 20자 상한은 나중에 순위표 한 줄에 들어가야
하기 때문이고, **이메일에서 파생할 때도 20자로 자른다.**

**중복 검사는 불리언만 돌려주는 `security definer` 함수로 한다.** RLS 아래에서는
남의 행을 볼 수 없어서다. 진짜 방어선은 유니크 인덱스이고 이 함수는 UX용이다.
아이디를 열거할 수 있게 되지만 어차피 공개될 값이라 감수한다. **자기 현재 아이디는
자기에게 사용 가능으로 보여야 한다** — 온보딩을 다시 밟는 사용자가 자기 아이디에
막히면 빠져나갈 수 없다.

**아이디는 이메일에서 파생해 미리 채운다.** 표시 이름에서 뽑는 흔한 방법(Sam Lee
→ `sam-lee`)은 한글 이름에 통하지 않는다 — 토이크레인을 기계로 변환하면 아무도
쓰지 않을 문자열이 나온다. 인증 경로 셋이 모두 이메일 주소를 남기고 그 로컬
파트는 이미 라틴 문자다: `alwaysfun2183@gmail.com` → `alwaysfun2183`.

**마찰을 줄이는 장치**는 레퍼런스에서 가져왔다 — 빈칸으로 시작하지 않기, 타이핑
중 즉시 가용성 표시, 중복이면 탭 한 번으로 고치는 대안 3개, 허용 문자 미리 고지,
중복일 때 다음 버튼 잠금. 두 필드를 한 화면에 두어 화면 수를 늘리지 않는다.

**가용성 표시는 초록 체크 하나로 한다.** 테두리는 중립으로 두고 문제일 때만
칠한다 — 아이디를 이메일에서 미리 채우므로 대부분 처음부터 사용 가능이고, 사건이
아닌 것에 계속 신호를 보낼 이유가 없다. 색은 `--app-success`이고 **이것이 그
토큰의 첫 사용처다.** 그래서 규칙을 함께 세운다: **입력이 방금 유효해졌다는 순간적
확인에만 초록을 쓰고, 계속 남아 있는 상태 표시(첨삭 통과, 목표 달성)는 무채색으로
둔다.** 그러지 않으면 대화 화면이 온통 초록이 된다.

초록을 고른 근거는 레퍼런스 11개가 전부 초록이었다는 것이다(ZIGZAG·happn·
Substack·Base·Bolt·Freenow·Quizlet·Twitch·Kraken·X·Coinbase). 특히 Twitch는
브랜드가 보라인데도 유효성 신호에는 초록을 쓴다. 앱 테마에 파랑 토큰이 아예 없다는
점도 같은 방향을 가리킨다. 체크 **모양**이 신호를 지므로 색만으로 구분하지 않는다.

아이디 변경은 처음엔 자유롭게 둔다. 남이 나를 찾을 표면이 아직 없어서 자주 바뀌어
곤란할 일이 없다 — 스코어보드가 생기면 그때 빈도 제한을 검토한다.

### 저장 위치

- **표시 이름과 아이디는 계정 값이라 프로필에 둔다.** 앱의 update 권한이 지금
  `display_name` 하나에만 걸려 있으므로(`grant update (display_name)`) 아이디까지
  넓힌다.
- **관심 분야와 레벨은 학습 설정으로 따로 둔다.** 용어집이 프로필을 **계정 정보**로
  정의하므로 취향은 프로필이 아니다. 사용자와 1:1인 테이블 하나이고, 이 행의
  존재가 곧 온보딩 완료 판정이다.
- 관심 분야는 정규화하지 않는다. "누가 로맨스를 좋아하나"를 물을 일이 없다.

### 온보딩 값 수정

관심 분야와 레벨은 **설정에서 바꿀 수 있어야 한다.** 특히 레벨은 사람이 늘기
때문에 못 바꾸면 앱이 같이 늘지 않는다. **온보딩과 설정이 같은 화면을 쓴다** —
`display-name-form.tsx`가 이미 그렇게 만들어져 있고, 검증 규칙이 갈리지 않게 하는
가장 확실한 방법이 규칙 공유가 아니라 화면 공유라는 이유도 거기 적혀 있다.

아이디 변경 빈도는 지금 제한하지 않는다. 남이 나를 찾을 표면이 아직 없다 —
스코어보드가 생기면 그때 검토한다.

### 온보딩에서 아직 안 정한 것

- **용어집의 프로필 정의가 아이디와 충돌한다.** 지금 정의는 "비공개 계정 정보"인데
  아이디는 공개될 값이다. 프로필이 비공개 필드와 공개 식별자를 함께 담는다는
  사실을 반영하도록 용어를 고쳐야 한다.
- **예약어 목록을 어떻게 운영할 것인가.** 제약으로 박으면 갱신할 때마다
  마이그레이션이 필요하다.
- **관심 분야 목록 확정.** 아래 가정의 8개는 초안이다. 이 목록이 곧 이 제품의
  킥이라 콘텐츠 품질과 함께 정해야 한다.

### 홈 — 날짜별 기록

- 홈은 에피소드 목록이 아니라 **날짜별 연습 기록**이다: 주간 날짜 스트립,
  선택한 날짜 아래 에피소드 카드, 우하단 New 버튼.
- 카드: 시각, 에피소드 제목, 총평 한 줄, 분야 태그, 목표 달성(n/3), 진행
  중이면 배지. 탭하면 대화로 재진입한다.

### 에피소드 만들기 — 단계별 위저드

- 토스식 한 화면 한 선택 위저드: **스토리 → 상대 역할 → 내 역할** 순서로,
  단계마다 AI가 만든 선택지를 탭해서 고른다.
- 선택지는 온보딩 관심 분야를 반영해 생성한다.
- 단계마다 다시 뽑기(부분 재생성)가 가능하고, 이전 단계로 돌아갈 수 있다.
- 씨앗 타이핑은 없다 — 쓰기가 아니라 고르기로 푼다.
- 마지막 브리핑에서 스토리·역할·AI가 세운 목표 3개를 보여주고 시작한다.

### 롤플레이 대화

- 유저는 자기 역할로 영어 작문, AI는 상대 역할로 영어 응답(스트리밍).
- **한글 허용**: 막히면 한글로 써도 된다. AI는 역할을 유지한 채 그 의미에
  응답하고, 그 버블의 첨삭은 "영어로는 이렇게 말해요" 표현 제시가 된다. 별도
  힌트 기능은 이것으로 대체한다.
- 이어하기 허용: 중간에 나가도 홈에서 돌아올 수 있다.
- 하루 에피소드 수 제한 없음.

### 첨삭과 해설 챗

- 첨삭은 유저 버블마다 붙고 상태는 셋: 교정 / 통과(아이콘만) / 표현 제시.
- 첨삭은 롤플레이 응답과 별도로 생성되어 나중에 붙는다 — 대화 흐름을 막지
  않는다.
- 첨삭을 탭하면 해설 챗: 그 첨삭 1건에 1:1로 붙는 저장되는 과외 대화. 한국어
  질문 가능. 에피소드 기록에 섞이지 않는다.
- AI 버블에는 첨삭이 없다.

### 종료 — 목표와 총평

- 에피소드마다 목표 3개를 AI가 세우고 체크리스트로 상시 노출한다.
- 턴마다 서버가 달성 여부를 판정해 체크한다.
- AI 역할은 남은 목표를 달성할 기회가 생기도록 대화를 몬다.
- 턴 예산: 소프트 캡부터 마무리 유도, 하드 캡이면 목표 미달이어도 자동 마무리.
  '마치기' 버튼은 언제나 있다.
- 어떤 경로로 끝나든 **총평**: 배운 표현 3–5개, 주요 교정 요약, 목표 결과.
  총평 한 줄이 홈 카드 요약이 되고, 흩어진 첨삭의 1차 복습 표면을 겸한다.

### 프로토타입

화면은 흐름별로 두 파일에 있다. 각각 자체 완결된 HTML이라 그냥 열면 된다.

- [prototype-onboarding.html](prototype-onboarding.html) — 관심 분야 → 레벨 →
  로그인 → 표시 이름 → 아이디. 마지막 단계가 에피소드 프로토타입의 홈으로
  이어진다. 로그인 화면은 새로 만드는 것이 아니라 이미 있는 sign-in 화면이다.
- [prototype-episode.html](prototype-episode.html) — 홈(날짜별 기록) →
  위저드 3단계 → 브리핑 → 대화·첨삭 → 해설 챗 → 총평.

### 화면 문구

화면 문구는 [danggeun-voice-for-copy](../../decisions/danggeun-voice-for-copy.md)를
따른다. 프로토타입의 카피가 그 규칙을 적용한 결과이니, 구현할 때 문구를 새로
지어내지 말고 프로토타입에서 가져온다.

프로토타입의 색은 `apps/mobile/src/global.css`의 앱 테마 변수를 그대로 옮긴
것이다(light/dark 양쪽). 프로토타입에서 색을 새로 만들지 않았으므로, 구현할 때도
시맨틱 변수만 쓴다 —
[uniwind-css-theme](../../decisions/uniwind-css-theme.md).

## 가정 — 반증이 나오면 기록 없이 뒤집는다

- 위저드 선택지는 단계당 3개.
- 역할 순서는 상대 역할 → 내 역할.
- 소프트 캡 유저 12턴, 하드 캡 20턴 — 자리표시자, 튜닝 대상.
- 관심 분야 초안: 로맨스, 미스터리·스릴러, 판타지·SF, 오피스 드라마, 여행
  어드벤처, 스포츠, 연예·덕질, 일상 코미디 — 목록은 프로토타입에서 확정.
- 레벨은 짧은 라벨 + 한 줄 설명의 3단계, CEFR 표기는 노출하지 않는다.
- 앱 UI 언어는 한국어, 연습 언어는 영어.
- **스토리·역할 소개문만 한다체를 쓴다** — "…쪽지를 두고 갔다." UI 문구가 아니라
  AI가 만든 이야기 본문이라 서사 문체가 맞다고 봤다. 나머지 화면 문구는 전부
  해요체다.
- 완료된 에피소드 카드를 탭하면 총평부터 열리고 대화를 다시 볼 수 있다.

  콜드스타트가 걸려 MVP 밖.
- 씨앗 직접 입력(타이핑으로 상황 지정).
- 스트릭·리마인더 등 습관 장치 — 홈이 날짜 구조라 얹기 좋지만 뒤로.
- 복습함(배운 표현 모아보기) — 총평이 1차 대체.
- 수익화 — RevenueCat 방향만 있고 범위 밖.

## 오프리밋 — 이 작업이 건드리면 안 되는 것

- 음성 입력·발음 평가. 라이팅 앱이다.
- 공개 콘텐츠 인프라 — 전면 비공개 RLS 전제를 유지한다.
- 기존 인증 경로(Apple·Google·이메일 OTP)와 계정 삭제 흐름.
- (기존 결정) Android·web 폴백 없음 — [ios-only](../../decisions/ios-only.md).

## 구현 방향 메모 — 방향만, 설계는 구현 세션 몫

- 대화 쓰기는
  [server-owned-chat-messages](../../decisions/server-owned-chat-messages.md)
  경계의 연장선: 에피소드 대화·해설 챗 쓰기는 Hono 스트리밍, 조회는 RLS 직접.
- 턴당 호출이 여러 개다(역할 응답 + 첨삭 + 목표 판정, 종료 시 총평). 첨삭·
  판정은 저렴한 모델로 분리하는 방향.
- 온보딩 완료 판정: 지금은 `display_name is null`이 첫 온보딩을 뜻한다
  ([private-auth-profiles](../../decisions/private-auth-profiles.md)). 관심
  분야·레벨이 온보딩에 추가되므로 판정 규칙 조율이 필요하고, 바꾸면 새 결정
  기록을 쓴다.
- 기존 범용 챗 화면(`chats/[id]`)은 스캐폴딩이었다 — 에피소드 대화 화면으로
  재편한다.

## 남은 리스크

- **킥 검증**: 스토리 생성이 실제로 재밌는가가 제품의 성패인데 아직 아무도 안
  봤다. 프로토타입에서 생성 품질을 가장 먼저 확인해야 한다.
- 목표 판정 오판(너무 후하거나 늦음) — 튜닝 전까지 종료 경험이 흔들릴 수 있다.
- 위저드 단계마다 선택지 생성을 기다린다 — 대기 경험 설계가 구현 과제다.
- 턴당 다중 호출의 비용·지연 — 모델 분리로 낮추는 방향이나 실측 전이다.
- 캡 수치(12/20)는 근거 없는 초기값이다.
