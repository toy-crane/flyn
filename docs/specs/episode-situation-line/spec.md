# 에피소드 상황 줄 명세

## 목표

- 사용자가 에피소드 대화의 어느 시점에 화면을 봐도, 이 에피소드가 어떤
  사건이고 이 대화로 무엇을 하려는 건지 바로 읽는다.
- 잠시 자리를 비웠다 돌아온 사용자가 상황 줄과 마지막 말풍선 몇 개만으로
  하던 일을 다시 잡는다.
- 제품 전제는 루트 `PRODUCT.md`를 따른다. 각 에피소드는 사건 하나를 일으키고
  질문 하나를 던지는데, 지금 화면은 그 사건을 홈 요약과 첫 장면 지문에서만
  말하고 대화 중에는 어디에도 보여 주지 않는다. 이 단위가 그 빈자리를 채운다.

승인한 화면은 [prototype.html](./prototype.html)에 있다. 홈은 진입 맥락으로만
담았고 바꾸지 않는다.

## 확정 범위

- 에피소드 화면에 사건과 목표를 담은 한 줄을 상시로 보여 준다. 이 줄을 상황
  줄이라고 부른다.
- 상황 줄은 헤더 안의 부제목이 아니라, 헤더 바로 아래에 옅은 강조색 배경으로
  헤더와 구분되는 띠(배너)로 보여 준다.
- 배너는 장면 이모지 하나와 문구로 구성하고, 왼쪽에서 시작한다. 이모지는
  에피소드 각본이 정하며, 첫 에피소드는 커피잔(☕)이다.
- 상황 줄은 대화 스크롤과 무관하게 항상 같은 자리에 보인다. 첫 장면이 열릴
  때부터 결말이 표시된 뒤까지 에피소드 화면이 살아 있는 동안 사라지지 않는다.
- 상황 줄의 문구는 에피소드마다 각본이 정하는 고정 문구다. 모델이 생성하지
  않는다.
- 문구는 [화면 문구 한국어 말투](../../decisions/korean-ui-writing.md)를
  따른다.

## 확정 제약과 이유

- 해결 방식은 고정 상황 줄이다. 사용자가 확정했다. 돌아올 때 전개를 요약해
  주는 방식(recap)과 견주었을 때, 고정 줄은 모델 호출과 프로토콜 변경 없이
  "이 대화가 뭘 하는 건지"를 언제나 답하고, 한 세션 안에 끝나는 짧은
  에피소드에서는 마지막 말풍선 몇 개가 "어디까지 했는지"를 이미 답한다.
- 형태는 배너다. 사용자가 헤더 부제목, 떠 있는 칩, 입력창 위 줄, 헤더
  프롬프트(애플 스타일)와 나란히 견주고 확정했다. 부제목은 헤더 글씨와 섞여
  묻히고, 떠 있는 칩은 말풍선을 가리며, 입력창 위는 수정 안내와 오류 표시가
  이미 쓰는 자리다. 배너는 색으로 헤더와 분리되면서 대화를 가리지 않는다.
  Material Design도 지속 안내를 상단 앱 바 바로 아래의 별도 띠로 두라고
  권한다.
- 앞머리는 시스템 아이콘이 아니라 각본이 정한 장면 이모지다. 사용자가 깃발,
  핀, 목표 라벨, 텍스트만과 견주고 확정했다. 목표를 그림으로 번역한 시스템
  아이콘은 어색하고, 이야기에서 나온 기호가 드라마의 결에 맞으며, 에피소드마다
  자기 표식이 생긴다.
- 배너 내용은 왼쪽 정렬이다. 사용자가 중앙 정렬과 견주고 확정했다. 중앙은
  제목과 같은 축이라 부제목처럼 읽히고, 문구 길이에 따라 이모지 자리가
  흔들린다.
- 상황 줄은 한국어로 쓴다. 첫 에피소드는 상황이 영어 없이도 이해돼야 한다는
  제품 조건과 같은 방향이다.

## 수용 기준

- 에피소드에 들어가 첫 장면이 열리면 헤더 아래에 상황 줄 배너가 보인다.
- 배너는 장면 이모지로 시작하고 문구가 왼쪽에서 이어진다.
- 대화가 여러 턴 진행된 뒤에도, 대화를 위로 스크롤한 상태에서도 배너가 같은
  자리에 보인다.
- 에피소드가 결말로 닫힌 뒤에도 배너가 보인다.
- 상황 줄의 문구가 사건과 목표를 담고, 화면 문구 한국어 말투 계약을 따른다.
- 저장소 루트에서 `bun run check`와 `bun run check-types`가 통과한다.

## 가정

아래는 에이전트가 정한 값이라 사용자가 뒤집을 수 있다.

- 첫 에피소드의 상황 줄 문구는 "잘못 나온 커피를 원하는 커피로 바꿔 보세요"다.
- 문구는 라벨 성격이라 마침표를 붙이지 않는다. 화면 문구 계약의 라벨 규칙을
  따른 판단이다.
- 상황 줄은 한 줄로 제한하고, 넘치면 말줄임으로 줄인다. 상시 고정이라
  길어지면 대화 공간을 잠식한다.
- 배너 배경은 강조색을 옅게 섞은 색으로, 헤더와 대화 양쪽에서 구분된다.
- 상황 줄은 정보 표시일 뿐 누르는 동작이 없다.
- 홈의 에피소드 요약 문구는 그대로 두고, 상황 줄은 별개의 문구로 쓴다. 홈
  요약은 시작 전에 상황을 소개하고, 상황 줄은 대화 중에 목표를 되새긴다.

## 제외

- 돌아올 때 전개를 요약해 주는 방식(recap). 에피소드가 길어지거나 저장과 이어
  하기가 생겨 한 세션을 넘어갈 때 다시 본다.
- 에피소드 저장과 복구. 화면을 벗어나면 사라지는 지금 동작은 그대로다.
- 일반 채팅 화면. 이 단위는 에피소드 화면만 다룬다.
- 에피소드 이름과 헤더 구조의 변경. 헤더 부제목과 프롬프트 방식은 검토 끝에
  제외했고, 네이티브 부제목 슬롯은 react-native-screens가 아직 지원하지
  않는다.
- 배너를 접거나 닫는 동작.

## 보류

- 에피소드가 늘어날 때 상황 줄 문구와 장면 이모지의 소유를 서버 각본으로
  옮길지. 지금은 에피소드가 하나라 앱의 다른 고정 문구와 같은 방식으로 두어도
  어긋날 것이 없다.

## 남은 위험

- 상시 고정 배너가 작은 화면에서 대화 공간을 줄인다. 한 줄 제한으로 누르되,
  실제 기기에서 확인해야 한다.
- 목표를 글로 미리 말해 주는 것이 사건의 긴장을 얼마나 덜어내는지는 써 봐야
  안다.
- 이모지는 플랫폼마다 모양이 달라, 배너의 인상이 iOS와 Android에서 조금 다를
  수 있다.
