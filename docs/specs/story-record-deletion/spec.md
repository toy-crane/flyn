# 대화 기록의 회차 선택과 삭제

## 목표와 승인 범위

사용자는 같은 스토리의 회차를 구분해 대화를 다시 보거나 이어가고, 필요 없는 회차를
삭제할 수 있다. 삭제해도 이미 쌓은 학습 기록과 노트에 담은 표현은 유지한다.

2026-09-14 화면과 삭제 정책을 확정했다. 대화 기록의 회차 카드, 에피소드 Sheet,
삭제 메뉴와 확인, 최근 대화 로딩, 화 수와 관계없이 적용할 진행 표시를 다룬다.

[제품 정의](../../../PRODUCT.md)의 영어를 실제로 쓰게 한다는 목적을 따른다.
연속 기록의 범위와 세는 기준은 [홈 학습 기록 명세](../home-streak/spec.md)를 따른다.
스토리, 에피소드, 회차와 대화 기록의 뜻은
[용어집](../../../GLOSSARY.md)을 따른다.

## 승인한 화면

[프로토타입](prototype.html)을 화면과 상호작용의 기준으로 사용한다. 대화 기록에서
카드를 누르고, 화를 고르고, 대화에서 돌아오는 흐름을 직접 확인할 수 있다.
상단 상태 선택으로 1화와 5화 스토리, 현재 화를 시작하기 전, 진행 중, 완료,
여러 회차, 삭제 후와 불러오는 중을 확인한다.

대화 화면은 선택 뒤의 이동을 확인하기 위한 축약 예시다. 실제 대화, 결말과 표현
돌아보기의 기능이나 모양을 이 예시로 대체하지 않는다. 본문은
[AI 에피소드 프로토콜](../../decisions/ai-episode-protocol.md), 종료 뒤 경험은
[에피소드 종료와 표현 돌아보기](../../decisions/episode-ending-and-review.md)를 따른다.

## 회차를 고르고 대화를 연다

- 기존 진입 경로, 새 대화, 표지와 소개, 카드 정렬과 빈 상태는
  [모바일 스토리 탐색](../../decisions/mobile-story-browsing.md)을 따른다.
- 카드의 본문을 누르면 선택한 회차의 에피소드 Sheet를 연다. 카드의 오른쪽 `···`를
  누르면 관리 메뉴만 연다. 두 동작은 서로 실행하지 않는다.
- Sheet 상단에서 스토리 이름과 회차를 시작한 날짜·시간을 확인한다.
- 목록에는 해당 회차에서 끝낸 화와 현재 진행할 화를 순서대로 포함한다. 끝낸 화가
  없을 때도 현재 1화를 보여 준다. 모든 화를 끝냈으면 끝낸 화만 보여 준다.
- 끝낸 화는 결과 한 줄을 보여 주며, 누르면 그 화의 대화를 읽기 전용으로 연다.
  대화 원본 없이 결과만 남은 화는 기존처럼 결과만 보여 주고 열지 않는다.
- 현재 화의 대화를 시작했으면 `이어서 하기`, 아직 시작하지 않았으면 `시작하기`를
  표시한다. 선택하면 Sheet를 닫고 해당 회차의 화를 연다.
- Sheet를 닫으면 대화 기록으로 돌아간다. 대화를 열거나 Sheet를 닫는 것만으로
  다른 회차의 진행, 순서와 이야기 기억은 바뀌지 않는다.
- 한 화만 있는 Sheet도 목록을 보여 준다. 짧은 목록은 낮게 시작하고 긴 목록은
  더 넓은 높이에서 스크롤할 수 있다. 같은 행동을 하는 하단 이어하기 버튼은 두지 않는다.
- 새 대화의 첫 장면만 열고 메시지를 보내지 않은 채 돌아오면 새 기록을 만들지 않는다.
  프로토타입의 시작 전 상태는 현재 화 행의 표시를 확인하는 자료이며, 이 규칙의 예외가 아니다.

Sheet와 화면 전환의 소유권은
[모바일 UI 렌더러 경계](../../decisions/mobile-ui-renderer-boundaries.md), 탭과 복귀 경로는
[모바일 탭과 상세 화면 배치](../../decisions/mobile-tab-navigation.md)를 따른다.
회차 카드와 화 행의 컴포넌트 이전은 [HeroUI 정렬 명세](../heroui-alignment/spec.md)와
겹친다. 먼저 구현한 쪽을 재사용하며 두 작업 모두 이 명세의 Sheet 구조를 따른다.

## 선택한 회차를 삭제한다

메뉴 문구는 `삭제`만 쓴다. 확인 화면은 다음 문구를 사용한다.

| 자리 | 문구 |
| --- | --- |
| 제목 | 이 회차를 삭제할까요? |
| 설명 | 이 회차의 모든 화에서 나눈 대화와 결말이 사라집니다. 되돌릴 수 없습니다. |
| 버튼 | 취소 / 삭제 |

- 확인 전과 취소 뒤에는 회차가 그대로 남는다. 확인하면 선택한 회차만 삭제한다.
- 삭제 범위와 남기는 기록은
  [회차 삭제와 학습 기록 보존](../../decisions/story-play-deletion.md)이 정한다.
  학습 기록 보존은 필수 동작이며 추후 결정할 항목이 아니다.
- 삭제가 끝나면 해당 카드가 사라진다. 다른 회차는 그대로 남고, 마지막 회차를
  지웠으면 기존 대화 기록의 빈 상태를 보여 준다. 삭제한 회차를 다시 열거나 이어갈 수 없다.
- 스토리 탭의 최근 대화에도 삭제 결과를 반영한다. 해당 스토리에 남은 대화 기록이
  없으면 목록에서 빠지고, 남은 기록이 있으면 그 기록에 맞는 기존 정렬 규칙을 따른다.
- 삭제에 실패하면 회차를 지운 것처럼 표시하지 않는다. 사용자는 실패를 확인하고
  다시 시도할 수 있다. 같은 삭제를 다시 요청해도 다른 회차나 학습 기록에는 영향이 없다.

진행 중 표시와 중복 실행 방지는
[모바일 작업 진행 표시](../../decisions/mobile-action-progress.md), 원본 삭제 뒤 표현의
수명은 [표현 저장 구조](../../decisions/expression-storage.md)를 따른다.

## 진행과 불러오는 상태를 표시한다

- 진행 바는 승인한 A안처럼 카드 본문 너비를 사용한다. 화 수와 완료 여부에 따른
  칸과 위치 문구는 [스토리 진행·결말 화면 표기](../../decisions/story-progress-and-ending-display.md)를 따른다.
- 최근 대화를 기다리는 영역에는 상태 문구 없이 공용 단독 스피너만 표시한다.
  로딩 중을 기록이 없는 상태로 표시하지 않는다. 로딩 이름은 화면 읽기에 전한다.
- 스피너의 크기, 색, 표시 시점과 기존 내용의 백그라운드 갱신 규칙은
  [모바일 작업 진행 표시](../../decisions/mobile-action-progress.md)를 따른다.
- 스토리 소개를 이미 알고 있으면 그 소개를 유지하고 최근 대화 영역에서 기다린다.
  아직 소개도 받지 못했으면 내용을 만들어 보여 주지 않는다. 조회 실패와 재시도는
  [모바일 스토리 탐색](../../decisions/mobile-story-browsing.md)의 기존 경로를 따른다.

화면 문구는 [UX 라이팅 원칙](../../decisions/ux-writing.md)을 따른다. 이 명세는
최근 대화 로딩을 다루며 다른 화면의 로딩 문구는 각 화면의 계약을 따른다.

## 수용 기준

- [ ] 1화짜리 스토리와 여러 화짜리 스토리 모두 같은 본문 너비에 진행 바를 표시한다.
- [ ] 완료 전후, 긴 화 제목과 밝은·어두운 화면에서 진행 표시와 삭제 메뉴가 겹치지 않는다.
- [ ] 카드 본문은 Sheet를 열고 `···`는 삭제 메뉴만 연다. 접기 쉐브론은 없다.
- [ ] 끝낸 화가 없어도 Sheet에서 현재 1화를 선택할 수 있다.
- [ ] 끝낸 화와 현재 화가 함께 있는 회차, 모든 화가 끝난 회차에서 맞는 목록과 동작을 보여 준다.
- [ ] 화 선택 뒤 대화와 대화 기록을 오가도 같은 회차의 진행을 유지한다.
- [ ] 삭제 확인을 취소하면 어떤 회차도 사라지지 않는다.
- [ ] 여러 회차 중 하나를 삭제하면 그 회차의 모든 화와 이야기 기억만 사라진다.
- [ ] 마지막 회차를 삭제하면 대화 기록의 빈 상태와 스토리 탭의 목록을 함께 갱신한다.
- [ ] 삭제한 회차의 원본 대화와 결말은 다시 열리지 않고 새 대화에도 이어지지 않는다.
- [ ] 완료한 회차를 삭제해도 완료한 날, 연속 기록과 날짜별 영어로 말한 횟수가 줄지 않는다.
- [ ] 미완료 회차를 삭제해도 그 회차에서 이미 영어로 말한 횟수가 줄지 않는다.
- [ ] 다시 로그인하거나 학습 기록을 새로 읽고 계산해도 삭제 전의 학습 사실을 유지한다.
- [ ] 삭제를 반복하거나 삭제가 실패해도 학습 기록을 빼거나 중복으로 더하지 않는다.
- [ ] 삭제한 회차에서 노트에 담은 표현은 원본 대화 없이도 계속 볼 수 있다.
- [ ] 최근 대화 로딩에서는 문구 없는 스피너를 표시하고, 완료 뒤 스피너와 접근성 대기 상태를 해제한다.
- [ ] 로딩, 조회 실패, 성공했지만 기록 없음 상태를 서로 구분한다.
- [ ] 사용자 본인의 회차만 삭제할 수 있고, 다른 사용자의 회차는 영향을 받지 않는다.

## 바꿀 수 있는 가정

다음은 승인한 동작을 구현할 때 조정할 수 있는 가정이다. 별도의 프로젝트 정책으로
확정한 값이 아니다.

- Sheet의 정확한 높이, 확장 지점, 닫기 동작과 전환 시간은 플랫폼의 기본 동작에 맞춘다.
  목록 길이에 맞는 시작 높이와 현재 화 접근은 유지한다.
- 삭제 실패는 확인하던 자리에서 알리고 다시 시도할 수 있게 한다. 성공 뒤에는
  카드가 사라지는 것으로 결과를 알리며 별도 완료 토스트는 두지 않는다.
- 뒤에서 데이터가 바뀌어 이미 사라진 회차를 다시 열려고 하면 대화 기록으로 돌아가
  현재 목록을 보여 준다. 오류 문구와 표시 위치는 기존 실패 표시 방식에 맞춘다.

## 제외 범위

- 스토리 콘텐츠 삭제, 여러 회차 일괄 삭제, 개별 화·메시지 삭제와 휴지통·복구는
  추가하지 않는다. 이번 삭제 단위와 확인 경험을 유지하기 위해 범위를 제한한다.
- 계정 삭제, 학습 횟수를 세는 기준과 연속 기록의 보상·알림은 바꾸지 않는다.
- AI 대화 생성, 교정, 표현 돌아보기와 노트의 별도 화면을 새로 설계하지 않는다.
- 구현 코드와 저장 구조는 이 명세에서 정하지 않는다.

## 남은 위험과 검증 범위

미룬 제품 결정은 없다. 다음 항목은 구현 과정에서 검증해야 한다.

- 연속 기록과 영어로 말한 횟수의 보존은 화면 캐시만 유지해서는 충족하지 못한다.
  삭제 뒤 다시 읽어도 남아야 하며, 기존 사용자의 학습 사실도 유실하지 않아야 한다.
- 삭제 실패·동시 요청·늦게 도착한 응답 때문에 삭제한 회차가 되살아나거나 학습 기록이
  달라지지 않는지 확인해야 한다.
- HTML 프로토타입은 더미 데이터다. 저장된 통계의 보존과 실제 삭제, 오류는 검증하지 않는다.
  로딩 상태는 표시 기준을 넘긴 상황을 고정해 보여 주며 실제 요청을 기다리지 않는다.
- 헤더, Sheet와 스피너의 HTML 표현은 네이티브 모양을 흉내 낸 자료다. 실제 앱에서는
  연결한 렌더러·진행 표시 계약을 우선하고 기기에서 크기와 접근성을 확인한다.
- 프로토타입에서는 좁은 화면과 넓은 화면, 밝은·어두운 모드, 회차와 화 선택,
  로딩·빈 상태 전환, 삭제 확인·취소·삭제 후 목록을 확인했다. 네이티브 동작 검증을 대신하지 않는다.
