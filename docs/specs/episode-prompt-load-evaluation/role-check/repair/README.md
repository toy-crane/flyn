# 초안을 원래 대화와 대조해 고치기

역할 정보 읽기는 40회 모두 맞았지만, R과 S의 장면 생성에서 역할 혼동이 남았다.
이를 본 뒤 설계한 탐색 실험이다. 앞선 실험의 현재 방식 A가 만든 초안 40개를
모두 Luna에게 다시 보여 주고 원래 대화와 대조해 최종 장면을 만들도록 한다.
오류가 있는 초안만 골라 고치지 않고, 맞는 초안을 망가뜨리는지도 확인한다.

Luna는 원래 무대와 대화, R의 역할 규칙, 후보 장면을 읽는다. 사람이 정리한 정답
일정은 받지 않는다. 원래 출력 형식을 유지하고 대사·결말·기록을 모두 반환한다.
이 단계는 참·거짓을 출력하는 모델 채점이 아니라 장면 생성 방식의 후보이다.

고정한 [manifest](manifest.json)에 원래 초안과 수정 지시를 보존한다. 실행 코드는
상위 `reproduction/repair.ts`다. 기존 scratch의 `data` 폴더가 필요하며,
`bun --cwd apps/api "$role_scratch/repair.ts" prepare` 다음 `run`으로 실행한다.
모델 호출은 40회다. 결과는 조건을 가린 뒤 별도로 읽고 원래 초안의 관찰과 비교한다.

최종 답을 검토한 뒤 사용자에게 보여 주는 방식으로 적용하면 두 호출이 끝날 때까지
기다려야 한다. 초안 생성 시간과 검토 시간의 합은 예상값으로 기록한다. 사후에
고른 방식이고 같은 입력 묶음을 다시 쓰므로 새 이야기에서의 확인은 별도로 필요하다.
제품 코드에는 적용하지 않는다.

실행 때는 초안 대응 번호와 반복 번호를 가린 40개 수정 대사를 읽었다. 수정 방식
하나만 읽었으므로 방법 자체를 숨긴 검토는 아니었다. 원래 계획한 조건 가림보다
검토 범위가 좁다는 한계를 [결과 보고서](../results.md)에 함께 기록했다.
