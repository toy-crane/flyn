# 채팅 움직임과 답변 대기 표시

## 목적

플린의 전송, 최신 메시지 이동, 답변 완료가 각각 한 번의 안정된 변화로 보이게 한다.
답변을 기다리는 동안에는 작은 말풍선 안의 점 세 개를 보여 준다.

[제품 정의](../../../PRODUCT.md)의 영어 드라마와 그 자리에서 받는 교정을 유지한다.
사용자가 영어 문장을 읽고 다음 메시지를 쓰는 흐름을 화면 움직임이 방해하지 않게 한다.

## 승인된 범위

일반 채팅, 에피소드 본 채팅과 AI에게 물어보기의 공통 채팅 경험에 적용한다.
대화 기록의 읽기 전용 화면에는 전송이나 대기 상태를 새로 만들지 않는다.

### 전송할 때 한 번 이동

- 보내면 입력창을 비우고 키보드를 먼저 닫는다. 입력창이 제자리에 놓인 뒤 보낸
  질문을 목록 스크롤 한 번으로 위쪽에 놓는다. 키보드가 이미 닫혀 있으면 바로 옮긴다.
- 빈 대화의 첫 질문은 처음부터 위쪽에서 시작한다. 이후 질문은 헤더와 상황 줄 아래
  12px에 놓고, 답변이 그 아래로 이어지게 한다. 수정해서 보내면 수정한 질문의
  자리를 기준으로 같은 순서를 적용한다.
- 말풍선 자체의 진입 애니메이션은 없앤다. 이동 목표는 질문과 뒤쪽 빈 영역이 자리를
  잡은 뒤 확정하고, 도착한 질문을 다시 옮기지 않는다.
- 답변이 빨리 도착해도 질문 이동 중에는 자동 추적이 끼어들지 않는다. 사용자가
  이전 메시지를 읽으려고 움직이면 그 의도를 우선하고 읽던 위치를 유지한다.

### 최신 메시지 버튼

- 버튼을 누르면 끝에 도착한 뒤 자동 추적을 켜고 버튼을 숨긴다. 이동 중에 답변이
  늘어나도 순간적으로 끝으로 당기거나 도착 후 다시 움직이지 않는다.
- 끝까지 거리가 한 화면보다 멀면 마지막 한 화면만 부드럽게 지나간다. 가까우면
  남은 거리만 이동한다. 사용자가 중간에 이동을 멈추면 그 위치를 유지한다.
- 버튼은 입력창 뒤에서 올라왔다 같은 길로 내려가 사라진다. 최종 위치에서 갑자기
  나타나거나 내려가는 중간에 잘리지 않는다. 버튼 크기와 Glass 투명도는 움직이지 않는다.
- 중앙 44px 버튼과 AI에게 물어보기로 돌아가는 표시의 배치를 유지한다. 입력창이
  여러 줄이거나 오류·수정 안내가 있어도 버튼이 가려지거나 다른 표시와 겹치지 않는다.
- 숨은 버튼은 터치와 화면 읽기 기능에서 제외한다.

### 답변 완료 때 높이 유지

- 복사와 다시 받기를 제공하는 화면에서는 답변 본문이 나타난 때부터 동작 줄의
  공간을 확보한다. 답변이 끝나면 버튼만 그 자리에 표시한다.
- 답변을 기다리거나 받는 동안 버튼은 보이지 않고 동작하지 않는다. 마지막 본문을
  반영한 뒤 완료 상태로 바뀌었다는 이유만으로 답변 높이나 목록 위치가 달라지지 않는다.
- 에피소드 본 채팅처럼 메시지 동작을 제공하지 않는 화면에는 버튼과 빈 공간을 모두
  추가하지 않는다. 배울 표현과 에피소드 마무리가 실제로 생겨 차지하는 공간은 유지한다.

### 지난 메시지 유지

- 내용과 표시 조건이 같은 지난 메시지 본문은 다른 답변의 시작과 완료만으로 다시
  그리지 않는다. 수정 중 흐리게 보이는 표현 등 실제로 바뀌어야 하는 상태는 갱신한다.
- 답변을 받는 동안에도 기존 본문과 메뉴를 감싸는 영역을 유지한다. 메뉴를 사용할 수
  있는지는 기존 정책대로 바꾸고, 그 변경 때문에 본문이 사라졌다 다시 나타나지 않는다.
- 네이티브 Markdown, 본문 선택, 복사, 다시 받기와 배울 표현의 동작을 유지한다.

### 점 세 개로 답변 대기 표시

- 첫 글자가 300ms 안에 오면 대기 표시를 생략한다. 그보다 늦으면 답변 자리의 작은
  말풍선 안에 점 세 개를 보여 준다. `Thinking`과 별도 상태 문구는 화면에 쓰지 않는다.
- 세 점은 왼쪽부터 차례로 밝아졌다 어두워진다. 위치와 크기는 바뀌지 않는다.
  말풍선과 점은 기존 표면색과 본문색을 따른다.
- 첫 글자가 오면 같은 자리에서 답변으로 교체한다. 대기 표시를 별도 메시지로 남기거나
  대기 표시와 답변을 동시에 보여 주지 않는다. 요청을 중지하거나 실패해도 점을 없앤다.
- 화면 읽기 기능에는 `답변을 준비하고 있어요.`라는 상태 하나를 제공한다. 점을
  각각 읽거나 반복 동작마다 같은 상태를 알리지 않는다.
- 동작 줄이기에서는 점 세 개를 정지 상태로 보여 준다. 질문과 최신 메시지 이동,
  버튼의 나타남과 사라짐에도 이동 애니메이션을 쓰지 않는다.

## 수용 기준

- 키보드가 열린 상태에서 한 줄과 여러 줄 질문을 각각 보내면, 키보드 닫기 뒤 질문이
  한 번 이동한다. 녹화에서 말풍선이 입력창 뒤에 겹치거나 도착 후 다시 움직이지 않는다.
  키보드가 닫혀 있을 때, 첫 질문과 수정한 질문을 보낼 때도 정해진 위치에 도착한다.
- 질문 이동 중 첫 글자가 도착해도 이동이 끊기거나 두 번으로 나뉘지 않는다. 이동 중
  이전 메시지로 스크롤하면 자동 추적이 읽던 위치를 빼앗지 않는다.
- 마지막 메시지에서 반 화면 떨어진 경우와 세 화면 이상 떨어진 경우에 최신 메시지
  버튼을 눌러 비교한다. 가까운 경우는 남은 거리만, 먼 경우는 마지막 한 화면만
  부드럽게 지나가고 끝에 도착한 뒤 버튼이 사라진다.
- 사용자가 최신 메시지 이동을 손으로 멈춘 뒤에도 목록을 읽고 키보드를 다시 열고
  닫을 수 있다. 전송 중 앱을 나갔다 돌아와도 키보드 높이만큼의 빈 공간이 남거나
  입력창과 목록이 움직이지 않는 상태로 남지 않는다.
- 입력창 한 줄·여러 줄, 수정·오류 안내, AI에게 물어보기로 돌아가는 표시가 있는
  경우에도 최신 메시지 버튼이 정해진 자리로 오간다. 숨은 버튼은 눌리거나 읽히지 않는다.
- 복사와 다시 받기를 제공하는 답변은 마지막 본문 반영 후 완료될 때 목록 위치와
  본문 높이가 그대로다. 완료 후 두 버튼이 동작한다. 에피소드에는 빈 동작 줄이 없다.
- 답변 시작과 완료를 계측했을 때 내용과 표시 조건이 같은 지난 본문을 다시 그린
  횟수는 0회다. 해당 본문이 사라졌다 다시 생기거나 선택 범위가 끊기지 않는다.
- 300ms 이전에 첫 글자가 오는 답변에는 점이 나타나지 않는다. 늦은 답변에는 점 세
  개만 나타나고, 첫 글자·중지·실패 각각에서 사라진다. 빠른 답변을 별도로 늦추지 않는다.
- 동작 줄이기에서 점의 밝기·위치·크기가 고정되고 대기 상태는 계속 전달된다.
  VoiceOver와 TalkBack은 점마다 읽지 않고 대기 상태 하나를 읽는다.
- iOS와 Android에서 일반 채팅, 에피소드와 AI에게 물어보기를 확인한다. 라이트·다크,
  글자 크기 확대에서도 겹침과 잘림이 없다. 실제 네이티브 실행과 녹화로 확인한 범위를
  기록하며, 브라우저 비교나 모킹한 테스트만으로 움직임을 검증했다고 보고하지 않는다.

## 제약과 이유

- 움직임은 [채팅 스크롤](../../decisions/mobile-chat-scrolling.md), 점 세 개와 본문은
  [AI 채팅 표현](../../decisions/mobile-ai-chat-rendering.md), 답변 동작은
  [채팅 메시지 동작](../../decisions/mobile-chat-message-actions.md) 계약을 따른다.
- 키보드와 질문이 서로 다른 방향으로 동시에 움직이지 않도록 순서를 나눈다.
  키보드를 닫는 시간만큼 질문 배치가 늦어지는 것은 받아들인다.
- 최신 메시지로 도착하기 전에 자동 추적을 켜지 않는다. 스트리밍으로 바뀌는 목록
  높이가 진행 중인 스크롤과 동시에 위치를 정하는 일을 막기 위해서다.
- 복사와 다시 받기는 플린의 기존 기능이다. Dearly가 이 기능을 제거한 제품 판단은
  가져오지 않고, 완료 때 공간이 바뀌지 않는 원칙을 적용한다.
- 점 세 개는 별도 문구를 읽지 않고도 답장을 기다리는 상태를 전달한다. 점 하나와
  회전 표시 옆 문구를 함께 비교한 뒤 사용자가 작은 말풍선의 점 세 개를 선택했다.
- 서버 요청, 모델, 스트리밍 프로토콜과 대화 저장 정책은 바꾸지 않는다.

## 바꿔도 되는 기본값

- 한 화면은 키보드와 입력창을 고려한 목록의 보이는 높이다.
- 점 지름은 6px, 점 사이 간격은 5px, 반복 주기는 1,200ms, 점 사이 시작 간격은
  200ms로 둔다. 투명도는 0.3~0.95이며 동작 줄이기에서는 0.65로 고정한다.
- 대기 말풍선은 높이 36px, 가로 안쪽 여백 14px, 모서리 16px로 시작한다.
  대기 표시가 나타나는 시간은 기존 200ms를 유지한다. 첫 글자가 오면 이 시간을
  마저 기다리지 않고 답변을 보여 준다.
- 최신 메시지 버튼은 나타날 때 200ms, 사라질 때 160ms의 ease-out으로 시작한다.
  질문과 목록의 이동 시간은 플랫폼의 스크롤 동작을 따르며 숫자를 새 정책으로 고정하지 않는다.
- 위 수치는 비교 예시와 기존 표현에서 고른 기본값이다. 네이티브 화면에서 읽기와
  연결이 어색하면 승인된 모양과 동작의 뜻을 유지하는 범위에서 조정한다.

## 범위 밖

- 사진 첨부, 업로드, 미리보기: 현재 채팅 기능에 없다.
- 사용자 말풍선 여백 축소와 최신 메시지 버튼의 오른쪽 배치: 이번에 선택한 네 가지
  개선에 포함하지 않는다. 기존 영어 문장, 배울 표현과 돌아가기 표시의 배치를 유지한다.
- Markdown 렌더러 교체, 스크롤 목록 교체와 새 그래픽 도구 도입: 화면 동작을
  다듬기 위해 기술 구성을 새로 선택하지 않는다.
- 대화 기록 복원, 읽던 위치 저장, 답변 완료 뒤 본문 크기와 무관한 에피소드 마무리
  동작 변경: 각각의 기존 계약을 따른다.

## 남은 위험과 확인 범위

- 이번 결정은 Flyn 코드와 Dearly 변경 기록을 비교한 결과다. Flyn 네이티브 화면의
  흔들림이나 개선 효과를 아직 측정하지 않았다.
- Dearly와 Flyn은 키보드 및 목록 라이브러리 버전이 다르다. Dearly의 닫힘 신호 대기와
  스크롤 중단 처리도 완성된 해법으로 보지 않는다. 현재 버전에서 동작을 확인해야 한다.
- 작은 말풍선에서 답변 첫 줄로 바뀔 때 높이가 달라질 수 있다. 첫 줄이 같은 자리에서
  시작하고 읽던 위치를 불필요하게 움직이지 않는지 네이티브 화면에서 확인해야 한다.
- Glass 뒤로 버튼이 들어갈 때 비쳐 보일 수 있다. 다 숨은 뒤 잔상이 남는지 확인한다.
- 점의 모양과 밝기 변화는 대화 안의 비교에서 선택했다. 네이티브 앱의 키보드·목록과
  함께 움직이는 모습까지 승인하거나 검증한 것은 아니다.
- 구현에 앞서 사용자가 더 정해야 할 동작은 없다.
