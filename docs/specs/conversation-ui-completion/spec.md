# 대화 화면과 회차 선택의 누락 보완

## 상태와 목표

2026-09-15 사용자가 기존 구현 명세를 정리하고 누락을 보완할 새 명세 하나를 요청했다.
기준 코드는 `fc94722`다. 이 명세의 보완 작업은 아직 구현하지 않았다.

사용자는 배울 표현을 펼치고 접어도 읽던 원문을 놓치지 않고, 종료 축하의 순서를
알아볼 수 있다. 회차의 화 목록에서는 다음에 할 행동을 구분하고, 삭제 메뉴에서는
되돌릴 수 없는 행동임을 알아본다. [제품 정의](../../../PRODUCT.md)의 대화와 그 자리의
학습 도움을 유지하며, 대화 생성이나 학습 내용은 바꾸지 않는다.

## 이미 구현된 범위

기존 세 명세의 구현된 기능은 아래 결정 계약이 소유한다. 기존 명세 파일은 정리하고
승인한 시안은 이 폴더로 옮겼다. 아래 표는 코드가 있다는 뜻이며 모든 기기 검증을
마쳤다는 뜻은 아니다. 남은 구현과 검증은 이 명세의 완료 조건으로 남긴다.

| 기존 명세 | 구현된 내용 | 동작을 소유하는 결정 |
| --- | --- | --- |
| 에피소드 대화 화면 개선 | 말풍선 아래 대사 뜻과 같은 본문 역할, 반복 아이콘 제거, 공통 질문 링크, 높이·투명도 전환, 복원 시 진입 효과 생략, 종료 직후 카드와 버튼 대기, 다시 읽기의 CTA만 표시 | [대사 뜻](../../decisions/mobile-utterance-translation.md), [교정](../../decisions/mobile-episode-correction.md), [종료](../../decisions/episode-ending-and-review.md) |
| 표현 돌아보기 화면 개선 | 모든 표현이 자연스러울 때만 가운데 칭찬, 다음 이야기의 별도 카드와 카드 밖 Primary 버튼, 지연 로딩과 조회 실패·재시도 | [종료와 돌아보기](../../decisions/episode-ending-and-review.md), [작업 진행 표시](../../decisions/mobile-action-progress.md) |
| 대화 기록의 회차 선택과 삭제 | 카드 전체 너비의 진행 바, 카드에서 여는 화 선택 Sheet, 현재 화 시작·이어하기와 완료 화 다시 읽기, 회차 삭제와 목록 갱신, 학습 사실·저장한 표현 보존 | [스토리 탐색](../../decisions/mobile-story-browsing.md), [진행 표기](../../decisions/story-progress-and-ending-display.md), [삭제와 보존](../../decisions/story-play-deletion.md) |

표현 돌아보기에서는 이번 감사로 새로운 코드 누락을 찾지 못했다. 칭찬 위의 그림과
Lottie는 명시적으로 보류한 선택이므로 추가하지 않는다. 삭제 뒤 학습 사실을 남기는
저장 경로는 있으나, 이를 보여 줄 홈 화면까지 구현됐다는 뜻은 아니다.

## 승인한 시안의 사용 범위

| 자료 | 이 명세에서 확인할 것 |
| --- | --- |
| [대화 시안](episode-chat.prototype.html) | `Default`, `대화 종료`, `다시 읽기`, `긴 대사`의 배치, 질문 링크, 펼침 전환과 천천히 퍼지는 축하 |
| [표현 돌아보기 시안](expression-review.prototype.html) | 칭찬과 표현 목록의 구분, 예고 카드와 카드 밖 버튼, 로딩과 빈 상태의 회귀 확인 |
| [회차 선택과 삭제 시안](story-records.prototype.html) | 1화·5화, 시작 전·진행 중·전체 완료, 여러 회차의 선택, 현재 화 강조, 위험 색의 삭제 메뉴, 로딩·삭제 후 빈 상태 |

세 HTML 파일은 기존 승인본을 내용 변경 없이 옮긴다. 예시 스토리·문장·시간, 정해진
입력 횟수 뒤 종료, 시연용 답변과 데이터 처리는 구현 계약이 아니다. 대화 시안의 질문
시트와 돌아보기, 돌아보기 시안의 주변 화면, 기록 시안의 축약 대화는 연결 확인용이다.
이를 근거로 다른 화면이나 교정 카드의 내용을 다시 설계하지 않는다.

HTML의 헤더·Sheet·스피너·SVG를 그대로 복제하지 않는다. 실제 앱은
[렌더러 경계](../../decisions/mobile-ui-renderer-boundaries.md),
[컴포넌트 선택](../../decisions/mobile-component-selection.md),
[타이포그래피](../../decisions/mobile-typography.md),
[아이콘 렌더링](../../decisions/mobile-icon-rendering.md)을 따른다.
글꼴·여백·Sheet 높이는 플랫폼과 큰 글자에 맞춰 조정한다.

## 보완할 여섯 가지

### 1. 펼침 표시도 설명과 함께 전환한다

현재 [교정 카드](../../../apps/mobile/src/features/episode/ui/correction-note.tsx)는
설명과 높이를 전환하지만 `expand`와 `collapse` 아이콘은 조건부로 교체한다.
펼침·접기에 맞춰 쉐브론이 회전하도록 보완한다. 같은 동작이 영어 교정과 한국어 입력
안내에 적용돼야 한다. 접힌 한 줄이 펼친 카드로 바뀌는 현재 내용 구조는 유지한다.

완료 기준은 아이콘 속성이나 애니메이션 설정의 존재가 아니라, 설명 높이와 표시가
함께 전환하는 실제 화면이다. 빠르게 다시 눌러도 마지막 선택으로 끝나야 한다.

### 2. 종료 축하의 순서를 알아볼 시간을 준다

현재 [종료 카드](../../../apps/mobile/src/features/episode/ui/episode-closing.tsx)와
[Lottie 생성 코드](../../../scripts/closing-celebration/lottie.ts)의 움직임은 승인 시안보다
짧다. 카드, 마크, 체크, 고리와 조각, 결과 문장이 차례로 드러나는 경험을 보완한다.

| 움직임 | 승인 시안의 기준 | 현재 코드 |
| --- | --- | --- |
| 카드 진입 | 약 600ms | 260ms |
| 마크 등장 | 약 800ms | 300ms |
| 체크 그리기 | 약 550ms | 200ms |
| 고리 확산 | 약 1,400ms | 420ms |
| 조각 이동 | 약 2,100ms, 약 250ms 뒤 시작 | 1,150ms |

이 수치는 각 움직임의 길이이며 전체 재생 시간을 뜻하지 않는다. 정확한 수치 일치는
필수 조건이 아니다. 구현은 시안의 느린 전환을 출발점으로 삼고, 달리 정한 값은 실제
기기 녹화와 조정 이유를 남긴다. 효과가 너무 빨리 끝나 단계를 알아보기 어렵거나,
연출 때문에 준비된 CTA를 누르지 못하는 결과는 완료로 보지 않는다.

성공과 타협·실패의 차이, 한 번의 햅틱, 테마 색과 Lottie 자산은 종료 계약을 따른다.
목표를 이루지 못한 결말에 고리나 `해냈어요!`를 새로 넣지 않는다.

### 3. 고리와 조각의 출발점이 카드에 가려지지 않는다

현재 `CelebrationBurst` 뒤에 불투명한 결과 카드를 그려 카드와 겹치는 고리와 조각이
가려진다. iOS에서는 카드 위쪽 밖의 조각은 보였지만 안쪽에서 이어지는 모습이 가려졌다.

성공 결말의 고리는 마크 주위에서 온전히 보여야 한다. 조각은 마크에서 터져 카드 안과
위·양옆 바깥으로 이어져야 한다. 카드 경계에서 잘리거나 불투명한 표면 뒤로 사라지는
부분을 없앤다. 장식은 화면 안에 머물고 결과 문장과 CTA를 계속 가리지 않는다.
장식 때문에 대화 스크롤, 버튼 누름과 화면 읽기가 막히지 않아야 한다.

### 4. 펼치고 접어도 읽던 원문이 튀지 않는다

iOS에서 교정 카드를 펼쳤다가 접자, 손으로 목록을 스크롤하지 않았는데도 같은 사용자
원문이 더 아래로 이동하고 지난 장면이 드러났다. 원인이 높이 전환인지
[채팅 목록의 위치 보정](../../../apps/mobile/src/features/chat/ui/chat-panel.tsx)인지는
분리 검증이 필요하다. 특정 라이브러리 설정이 원인이라고 단정하지 않는다.

이전 대화를 읽는 상태에서 원문의 화면 위치를 기준으로 펼침 전과 접기 후를 비교한다.
내용과 화면 높이가 같고 손으로 스크롤하지 않았다면 같은 위치로 돌아와야 한다.
자연스러운 공간 변화 뒤에 두 번째 위치 보정이 발생해서는 안 된다. 목록 끝의 물리적
경계나 키보드 변화가 있는 경우는 별도로 기록해 원인과 구분한다.

대사 뜻 표시·숨김, 늦게 도착한 교정도 함께 확인한다. 최신 내용 추적, 이전 대화 읽기,
전환 도중 손으로 스크롤하기는 [스크롤 계약](../../decisions/mobile-chat-scrolling.md)을
따른다. 원문 말풍선 자체의 별도 진입 이동과 글자별 반복 효과는 추가하지 않는다.

### 5. 현재 진행할 화를 구분한다

현재 [화 선택 Sheet](../../../apps/mobile/src/screens/stories/story-play-episodes-route.tsx)는
현재 화와 끝낸 화에 같은 행 배경을 쓰고, `시작하기`·`이어서 하기`도 회색 설명으로 보인다.
시안처럼 현재 화에 옅은 강조색 배경을 두고 행동 문구에 강조색과 굵기를 적용한다.

이는 Sheet 안에서 현재 화를 알아보게 하는 상태 표현이다. 특정 회차를 대표로 고르는
변경이 아니다. `ListGroup`과 공용 행의 기본 구조·크기·여백·누름 반응을 유지한다.
범위는 [컴포넌트 선택](../../decisions/mobile-component-selection.md)에 명시했다.
모든 화를 끝냈다면 강조할 현재 화를 만들지 않는다.

### 6. 삭제 메뉴에서 위험한 행동임을 알린다

현재 [삭제 메뉴](../../../apps/mobile/src/screens/stories/story-records-screen.tsx)는
일반 글자색의 `삭제`만 표시한다. HeroUI `Menu.Item`의 `danger` 변형과 휴지통 아이콘을
사용해 시안의 의미를 복원한다. 고정된 빨간색 값을 넣거나 메뉴를 직접 다시 만들지 않는다.

색만으로 의미를 전달하지 않고 `삭제` 문구와 아이콘을 함께 둔다. 확인 문구와 취소,
실패·재시도, 삭제 단위와 학습 사실 보존은 [삭제 계약](../../decisions/story-play-deletion.md)을
그대로 따른다. 메뉴를 누르는 것만으로 삭제하거나 회차 Sheet를 함께 열지 않는다.

## 완료 조건

### 구현 보완

- [ ] 영어 교정과 한국어 입력 안내에서 설명 높이와 쉐브론 회전이 함께 전환한다.
- [ ] 새 교정 등장, 설명 펼침·접기, 짧고 긴 대사 뜻 표시·숨김을 빠르게 반복해도 빈 공간,
  겹친 글, 숨은 누름 영역이 남지 않는다. 질문 시트를 닫으면 해당 카드의 펼침 상태를 유지한다.
- [ ] 이전 대화를 읽는 상태에서 펼침 전과 접기 후 원문의 위치를 비교해 튐이 없음을 확인한다.
  늦은 교정 도착은 읽던 위치를 바꾸지 않고, 최신 내용 추적은 필요한 내용을 계속 보여 준다.
  전환 중 손으로 스크롤하면 자동 이동을 멈춘다.
- [ ] 실제 재생 속도로 축하의 단계와 천천히 퍼지는 조각을 알아볼 수 있다. 선택한 시간과
  시안에서 조정한 이유를 녹화 근거와 함께 남긴다.
- [ ] 성공 결말의 고리 전체와 조각의 출발점, 카드 위·양옆의 확산이 보인다.
  밝은·어두운 화면 모두 장식이 카드 뒤에 숨지 않고 CTA와 결과를 가리지 않는다.
- [ ] 시작 전·진행 중인 현재 화는 배경과 행동 문구로 구분되고 완료한 화는 기존 결과를
  보여 준다. 현재 화가 없는 회차는 강조 행 없이 끝낸 화만 보여 준다.
- [ ] 삭제 메뉴의 위험 색과 휴지통 아이콘이 두 테마에서 보이며 메뉴와 Sheet 누름이 분리된다.

### 기존 동작과 남은 환경 검증

- [ ] 진행 중·종료한 대화에서 말풍선, 아이콘 없는 뜻, 아이콘 줄 순서를 유지한다. 뜻은
  말풍선과 같은 본문 역할이며 복사·담기는 영어 원문을 다룬다. 두 질문 링크는 공통
  `LinkButton`을 쓰고 각 내용을 출처로 연다. 번역·교정 모델이나 저장 요청을 바꾸지 않는다.
- [ ] 복원한 뜻과 교정은 새 등장 효과를 재생하지 않는다. 이후 직접 켜기·끄기·펼침·접기는
  전환한다. 동작 줄이기에서는 이동·확산·크기·회전 효과 없이 필요한 내용을 바로 보여 준다.
- [ ] 종료 직후 확인 중인 메시지가 있어도 결과 카드는 즉시 보이고 CTA만 기다린다.
  모든 확인이 성공 또는 실패로 끝나면 버튼이 열리며, 재시도 중에는 다시 기다린다.
  확인 중 안내는 해당 메시지 곁에만 두고, 버튼 활성화나 재시도가 축하를 반복하지 않는다.
- [ ] 성공·타협·실패의 연출 차이와 햅틱을 유지한다. 축하 중에도 준비된 CTA와 스크롤을
  사용할 수 있고, 효과가 끝나도 결과 카드와 버튼은 남는다. 화면을 떠나면 장식과 지연된
  효과가 다음 화면에 나타나지 않는다.
- [ ] 기록에서 열기, 앱 재진입, 돌아보기에서 복귀하면 큰 완료 카드·마크·결과 요약 없이
  하단 CTA만 보인다. 미완료 확인이 남으면 그 버튼만 기다리고 준비된 도움은 계속 읽을 수 있다.
- [ ] 돌아보기의 카드 있음, 모두 자연스러움, 사용자 메시지 없음, 확인 실패·누락·`unclear`를
  각각 확인한다. 모든 확인이 자연스럽고 사용자 메시지가 하나 이상일 때만 가운데 칭찬을 보인다.
  목록 지연 1초 전후, 조회 실패·재시도에서 스피너·접근성·하단 이동을 확인한다.
- [ ] 돌아보기의 다음 화 시작, 끝낸 다음 화 다시 보기, 마지막 화의 기록 이동을 확인한다.
  예고 카드와 바깥 Primary 버튼은 목록·칭찬·빈 상태·오류 사이에도 같은 하단 배치를 유지한다.
- [ ] 1화·여러 화의 전체 너비 진행 바, 긴 제목, 짧은·긴 Sheet, 완료한 화가 없음·일부 완료·
  전체 완료를 확인한다. 대화 원본이 없는 화는 결과만 표시하고 열지 않는다. 같은 회차로
  이동·복귀하며 다른 회차의 진행·기억·정렬을 바꾸지 않는다. 첫 장면만 열면 새 기록이 생기지 않는다.
- [ ] 삭제 확인 취소·실패·재시도·반복 요청과 여러 회차 중 하나·마지막 회차 삭제를 확인한다.
  목록과 최근 대화가 함께 갱신되고 삭제한 대화·결말은 다시 열리지 않는다. 조회 로딩은
  알려진 소개를 유지하며 빈 상태·오류와 구분하고, 완료 뒤 접근성 대기 상태도 해제한다.
- [ ] 삭제 후 다시 로그인·조회해도 완료한 날과 날짜별 영어 사용 사실, 미완료 회차의 영어
  사용 사실과 저장한 표현이 남는다. 반복·실패·동시 요청과 늦은 응답이 중복 집계나 회차
  복원을 만들지 않으며 다른 사용자의 회차를 지울 수 없다. 기존 DB·API 검증을 재사용하고
  실행한 근거를 남긴다. 홈 표시 검증은 [홈 명세](../home-streak/spec.md)가 맡는다.
- [ ] 위 화면 변경은 iOS·Android 모두에서 확인한다. 밝은·어두운 화면, 동작 줄이기,
  작은 화면 높이, 최대 시스템 글자 크기에서 마지막 대사·본문·CTA가 잘리거나 겹치지 않는다.
  화면 읽기로 접힘 상태, 질문 링크, 진행·비활성 버튼, 화 선택과 삭제를 구분할 수 있다.

## 검증 방법과 현재 근거

- 기준 커밋에서 관련 Jest 5개 파일의 45개 테스트가 통과했다. `Reanimated`는 mock이므로
  이것만으로 실제 움직임·읽기 위치·겹침을 검증했다고 하지 않는다. 구조와 상태 전이는
  자동 테스트로, 움직임과 실제 누름은 앱 화면으로 확인한다.
- iOS의 우리 동네 카페 1화에서 교정 펼침·접기, 성공 종료, 돌아보기와 복귀, 완료 1화와
  시작 전 2화의 Sheet, 삭제 메뉴를 확인했다. 접기 뒤 위치 변경, 빠른 축하와 장식 가림,
  현재 화와 삭제의 강조 차이를 확인했다. 삭제 실행과 DB 테스트는 이 감사에서 다시 실행하지 않았다.
- Android, 실제 칭찬·지연·실패 화면, 최대 글자·작은 화면·동작 줄이기·어두운 화면은
  이 감사의 실행 근거가 없다. 확인하지 않은 항목을 완료 처리하지 않는다.
- 이번 감사의 시안 비교는 HTML의 DOM·CSS·이벤트 코드를 기준으로 했다. 브라우저의
  로컬 URL 열기가 차단되어 새 재생 비교는 하지 못했다. 시안 소스와 앱 녹화의 근거 수준을 구분한다.
- 구현 검증은 저장소 루트의 `bun run dev <ios|android>`와 해당 worktree 기기를 쓴다.
  [인증 계약](../../decisions/mobile-authentication.md)의 로컬 이메일 로그인으로 진입한다.
  플랫폼·커밋·시나리오·실행 결과를 남기고, 펼침 전·중·후와 축하 시작·중간·끝은 녹화로
  비교한다. `agent-device` 세션은 로그아웃까지 이어서 진행하고 끝나면 닫는다.

## 별도로 남는 작업과 제외 범위

- [입력창 비우기](../episode-closing-and-input-clear/spec.md)는 빠른 입력·한글 조합·자동
  수정 직후의 전송 경합을 다룬다. 종료 대기 구현은 재사용하며 이 명세에서 입력 처리를 바꾸지 않는다.
- [홈 학습 기록](../home-streak/spec.md)과 [표현 노트 동작](../expression-note-actions/spec.md)은
  별도 활성 명세다. 학습 사실 보존을 홈 화면 구현으로 취급하지 않는다.
- 돌아보기의 그림·Lottie와 새 빈 상태 문구, 결말별 칭찬 문구는 종료 계약의 재검토 조건으로
  남긴다. 이 명세에서 새로 정하지 않는다.
- 결말 판정, 대화·교정 생성과 저장 구조, 일반 AI 질문·스토리 만들기 화면, 입력창 형태,
  새 애니메이션 라이브러리·소리·마스코트, 결말 카드의 목록 안 이동은 범위 밖이다.
- 스토리·개별 화·메시지·일괄 삭제, 휴지통·복구, 계정 삭제와 학습 집계 기준을 바꾸지 않는다.
- 에이전트 가정(사용자가 바꿀 수 있음): 현재 공용 컴포넌트와 의미 색을 재사용한다.
  시간·간격·강조색 농도는 읽기와 접근성을 해치지 않는 범위에서 실제 기기로 조정한다.
  HTML의 고정 수치를 앱 전체의 새 디자인 규칙으로 만들지 않는다.
