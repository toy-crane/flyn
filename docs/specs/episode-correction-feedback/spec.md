# 대화 중 교정과 영어 표현 안내 개선

## 목적

사용자가 메시지를 보낸 뒤 표현을 확인 중인지, 고칠 부분이 있는지, 문제가 없는지,
확인하지 못했는지 알 수 있게 한다. 표현 확인이 늦어도 캐릭터와 대화를 계속한다.
반복된 실수도 일관되게 교정하고, 한국어로 쓴 말에는 영어 표현을 알려 준다.

이 문서는 합의한 제품 동작과 바꿀 수 있는 기본값을 구분해 정리한다.
구현과 검증 근거는 [검토 기록](notes.md)에 남긴다.

## 적용 범위와 기준

- 진행 중인 에피소드의 사용자 메시지에 적용한다. 템플릿 채팅은 바꾸지 않는다.
- 영어 교정과 한국어 입력 안내는 같은 카드 배치와 접기·펼치기 동작을 쓴다.
- 영어 교정의 제목은 `더 자연스러운 영어 표현`이다.
- 한국어 입력 안내의 제목은 `이럴 때 쓰는 영어 표현`이다.
- `배울 표현`은 문서에서 두 안내를 함께 부르는 이름이며 카드 제목으로 쓰지 않는다.
- 기존 [모바일 대화 중 교정](../../decisions/mobile-episode-correction.md),
  [모바일 AI에게 물어보기](../../decisions/mobile-ask-ai.md),
  [AI 에피소드 프로토콜](../../decisions/ai-episode-protocol.md)을 함께 따른다.

## 메시지 입력 안내

에피소드의 빈 메시지 입력창에는 `영어나 한국어로 적어 주세요.`를 보여 준다.
두 언어로 입력할 수 있음을 알리고, 텍스트 입력에 맞게 `말해 보세요` 대신
`적어 주세요`를 쓴다.

## 표현을 확인하는 동안

메시지를 보내면 그 메시지 아래에 작은 로딩 표시와 `표현을 확인하고 있어요.`를
곧바로 보여 준다. 이 영역은 자동 작업의 일반적인 1초 대기 규칙을 적용하지 않는다.

캐릭터 답변이 끝나면 표현 확인이 진행 중이어도 다음 메시지를 보낼 수 있다.
교정이 나중에 도착하거나 여러 결과의 도착 순서가 달라져도 각각 원래 메시지에 붙는다.
수정이나 다시 받기로 사라진 메시지에는 늦은 결과가 다시 나타나지 않는다.

결과를 받으면 같은 메시지의 확인 중 표시를 결과로 바꾼다. 교정, 영어 표현 안내,
문제없음과 실패를 한 메시지에 동시에 표시하지 않는다.

## 결과별 내용

| 결과 | 사용자에게 보여 주는 내용 |
| --- | --- |
| 영어 교정 | 고친 영어 문장. 펼치면 `더 자연스러운 영어 표현`, 원문, 고친 문장과 이유를 보여 준다. |
| 한국어 입력의 영어 안내 | 같은 뜻의 영어 문장. 펼치면 `이럴 때 쓰는 영어 표현`, 원문, 영어 문장과 핵심 표현의 뜻을 보여 준다. |
| 문제없음 | 체크 아이콘과 `자연스러운 표현이에요.`를 작은 한 줄로 보여 준다. |
| 확인 실패 | 다른 상태와 다른 색의 `표현을 확인하지 못했어요.`와 바로 뒤의 작은 새로고침 아이콘을 보여 준다. |

### 영어 교정

- 문법, 낱말 선택, 오타, 대소문자와 문장부호를 모두 확인한다.
- 같은 실수를 앞서 알려 줬거나 같은 규칙을 올바르게 쓴 적이 있어도, 다시 나타난
  실수는 해당 메시지에서 교정한다. 학습자가 이미 아는지 추측해서 교정을 숨기지 않는다.
- 원문의 뜻과 올바른 표현은 유지하고 필요한 부분만 고친다. 이미 자연스러운 문장을
  취향 차이만으로 다시 쓰지 않는다.
- 문제가 없다고 판정한 영어 문장에만 문제없음 안내를 보여 준다. 빈 결과, 확인 실패,
  판정하지 않은 메시지를 문제없음으로 바꾸지 않는다.

### 한국어 입력의 영어 안내

- 원문의 뜻과 대화 상황에 맞는 자연스러운 영어 문장 하나를 제안한다.
- 설명은 선택한 B안처럼 핵심 영어 표현과 한국어 뜻을 짧게 연결한다.
  예를 들어 `오늘은 일찍 집에 가고 싶어.`에 영어 문장을 제안하고,
  `‘집에 가다’는 head home이라고 해요.`처럼 설명한다. 예문의 영어 문장 자체는
  고정 답안이 아니며 같은 뜻을 자연스럽게 전달하면 된다.
- 한국어 입력을 틀린 영어로 취급하지 않는다. 원문과 영어 문장의 대응하는 부분을
  짚는 방식은 기존 카드의 표시를 사용한다.
- 한국어라는 이유로 안내를 생략하거나 `자연스러운 표현이에요.`를 보여 주지 않는다.
- 한국어 입력 안내는 교정의 보라색과 다른 색으로 표시한다. 색 외의 배치나
  접기·펼치기 방식은 별도로 만들지 않는다.

## 카드와 AI에게 물어보기

- 기본 상태는 접힘이다. 영어 문장을 누르면 같은 자리에서 카드로 펼쳐지고,
  접으면 다시 영어 문장만 남는다. 펼친 카드와 접힌 문장을 중복해서 보여 주지 않는다.
- 표현이 여러 개면 기존처럼 항목을 나누되 문장 전체를 불필요하게 반복하지 않는다.
  제목 뒤의 항목 수 표시도 기존 규칙을 따른다.
- 카드 아래에는 `AI에게 물어보기`만 남기고 버튼을 더 크게 만든다.
  기존의 배경색과 테두리, 굵은 글씨를 유지하고 가로 폭과 높이만 키운다.
  HeroUI Native를 감싼 프로젝트 공통 `Button`을 사용한다.
- `다시 보내기`, 고친 문장을 본 채팅 입력창에 넣는 동작과
  `고쳐서 다시 보냈어요` 표시를 제거한다.
- AI에게 물어보기 대화창의 높이와 기존 열기·닫기 동작은 유지한다. 출처에는 원문과
  영어 문장, 해당 카드의 제목을 보여 준다. 돌아오면 카드는 그대로 펼쳐져 있다.
- 교정과 영어 안내는 기존 배울 표현의 저장 수명을 따른다. 다시 들어오면 저장된
  결과가 같은 메시지에 복원된다. 저장된 결과가 없는 과거 메시지를 문제없음으로
  간주하거나 일괄 재분석하지 않는다.

## 실패와 재시도

- 확인 요청이 실패하거나 시간 초과로 끝나면 확인 중 표시를 실패 표시로 바꾼다.
- 새로고침 아이콘의 접근성 이름은 `표현 다시 확인`이다. 별도의 글자 버튼은 두지 않는다.
- 아이콘을 누르면 그 메시지의 표현만 다시 확인한다. 사용자 메시지나 캐릭터 답변을
  새로 만들지 않고 이야기 진행도 바꾸지 않는다.
- 재시도 중에는 `표현을 확인하고 있어요.`와 같은 아이콘 자리의 로딩 표시를
  보여 준다. 중복 요청을 막고 접근성 상태에도 진행 중임을 알린다.
- 재시도 결과는 해당 메시지의 이전 실패 표시를 대신한다. 다시 실패하면 같은 자리에서
  다시 시도할 수 있다. 실패 여부는 다른 메시지의 결과에 영향을 주지 않는다.

## 바꿀 수 있는 기본값

다음은 사용자에게 추가 선택을 요구하지 않은 구현 기본값이다. 기존 동작을 잇거나
쉽게 바꿀 수 있는 표시·입력 처리이므로, 실제 구현에서 문제가 확인되면 조정한다.

- AI에게 물어보기 버튼은 카드의 가로 폭 전체를 쓰고 높이는 48 이상으로 잡는다.
  새로고침 아이콘은 약 14 크기로 보이되 누를 수 있는 영역은 44×44 이상을 확보한다.
- 한영이 섞여 한 뜻을 전달하면 한국어 입력 안내처럼 전체 뜻을 자연스러운 영어로
  표현한다. 원문에 이미 자연스러운 영어가 있으면 가능한 한 유지한다.
- 대화 문맥으로도 뜻을 알 수 없는 입력에는 뜻을 만들어 붙이지 않는다.
  `표현의 뜻을 파악하기 어려워요.`를 중립적인 한 줄로 안내한다. 이 결과를
  문제없음이나 통신 실패로 표시하지 않는다.
- 한국어 안내는 검토한 청록색, 실패는 붉은 계열을 기본값으로 삼는다. 정확한 색상값은
  확정한 제품 결정이 아니며 라이트·다크 화면에서 기존 보라와의 구분과 글자 대비를
  확인해 정한다. 색상은 기존 프로젝트 색상 관리 규칙을 따른다.
- 확인 중과 실패처럼 안내 상태는 현재 대화 화면에서 메시지별로 유지한다.
  과거 상태의 장기 보관이나 복원 규칙을 새로 만들지는 않는다.

## 완료 조건

1. 메시지를 보내면 결과가 오기 전에도 해당 메시지에 확인 중 표시가 보인다.
2. 캐릭터 답변만 끝난 상태에서 다음 메시지를 보낼 수 있고, 늦은 결과는 원래
   메시지에 붙는다. 지워진 메시지의 결과는 나타나지 않는다.
3. 같은 실수를 두 번 보내면 두 메시지에 각각 교정이 붙는다. 오타·대소문자·문장부호
   오류만 있는 문장도 확인 범위에서 빠지지 않는다.
4. 실제로 문제가 없는 영어 문장에는 문제없음 안내만 보인다. 교정, 제안이나 실패와
   문제없음 안내가 겹치지 않는다.
5. 한국어 메시지에는 뜻이 같은 영어 문장과 B안의 설명이 보이며, 두 종류의 카드가
   확정한 제목을 사용한다. 제목이 길어져도 접기 버튼과 겹치거나 잘리지 않는다.
6. 두 카드 모두 같은 방식으로 접고 펼칠 수 있다. 저장된 교정과 영어 안내를 다시
   열어도 원문, 영어 문장, 설명과 안내 종류가 유지된다.
7. 확인 실패 후 새로고침을 누르면 로딩이 보이고 중복 요청이 발생하지 않는다.
   재시도 전후에 본 채팅의 메시지와 캐릭터 답변이 추가되거나 바뀌지 않는다.
8. 다시 보내기와 전송 완료 표시는 보이지 않는다. 커진 AI에게 물어보기 버튼으로
   기존 높이의 대화창을 열고 닫을 수 있다.
9. 라이트·다크 모드, 작은 화면과 글자 확대에서 제목과 본문을 읽을 수 있고,
   접근성 이름과 진행 중 상태가 보이는 내용과 맞는다.
10. 에피소드의 빈 메시지 입력창에는 `영어나 한국어로 적어 주세요.`가 보인다.

## 미룬 사항과 남은 위험

- 모델 판정 호출을 짧은 영어, 반복 실수, 긴 대화와 한국어 입력에서 각각 한 번씩
  측정했다. 변경 전은 약 3.8–6.9초, 변경 후는 약 3.6–5.5초였다. 소수 호출의
  참고값이며 앱 전송부터 표시까지의 전체 시간이나 일반적인 속도 개선율을 뜻하지
  않는다. 판정은 30초, 앱의 확인 대기는 35초로 제한한다. 특정 응답 시간을 약속하지 않는다.
- 라이트 모드의 보라 글자를 조금 어둡게 바꿔 배경 대비를 약 4.69:1로 보완했다.
  iPhone에서 라이트·다크 화면과 글자 확대를 확인했다. 다른 화면 크기와 Android의
  실제 배치는 이번 기기 검증에 포함하지 않았다.
- 한국어 표현을 영어로 옮길 때 뉘앙스를 바꾸거나, 표기 교정을 불필요하게 많이
  보여 줄 수 있다. 대표 입력으로 뜻 보존과 반복 교정의 일관성을 확인해야 한다.
- 새 제목이 기존보다 길어졌으므로 항목 수와 접기 버튼을 함께 표시할 때 공간을 확인한다.

## 이번 범위에서 바꾸지 않는 것

끝난 화의 복습, 오늘 배운 표현 보관함, 표현별 점수나 통계, 다른 언어 지원,
AI에게 물어보기 대화의 장기 저장, 템플릿 채팅과 에피소드 이야기 규칙은 바꾸지 않는다.
이번 작업은 메시지 옆에서 영어 표현을 확인하고 이해하는 경험에 집중한다.

`PRODUCT.md`에는 다시 보내기와 이미 아는 실수의 생략이 남아 있다. 이번 논의에서
사용자가 확인한 제거·반복 교정 요구는 이 명세와 결정 계약에 반영했다.
`PRODUCT.md` 자체는 수정하지 않았으며 구현할 때 이 차이를 놓치지 않아야 한다.
