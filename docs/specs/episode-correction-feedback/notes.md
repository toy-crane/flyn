# 대화 중 교정 개선 논의

## 확정한 변경

- 사용자는 2026-09-07에 고쳐서 다시 보내기가 필요하지 않다고 확인했다.
- 교정 카드에는 AI에게 물어보기만 남긴다. 다시 보내기 버튼, 고친 문장을 본 채팅
  입력창에 넣는 동작과 다시 보냈다는 표시를 제거한다.
- 사용자는 AI에게 물어보기 대화창의 현재 높이를 유지하기로 확인했다.
  크기 변경은 교정 카드의 버튼에만 적용한다.
- 현재 결정 계약에 이 방향을 반영했다. 제품 코드는 아직 바꾸지 않았다.
- 문장에 문제가 없으면 사용자에게 그 사실을 알린다. 작업 완료만 말하는
  `확인했어요`는 이 요구를 전달하지 못하므로 사용하지 않는다.
- 사용자는 2026-09-07에 1번 안을 선택했다. 사용자 말풍선 아래에 작은 한 줄로
  상태를 표시한다. 문제없음은 체크 아이콘과 `자연스러운 표현이에요.`로 알린다.
- 사용자는 메시지를 보내면 바로 `표현을 확인하고 있어요.`를 보여 주고,
  교정이 늦어도 다음 대화를 계속할 수 있게 하는 방향을 확인했다.
  캐릭터 답변이 끝나면 교정 완료를 기다리지 않고 다음 메시지를 보낼 수 있다.
  교정은 늦게 도착해도 원래 메시지에 붙는다. 실제 속도는 측정한 뒤 개선 방법을
  정하며, 현재 논의에서는 대기 시간 수치를 약속하지 않는다.
- 반복된 실수도 해당 메시지마다 교정한다. 앞서 같은 규칙을 알려 줬다는 이유로
  교정을 생략하지 않는다. 같은 표현의 판정이 달라 보이는 문제를 없애기 위한 변경이다.
- 사용자는 교정 범위의 1번 안을 선택했다. 문법, 낱말 선택, 오타, 대소문자,
  문장부호를 모두 교정한다. 이미 자연스러운 문장을 취향 차이로 바꾸지는 않는다.
- 한국어로 쓴 메시지에는 같은 뜻을 영어로 어떻게 표현하는지 짧은 설명과 함께
  알려 준다. 한국어 입력을 교정 대상이 없다는 안내로 끝내지 않는다.
- 에피소드 입력창의 placeholder는 `영어나 한국어로 적어 주세요.`로 확정했다.
  두 언어를 모두 입력할 수 있음을 알리고, 텍스트 입력에 맞는 동사를 쓴다.
- 한국어 입력의 안내는 기존 교정과 같은 모양과 접기·펼치기 동작을 유지한다.
  시각적인 구분은 색상으로 한다. 사용자가 요청한 세 가지 안은 표시 방식이 아니라
  안에 들어갈 내용과 설명 문구에 대한 안이다.
- 사용자는 B안(2번, 핵심 표현 설명)을 선택했다. 한국어 원문과 같은 뜻의 영어
  문장을 보여 주고, 핵심 영어 표현과 한국어 뜻을 짧게 연결해 설명한다.
  예: `‘집에 가다’는 head home이라고 해요.`
- 카드 제목은 영어 교정이 `더 자연스러운 영어 표현`, 한국어 입력의 영어 안내가
  `이럴 때 쓰는 영어 표현`으로 확정했다. 두 제목의 형태를 맞추면서 각각의 쓰임을
  알린다. 카드 제목에 `배울 표현`을 쓰지 않는다.
- 한 메시지에 교정과 문제없음 표시를 함께 보여 주지 않는다.
- 교정 확인 실패는 다른 상태와 다른 색의 `표현을 확인하지 못했어요.`로 알린다.
  문구 바로 뒤에 작은 새로고침 아이콘 버튼을 둔다. 이 버튼은 그 메시지의 교정만
  다시 확인한다. 사용자 메시지를 다시 보내거나 캐릭터 답변을 새로 만들지 않는다.
- 재시도 중에는 같은 아이콘 자리에 로딩 표시를 두고 중복 요청을 막는다.
  미리보기의 기본값은 아이콘 14px, 누를 수 있는 영역 44×44px, 접근성 이름
  `표현 다시 확인`이다. 화면에는 별도의 `다시 확인` 글자 버튼을 두지 않는다.

## 해결할 문제

- 교정이 늦게 나타나고 준비 중이라는 표시가 없어, 사용자가 교정이 나올지 알 수 없다.
- 현재 화면에서는 교정 없음, 확인 중, 확인 실패를 구분할 수 없다.
- 사용자는 AI에게 물어보기 버튼이 더 크게 보이도록 요청했다.
- 교정의 실제 대기 시간은 아직 측정하지 않았다. 상태 표시 모양은 정했지만
  속도 개선 방법은 아직 정하지 않았다.
- 현재 코드는 이미 알려 준 규칙, 오타와 한국어 입력 등을 교정에서 제외한다.
  확정한 요구에 맞게 반복 실수와 표기 오류를 포함하고, 한국어에는 영어 표현을
  안내해야 한다. 빈 교정 목록만으로 문장에 문제가 없다고 표시하면 안 된다.
- 앞선 세 가지 UI 제안에서 교정 있음 상태에 문제없음 문구가 함께 나타났다.
  미리보기의 상태별 표시 조건 오류이며 제품 요구가 아니다.

## 제품 전제와의 차이

`PRODUCT.md`의 Core loop와 Capabilities and boundaries에는 고쳐서 다시 보내는
흐름이 남아 있다. 사용자는 이번 논의에서 그 기능을 제거하기로 확인했다. 이 문서는
그 변경을 기록하며 `PRODUCT.md`를 수정하지 않는다. 구현 인계 때 이 차이를 명시한다.
같은 패턴의 반복을 하나로 묶는다는 기존 문구는 메시지별 교정을 생략하는 근거로
사용하지 않는다. 표현 보관함에서 묶어 보여 주는 방식은 이번 단위의 범위가 아니다.

## 구현 때 확인할 내용

- 보라색과 청록색을 나란히 보여 주고 라이트 모드도 확인할 수 있게 제시했다.
  다른 색으로 구분하는 요구는 확정됐으며 청록색의 정확한 값은 구현 명세의
  바꿀 수 있는 기본값으로 남긴다.
- 한국어와 영어가 섞인 입력, 문맥으로도 뜻을 알 수 없는 입력의 처리 방식은
  구현 명세의 가정으로 명시한다. 별도 언어 모드나 사용자 설정은 추가하지 않는다.
- 실패 상태는 붉은 계열로 제안한다. 실제 색 토큰은 구현할 때 기존 색상 규칙에
  맞춰 정한다.
- 색상 비교 중 기존 라이트 모드 `learn` 글자와 `learn-surface` 배경의 대비를
  색상값으로 계산한 결과 약 4.4926:1이었다. 실제 화면에서 작은 글씨의 대비를
  다시 확인하고 필요하면 보완한다. 청록 후보의 같은 계산값은 라이트 약 4.80:1,
  다크 약 8.29:1이다. 브라우저에서 실제 색을 렌더링한 검증은 하지 못했다.

## 바꿀 수 있는 가정과 제안

- AI에게 물어보기 버튼은 교정 카드의 가로 폭 전체를 쓰는 것으로 가정한다.
  열린 대화창 높이는 사용자가 확인한 대로 유지한다.
- 기존처럼 접으면 영어 문장이 보이고,
  펼치면 확정한 카드 제목, 원문, 영어 문장, 설명, AI에게 물어보기 버튼이 보인다.
  색을 비교하는 미리보기에서는 모두 펼쳐 놓는다. 앱의 기본 상태는 접힘이다.
- 미리보기의 한국어 안내 색은 청록색을 임시로 사용한다. 실제 색상은 아직
  확정하지 않았다. 기존 보라색은 전역 CSS의 실제 값을 사용해 함께 비교한다.

이 문서는 논의 기록이다. 구현할 제품 동작과 바꿀 수 있는 기본값, 미룬 사항은
[구현 명세](spec.md)에 정리했다. 이 논의 시점에는 제품 코드를 바꾸지 않았다.

## 구현 검증 · 2026-09-07

- 장면 응답과 표현 확인 요청을 나눴다. 전송 직후 메시지 아래에 확인 중 표시가
  나오며 장면이 끝나면 교정을 기다리지 않고 다음 말을 보낼 수 있다.
- 서버는 저장된 사용자 메시지와 그 앞의 문맥을 읽고, 교정·문제없음·뜻을 알 수
  없음 결과를 구분한다. 반복 실수도 매번 확인한다. 저장된 교정은 같은 메시지의
  재요청에서 그대로 반환한다. 이전 다시 받기 중복 교정 후속 항목은 해결되어 삭제했다.
- 실제 모델로 자연스러운 문장, 오타·대소문자·문장부호 오류, 반복 실수, 한국어,
  한영 혼합과 뜻을 알 수 없는 입력을 확인했다. 한국어 설명에 문법 규칙이 섞인
  사례를 확인해 핵심 영어 표현과 한국어 뜻만 연결하도록 보완했다.
- 전체 `bun run check`, `bun run check-types`, `bun run test`가 통과했다.
  API 99개, 모바일 75개 묶음의 534개, 개발 도구 176개 테스트가 통과했다.
  새 화면 통합 테스트는 실제 AI SDK 채팅 전송을 지나며 즉시 로딩, 장면과 교정의
  독립적인 완료, 재시도, 중복 차단, 역순 도착, 삭제된 메시지와 시간 초과 뒤의
  늦은 결과 무시를 확인한다. 데이터베이스 구조는 바꾸지 않았다.
- 실제 기기는 `kim의 iPhone`(iPhone 14, 가로 390pt)이다. 이 worktree의 API 3941,
  Metro 8122를 연결했다. 앱의 이메일 코드 로그인으로 만든 별도 로컬 계정에서
  영어·한국어 전송, 교정 접기·펼치기, 커진 AI에게 물어보기 버튼, 기존 시트의
  질문·닫기, 두 종류의 저장 후 복원, 자연스러운 표현 안내를 확인했다.
- 로컬 표현 판정에만 일시적인 오류를 넣어 실패 문구와 바로 뒤 새로고침을 확인했다.
  오류를 제거한 뒤 재시도 로딩, 비활성 버튼, 같은 메시지의 교정 복구를 확인했다.
