# 컴포넌트 선택 규칙에 맞춰 시안 없이 되돌릴 수 있는 것을 정리한다

## 배경

2026-09-13 디자인 시스템 감사에서 HeroUI Native를 근거 없이 우회한 자리 12곳과
실제 결함 3건이 나왔다. 사용자가 [모바일 컴포넌트 선택](../../decisions/mobile-component-selection.md)
규칙을 확정했다. 이 스펙은 그 규칙 가운데 시안 비교 없이 바로 옮길 수 있는
것만 다룬다. 카드와 목록 행은 HeroUI `Card`, `ListGroup`, `Accordion`으로 그린
시안을 비교한 뒤 별도 스펙으로 옮기고, 텍스트 역할 이전은 타이포그래피 값이
정해진 뒤 별도 스펙으로 한다.

## 사용자에게 보이는 결과

- 다크 모드에서 메시지 메뉴와 인증 코드 칸의 표면 색이 카드와 같아진다.
- 인증 코드 칸이 HeroUI 기본 크기(44×48pt)로 왼쪽에 모이고, 틀렸을 때의 빨간
  테두리가 HeroUI의 무효 상태 외곽선으로 바뀐다.
- 인증 화면의 오류 문구가 입력 칸에 붙은 필드 오류로 보인다.
- 채팅의 재시도 칩, 프로필 편집 알약, 교정 카드의 접기 버튼이 HeroUI 컴포넌트의
  눌림 반응을 갖는다. 크기와 자리는 지금과 같다.
- 공용 버튼의 가로 여백이 HeroUI 기본값으로 돌아간다. 하단 행동 버튼처럼 너비를
  부모가 정하는 자리는 달라지지 않는다.
- 그 밖의 화면 모양과 동작은 달라지지 않는다.

## 범위

- 결함 3건을 고친다. 다크 모드 `overlay`와 `field-background`를 `surface`와
  같은 값으로 전역 CSS에 등재한다. 소비자가 없는 HeroUI 토스트 설정과 반대
  방향을 설명하는 주석을 지운다. 인증 코드 화면이 무효 상태를 HeroUI
  `isInvalid`로 넘기고 직접 그린 테두리와 칸 폭 조정을 없애 HeroUI 기본 칸을 쓴다.
- 인증 오류 문구를 `TextField` 안의 HeroUI `FieldError`로 옮긴다. 접근성
  알림 역할은 유지한다.
- 채팅의 재시도 칩은 HeroUI `Chip`으로, 프로필 편집 알약은 공용 `Button`의
  작은 크기와 삼차 변형으로, 교정 카드의 접기 버튼은 HeroUI `CloseButton`으로
  바꾼다.
- 채팅의 보내기, 중지, 최신 메시지 버튼과 상태 줄의 재시도 아이콘을 공용 아이콘
  버튼 하나로 모은다. 44pt 원과 28pt 두 크기를 갖고 눌림 반응은 HeroUI
  `PressableFeedback`을 쓴다. 자체 비활성 표현(`opacity-40`)을 없애고 컴포넌트의
  비활성 상태를 쓴다.
- 공용 `Button`에서 `!important`로 HeroUI 크기 클래스를 덮는 여백과 높이
  재정의를 걷어낸다. 진행 중 상태에서 크기를 고정하는 처리는 남긴다.
- 로그인 버튼이 `useColorScheme` 대신 테마 브리지의 `useAppTheme`를 읽는다.

## 완료 기준

- 원시 `Pressable`이 남는 자리가 결정 계약의 예외 목록과, 시안을 기다리는
  카드·행 6곳뿐이다.
- 저장소에 `!important`로 HeroUI 클래스를 덮는 코드와 `opacity-40` 비활성
  표현이 없다.
- iOS 시뮬레이터의 다크 모드에서 메시지 메뉴, 인증 코드 칸, 카드의 표면 색이
  같다. 밝은 모드에서도 이음새가 없다.
- 인증 코드를 틀렸을 때 칸의 무효 표시가 보이고, 이메일과 닉네임과 아이디
  화면의 오류 문구가 입력 아래에 보인다.
- 기본 글자 크기와 최대 글자 크기로 앱을 완전히 닫고 다시 시작해 로그인,
  대화, 프로필 편집 화면의 버튼과 칩이 잘리거나 겹치지 않는다.
- 기존 자동 테스트가 모두 통과하고, 공용 아이콘 버튼과 `FieldError` 이전에는
  접근성 역할과 이름을 확인하는 테스트가 있다.

## 제약과 근거

- 컴포넌트 선택과 예외 목록은 [모바일 컴포넌트 선택](../../decisions/mobile-component-selection.md)이
  소유한다. 이 스펙은 그 목록에 새 예외를 더하지 않는다.
- 색 등재 위치와 `overlay`, `field-background` 규칙은
  [모바일 색상 시맨틱](../../decisions/mobile-color-semantics.md)이 소유한다.
- 로그인 버튼의 브랜드 모양과 진행 표시는
  [모바일 작업 진행 표시](../../decisions/mobile-action-progress.md)가 소유한다.
  이 스펙은 색 읽는 경로만 바꾼다.
- 글자 크기 검증 절차는 [모바일 타이포그래피](../../decisions/mobile-typography.md)를
  따른다.

## 가정

- 공용 `Button`의 여백을 HeroUI 기본값으로 되돌려도 하단 행동 버튼과 인증
  버튼의 너비는 부모가 정하므로 보이는 차이가 없다. 차이가 보이면 그 화면을
  시안으로 비교하고 값이 필요하면 전역 CSS 한 곳에서 재정의한다.
- HeroUI `Chip`과 `CloseButton`이 지금 자리의 크기 안에 들어간다. 들어가지
  않으면 그 자리만 되돌리고 이유를 예외 목록에 적는다.

## 손대지 않는 것

- 표현 카드, 교정 카드, 회차 카드, 스토리 행, 회차 행, 추천 아이디 행.
  [카드와 행 이전 스펙](../heroui-cards-and-rows/spec.md)이 맡는다.
- RN `Text`의 클래스와 HeroUI `Typography` 이전.
  [텍스트 역할 이전 스펙](../heroui-typography-roles/spec.md)이 맡는다.
- `@expo/ui`가 소유하는 설정 화면.

## 남은 위험

- HeroUI `FieldError`의 기본 문구 스타일이 지금 인증 오류 문구와 조금 다를 수
  있다. 역할 층이 정해지면 같이 맞춘다.
