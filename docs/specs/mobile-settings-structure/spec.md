# 모바일 설정 구조 명세

## 목표

- 사용자가 현재 탭에서 설정으로 자연스럽게 이동하고, 뒤로 가기로 같은 자리로
  돌아오게 한다.
- 설정 항목을 성격에 따라 묶어 필요한 항목과 위험한 동작을 빠르게 구분하게 한다.
- 여러 값 중 하나를 고르는 설정은 모든 선택지와 현재 값을 한 화면에서 확인하게
  한다.
- 행 오른쪽의 표시만 보고도 다음 화면 이동, 외부 이동, 즉시 실행과 현재 값을
  구분하게 한다.
- 계정 삭제는 찾을 수 있으면서도 실수로 실행하지 않도록 마지막 확인을 유지한다.

## 사용자에게 보이는 결과

- 설정은 시트가 아니라 현재 탭 위에 밀려 들어오는 `설정` 화면으로 열린다.
  화면을 열면 탭 막대는 가려지고, 닫기 버튼 대신 뒤로 가기 쉐브론이 보인다.
- 설정에서 `프로필`, `화면 모드` 같은 하위 화면을 열면 같은 화면 흐름 위에
  이어진다.
- 설정 첫 화면은 프로필 머리말, `계정`, `환경 설정`, `앱 정보`, 계정 삭제 순서로
  보인다.
- `화면 모드` 행은 현재 값을 보여 주고, 전용 화면에서 `라이트`, `다크`,
  `시스템 설정` 중 하나를 고르게 한다.
- `다크`를 고르면 운영체제가 라이트여도 설정, 선택 화면, 헤더, 상태 표시줄과
  로그인 화면까지 다크로 보인다. 앱을 다시 열면 첫 화면부터 저장된 모드로 그린다.
- 계정 삭제만 빨간 글자로 표시된다. 로그아웃은 일반 계정 동작으로 보인다.

## 확정 범위

설정 계층의 구조와 표현은 `toy-crane/dearly@0438e47`의
`docs/decisions/mobile-ui-foundation.md`가 정한 기준을 그대로 따른다. 볼 파일은
[Expo 참조 저장소 색인](../../references/expo-reference-repos.md)의 dearly
항목에 있다. 이 앱이 dearly와 다르게 두는 것은 [제외](#제외)에 적었다.

### 설정을 여는 방식

- 홈에서 설정을 열면 루트 Stack이 NativeTabs 위에 `설정`을 push한다. 설정
  화면에서는 탭 막대를 보여 주지 않는다.
- `설정`, `프로필`, `화면 모드`는 루트 Stack에 나란히 등록한 화면이다. 설정 전용
  중첩 Stack을 두지 않는다. 그래서 설정 첫 화면부터 루트 Stack의 네이티브 뒤로
  가기 버튼이 생기고, 앱이 툴바로 쉐브론을 그리지 않는다. 지금의
  `app/settings/_layout.tsx`와 시트 옵션 헬퍼는 지운다.
- 설정 첫 화면은 운영체제의 헤더와 `설정` 제목을 사용한다. 오른쪽 닫기 버튼은
  두지 않는다.
- 뒤로 가기는 쉐브론만 보여 주고 이전 화면 이름을 붙이지 않는다. iOS 가장자리
  스와이프와 Android 뒤로 가기 제스처·버튼도 같은 탭으로 돌아간다.
- `프로필`과 `화면 모드`는 설정 위에 이어지는 일반 하위 화면이다. 각 화면에서
  뒤로 가면 설정의 같은 스크롤 흐름으로 돌아온다.
- 세 화면은 헤더 옵션 헬퍼 하나를 공유하고, 헤더 규칙은 대화 화면과 같다. iOS는
  `headerTransparent`와 `scrollEdgeEffects: { top: "soft" }`로 투명 헤더를 두고
  앱이 헤더에 재질이나 배경색을 얹지 않는다. Android는 `background` 색의 Material
  App Bar다. Android 화면은 헤더 높이만큼 위쪽 여백을 더하지 않고, 화면 배경은
  Stack의 `contentStyle`이 칠한다.
- 홈의 설정 진입 컨트롤 접근성 이름은 `설정 열기`다. 시트를 언급하는 힌트와 닫기
  라벨은 지운다.

### 설정 첫 화면의 그룹

- 화면 위에는 현재 프로필 사진, 닉네임과 아이디를 가운데 정렬해 보여 준다. 프로필
  사진과 `프로필` 행은 모두 같은 `프로필` 화면을 연다.
- `계정` 섹션은 `프로필`, `로그아웃` 순서다.
- `환경 설정` 섹션은 `알림`, `햅틱 반응`, `화면 모드` 순서다.
- `앱 정보` 섹션은 `버전`을 보여 준다.
- `계정 삭제`는 제목 없는 단독 섹션으로 화면 맨 아래에 둔다.
- 각 설정 항목은 한 개의 행과 한 개의 누르기 영역만 가진다. 섹션 제목이나 행
  안쪽 일부에 별도 동작을 겹쳐 두지 않는다.

### 여러 값 중 하나 선택

- `화면 모드` 행에는 현재 선택한 `라이트`, `다크`, `시스템 설정` 중 하나를
  값으로 보여 준다.
- 행을 누르면 제목이 `화면 모드`인 전용 화면을 연다. 메뉴, 드롭다운, 같은 화면의
  임시 패널이나 단일 선택 대화상자로 대신하지 않는다.
- 선택 화면은 제목 없는 단독 섹션 하나에 세 값을 항상 모두 보여 주고 현재 값
  하나에만 선택 표시를 둔다. iOS는 `accent` 색의 `checkmark` 심벌을, Android는
  `RadioButton`을 행 오른쪽에 둔다. 두 플랫폼이 같은 화면이며 Android에서 Material
  단일 선택 다이얼로그로 갈라지지 않는다.
- 선택 상태는 화면 읽기 기능에도 같은 뜻으로 전달한다. iOS 행은 접근성 요소를
  하나로 합치고(`accessibilityElement("combine")`) 라벨, `선택됨`·`선택 안 됨`
  값과 선택된 행의 `isSelected` trait를 준다. Android 행은
  `selectable(selected, onPress, "radioButton")` modifier를 건다.
- 값을 고르면 즉시 앱 전체에 적용한다. 선택 화면은 자동으로 닫히지 않고 새 화면
  모드로 계속 보인다.
- 설정으로 돌아오면 행의 값이 새 선택으로 바뀌어 있다.
- 선택한 값은 이 기기에서 앱을 다시 열어도 유지한다. 저장된 값이 없는 기존 설치와
  새 설치는 `시스템 설정`으로 시작한다.
- `시스템 설정`을 고른 동안에는 앱을 다시 열지 않아도 운영체제 화면 모드 변경을
  따른다.
- `라이트`, `다크`, `시스템 설정` 라벨과 현재 값 라벨을 만드는 함수는 한 곳에 둔다.
  설정 행의 값과 선택 화면의 행이 같은 상수를 읽는다.

### 화면 모드의 원본과 저장

- 화면 모드 선택값과 그것을 바꾸는 함수는 테마 브리지가 소유하고 `useAppTheme`로
  내보낸다. 화면과 컴포넌트는 브리지에서 받은 값을 쓰고 React Native의
  `useColorScheme`를 직접 읽지 않는다. 지금 운영체제 모드를 직접 읽는 로그인
  버튼도 브리지 값을 따르게 고친다.
- 적용은 Uniwind의 `setTheme`로 한다. `시스템 설정`은 Uniwind의 system 값을 넘겨
  운영체제 변경 추종을 Uniwind에 맡긴다.
- 저장은 세션 저장에 이미 쓰는 이 기기의 `expo-sqlite/kv-store`다. 앱 시작 시
  동기로 읽어 첫 프레임부터 저장된 모드로 그린다. 읽은 값이 세 값 중 하나가
  아니거나 읽을 수 없으면 `시스템 설정`으로 본다.
- 상태 표시줄은 브리지가 계산한 실제 스킴을 따른다. `다크`를 고르면 운영체제가
  라이트여도 밝은 글자로 보이고, `시스템 설정`이면 운영체제를 따른다.
- 설정 계층의 `@expo/ui` `Host`는 선택한 모드를 `colorScheme`으로 받는다.
  `시스템 설정`이면 넘기지 않는다. 이것이 없으면 Uniwind 변수가 `Host` 안에
  전파되지 않아 설정 화면 자체가 운영체제 모드에 남는다.

### 설정 표면의 배경

- iOS 설정 폼은 시스템 grouped 배경을 감추고(`scrollContentBackground("hidden")`)
  페이지는 `background`, 그룹 안쪽 행은 `surface`를 쓴다. 행 배경은 행 단위
  modifier(`listRowBackground`)라 `Form`이 아니라 각 `FieldGroup.Section`에 건다.
  `Host`와 `FieldGroup`의 배경도 `background`다.
- Android는 Material 행 표면이 배경을 이미 소유하므로 이 modifier를 주지 않는다.
- 이유: 시스템 grouped 배경(라이트 `#F2F2F7`, 다크 순수 검정)이 `background`
  토큰(`#F4F4F6`, `#0B0B0D`)과 달라 push 전환과 투명 헤더 아래에서 이음새가
  보인다. 팔레트 값은 바꾸지 않는다.

### 행 오른쪽 표시

- 앱 안의 하위 화면을 여는 행은 iOS에서 쉐브론을 보여 준다. Android는 Material
  설정 표현을 유지하고 iOS 쉐브론을 복사하지 않는다.
- 현재 값도 보여 주는 이동 행은 값과 이동 표시를 함께 전달한다. `화면 모드`는
  iOS에서 현재 값 뒤에 쉐브론을 두고, Android에서는 현재 값만 보여 준다.
- 앱 밖의 주소나 다른 앱을 여는 행이 생기면 외부 이동 글리프를 보여 준다. 글리프는
  iOS `arrow.up.right`, Android `open_in_new`다.
- 로그아웃처럼 즉시 작업을 실행하는 행과 계정 삭제처럼 확인창을 여는 행에는
  쉐브론이나 외부 이동 글리프를 두지 않는다.
- iOS의 쉐브론과 글리프 아이콘은 접근성 트리에서 숨긴다. 행의 이름이 이미 뜻을
  전달한다.
- 스위치는 행 오른쪽의 스위치 자체가 상태와 동작을 나타낸다.
- 버전처럼 누를 수 없는 정보 행은 오른쪽에 값만 보여 준다.
- 작업 중 진행 표시는 해당 행의 오른쪽에 잠시 나타날 수 있다. 진행 중에도 행의
  이름과 자리는 바꾸지 않는다.

### 파괴적 동작

- `로그아웃`은 `계정` 섹션의 일반 글자색 행이다. 아이콘, 쉐브론과 채운 배경을
  두지 않는다. 누르면 현재 기기에서 로그아웃한다.
- 로그아웃이 진행되는 동안 같은 요청을 다시 시작할 수 없다. 행의 이름은 유지하고
  오른쪽에 진행 상태를 보여 준다. 실패하면 현재 화면에서 다시 시도할 수 있다.
- `계정 삭제`는 화면 맨 아래 제목 없는 단독 섹션에 둔다. 글자만 시스템의 위험
  색으로 표시하고 아이콘, 쉐브론과 채운 배경을 두지 않는다.
- 계정 삭제 행 아래에는 상시 설명을 두지 않는다. 위치, 여백과 글자색이 평소 경고를
  맡는다.
- 계정 삭제를 누르면 다른 화면으로 이동하지 않고 플랫폼 확인창을 연다. 확인창은
  삭제가 되돌릴 수 없고 다시 가입해도 이전 정보가 돌아오지 않는다는 점을 알린다.
- 확인 뒤 삭제가 진행되는 동안 문구는 `계정 삭제`로 유지하고 오른쪽에 진행 상태를
  보여 준다. 같은 요청을 다시 시작할 수 없다.
- 삭제에 실패하면 로그인 상태와 현재 화면을 유지하고 같은 단독 섹션에서 다시
  시도할 수 있게 한다. 실패 문구는 계정 삭제 섹션의 푸터에 보여 준다. 삭제가
  끝나면 로그인 화면으로 이동한다.
- 파괴적 동작을 내비게이션 바에 두지 않는다. 마찰은 확인창이 맡는다.
- `프로필` 화면에서는 계정 삭제를 제거한다. 그 화면은 프로필 사진, 닉네임과
  아이디 편집만 맡는다. 프로필 화면의 삭제 안내 문구 상수도 함께 지운다.

## 수용 기준

- 홈에서 설정을 열면 시트가 아니라 전체 화면으로 열리고 탭 막대가
  가려진다. 홈의 설정 진입 컨트롤은 `설정 열기`로 읽힌다.
- `설정`, `프로필`, `화면 모드`가 루트 Stack의 화면이고 설정 전용 중첩 Stack이
  없다. 설정 첫 화면에 닫기 버튼이 없고, 네이티브 뒤로 가기 쉐브론과 시스템 뒤로
  가기로 원래 탭의 같은 자리로 돌아간다.
- iOS 설정 계층의 헤더는 투명하고 스크롤하면 콘텐츠가 헤더 아래로 흐른다.
  Android는 `background` 색의 App Bar 아래에서 화면이 겹침 없이 시작한다.
- iOS 설정 화면의 페이지 배경이 `background`, 그룹 안쪽 행이 `surface`다. 라이트와
  다크 모두 push 전환에서 시스템 grouped 배경과의 이음새가 보이지 않는다.
- iOS와 Android에서 프로필 머리말, `계정`, `환경 설정`, `앱 정보`, 제목 없는 계정
  삭제 섹션이 확정된 순서로 보인다.
- `계정`에는 `프로필`, `로그아웃`만 있고, `환경 설정`에는 `알림`, `햅틱 반응`,
  `화면 모드`만 있으며, `앱 정보`에는 `버전`이 있다.
- 프로필 사진과 `프로필` 행이 같은 화면을 연다.
- `화면 모드` 행이 현재 값을 보여 주고, 누르면 세 선택지가 모두 보이는 전용 화면을
  연다.
- 선택 화면 제목과 설정 행 이름이 모두 `화면 모드`다. 현재 값 하나에만 선택
  표시가 있고 화면 읽기 기능도 그 값을 선택됨으로 전달한다.
- 화면 모드를 고르면 선택 화면이 닫히지 않은 채 바로 새 모드로 바뀐다. 뒤로 가면
  설정 행의 값과 설정 화면도 같은 모드로 보인다.
- 운영체제가 라이트인 채로 `다크`를 고르면 설정 계층의 `@expo/ui` 표면, 헤더,
  탭 화면, 상태 표시줄과 로그아웃 뒤의 로그인 화면이 모두 다크로 보인다.
- `라이트`와 `다크`는 앱을 다시 열어도 유지되고, 다시 연 앱의 첫 프레임부터 저장된
  모드로 그린다. `시스템 설정`은 앱이 열린 동안의 운영체제 화면 모드 변경도 따른다.
- Android TalkBack이 선택 화면의 행을 라디오 버튼으로 읽고 현재 값을 선택됨으로
  전달한다. iOS VoiceOver는 행 하나를 라벨, 값, 선택됨 상태로 읽는다.
- iOS의 `프로필`과 `화면 모드` 이동 행에는 쉐브론이 있고 Android에는 같은
  쉐브론이 없다. `화면 모드`는 두 플랫폼 모두 현재 값을 보여 준다.
- 스위치 행은 스위치, 버전 행은 값, 로그아웃과 계정 삭제 행은 평소 아무 오른쪽
  표시도 사용하지 않는다.
- 설정에서 빨간 글자는 `계정 삭제` 하나뿐이다. 로그아웃은 일반 글자색이고 계정
  삭제는 화면 맨 아래에 단독으로 보인다.
- 계정 삭제 행 아래에는 상시 설명이 없고, 누른 뒤 확인창에서 되돌릴 수 없음을
  확인한다.
- `프로필` 화면에는 계정 삭제가 없다.
- 로그아웃과 계정 삭제의 진행, 실패와 중복 실행 차단이 기존 동작을 유지한다.
  삭제 실패 문구는 계정 삭제 섹션의 푸터에 보인다.
- iOS와 Android 개발 빌드에서 라이트, 다크, 큰 글자, VoiceOver 또는 TalkBack과
  시스템 뒤로 가기를 확인한다.
- 모바일의 자동 검사와 타입 검사가 통과한다. 설정 화면 테스트 중 "계정 삭제는
  설정 목록에 없다", "로그아웃이 마지막 단독 그룹이다"와 시트 옵션 테스트는 이
  명세의 구조로 고쳐 쓴다.

## 확정 제약과 이유

- 설정은 잠깐 열었다 닫는 독립 시트가 아니라 프로필과 선택 화면으로 이어지는
  설정 계층이다. 일반 화면 전환은 첫 화면과 하위 화면에 같은 뒤로 가기 흐름을 준다.
- 그룹 이름은 행의 기능이 아니라 사용자가 찾는 대상에 맞춘다. 계정, 환경 설정과
  앱 정보를 나누면 즉시 실행, 저장된 선택과 읽기 전용 정보가 섞이지 않는다.
- 여러 값을 메뉴에 숨기지 않는다. 전용 화면은 가능한 값, 현재 선택과 선택 뒤
  결과를 한 번에 보여 준다.
- 오른쪽 표시는 누를 수 있다는 장식이 아니라 행이 일으키는 결과를 말한다. 모든
  누를 수 있는 행에 쉐브론을 붙이면 내부 이동과 실행을 구분할 수 없다.
- 계정 삭제의 마찰은 상시 설명이 아니라 확인창이 맡는다. 평소에는 마지막 위치와
  빨간 글자가 위험을 알리고, 실제 실행 직전에 결과를 다시 밝힌다.
- 로그아웃을 일반 계정 동작으로 두어 같은 화면의 위험 색은 되돌릴 수 없는 계정
  삭제에만 사용한다.

## 가정

- 화면 모드 선택은 계정이 아니라 기기에 속한다. 같은 계정의 다른 기기와 동기화하지
  않고, 한 기기에서 계정을 바꿔도 마지막 선택을 유지한다.
- 저장 키는 `theme-preference`이고 값은 `light`, `dark`, `system` 중 하나다. 더
  나은 이름이 확인되면 바꿀 수 있다.
- 현재 설정에는 외부 이동 행이 없다. 글리프는 위에서 정했고 그런 행을 추가할 때
  적용한다.
- `알림`과 `햅틱 반응`의 저장 범위와 실제 기능은 이번 작업에서 바꾸지 않는다. 두
  스위치는 지금 화면 안의 임시 값이라 앱을 다시 열면 초기값(알림 꺼짐, 햅틱 켜짐)으로
  돌아온다. 이 명세의 수용 검사에서 그것을 결함으로 세지 않는다.
- 이 앱의 `@expo/ui`는 `57.0.14`, `uniwind`는 `1.10.1`이 설치돼 있고, 명세가 이름
  붙인 `selectable`, `RadioButton`, `accessibilityAddTraits`, `Host colorScheme`,
  `Uniwind.setTheme`가 그 판에 있다.

## 제외

- 프로필 사진, 닉네임과 아이디의 편집·저장 규칙 변경.
- 알림 권한 요청, 알림 전송과 햅틱 동작의 실제 연결 또는 저장 방식 변경.
- 이용약관, 개인정보 처리방침, 구독, 사용량이나 다른 설정 행 추가.
- 라이트와 다크 팔레트 자체의 변경 또는 새 브랜드 색상 추가.
- 탭의 정보 구조나 탭 구성 변경.
- 계정 삭제가 지우는 서버 데이터, 권한과 삭제 순서 변경.
- 별도 계정 삭제 안내 화면, 재로그인이나 확인 문구 입력 추가.
- 대화·에피소드 화면이 자체 Stack의 첫 화면에 툴바 쉐브론을 그리는 기존 방식. 이
  명세는 설정에만 네이티브 뒤로 가기를 적용하고 그 두 화면은 손대지 않는다.

dearly 기준 중 이 앱이 가져오지 않는 것:

- 글자 배율 상한(iOS `dynamicTypeSize` 상한, `MAX_FONT_SIZE_MULTIPLIER`, Android
  font scale config plugin). [모바일 타이포그래피](../../decisions/mobile-typography.md)가
  본문에 전역 제한을 두지 않기로 했다.
- Native Tabs 없이 Stack 하나로 앱을 구성하는 정보 구조와 "Stack 헤더 옵션을
  전역에서 한 번 정한다"는 규칙. 이 앱의 루트 Stack은 `headerShown: false`라 설정
  세 화면만 옵션 헬퍼를 공유한다.
- 로딩 인디케이터를 감싸지 않고 기본값만 쓰는 규칙.
  [모바일 작업 진행 표시](../../decisions/mobile-action-progress.md)의 결정을
  유지한다.
- `@react-native-async-storage/async-storage`와 저장값을 읽을 때까지 첫 프레임을
  비우는 게이트. 이 앱은 동기로 읽는 `expo-sqlite/kv-store`를 쓴다.
- 행 앞 아이콘, 런타임 버전 행, `seedColor` 전달, 분석 이벤트.

## 유보

- 화면 모드 선택을 계정에 저장해 여러 기기에서 맞출지.

## 남은 위험

- 화면 모드가 바뀌는 순간 선택 화면, 그 뒤의 설정, 운영체제 헤더와 탭 화면이 한
  프레임 안에서 같은 모드로 갱신되지 않을 수 있다.
- 설정을 시트에서 일반 화면으로 바꾸면 탭 막대 가림과 원래 탭의 스크롤 위치
  복원에 회귀가 생길 수 있다. iOS 투명 헤더 아래에서 프로필 머리말이 헤더에 가려지지
  않는지도 확인한다.
- 기기에 저장된 예전 화면 모드 값이 없거나 읽히지 않을 때 `시스템 설정`으로 안전하게
  돌아오는지 확인해야 한다.
- `useColorScheme`를 직접 읽는 곳이 로그인 버튼 말고 더 있으면 그 화면만 운영체제
  모드에 남는다. 구현 때 검색해서 모두 브리지로 옮긴다.
