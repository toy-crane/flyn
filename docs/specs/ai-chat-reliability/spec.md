# AI 채팅 운영 안정화

## 상태

- 이 문서는 확정된 구현 스펙이다.
- 구현은 한 작업 세션에서 끝낸다.
- 부모 스펙은 [AI 채팅](../ai-chat/spec.md)이다. 부모 스펙의 제품 범위와 보안
  경계는 유지하며, 오류 재시도와 모델 호출 제한에 충돌이 있으면 이 문서가
  우선한다.

## 목적

부분 응답 뒤 실패한 채팅이 같은 중단 응답만 반복하는 문제를 없애고, 모델 호출이
무한히 기다리거나 저장 가능한 크기를 넘지 않게 한다. 운영 로그는 실패율과 비용을
판단하는 데 필요한 값만 남기고 사용자 대화 내용은 남기지 않는다.

## 재시도

사용자 메시지와 정상 완료된 AI 메시지의 기존 멱등 동작은 유지한다. 다만
`stopped` AI 메시지는 완성된 답변이 아니므로 이후 같은 사용자 메시지 요청의
재생 대상이 아니다.

| 저장된 AI 메시지 | 같은 사용자 메시지가 다시 오면 |
| --- | --- |
| 없음 | 새 모델 호출을 시작한다 |
| `complete` | 저장된 완료 응답을 재생한다 |
| `stopped` | 기존 부분 응답을 버리고 새 모델 호출을 시작한다 |

- 모델 또는 전송 오류가 나도 사용자 메시지는 남고 현재 화면에 `다시 시도`를
  제공한다.
- 사용자가 `다시 시도`를 누르면 실패한 부분 AI 응답을 화면에서 제거하고 같은
  사용자 메시지로 새 응답을 요청한다.
- 새 요청은 실제 모델 호출이어야 한다. 저장된 `stopped` 내용을 정상 응답처럼
  재생해서는 안 된다.
- 첫 내용이 오기 전에 실패한 경우에도 같은 흐름을 쓴다. 지울 AI 메시지가 없을
  뿐이다.
- 사용자가 직접 누른 `중단`은 오류가 아니다. 이미 받은 내용을 지금처럼
  `stopped` 메시지로 보존하고 오류 UI를 띄우지 않는다.
- 별도 generation ID나 실행 이력 테이블은 만들지 않는다. 같은 질문의 여러
  답변을 보관하는 제품 요구가 생길 때 다시 연다.

## 모델 호출 제한

- 첫 content chunk는 호출 시작 후 **20초** 안에 와야 한다.
- content chunk가 시작된 뒤 다음 content chunk까지 간격은 **20초**를 넘지
  않는다.
- 내부 재시도를 포함한 한 모델 호출의 전체 시간은 **90초**를 넘지 않는다.
- timeout은 일반 모델 오류와 같은 사용자 흐름을 쓴다. 사용자 메시지는 남고
  부분 AI 응답은 재시도할 때 제거한다.
- AI SDK의 기본 provider 재시도 횟수인 2회를 유지하며 별도 값을 지정하지 않는다.
- 한 응답의 출력 상한은 **4,000 tokens**다.
- 출력 상한에 도달한 응답은 받은 내용까지 보존하고 자동으로 이어 쓰지 않는다.
  이 경우의 finish reason은 운영 로그에서 구분한다.

이 값들은 현재 텍스트 채팅의 안전한 기본값이다. 실제 운영 분포가 다른 값을
요구하면 결정 기록 없이 조정할 수 있다.

## 운영 관측

모델 호출 시도마다 구조화된 운영 이벤트 하나를 남긴다.

- opaque request ID
- 모델 ID
- 전체 소요 시간
- finish reason
- 완료, 사용자 중단, 오류, timeout 중 하나인 결과
- input, output, total token usage

다음 값은 로그에 남기지 않는다.

- 사용자 메시지와 AI 응답 본문
- 시스템 지침
- 이메일, access token, authorization header
- Gateway key를 포함한 모든 secret

전체 OpenTelemetry 파이프라인이나 별도 관측 저장소는 도입하지 않는다. 우선
Vercel의 구조화 로그로 실제 실패율, 지연, 사용량을 확인한다.

## 유지할 경계

- 모바일은 마지막 사용자 메시지 ID와 본문만 보내고, 서버는 과거 기록을 DB에서
  읽는다.
- 사용자와 AI 메시지 쓰기는 인증된 Hono 스트리밍 경계가 계속 소유한다.
- 모델은 AI SDK를 통해 Vercel AI Gateway로 호출하고 `AI_MODEL` 환경 변수로만
  선택한다.
- `useChat`, `expo/fetch`, iOS용 streaming response header와 abort 전달은
  유지한다.
- 메시지는 계속 text content와 `complete | stopped` 상태만 저장한다.

## 제외 범위

- 사용자별 호출 제한과 과금 정책
- 대화 context 자르기, 요약, compaction
- resumable stream, background generation, 알림
- 도구 호출, reasoning, 파일·이미지·음성 및 `UIMessage.parts` 저장 전환
- model picker와 모델별 설정 UI
- generation ID, 실행 이력 테이블, 같은 질문의 여러 답변 보관
- 전체 OpenTelemetry와 AI SDK DevTools
- AI SDK 패키지 업데이트
- 채팅 화면의 레이아웃과 시각 디자인 변경

## 완료 조건

- `complete` 응답의 같은-ID 재요청은 모델을 다시 호출하지 않고 저장된 응답을
  재생한다.
- `stopped` 응답에서 다시 시도하면 저장된 부분 응답을 재생하지 않고 모델을
  새로 호출한다.
- 모델 오류 뒤 부분 AI 응답은 다시 시도하는 즉시 사라지고 사용자 메시지는
  유지된다.
- 사용자가 직접 중단한 부분 응답은 `stopped`로 남는다.
- 첫 chunk, chunk 간격, 전체 timeout과 4,000-token 출력 상한이 모델 호출에
  적용된다.
- 정상 완료, 사용자 중단, 오류, timeout, 출력 상한 도달을 로그에서 구분할 수
  있고 사용자 대화 내용과 secret은 로그에 없다.
- 재시도와 제한 동작을 가짜 모델 경계의 자동 테스트로 재현한다.
- `bun run check`가 통과한다.

## 가정과 남은 위험

- 동시에 도착한 같은 사용자 메시지가 AI 메시지 저장 전에 경합하면 모델 호출이
  중복될 수 있다. generation 실행 상태를 만들지 않는 대가로 이번 범위에서는
  받아들인다.
- 긴 채팅은 여전히 모델 context 한도를 넘을 수 있다. 운영 usage를 확인한 뒤
  별도 스펙에서 다룬다.
- 사용자별 호출 제한은 공개 운영 전에 별도 태스크로 정해야 한다.
- 실제 Gateway 오류와 지연 분포는 Gateway credential이 있는 환경에서만 확인할
  수 있다.
