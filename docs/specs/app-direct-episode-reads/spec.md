# 화면 조회를 앱 직접 조회로 옮긴다

## 목적

Hono API가 모델을 부르는 경로만 소유하게 만든다. 홈, 스토리 목록, 스토리 상세,
끝난 화 다시 열기가 쓰는 화면 데이터는 모바일 앱이 로그인 사용자의 권한으로
Supabase에서 직접 읽는다.

## 사용자에게 보이는 결과

- 네 화면은 이관 전과 같은 내용을 같은 규칙으로 보여 준다. 이 작업은 화면
  동작을 바꾸지 않는다.
- 화면 조회가 AI 서버를 지나지 않으므로, AI 서버가 응답하지 못해도 탐색과 복습
  화면은 열린다. 에피소드를 실제로 진행하는 일은 지금처럼 AI 서버가 필요하다.

## 범위

- 대상은 `GET /ai/episode/home`, `GET /ai/episode/stories`,
  `GET /ai/episode/stories/:storyId`, `GET /ai/episode/:episodeId`가 답하던 화면
  데이터 전부다. 이어 하기 카드와 진행 중 목록, 스토리 카드와 진행 바, 에피소드
  목록의 끝남·다음·잠김 상태, 저장된 대화와 배울 표현, 결말과 다음 화 예고,
  읽기 전용 여부가 여기 속한다.
- 앱은 이 데이터를 Supabase에서 직접 읽는다. 원격 상태 관리는
  [모바일 원격 데이터 상태](../../decisions/mobile-remote-data.md)를 그대로
  따른다.
- 지금 플레이할 화의 판단은 데이터베이스가 소유한다. 데이터베이스에는 이미 그
  판단(`episode_is_current`)이 있고 플레이 열기 정책과 `finish_episode`가
  그것을 쓴다. 목록 화면이 읽기 좋은 형태의 조회를 데이터베이스가 하나 더 열되,
  클라이언트가 부르는 조회는
  [쓰기 규칙이 사는 자리](../../decisions/supabase-write-rules.md)대로 공개
  API로 다룬다. 앱은 이 답을 읽어 화면을 조립할 뿐, 같은 판단을 앱 코드로 다시
  만들지 않는다.
- 이관이 끝나면 네 GET 경로를 API에서 제거한다. Hono에는 모델을 부르는 경로와
  상태 확인만 남는다.
- [AI 에피소드 프로토콜](../../decisions/ai-episode-protocol.md) 중 이 네 경로의
  소유권 항목은 이 명세가 대체한다. 구현을 마치면 계약을 결과에 맞게 고친다.

## 수용 기준

- 로그인 사용자가 홈, 스토리 목록, 스토리 상세, 끝난 화 다시 열기에서 이관 전과
  같은 데이터를 본다. 잠긴 화는 제목만 보이고 예고는 감춘다. 결말은 났는데 남은
  메시지가 없는 화는 다시 열 수 없다.
- 이 화면들을 그리는 동안 앱이 AI 서버 주소로 요청을 보내지 않는다. AI 서버를
  꺼 둔 채로도 네 화면이 그려진다.
- 홈이 권하는 화와 실제로 열 수 있는 화가 같다. 앱이 어긋난 화를 열려 하면
  지금처럼 데이터베이스가 거절한다.
- 진행 판단의 원본이 데이터베이스 한 곳이다. 같은 판단을 앱이 다시 구현한
  코드가 없다.
- API에는 모델을 부르지 않는 화면 조회 경로가 남지 않는다.

## 확정한 제약과 이유

- 판단은 데이터베이스, 표현은 앱. AI 경로가 각본과 기억 읽기를 유지하는 한
  판단을 앱에 복제하면 데이터베이스, 서버, 앱 세 곳이 되고, 규칙이 바뀔 때
  구버전 앱이 서버 게이트와 어긋난다. 원본을 데이터베이스에 두면 서버와 앱이
  같은 답을 읽는다.
- 홈 정렬, 카드 구성, 예고 감춤 같은 표현 조립은 앱이 소유한다. 어긋나도 화면
  문제로 그치고 데이터는 정책이 지킨다.
- 쓰기 경로는 바꾸지 않는다. 플레이 열기, 메시지 저장, 결말 확정은 지금
  그대로다.

## 가정

- 배포된 실사용자가 없어 기존 GET 경로를 유예 없이 제거해도 되는 단계다.
  실사용자가 생긴 뒤라면 제거 시점을 따로 정한다.

## 손대지 않는 것

- `POST /ai/episode`, `POST /ai/episode/ask`, `POST /ai/chat`과 대화 저장 규칙은
  AI 에피소드 프로토콜 그대로다.
- 계정 삭제 Edge Function 경계, 쓰기 규칙 계약, 프로필·아바타·스토리 표지
  경로도 그대로다.
- 홈의 최근 스토리가 시작 시각을 쓰는 기존 결함은 여기서 고치지 않는다. 이관의
  검증 기준이 동작 보존이라서, 동작 변경을 섞으면 이관 결함과 구분할 수 없다.
  [follow-up](../../follow-ups/home-recent-story-uses-start-time.md)이 그 일을
  들고 있다.

## 미룬 것

- 없다.

## 남은 위험

- 화면 하나가 조회 여러 개를 직접 하므로 기기 네트워크 품질에 따라 체감이
  달라질 수 있다. 지금도 서버가 같은 쿼리를 두 개 실행하므로 총량은 비슷하고,
  1분 캐시가 반복 진입을 줄인다.
- 저장된 대화의 part 형식을 앱이 직접 읽게 된다. 앱은 이미 스트리밍에서 같은
  형식을 그리므로 새 결합은 아니지만, AI SDK를 올릴 때 저장 형식과 앱 해석을
  함께 확인해야 한다.
