# 01 — 교정과 안내 항목에 뜻이 담긴다

## Outcome

사용자가 영어 교정이나 한국어 안내를 책갈피로 담으면, 표현 돌아보기가 그 메시지에 대해 이미 만들어 둔 고친 문장의 뜻이 항목에 함께 저장된다. 규칙을 바꾸기 전에 담아 둔 항목도 곁에 있던 메시지가 남아 있으면 뜻이 채워진다. 인물 대사는 지금처럼 뜻 없이는 저장되지 않는다. 뜻을 새로 만들지 않으므로 모델을 부르는 곳은 늘지 않는다.

## Blockers

None.

## Acceptance criteria

- [x] 교정 항목을 뜻과 함께 저장해도 거절되지 않는다. 뜻 없이 저장해도 거절되지 않는다.
- [x] 인물 대사 항목을 뜻 없이 저장하려 하면 지금처럼 거절된다. 뜻의 길이 한도는 인물 대사와 같다.
- [x] 교정과 안내를 책갈피로 담으면 표현 돌아보기 카드가 보여 주는 것과 같은 뜻이 항목에 담긴다. 모델 호출은 인물 대사를 담을 때 한 번뿐이다.
- [x] 규칙을 바꾸기 전에 담은 교정 항목은 메시지가 남아 있으면 그 메시지의 뜻을 갖고, 메시지가 지워진 항목은 뜻이 빈 채로 나머지가 그대로다.
- [x] 표현 노트 조회가 교정과 안내 항목의 뜻을 돌려준다. 지금 카드는 그 값을 아직 그리지 않아도 된다.
- [x] [표현 노트 스펙](../../saved-expressions/spec.md)의 "영어 교정과 한국어 안내는 만들 값이 없어 뜻이 없다"는 문장이 "표현 돌아보기의 뜻을 옮겨 담는다"로 바뀐다.

## Constraints

- 데이터 규칙은 [스펙](../spec.md)의 `저장 항목의 뜻`을 따른다. 규칙은 [쓰기 규칙이 사는 자리](../../../decisions/supabase-write-rules.md)에 따라 데이터베이스가 소유한다.
- 스키마는 [Supabase 스키마 작업 방식](../../../decisions/supabase-schema-workflow.md)대로 선언형 스키마를 고친 뒤 마이그레이션을 만든다. 옛 항목을 채우는 문장은 선언형 diff가 표현하지 못하므로 같은 마이그레이션에 손으로 더하고 근거를 남긴다.
- 저장 경로와 세션 조회는 [AI 에피소드 프로토콜](../../../decisions/ai-episode-protocol.md)을 따른다.
- 이 작업은 앱 화면을 바꾸지 않는다. 카드에 뜻 줄을 그리는 것은 작업 05다.

## Verification

- `bun run db:test`가 교정 항목의 뜻 허용과 인물 대사의 뜻 필수를 확인하는 테스트를 포함해 통과한다.
- API 테스트가 배울 표현을 담을 때 뜻이 함께 저장되고 모델 호출이 없음을 확인하며 통과한다.
- 마이그레이션을 빈 데이터베이스에서 처음부터 재생하고, 뜻 없이 담긴 옛 교정 항목이 메시지가 있으면 채워지고 없으면 비어 있는 것을 로컬 스택에서 확인한다.
- `bun run check`가 통과한다.

## Review checkpoint
