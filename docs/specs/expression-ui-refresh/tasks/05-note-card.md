# 05 — 표현 노트 카드가 세 칸이 된다

## Outcome

사용자가 `노트` 탭에서 보는 카드가 출처 한 줄, 영어 문장, 한국어 뜻의 세 칸이다. 인물 이름과 `내 표현` 칩은 없고 종류는 형광펜의 유무로 구분된다. 교정과 안내 카드는 출처 줄 오른쪽 쉐브론으로 `내가 쓴 문장`과 `이렇게 쓰는 이유`를 그 자리에서 펼친다. 카드 아래 오른쪽에 복사와 휴지통이 서고, 휴지통은 `표현을 삭제할까요?` 확인창을 연다. 밀어서 지우는 동작은 없다.

## Blockers

작업 01. 교정 카드의 한국어 줄에 담을 뜻이 있어야 한다.
작업 03. 카드 아래 줄이 03이 정한 아이콘 줄이다.

## Acceptance criteria

- [ ] 인물 대사, 교정, 한국어 안내 카드가 모두 출처, 영어, 한국어 세 칸이고 인물 이름과 칩이 없다. 출처는 `스토리 제목 · N화` 하나다.
- [ ] 긴 문장은 잘리지 않고 카드가 길어진다.
- [ ] 교정 카드의 한국어 줄에 고친 문장의 뜻이 보인다. 뜻이 없는 옛 항목은 한국어 줄만 빈다.
- [ ] 교정과 안내 카드를 누르면 쉐브론이 뒤집히며 `내가 쓴 문장`과 `이렇게 쓰는 이유`가 그 자리에서 펼쳐진다. 원문의 어긋난 자리에 밑줄이 있고, 섹션은 라벨과 여백으로만 나뉘며 구분선과 띠가 없다. `내가 쓴 문장` 위에 여백이 있다.
- [ ] 인물 대사 카드는 쉐브론이 없고 눌러도 펼쳐지지 않는다.
- [ ] 카드 아래 오른쪽에 복사와 휴지통이 있다. 복사는 영어 문장을 클립보드에 넣는다. 아이콘을 눌렀을 때 카드가 함께 펼쳐지지 않는다.
- [ ] 휴지통을 누르면 제목 `표현을 삭제할까요?`, 본문 없음, 버튼 `취소`와 `삭제`인 플랫폼 기본 확인창이 뜬다. `삭제`를 누르면 카드가 사라지고 `취소`를 누르면 그대로다.
- [ ] 카드를 옆으로 밀어도 아무 일이 없다.
- [ ] 빈 화면과 불러오기 실패 화면은 그대로다.
- [ ] iOS 기본 글자 크기와 큰 접근성 글자 크기, 밝은 화면과 어두운 화면에서 세 칸, 펼친 두 섹션, 아이콘 줄, 확인창이 겹치거나 잘리지 않는다.
- [ ] 접근성 이름이 복사는 `표현 복사`, 휴지통은 `삭제`, 펼치는 카드는 펼침 상태를 알린다.
- [ ] [표현 노트 스펙](../../saved-expressions/spec.md)의 카드 구성(출처 표시, 띠와 세 덩어리, 밀어서 삭제)이 이 카드로 바뀐다.

## Constraints

- 카드 모양은 [시안](../prototypes/note.html)과 같다. 라벨과 문구는 [스펙](../spec.md)과 [화면 문구 한국어 말투](../../../decisions/korean-ui-writing.md), [용어집](../../../../GLOSSARY.md)을 따른다.
- 확인창은 [모바일 계정 삭제](../../../decisions/mobile-account-deletion.md)가 쓰는 플랫폼 기본 확인창과 같은 형태다.
- 카드는 작업 06의 기억해 둘 표현이 같이 쓸 수 있어야 한다. 첫 줄의 내용과 아이콘 줄의 둘째 아이콘만 다르다.
- 같은 역할의 크기와 간격 기준은 [모바일 UI 일관성 검토](../../../decisions/mobile-ui-consistency-review.md)를 따른다.
- 카드에서 대화로 이동하는 동작은 만들지 않는다. 아이콘 줄의 셋째 자리를 비워 둔다.

## Verification

- `bun run test`가 세 칸 구성, 펼침, 확인창의 취소와 삭제, 밀어도 삭제되지 않음을 확인하는 테스트를 포함해 통과한다.
- `bun run check`가 통과한다.
- `agent-device` 한 세션에서 세 종류를 담은 뒤 `노트` 탭에서 세 카드를 확인하고, 교정 카드를 펼치고, 복사하고, 휴지통으로 취소와 삭제를 차례로 확인한다. 큰 접근성 글자와 어두운 화면에서 같은 카드를 다시 본다.
