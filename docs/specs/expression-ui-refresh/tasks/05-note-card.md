# 05 — 표현 노트 카드가 세 칸이 된다

## Outcome

사용자가 `노트` 탭에서 보는 카드가 출처 한 줄, 영어 문장, 한국어 뜻의 세 칸이다. 인물 이름과 `내 표현` 칩은 없고 종류는 형광펜의 유무로 구분된다. 교정과 안내 카드는 출처 줄 오른쪽 쉐브론으로 `내가 쓴 문장`과 `이렇게 쓰는 이유`를 그 자리에서 펼친다. 카드 아래 오른쪽에 복사와 휴지통이 서고, 휴지통은 `표현을 삭제할까요?` 확인창을 연다. 밀어서 지우는 동작은 없다.

## Blockers

작업 01. 교정 카드의 한국어 줄에 담을 뜻이 있어야 한다.
작업 03. 카드 아래 줄이 03이 정한 아이콘 줄이다.

## Acceptance criteria

- [x] 인물 대사, 교정, 한국어 안내 카드가 모두 출처, 영어, 한국어 세 칸이고 인물 이름과 칩이 없다. 출처는 `스토리 제목 · N화` 하나다.
- [x] 긴 문장은 잘리지 않고 카드가 길어진다.
- [x] 교정 카드의 한국어 줄에 고친 문장의 뜻이 보인다. 뜻이 없는 옛 항목은 한국어 줄만 빈다.
- [x] 교정과 안내 카드를 누르면 쉐브론이 뒤집히며 `내가 쓴 문장`과 `이렇게 쓰는 이유`가 그 자리에서 펼쳐진다. 원문의 어긋난 자리에 밑줄이 있고, 섹션은 라벨과 여백으로만 나뉘며 구분선과 띠가 없다. `내가 쓴 문장` 위에 여백이 있다.
- [x] 인물 대사 카드는 쉐브론이 없고 눌러도 펼쳐지지 않는다.
- [x] 카드 아래 오른쪽에 복사와 휴지통이 있다. 복사는 영어 문장을 클립보드에 넣는다. 아이콘을 눌렀을 때 카드가 함께 펼쳐지지 않는다.
- [x] 휴지통을 누르면 제목 `표현을 삭제할까요?`, 본문 없음, 버튼 `취소`와 `삭제`인 플랫폼 기본 확인창이 뜬다. `삭제`를 누르면 카드가 사라지고 `취소`를 누르면 그대로다.
- [x] 카드를 옆으로 밀어도 아무 일이 없다.
- [x] 빈 화면과 불러오기 실패 화면은 그대로다.
- [x] iOS 기본 글자 크기와 큰 접근성 글자 크기, 밝은 화면과 어두운 화면에서 세 칸, 펼친 두 섹션, 아이콘 줄, 확인창이 겹치거나 잘리지 않는다.
- [x] 접근성 이름이 복사는 `표현 복사`, 휴지통은 `삭제`, 펼치는 카드는 펼침 상태를 알린다.
- [x] [표현 노트 스펙](../../saved-expressions/spec.md)의 카드 구성(출처 표시, 띠와 세 덩어리, 밀어서 삭제)이 이 카드로 바뀐다.

## Constraints

- 카드 모양은 [시안](../prototypes/note.html)과 같다. 라벨과 문구는 [스펙](../spec.md)과 [화면 문구 한국어 말투](../../../decisions/korean-ui-writing.md), [용어집](../../../../GLOSSARY.md)을 따른다.
- 확인창은 [모바일 계정 삭제](../../../decisions/mobile-account-deletion.md)가 쓰는 플랫폼 기본 확인창과 같은 형태다.
- 카드는 작업 06의 기억해 둘 표현이 같이 쓸 수 있어야 한다. 첫 줄의 내용과 아이콘 줄의 둘째 아이콘만 다르다.
- 같은 역할의 크기와 간격 기준은 [모바일 UI 일관성 검토](../../../decisions/mobile-ui-consistency-review.md)를 따른다.
- 카드에서 대화로 이동하는 동작은 만들지 않는다. 아이콘 줄의 셋째 자리를 비워 둔다.

## Verification

- `bun run test`가 세 칸 구성, 펼침, 확인창의 취소와 삭제, 밀어도 삭제되지 않음을 확인하는 테스트를 포함해 통과한다.
- `bun run check`가 통과한다.
- `agent-device` 한 세션에서 세 종류를 담은 뒤 `노트` 탭에서 세 카드를 확인하고, 교정 카드를 펼치고, 복사하고, 휴지통으로 취소와 삭제를 차례로 확인한다. 큰 접근성 글자와 어두운 화면에서 같은 카드를 다시 본다.

## Execution

- Verification: 2026-09-10. `bun run test` 통과(모바일 85개 파일 601개, API 228개, 스크립트 299개), `bun run check` 통과. `expression-card.test.tsx`가 세 칸, 뜻 없는 항목의 빈 한국어 줄, 쉐브론과 펼침, 아이콘을 눌러도 펼쳐지지 않음, 읽는 이름, 민 손가락을 누른 것으로 세지 않음을 확인한다. `expression-note-screen.test.tsx`가 세 종류의 형광펜, 인물 이름과 칩이 없음, `스토리 제목 · N화` 출처, 확인창의 제목과 두 버튼, `취소`와 `삭제`의 결과를 확인한다. iOS 시뮬레이터 `flyn-slot-1`에서 인물 대사, 교정, 안내를 담아 세 카드를 세우고, 교정 카드를 펼쳐 `내가 쓴 문장`의 밑줄과 `이렇게 쓰는 이유` 두 줄을 보고, 복사가 체크로 바뀌는 것과 그때 카드가 펼쳐지지 않는 것을 보고, 휴지통으로 `취소`와 `삭제`를 차례로 눌러 확인했다. 접근성 글자 크기를 가장 크게, 화면을 어둡게 두고 같은 카드를 다시 보아 세 칸과 펼친 두 섹션, 아이콘 줄이 겹치거나 잘리지 않는 것을 확인했다. Android 에뮬레이터 `flyn_dev_1`에서도 카드, 펼침, Material 확인창의 `취소`와 `삭제`를 확인했다. Android 확인창은 본문이 없어도 제목과 버튼 사이에 빈 자리를 남기는데, 플랫폼 기본 모양이라 그대로 둔다.
- Blocker: —
- Revision: 카드를 옆으로 밀면 카드가 펼쳐졌다. 카드가 넓어서 미는 동안 손가락이 카드 안에 머물고, 떼는 순간 누른 것으로 처리된다. 밀어서 지우던 습관이 남은 사람에게 뜻하지 않은 화면이 열려서, 누른 자리와 뗀 자리가 12pt 넘게 벌어지면 펼치지 않게 했다. 판정은 `isTap`으로 떼어 내 단위 검사로 고정했다.
- Revision: 카드의 읽는 이름을 iOS가 짓게 두지 않고 손으로 적는다. 기기에서 보니 목록 첫 카드만 세 칸을 이어 읽지 못하고 `testID`를 대신 읽었다. `headerLabel`을 받아 출처, 영어, 한국어를 이어 붙이고 `accessible`을 켜서, 두 플랫폼 모두 같은 이름을 읽는다.
- Revision: 카드를 `shared/ui/expression-card.tsx`에 두고 `features/note`는 감싸기만 한다. 작업 06의 기억해 둘 표현이 같은 카드를 쓰는데 그쪽은 다른 기능이라, [모바일 코드 구조](../../../decisions/mobile-code-architecture.md)의 "한 기능은 다른 기능을 import하지 않는다"를 지키려면 공용 자리가 필요했다. 공용 카드는 표현의 종류를 알지 못한다. 첫 줄에 무엇을 쓸지, 형광펜을 무슨 색으로 입힐지, 아이콘 줄에 무엇을 세울지는 부르는 쪽이 정해서 넘긴다.
- Revision: 시안의 첫 줄은 노트가 8pt, 기억해 둘 표현이 6pt 간격인데 공용 카드가 8pt 하나로 쓴다. 스펙이 "다른 점은 첫 줄의 내용과 아이콘 줄의 둘째 아이콘뿐"이라고 정했으므로 간격은 한 값으로 맞춘다.
- Revision: 펼친 카드의 이유 줄을 이유 글자만으로 구분하던 것을 줄 번호까지 넣어
  구분한다. 서버는 짚은 자리와 고친 글로 항목을 가리므로 이유가 겹치는 것을 막지
  않는다. 같은 이유가 두 번 오면 두 줄이 같은 열쇠를 써서 다시 그릴 때 흔들렸다.
- Revision: 아이콘 줄의 겹침(-2pt)과 흐르는 동안의 불투명도는 클래스가 아니라
  `style`에 값으로 남긴다. [모바일 Uniwind 스타일링](../../../decisions/mobile-uniwind-styling.md)은
  고정된 값을 클래스로 옮기라고 하지만, 이 둘은 `icon-row.test.tsx`가 8pt라는
  계산과 "자리만 지킨다"는 상태를 그 값으로 재고 있다. 토스트 층의 자리와 쌓는
  순서도 같은 이유로 값으로 남는다. 알약이 말풍선 뒤로 깔리던 것을 기기에서 보고
  고친 자리이고 그 값을 검사가 지킨다.
