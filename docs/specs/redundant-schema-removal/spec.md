# 쓰지 않거나 겹치는 테이블과 열 정리

## 목적과 승인 범위

읽는 곳이 없거나 같은 사실을 다른 열과 겹쳐 적은 테이블 하나와 열 네 개를 지운다. 사용자가 보는 화면과 동작은 바뀌지 않는다.

2026-09-15 사용자가 아래 삭제를 결정했다.

| 대상 | 지우는 이유 | 남는 판단 근거 |
| --- | --- | --- |
| `language_levels` 테이블 | 결말마다 쓰지만 앱, 서버, 프롬프트 어디에서도 읽지 않는다. 사용자가 지금 필요 없다고 결정했다. | 없음. 대화 안에서 상대가 사용자의 수준에 맞추는 동작은 이 테이블과 무관하다. |
| `episode_plays.started_at` | 읽는 곳이 없고, 값이 `created_at`과 같다. | `created_at` |
| `profiles.username_changed_at` | 아이디를 바꿀 때 쓰지만 읽는 곳이 없다. | `username_locked_until` |
| `retired_usernames.retired_at` | 이전 아이디를 보호할 때 쓰지만 읽는 곳이 없다. | `protected_until` |
| `story_plays.started_at` | 모든 행에서 `created_at`과 같은 값이다. 회차 행은 첫 사용자 메시지에 생기고 두 값 모두 바뀌지 않는다. | `created_at`을 회차 시작 시각으로 읽는다. |

`language_levels`가 사라지면 결말에서 사용자의 영어 수준을 쓰는 일도 없앤다. 결말 기록은 결과와 이야기 기억 세 가지(선택, 관계, 질문)만 남긴다.

## 필수 결정 계약

- [데이터베이스 공통 필드](../../decisions/database-common-fields.md): 사건 시각 열을 둘지, `created_at`을 사건 시각으로 읽을지의 기준. 이번에 이 기준을 더했다.
- [AI 에피소드 프로토콜](../../decisions/ai-episode-protocol.md): 결말 출력이 갖는 기록 항목과 저장 위치. 이번에 수준 항목을 뺐다.
- [검증과 내부 테스트 배포](../../decisions/continuous-delivery.md): DB, API, 앱의 배포 순서와 이전 API·앱 접근을 보존하는 규칙.
- [Supabase 스키마 작업 방식](../../decisions/supabase-schema-workflow.md): 선언형 원본, 마이그레이션 생성, 데이터를 지우는 문장의 승인 방식.
- [모바일 스토리 탐색](../../decisions/mobile-story-browsing.md): 대화 기록 회차 카드의 제목과 순서.
- [모바일 프로필 식별자와 온보딩](../../decisions/mobile-profile-identity-and-onboarding.md): 아이디 변경 제한과 이전 아이디 보호.
- [AI 프롬프트 평가](../../decisions/ai-prompt-evaluation.md): 결말 프롬프트를 바꿨을 때 돌리는 평가.

## 제품 전제

[PRODUCT.md](../../../PRODUCT.md)의 교정, 이야기 기억, 스토리 단위 인물과 세계는 그대로 유지한다. 학습 언어를 영어 전용으로 굳히지 않는다는 전제에 따라 `stories.target_language`는 지우지 않는다.

PRODUCT.md의 "언어 수준은 계정에 따로 남긴다"는 이번 결정과 어긋난다. 이 문장은 이 명세가 고치지 않고 `define-product`로 따로 고친다. 같은 문단의 "상대는 사용자의 수준에 맞춰 어휘 난이도와 한 번에 주는 정보량을 조절"하는 대화 안의 동작은 그대로 유지한다.

## 요구 동작

### 바뀌지 않는 사용자 경험

- 대화 기록의 회차 카드는 전환 전과 같은 시작 날짜와 시간을 제목으로 쓰고, 같은 순서로 선다. 기존 회차의 표시 시각도 바뀌지 않는다.
- 아이디를 바꾸면 30일 동안 다시 바꿀 수 없고, 이전 아이디는 같은 기간 다른 계정이 가져가지 못한다. 프로필 화면이 보여 주는 다시 바꿀 수 있는 날짜도 그대로다.
- 결말이 나면 종류와 결과가 화면에 보이고, 선택·관계·질문이 같은 회차의 다음 화에 들어간다.
- 연속 기록, 영어로 말한 횟수, 표현 노트, 회차 삭제와 계정 삭제는 바뀌지 않는다.

### 유지하는 값

아래 값은 다른 곳과 겹쳐 보이지만 일부러 복사해 둔 것이라 지우지 않는다.

| 값 | 유지하는 이유 |
| --- | --- |
| `episode_plays.user_id`, `episode_messages.user_id`, `episode_characters.story_id` | 복합 외래키로 부모와 어긋나지 않게 묶고, 정책이 조인 없이 판단한다. |
| `expressions`의 `text`, `speaker`, `original`, `episode_id` | 노트에 담은 표현은 원본 대화를 지워도 남는다. |
| `learning_events` | 회차를 지워도 연속 기록과 영어로 말한 횟수가 남는다. |
| `story_plays.last_user_message_at` | 메시지를 지워도 뒤로 가지 않고 최근 대화 정렬을 받친다. |
| `episode_messages.expression_status` | `natural`, `unclear`는 표현 행이 없어 계산할 수 없다. |
| `expressions.kind`의 `correction`, `translation` | 판별 규칙이 바뀌어도 지난 카드의 제목이 바뀌지 않는다. |
| `stories`의 `owner_id`, `slug`, `position` | 주인, seed가 찾는 키, 공식 목록의 순서라는 다른 일을 한다. |
| `stories.completion_title`, `completion_copy` | 마지막 화의 스토리 완주 안내로 나간다. |
| `characters.content_key` | seed가 이름과 순서가 바뀐 같은 인물을 찾는다. |
| `expressions.claim_token`, `expires_at` | 대사 번역의 중복 생성을 막는다. |
| `stories.target_language` | 위 제품 전제를 따른다. |

### 전환과 호환

- DB가 API보다 먼저 배포되므로, 새 스키마가 올라가는 순간 운영 중인 API로도 결말 기록과 대화 기록 조회가 실패하지 않아야 한다. 결말 기록은 수준 값 없이도 성공하고, 대화 기록은 `story_plays.started_at` 없이도 읽혀야 한다.
- 앱이 받는 회차 시작 시각은 이미 설치된 앱이 계속 읽을 수 있게 응답의 이름과 값을 유지한다.
- 전환을 마치면 선언형 스키마, 데이터베이스 함수, API, 생성 타입, 자동 테스트에 수준을 받거나 쓰는 자리와 지운 열 이름이 남지 않는다. 호환을 위해 잠시 둔 자리도 남기지 않는다.
- 지운 데이터는 되살리지 않고 따로 보관하지 않는다. 데이터를 지우는 문장 윗줄의 `-- 삭제 이유:`에는 무엇이 사라지는지와 2026-09-15 사용자 결정을 적는다. `DB:destructive-approved` 라벨은 사람만 붙인다.

## 수락 기준

1. 선언형 스키마와 실제 로컬 DB에 `language_levels` 테이블과 `episode_plays.started_at`, `profiles.username_changed_at`, `retired_usernames.retired_at`, `story_plays.started_at` 열이 없다. 생성 타입에도 없다.
2. 결말 기록은 수준 값을 받지 않는다. 결말 출력에 수준 항목이 없고, 결과와 선택·관계·질문이 모두 있으면 결말이 확정된다. 세 기록 중 하나라도 공백뿐이면 전처럼 확정하지 않는다.
3. 결말이 난 화의 종류, 결과, 선택·관계·질문이 저장되고 같은 회차의 다음 화 프롬프트에 들어간다. 이미 끝난 화에 결말이 다시 와도 앞의 기록을 바꾸지 않는다.
4. 대화 기록 회차 카드의 제목 시각과 순서가 전환 전과 같다. 이어서 대화해도 시작 시각과 순서가 바뀌지 않는다.
5. 아이디를 처음 정하면 제한이 걸리지 않고, 바꾸면 30일 제한과 이전 아이디 보호가 걸린다. 제한 중에는 다시 바꿀 수 없고, 같은 아이디를 두 번 내놓으면 가장 최근에 내놓은 때부터 보호한다. 자기가 내놓은 아이디는 되찾을 수 있다.
6. 전환 직전의 API 코드를 새 스키마에 붙여도 결말 기록과 대화 기록 조회가 성공하는 상태를 거친 뒤 호환 자리를 없앤다. 최종 상태는 기준 1과 위 전환 조건을 만족한다.
7. 연속 기록, 영어로 말한 횟수, 회차 삭제, 계정 삭제의 기존 DB 검사가 통과한다.
8. 저장소의 DB 검증(전체 재생, pgTAP, 생성 타입과 선언형 스키마 일치), workspace 검사와 결말 프롬프트 평가가 통과한다. 평가 방식은 AI 프롬프트 평가 계약을 따른다.
9. PR의 파괴적 마이그레이션 검사가 삭제 문장을 모두 찾고, 각 문장 윗줄에 삭제 이유와 결정 날짜가 있다.

## 가정

- 에이전트가 정한 범위(사용자가 바꿀 수 있음): 테이블을 지우면서 결말 출력의 수준 항목도 없앤다. 저장하지 않는 값을 모델이 계속 쓰게 둘 이유가 없다고 판단했고, 이 범위를 안내한 뒤 사용자가 이의 없이 다음 결정으로 넘어갔다.
- 에이전트가 정한 기본값: 이미 있는 보존 사례 `supabase/upgrade-tests/20260908155308/`, `20260914091349/`의 검사는 지운 테이블과 열을 가리킨다. 과거 마이그레이션처럼 당시의 기록으로 두고 고치지 않는다. CI는 새 마이그레이션과 바뀐 사례만 돌리므로 영향이 없다.
- 에이전트가 정한 기본값: `apps/api/eval/results`의 지난 평가 결과에 남은 수준 항목은 당시 실행 기록으로 둔다.

## 범위 밖

- 사용자의 영어 수준을 계정에 모아 난이도를 맞추는 개인화 기능: 지금 필요 없다고 결정했다. 만들게 되면 과거 관찰 없이 새로 시작한다.
- 위 유지하는 값의 구조 변경: 각자 복사해 둔 이유가 있고 다른 결정 계약이 소유한다.
- 스토리 목록 조회가 쓰지 않는 완주 안내 열까지 함께 읽는 API 정리: 스키마를 바꾸지 않는 코드 정리다.
- PRODUCT.md 수정: `define-product`가 맡는다.

## 남은 위험

- PRODUCT.md를 고치기 전까지 제품 전제와 이 명세가 어긋난다. 그 사이 다른 작업이 PRODUCT.md를 근거로 언어 수준 저장을 되살리려 할 수 있다.
- 운영 DB의 언어 수준 관찰과 세 시각 값은 되돌릴 수 없게 사라진다. 운영 데이터의 행 수는 확인하지 않았다.
- `created_at`을 회차 시작 시각으로 읽는 것은 회차 행이 첫 사용자 메시지에 생긴다는 전제에 기댄다. 회차를 더 일찍 만들게 되면 공통 필드 계약의 재검토 조건에 따라 시작 시각을 다시 둔다.
- 아이디를 두 번 내놓은 경우의 보호 기준은 지금 `retired_at`과 `protected_until`을 함께 고친다. `retired_at`을 지운 뒤에도 `protected_until`이 최근 시점으로 갱신되는지 기준 5로 확인해야 한다.
