# 롤플레잉 에피소드

flyn은 AI 롤플레잉으로 영어 작문을 연습하는 앱이다. 이 문서는 에피소드 생성,
롤플레잉 대화, 대화 종료까지 한 에피소드의 전 구간에 대해 확정된 결정을 담는다.

승인된 화면은 [index.html](index.html)에서 열 수 있다. 각 파일은 상단 탭으로
화면을, state 알약으로 상태를 전환한다.

- [creation.html](creation.html) — 에피소드 생성 3스텝
- [goals.html](goals.html) — 대화 화면의 목표와 상황
- [conversation.html](conversation.html) — 말풍선, 첨삭 시트, 문장 대화
- [ending.html](ending.html) — 종료 전환과 결과

## 제품 정의

flyn의 대화 단위는 **롤플레잉 에피소드** 하나다. 자유 주제 채팅 표면은 제공하지
않는다. 기존 채팅 구현(스트리밍, 메시지 소유권, 스크롤·키보드 경계, 재시도)은
버리지 않고 에피소드 대화의 기반으로 재사용한다.

한 에피소드는 **상황·역할·목표 3개**로 이루어지고, 목표를 모두 달성하거나 턴
상한에 도달하면 끝난다.

## 에피소드 생성

- 생성은 **한 화면 안의 3스텝**이다. ① 상황 → ② 역할 → ③ 목표 순으로 큰 제목이
  바뀌고, 화면은 넘어가지 않는다.
- 이전 스텝의 결정은 **내비게이션이 나른다.** ②의 타이틀은 선택한 상황,
  ③은 타이틀에 상황·서브타이틀에 역할이 들어간다. 본문에는 현재 질문만 둔다.
- ① 상황은 취향과 영어 수준을 반영한 **후보 3개 중 선택**한다. 목록 아래 `다른
  상황 보기`가 후보 전체를 교체한다.
- ② 역할은 상대와 내 역할을 **한 화면에 함께** 둔다. 각각 편집 가능한 입력이고,
  재생성 버튼은 입력 밖 레이블 오른쪽에 둔다.
- ③ 목표 3개는 **읽기 전용**이다. 직접 수정할 수 없고 `다른 목표 보기`로 3개를
  묶어서만 다시 만든다.
- 상황을 바꾸면 역할과 목표가 함께 재생성된다. 역할을 바꾸면 목표만 재생성된다.
- 턴 상한은 에피소드 필드가 아니라 **코드가 소유하는 시스템 상수**이며 생성
  화면에 노출하지 않는다. 현재 값은 20턴이고, **턴은 사용자 메시지 하나**를 센다.

## 롤플레잉 대화

### 화면 구성

각 요소는 하나씩만 말한다. 같은 정보를 두 곳에서 반복하지 않는다.

| 요소 | 담당 |
| --- | --- |
| 네이티브 헤더 | 시나리오 제목과 역할 |
| 상황 카드 | 상황 설명. 접힘/펼침 |
| 목표 바 | 지금 할 목표와 전체 목록 |
| 대화 흐름 | 목표 달성 기록 |

- 상황 카드는 대화 목록의 첫 요소이며 **제자리에서 펼쳐진다.** 접힌 상태의
  라벨은 `상황 자세히 보기`다.
- 목표 바는 **composer 바로 위**에 상주한다. 접히면 지금 할 목표 한 줄,
  펼치면 같은 자리에서 턴 진행과 목표 3개 전체가 나온다. 완료는 초록 체크,
  현재는 파란 링, 남은 것은 회색 원으로 구분한다.
- 목표를 달성하면 대화 흐름에 초록 한 줄이 영구히 남아, 스크롤만으로 언제
  달성했는지 되짚을 수 있다.
- 헤더에 `목표` 버튼은 두지 않는다. 목표는 탭 없이 항상 보여야 한다.
- 턴은 목표 바를 펼쳤을 때만 보인다. 상시 노출하면 없는 압박을 만든다.

### 입력과 전달

- 말풍선에는 **실제로 상대에게 전달된 문장**이 남는다.
- 한글로 쓰면 **번역된 영어가 전달**되고 말풍선에 그 영어가 남는다.
- 영어로 쓰면 **원문 그대로 전달**되고 말풍선에 원문이 남는다. 교정본을 대신
  보내지 않는다.
- AI는 어색한 영어도 **의도를 선해해 자연스럽게 반응**한다. 정말 알아들을 수
  없을 때만 되묻는다.
- 한글 입력은 막힐 때 쓰는 **비상구**다. 기능은 온전히 두되 UI에서 앞세우지
  않는다. composer 문구는 `영어로 써 보세요`다.

### 말풍선의 세 가지 표시

말풍선 옆 표시는 세 가지이며, 두 개는 누를 수 있고 하나는 상태다.

| 표시 | 뜻 | 탭 |
| --- | --- | --- |
| 번역 아이콘 | 한글로 썼다 | 시트 열림 |
| `info.circle` | 더 자연스럽게 쓸 여지가 있다 | 시트 열림 |
| 초록 체크 | 그대로 잘 통했다 | 없음 |

- 누를 수 있는 두 표시는 원형 버튼으로, 상태 표시인 체크는 배경 없는 플랫
  아이콘으로 그려 구분한다. 터치 영역은 44×44pt다.
- 말풍선 본문에는 밑줄을 넣지 않는다. 밑줄은 시트의 개선 문장에만 붙는다.
- 커스텀 글리프나 `ellipsis`는 쓰지 않는다. `ellipsis`는 명령 메뉴를 뜻한다.

### 첨삭 시트

- 표시를 탭하면 **하단 시트 하나**가 열린다. 번역이든 교정이든 같은 컴포넌트이며
  내용만 다르다. medium detent와 grabber를 쓴다.
- 교정: `이렇게 쓰면 더 자연스러워요` → 개선 문장(바뀐 자리에 밑줄) → 항목별 이유.
- 번역: `내가 쓴 한글` → 원문 → 표현 노트와 대체 표현.
- 시트 하단의 `더 물어보기`가 **문장 질문**을 연다. 창 상단에 대상 문장이
  인용 카드로 고정되고, 헤더 서브타이틀에 원래 에피소드 이름이 남는다.
- 문장 질문은 저장된다. 같은 문장에서 다시 열면 지난 내용이 이어서 나온다.
  진입점이 그 문장 하나뿐이므로 별도의 목록 화면은 만들지 않는다.

## 대화 종료

- 목표를 모두 달성하거나 턴 상한에 도달하면 composer가 사라지고 `결과 보기`
  버튼으로 바뀐다. 위에 끝난 이유가 한 줄 붙는다. 대화는 화면에 그대로 남는다.
- 결과 화면 헤더는 **뒤로 가기와 `다시 하기`**만 갖는다. 시나리오 제목은 본문
  맨 위 작은 줄로 내려 잘림 없이 보이게 한다.
- 본문 순서는 시나리오 제목 → 결과 헤드라인 → 목표 → 이번 글쓰기 → 내가 쓴
  문장이다.
- 목표 결과는 달성과 미달성을 체크와 빈 원으로 표시한다. X 표시는 쓰지 않는다.
- **이번 글쓰기**는 AI 총평 한 문단이다. 개별 실수가 아니라 반복되는 약점을
  짚고 다음에 챙길 것을 알려준다.
- **내가 쓴 문장**은 발화 전체를 목록으로 두고, 대화 화면의 세 표시를 그대로
  재사용한다. 화살표가 있는 줄을 탭하면 대화 중과 같은 시트가 열린다.
- 턴 수와 문장 수를 요약하는 문장은 두지 않는다. 개수는 섹션 타이틀이 담는다.
- 하단은 결과와 무관하게 `새 에피소드 시작`과 `대화 보기`로 고정한다.

## 모델 호출

- 역할이 다른 모델을 **셋** 쓴다. 롤플레잉은 큰 모델, **판정과 에피소드 생성은
  작은 모델**이다. 모델 ID는 모두 코드에 고정한다.
- 모바일은 지금처럼 **한 번만 요청**한다. 롤플레잉 스트림과 판정 호출은 Hono
  안에서 병렬로 돈다. 두 호출을 나누는 이유는 요구하는 모델 크기가 다르고,
  판정이 실패해도 대화가 계속되어야 하며, 프롬프트가 각자 한 가지만 해야
  하기 때문이다.
- 판정 결과는 `createUIMessageStream`으로 **같은 스트림에 data part로 얹어**
  보낸다. 설치된 `ai` 7.0.40이 `createUIMessageStream`·`DataUIPart`·
  `ChatOnDataCallback`을 제공하며, `@ai-sdk/react` 4.0.43이 그 타입을 그대로
  쓴다.
- **판정 호출 하나가 판정·개선문·이유를 모두 낸다.** 나중에 만들지 않는다.
  작은 모델이라 출력이 조금 느는 비용보다, 호출 경로가 하나 더 생기고 시트가
  네트워크에 의존하게 되는 비용이 크다. 결과 화면에서 문장을 연달아 볼 때도
  전부 즉시 뜬다.
- 판정은 롤플레잉 응답보다 늦게 도착할 수 있다. 표시 자리는 44pt 고정 열이라
  비워 두었다가 채우면 레이아웃이 흔들리지 않는다.
- 에피소드 생성은 **두 번** 부른다. ① 시나리오 후보 3개 → ② 선택한 시나리오의
  역할과 목표. 한 번에 다 만들면 작은 모델이 긴 구조화 출력에서 품질을 잃고,
  고르지 않은 후보의 역할·목표가 버려진다. 재생성은 해당 부분만 다시 부른다.
- 선택 즉시 ②를 백그라운드로 앞당기지 않는다. 복잡성에 비해 이득이 적다.
  따라서 `② 생성 중` 상태는 실제로 보이는 상태다.

## 데이터

기존 `chat_rooms`·`chat_messages`는 폐기하고 새로 만든다.

| 테이블 | 담는 것 |
| --- | --- |
| `episodes` | 시나리오, 상대와 내 역할, 상태, 턴 상한, 총평 |
| `episode_goals` | 목표 3행. 순서, 문장, 달성 시각, 달성한 메시지 |
| `episode_messages` | 전달된 문장, role, status |
| `message_feedback` | 입력 원문, 판정, 개선문, 이유 |
| `sentence_question_messages` | 문장 질문에서 주고받은 말 |

- `episodes`는 **턴 상한을 생성 시점 값으로 복사해 갖는다.** 상수를 바꿔도 이미
  끝난 에피소드의 종료 사유가 흔들리지 않아야 한다.
- `episode_goals`가 **달성한 메시지**를 갖는 이유는 대화 흐름에 남는 완료 줄의
  위치를 정하기 위해서다. 시각만으로는 어디에 끼울지 알 수 없다.
- `message_feedback`을 나눈 이유는 AI 메시지에는 값이 전부 비고, 판정이 늦게
  도착하므로 **행이 없음이 곧 판정 전**이 되어 상태를 따로 표현할 필요가 없기
  때문이다.
- `sentence_question_messages`는 부모 메시지를 참조한다. 문장 질문은 문장당
  하나뿐이라 별도의 방 테이블이 필요 없다.
- 턴 수는 사용자 메시지를 세면 나오므로 컬럼으로 두지 않는다.
- 권한은 기존 패턴을 따른다. **앱은 읽기와 에피소드 삭제만** 할 수 있고 쓰기는
  전부 service_role이다. 에피소드 생성부터가 AI 호출이라 앱에 insert 권한을 줄
  이유가 없다.

## 문구

사용자 문구는 [당근 voice 계약](../../decisions/danggeun-voice-for-copy.md)을
따른다. 이 화면들에서 확정된 문구는 다음과 같다.

- 생성 스텝 제목: `이런 상황 어때요?` / `이런 역할 어때요?` / `이번 대화의 목표예요`
- 시트 액션: `더 물어보기`
- 결과 헤더 액션: `다시 하기`
- 결과 하단: `새 에피소드 시작`, `대화 보기`

## Why

말풍선에 전달된 문장을 남기는 이유는 이 앱이 파는 것이 "내 영어가 실제로
통하는가"이기 때문이다. 교정본을 보내면 사용자는 언제나 완벽한 영어를 말하는
사람이 되어 롤플레잉이 실력을 비추지 못한다. 원문을 보내면 대화 자체가 검증이
되고, 체크와 첨삭 표시가 각각 "그대로 통했다"와 "통했지만 더 나은 표현이 있다"는
뜻을 갖는다.

턴 상한은 목표가 아니라 안전망이다. 목표 3개에 각 2턴, 인사와 마무리에 2턴이면
8턴이라 10턴은 옆길로 새는 순간 상한에 걸린다. 옆길로 새는 것이 롤플레잉의
연습 가치이므로 상한은 자주 부딪히지 않을 만큼 넉넉해야 한다.

## Assumptions

반증이 나오면 계약 변경 없이 뒤집는 기본값이다.

- 상황 후보는 3개를 보여준다.
- 선택한 시나리오 텍스트는 선택 후에도 직접 고칠 수 있다.
- 첨삭 시트는 medium detent로 충분하다. 내용이 커지면 다시 본다.
- 문장 대화는 별도 화면으로 push한다. 시트 위에 시트를 쌓지 않는다.
- 결과 화면의 문장 목록은 발화 전체를 나열한다. 첨삭이 있는 것만 추리지 않는다.

## Evidence worth preserving

- 애플 HIG는 [컨텍스트 메뉴가 기본적으로 숨겨져 있어 존재를 모를 수 있으니 항상
  메인 인터페이스에도 같은 항목을 두라](https://developer.apple.com/design/human-interface-guidelines/context-menus)고
  명시한다. 롱프레스 단독은 주 경로가 될 수 없다.
- HIG는 [info 버튼을 "행의 내용에 대한 더 많은 정보를 드러낼 때만" 쓰라](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)고
  규정한다. 첨삭 시트가 정확히 이 용도다.
- 애플 메시지는 말풍선을 탭해도 아무 일도 일어나지 않는다. 표시 없는 탭은
  발견되지 않는다.
- Apple Writing Tools의 인라인 밑줄은 **이미 적용된 변경**을 뜻한다. 교정 전
  문장에 밑줄을 그으면 의미가 반대가 된다.
- 원형 화살표는 iOS에서 새로고침을 뜻한다. 재시작 액션에 쓰면 예상과 다른 일이
  벌어진다.
- 실제 앱들의 지속 목표 표시는 헤더 아래 또는 composer 위로 수렴하고, 밀도는
  예외 없이 "현재 것 하나만 한 줄"이다. 전체 목록을 기본 노출하는 사례는 없었다.
- 위저드에 리캡을 덧대는 방식은 어떤 스타일을 입혀도 이질감이 남았다. 토스식
  누적 폼은 이전 결정이 화면의 일부가 되어 구분 문제 자체를 없앤다.

## Deferred

- **턴 표시 자리.** 지금은 목표 바를 펼쳤을 때만 보인다. 남은 턴이 적을 때만
  드러내는 경고성 표시가 후보다. 상한에 임박한 사용자가 그 사실을 모르면 대화가
  갑자기 끝난 것처럼 느낄 수 있다.
- **표현 저장.** 첨삭받은 문장을 모아 두는 자리를 만들지 정하지 않았다. 만들면
  복습 화면이 새로 필요하다.
- **판정 실패 시 표현.** 롤플레잉은 성공했는데 판정만 실패하면 표시가 영영 안
  붙는다. 재시도할지, 빈 채로 둘지 정하지 않았다.
- **에피소드 목록과 이력.** 지난 에피소드를 어디서 다시 여는지 정하지 않았다.
- **한글 입력 비율.** 비상구로 위치를 낮췄지만, 계속 한글만 쓰는 사용자를 어떻게
  다룰지는 정하지 않았다.
- **중간 이탈.** 대화 도중 나갔을 때 이어할 수 있는지 정하지 않았다.

## Risks

- 영어 원문을 그대로 보내므로 초급 사용자의 문장이 심하게 깨지면 대화가 어긋날
  수 있다. AI의 선해 지침이 이를 감당하지 못하면 목표 달성이 막히고 에피소드가
  실패로 끝난다.
- 목표 3개는 AI가 만들고 판정도 AI가 한다. 판정이 흔들리면 사용자는 달성했다고
  느끼는데 표시는 안 되는 상황이 생긴다.
- 결과 화면의 총평은 반복 약점을 짚어야 가치가 있는데, 5문장 남짓의 표본으로
  패턴을 말하면 근거가 약한 지적이 나올 수 있다.
- 한글 입력이 편한 길로 남아 있는 한, 작문 연습이라는 목적이 침식될 여지가 있다.
