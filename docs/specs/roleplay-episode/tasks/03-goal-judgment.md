# 03. 목표 달성을 판정한다

상태: 시작 전

## 전달되는 행동

사용자가 발화할 때마다 판정이 롤플레잉과 함께 돌아 목표 달성을 알아본다.
달성하면 대화 흐름에 초록 한 줄이 그 발화 자리에 영구히 남아, 스크롤만으로
언제 달성했는지 되짚을 수 있다. 목표 바는 곧바로 다음 목표로 넘어가고, 완료는
초록 체크, 현재는 파란 링, 남은 것은 회색 원으로 갈린다.

판정은 롤플레잉 응답보다 늦게 도착할 수 있고 대화는 그대로 먼저 흐른다. 판정만
실패하면 대화 화면에는 아무것도 알리지 않고, 다음 판정 호출이 못 채운 발화까지
함께 판정해 조용히 메운다.

## 블로커

- **02** — 판정 대상인 저장된 사용자 발화와, 판정 결과가 얹히는 롤플레잉 스트림이
  02에서 생긴다.

## 완료 기준

- [ ] 모바일은 발화 한 번에 요청을 한 번만 보낸다
- [ ] 롤플레잉 응답과 판정이 서버 안에서 병렬로 돌고 판정이 같은 스트림으로 도착한다
- [ ] 목표를 달성하면 그 발화 자리에 초록 한 줄이 남고, 다시 들어와도 같은 자리에 있다
- [ ] 목표 바가 달성 즉시 다음 목표로 넘어가고 세 상태가 눈으로 갈린다
- [ ] 판정이 늦게 와도 대화는 먼저 흐른다
- [ ] 판정만 실패하면 대화 화면에 아무 알림도 뜨지 않고 대화가 계속된다
- [ ] 판정이 빠진 발화가 다음 판정에서 함께 채워진다
- [ ] 판정 한 번이 판정·개선문·이유를 함께 남긴다

## 제약

- 판정 호출은 하나다. 개선문이나 이유를 나중에 따로 부르지 않는다.
- 판정 결과는 data part로 롤플레잉 스트림에 얹어 보낸다. 별도 요청을 만들지
  않는다.
- `message_feedback`은 이 태스크가 만든다. **행이 없음이 곧 판정 전**이므로
  판정 전 상태를 나타내는 빈 행을 미리 만들지 않는다.
- 개선문과 이유는 저장만 하고 화면에 드러내지 않는다. 드러내는 것은 04다.
- 판정 프롬프트는 판정 한 가지만 한다. 롤플레잉 프롬프트에 섞지 않는다.
