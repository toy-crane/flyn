# 스토리 선택 명세

## 목표

- 미리 만들어 둔 여러 스토리 중에서 사용자가 하나를 골라 시작하고, 하던
  스토리로 막힘 없이 돌아가는 화면 구조를 만든다.
- 스토리를 만드는 기능은 범위가 아니다. 콘텐츠는 제품이 미리 만든다.
- 구조와 이름의 근거는 [스토리 구조](../../decisions/story-structure.md)가,
  콘텐츠와 저장은
  [스토리 콘텐츠 데이터베이스 명세](../story-content-database/spec.md)가,
  진행과 결말의 표기 문법은
  [스토리 진행·결말 화면 표기](../../decisions/story-progress-and-ending-display.md)가
  소유한다. 제품 전제는 루트 `PRODUCT.md`를 따른다.
- 승인된 화면 전체는 [prototype.html](./prototype.html)이 기준이다. 문서와
  프로토타입이 다르면 프로토타입이 승인된 쪽이다.

## 확정 범위

- 탭은 홈과 스토리 둘이다. 템플릿에서 온 Activity·Saved 더미 탭은 지운다.
- 화면은 이 단위를 스토리라고 부른다. 탭 라벨도 스토리다. "이야기"는
  지금처럼 에피소드를 가리키는 자리("다음 이야기")에 남는다.
- 홈과 스토리 탭은 같은 스토리 카드 컴포넌트를 공유한다. 카드 구성은 표지
  타일(72pt 정사각), 스토리 제목, "n화 · 화 제목" 한 줄, 보조 한 줄(예고
  또는 상황 훅), 분절 진행 바, 하단 전체 폭 버튼이다.
- 이어 하기 카드는 홈에만 노출한다. 두 탭에 같은 카드를 중복 노출하지
  않는다. 홈은 잇는 자리, 스토리 탭은 고르고 되돌아보는 자리라는 역할
  구분을 지키기 위해서다.
- 홈은 진행을 잇는 자리다.
  - 섹션 제목 아래 이어 하기 카드 하나를 보여 준다. 제목은 진행 중이면
    "이어 하기", 처음 온 사용자면 "첫 이야기"다.
  - 카드의 버튼 문구는 상태를 따라 바뀐다. 화 사이면 "3화 시작하기",
    진행하다 만 화면 "이어서 하기", 처음이면 "1화 시작하기"다. 카드 어디를
    눌러도 버튼과 같은 곳(에피소드)으로 간다.
  - 진행 중인 스토리가 여럿이면 최근 것을 카드로, 나머지는 아래 "진행 중인
    스토리" 목록 행으로 보여 준다.
  - 처음 온 사용자에게는 제품이 정한 첫 스토리의 1화 카드를 보여 준다.
  - 모든 스토리를 완주했으면 스토리 탭으로 안내하는 카드를 보여 준다.
- 스토리 탭은 "모든 스토리" 목록 하나다.
  - 모든 공식 스토리를 정해진 순서로 보여 준다. 행 구성은 표지 타일, 제목,
    한국어 상황 훅 한 줄(말줄임 한 줄 고정), 분절 진행 바다.
  - 행을 누르면 스토리 상세가 열린다.
  - 상황 훅은 "첫 해외 출장인데, 호텔에 제 예약이 없대요"처럼 사용자에게
    벌어진 사건을 1인칭 한 줄로 쓴다. 스토리의 한 줄 소개 데이터가 이
    형식으로 쓰인다. 영어 대사 인용은 목록 행에 쓰지 않고, 공간이 있는 큰
    카드(홈 이어 하기 카드)와 스토리 상세에서만 쓴다.
- 진행 상태는 분절 진행 바 하나로 표기한다. 화 수만큼 칸을 나눠 빈 바는
  시작 전, 부분 채움은 진행 중, 가득 참은 완료다. 바 옆에 화 번호, 체크,
  상태 낱말을 붙이지 않는다. "5화 중 2화 완료" 같은 문장형 표기는 쓰지
  않는다. 근거와 세부 규칙은
  [스토리 진행·결말 화면 표기](../../decisions/story-progress-and-ending-display.md)가
  소유한다.
- 스토리 상세는 소개, 진행 바, 시작·이어 하기 버튼, 에피소드 목록을 보여
  준다.
  - 목록 제목은 "에피소드 목록"이다. 총 화 수는 "에피소드 5개"처럼 센다.
  - 끝낸 화 행에는 결말 낱말 대신 그 화에서 얻어낸 결과 한 줄("원하는
    커피로 바꿔냈어요.")이 붙는다. 이야기 기억의 "사건의 결과"를 그대로
    쓴다. 행을 누르면 대화 기록이 읽기 전용으로 열린다.
  - 다음 화 행은 제목과 예고를 보여 주고 accent 화 번호와 굵은 제목으로
    구분한다. 칩은 붙이지 않는다.
  - 아직 열리지 않은 화는 제목을 공개하고 예고만 감춘다. 흐린 처리와 잠금
    아이콘으로 구분한다. 궁금증은 제목이 만들고, 스포일러는 예고에 있다는
    판단이다.
  - 완주한 스토리의 상세에 완주 안내 카드를 두지 않는다. 완주 안내 문구는
    마지막 화를 끝내는 마무리 순간에만 쓴다.
- 대화 기록은 읽기 전용이며, 끝에 "끝" 구분선과 결과 문장이 붙는다. 읽기
  전용을 설명하는 안내 문구는 두지 않는다. 입력창이 없다는 것으로 충분하다.
- 성공·타협·실패 세 낱말은 서버 내부 어휘로만 남고 화면 어디에도 노출하지
  않는다.
- 여러 스토리를 동시에 진행할 수 있다. 스토리마다 이야기 기억과 진행이 따로
  이어지고 서로 섞이지 않는다.
- 처음 온 사용자도 첫 화를 끝내기 전에 스토리 탭에서 다른 스토리를 시작할 수
  있다.
- 스토리는 한 줄 소개(상황 훅)와 표지 이미지를 콘텐츠 데이터로 가진다.
  스토리 콘텐츠 데이터베이스 명세가 정한 스토리 데이터(제목, 완주 안내,
  순서)에 더해지는 항목이다.
- 표지는 스토리마다 대표 캐릭터 포트레이트 일러스트 1장이다. 출시 스토리
  분량(5개 내외)의 이미지는 사용자가 콘텐츠 제작 때 미리 생성해 둔다.

## 확정 제약과 이유

- 홈과 스토리 탭의 분리는 사용자가 확정했다. 홈은 잇는 자리, 스토리 탭은
  고르고 되돌아보는 자리로 역할이 갈리고, 이어 하기 카드의 중복 노출 금지도
  같은 근거에서 사용자가 확정했다.
- 화면 이름 스토리는 사용자가 확정했다. "이야기"는 이미 에피소드를 가리키는
  문구에 쓰여, 한 개념 한 표현 원칙상 두 단위에 겹쳐 쓸 수 없다. 근거는
  [스토리 구조](../../decisions/story-structure.md)가 소유한다.
- 첫 화 전 선택 개방은 사용자가 확정했다. `PRODUCT.md`의 "첫 에피소드는
  사용자가 고르지 않고 제품이 정한다"는 기본 동선에 대한 말로 해석한다.
  홈의 기본 동선은 여전히 제품이 정한 첫 화이고, 스토리 탭에서 스스로
  고르는 것은 막지 않는다.
- 진행 표기(분절 바)와 결말 표기(결과 문장, 내부 낱말 비노출)는 2026-08
  리서치와 시안 비교를 거쳐 사용자가 확정했다. 근거와 재검토 조건은
  [스토리 진행·결말 화면 표기](../../decisions/story-progress-and-ending-display.md)가
  소유한다.
- 카드 컴포넌트 공유와 하단 전체 폭 버튼은 세 가지 카드 구성 시안을 비교해
  사용자가 확정했다. 이어 하기가 화면에서 가장 강한 CTA여야 한다는 요구가
  근거다.
- 잠긴 화의 제목 공개는 사용자가 확정했다. 2026-08 리서치에서도 제목과
  자리를 공개하고 열기만 잠그는 것이 지배적 관행이었다.
- 이 명세는 스토리 콘텐츠 데이터베이스 명세 위에 선다. 스토리·에피소드가
  데이터로 존재하고, 진행 중 장면이 계정에 남고, 끝난 화의 대화 기록을 읽을
  수 있다는 전제를 그 명세가 만든다. 지금 스키마에는 아직 없으므로 그
  구현이 먼저다.

## 수용 기준

- 스토리 탭에 모든 공식 스토리가 정해진 순서로 보이고, 각 행에서 표지 타일,
  제목, 한국어 상황 훅, 분절 진행 바를 읽을 수 있다.
- 진행 상태는 화면 어디서든 분절 바로만 보이고, "n화 중 m화 완료" 같은
  문장형 표기와 상태 낱말 칩이 어디에도 없다.
- 홈에 이어 하기 카드가 섹션 제목과 함께 보이고, 스토리 탭에는 이어 하기
  섹션이 없다.
- 홈 카드와 스토리 탭 행이 같은 스토리 카드 컴포넌트를 사용한다.
- 시작 전 스토리의 상세에서 1화를 시작할 수 있고, 시작하면 그 스토리가 홈
  이어 하기에 나타난다.
- 진행 중 스토리의 홈 카드를 누르면(버튼 포함) 진행하던 장면부터 이어진다.
  화 사이라면 다음 화가 시작된다.
- 두 스토리를 번갈아 진행해도 각자의 진행 상태와 이야기 기억이 섞이지
  않는다.
- 새 계정의 홈에 제품이 정한 첫 화 카드가 "첫 이야기" 제목과 함께 보이고,
  그 화를 끝내지 않아도 스토리 탭에서 다른 스토리를 시작할 수 있다.
- 끝낸 화 행에 그 화의 결과 한 줄이 보이고, 행을 열면 대화 전부를 읽을 수
  있되 입력할 수 없다. 기록 끝에는 "끝" 구분선과 결과 문장이 보인다.
- 아직 열리지 않은 화는 제목이 보이고 예고는 보이지 않으며 열 수 없다.
- 성공·타협·실패 낱말이 화면 어디에도 노출되지 않는다.
- 홈에 끝낸 화 목록이 더는 없고, Activity·Saved 탭이 없다.
- 저장소 루트에서 `bun run check`와 `bun run check-types`가 통과한다.

## 가정

아래는 에이전트가 정한 값이라 사용자가 뒤집을 수 있다.

- 표지 타일은 72pt 정사각에 라운드 14pt다. 이미지가 아직 없는 스토리는
  시그니처 색 그라데이션과 이모지 타일로 대체한다.
- 결과 한 줄은 해요체 짧은 문장으로 다듬는다. 이야기 기억의 "사건의 결과"를
  쓰되, 길이와 말투를 맞추는 규칙은 구현에서 정한다.
- 홈 이어 하기 카드의 보조 한 줄은 화 사이일 때 예고(상황 훅), 진행하다 만
  화일 때 "진행하던 장면부터 이어가요."다.
- 상세 시작 전 헤더의 총량 표기는 "에피소드 5개"다.
- 스토리 상세로 가는 길은 스토리 탭 행뿐이다. 홈 카드는 어디를 눌러도
  에피소드로 간다.
- 뒤로 가기 버튼은 네이티브 셸의 기본 동작을 따르고 커스텀하지 않는다.
  iOS 기본값은 이전 화면 제목을 라벨로 쓰고 길면 시스템이 "뒤로"로 줄인다.
  프로토타입의 "‹ 스토리" 표기는 이 기본값을 흉내 낸 것이다.

## 제외

- 스토리 제작, 공유, 탐색 피드. 제품 정의를 먼저 거친다.
- 추가 스토리의 콘텐츠 제작. 출시 5개 내외의 스토리와 표지 이미지는
  사용자가 별도로 만든다. 이 구조는 스토리 하나로도 성립한다.
- 스토리 생성 기능에 이미지 생성 API를 붙이는 일. 추후 과제다.
- 커밍순 카드(다음 스토리 예고), 신작 점 표시, 상태 낱말 칩. 시안 검토에서
  사용자가 제외했다.
- 끝난 화 다시 하기. 결말 확정 결정을 유지한다.
- 복습(오늘 배운 표현) 화면과 셋째 탭.

## 보류

- 스토리가 많아질 때의 검색, 분류, 추천. 공식 스토리가 한 자릿수인 동안은
  순서 목록으로 충분하다.
- 표지 일러스트의 스타일 가이드. 사용자가 이미지를 만들며 정한다.
- 마무리 화면에서 완주 안내 문구를 쓰는 구체 위치와 모양. 완주 안내가
  마무리 순간의 몫이라는 결정까지만 이 명세가 정한다.

## 남은 위험

- 스토리 콘텐츠 데이터베이스 명세가 아직 구현되지 않았다. 이 화면 구조는 그
  구현 없이는 세울 수 없어 순서가 묶인다.
- 스토리 데이터에 필요한 항목이 늘었다(상황 훅 한 줄, 표지 이미지). 콘텐츠
  DB 구현이 이 항목을 함께 반영해야 한다.
- 결과 한 줄은 모델이 남기는 이야기 기억에서 오므로 길이와 말투가 흔들릴 수
  있다. 표기 규칙과 잘라내기 기준이 구현에서 필요하다.
- 공식 스토리가 하나뿐인 동안 스토리 탭이 빈약해 보인다. 구조 검증은
  가능하지만, 고르는 경험의 검증은 두 번째 스토리가 있어야 한다.
- 첫 화 전 선택을 열어 두면 사용자가 수준 파악 전에 어려운 스토리로 갈 수
  있다. 각 스토리의 1화도 각본이라 통제는 남지만, 출발 난이도 설계가 콘텐츠
  제작의 몫이 된다.
