# 상황에 맞는 영어 표현 제안

## 목적

사용자가 지금 하려던 말을 그 상황에 맞는 영어로 배운다. 의미 전달, 언어의 정확성,
상황에 맞는 표현을 구분한다. 뜻이 통하더라도 실제 오류는 고치고, 오류가 없어도
배울 차이가 있으면 표현을 제안한다. 제안한 문장을 유일한 정답으로 가르치지 않는다.

## 승인한 화면

[프로토타입](prototype.html)은 대화 중 배울 표현의 표시와 상호작용 기준이다.
상단 state 메뉴에서 17가지 사례를 확인한다. 사례 이름은 검토 도구에만 있으며
앱에는 표시하지 않는다. 새 카드는 접힌 상태로 나타나고 사용자가 펼쳐 설명을 읽는다.

프로토타입은 고정 예시다. 모델의 실제 답변 품질을 입증하지 않는다. 상단 검토 도구,
더미 대화 전송, 물어보기의 고정 답변, 재시도의 즉시 완료는 제품 동작의 기준이 아니다.

## 의존하는 결정 계약

- [AI 에피소드 프로토콜](../../decisions/ai-episode-protocol.md): 판정, 표기,
  원문과 제안문의 대응, 기존 결과 보존과 서버 검사 기준을 정한다.
- [모바일 대화 중 교정](../../decisions/mobile-episode-correction.md): 카드 배치,
  오류 표시와 표현 강조, 확인 상태, 접기·펼치기 및 재시도를 정한다.
- [모바일 AI에게 물어보기](../../decisions/mobile-ask-ai.md): 출처를 둔 시트와
  본 대화로 돌아오는 동작을 정한다. 이번 작업에서 별도 대화 기능을 바꾸지 않는다.
- [AI 프롬프트 평가](../../decisions/ai-prompt-evaluation.md): 평가 실행 방식,
  기존·새 출력 비교와 기록을 정한다.
- [UX 라이팅 원칙](../../decisions/ux-writing.md): 고정 UI 문구를 정한다.

## 승인된 범위

### 판정과 제안

- 문법적으로 맞아도 상황에 더 잘 맞고 배울 차이가 있는 영어 문장 하나를 제안한다.
- 이미 상황에 적절하면 그대로 두고 문제없음을 알린다. 동의어, 축약형, 공손함,
  어려운 숙어나 문장 길이만 바꾸는 것을 배움으로 보지 않는다.
- 원문의 뜻, 요청한 행동, 감정과 태도를 유지한다. 낱말과 문장 구조는 바꿀 수 있다.
- 새 메시지마다 같은 기준으로 확인한다. 반복 여부를 따로 판정하거나 관리하지 않는다.
- 실제 오류에는 고칠 이유를, 오류 없는 표현의 제안에는 그 상황에서 배울 이유를
  설명한다. 뜻이 통한다는 이유로 실제 오류를 넘어가지 않고, 대안이 있다는 이유로
  올바른 원문을 틀렸다고 설명하지 않는다.
- 문맥으로도 뜻이 불분명하면 뜻을 만들어 제안하지 않는다.
- 한국어·한영 혼합 입력은 영어 표현을 안내하며 한국어를 오류로 표시하지 않는다.

### 화면에서 확인할 수 있는 구분

- 원문에서는 실제 오류가 있는 부분에만 밑줄을 표시한다. 단순한 표현 제안 때문에
  바뀐 원문이나 한국어 원문에는 오류 밑줄을 붙이지 않는다.
- 제안문에서는 배울 핵심 표현을 강조한다. 원문의 오류 표시와 제안문의 강조가
  반드시 같은 범위일 필요는 없다.
- 오류와 제안이 함께 있으면 하나의 카드에서 둘을 다룬다. 문장 전체를 바꾸는
  제안은 원문과 제안문을 한 번씩 보여 주고, 고칠 이유와 배울 이유를 구분해 설명한다.
- 서로 독립된 여러 오류는 기존처럼 표현 조각별 항목으로 보여 줄 수 있다.
  각 항목에 원문, 제안 표현과 해당 이유가 대응해야 한다.
- 오류 수정과 표현 제안을 나누는 별도 배지나 선택 단계는 만들지 않는다.
- 확인 실패도 다른 확인 상태와 같은 말풍선 아래 간격, 줄 높이와 오른쪽 정렬을
  쓴다. 재시도 버튼의 누름 영역 때문에 문구가 아래로 내려가지 않는다.
- 복사와 저장은 모든 수정을 반영한 제안문 전체를 다룬다.

## 수용 기준

1. 포장 주문 문맥에서 `Can I take this coffee with me?`에 `to go` 같은 배울
   표현을 제안하고, 원문을 문법 오류로 설명하거나 밑줄로 표시하지 않는다.
2. 같은 문맥에서 `Can I get this coffee to go?`는 대안을 만들기 위해 바꾸지 않는다.
3. `I wants this coffee in a cup I can take away.`에서는 `wants`만 오류로 짚는다.
   `I want this coffee to go.`처럼 제안하며 want와 to go의 설명을 구분한다.
4. `I want my money back.`의 환불 요구를 교환 요청이나 사과로 바꾸지 않는다.
   직설적인 태도만으로 오류를 만들거나 공손함을 강요하지 않는다.
5. 여러 오류와 긴 문장에서도 실제 오류를 빠뜨리지 않고 뜻을 유지한다. 원문에 없는
   수량, 알레르기, 환불 요구, 양보 같은 사실과 의도를 추가하지 않는다.
6. 같은 원문이라도 앞선 상황이 다르면 제안의 적절성을 다시 판단한다. 특정 문장을
   보면 문맥과 관계없이 같은 숙어를 붙이지 않는다.
7. 기존 문법·철자 오류는 계속 고친다. 표기나 채팅 말투만 다른 문장은 그대로 둔다.
8. 한국어·한영 혼합 안내, 뜻을 알 수 없음, 확인 중, 실패와 재시도를 구분해 표시한다.
9. 새 판정 결과가 실제 서버 검사와 저장을 거쳐 화면에 표시된다. 큰 문장 구조 변경을
   유효한 이유 없이 실패로 처리하지 않는다. 원문 표시, 제안문 강조, 이유와 돌아보기
   내용이 서로 맞는다.
10. 접기·펼치기, 물어보기 복귀, 복사·저장과 재시도가 기존 대화 흐름을 지킨다.
    작은 화면과 다크 모드에서도 오류와 제안의 차이를 읽을 수 있다.

## eval 요구사항

- 기존 문법·철자·표기·채팅 말투 사례를 유지한다.
- 다음 묶음을 추가한다: 문법은 맞지만 배울 표현이 있는 경우, 이미 적절한 표현,
  오류와 제안이 함께 있는 경우, 같은 문장에 다른 문맥을 준 경우, 태도 보존,
  뜻과 사실 보존, 긴 문장과 여러 오류, 한국어·한영 혼합, 뜻이 불분명한 입력.
- 표현 제안의 정답을 특정 문장 하나로 고정하지 않는다. 각 사례에 보존할 뜻과 태도,
  배울 차이, 추가하면 안 되는 사실과 요구를 적는다. 정답이 명확한 철자 교정 등은
  정확한 문자열 비교를 유지할 수 있다.
- 실제 오류만 원문 표시 대상인지, 올바른 표현을 오류로 설명하지 않는지,
  제안문의 강조와 설명이 대응하는지 확인한다.
- 데이터 구조와 원문·제안문 대응은 자동 검사한다. 프롬프트 출력만 통과하고 실제
  서버에서 거절되는 결과가 없도록 실제 결과 검증 경로의 수용 여부도 확인한다.
- 자연스러움과 배울 가치는 기존·새 프롬프트의 출력 전문을 비교해 판단한다.
  종전 프롬프트가 놓친 배움을 확인하되, 기존에 잘 처리하던 입력이 나빠지지 않아야 한다.
- 사례별 3회 실행한다. 출력과 실패 이유를 남기며, 실제 모델 평가는 일반 CI와 분리한다.
- 실패 문구 위치, 접기·펼치기와 재시도 동작은 프롬프트 eval 대신 UI 검증으로 확인한다.

## 제외하는 범위

- 반복 실수 추적, 반복 횟수 표시, 반복 여부에 따른 별도 처리.
- 모든 문장에 대안 만들기, 여러 대안 나열하기, 교정 강도 설정과 새 화면.
- 이미 저장된 판정을 다시 생성하거나 과거 데이터를 삭제하는 작업.
- 본 대화와 물어보기의 진행 방식, 한국어 안내의 목적, 저장·노트의 소유권 변경.

## 가정과 남은 위험

- 변경 가능한 가정: 현재 제목과 카드 구조를 유지한다. 복합 제안의 짧은 설명들은
  원문·제안문 아래 나누어 놓는다. 프로토타입의 정확한 여백과 아이콘 대체물은
  네이티브 디자인 시스템에 맞춘다.
- 상황에 맞는 표현의 판단에는 편차가 있다. 과도한 제안, 뜻·태도 변경과 오류 오판을
  eval에서 함께 확인한다. 예시 문장과 같다는 것만으로 품질을 확정하지 않는다.
- 기존 데이터가 새 오류 표시와 표현 강조를 구분할 수 없을 수 있다. 기존 기록은
  보존하며, 새로운 판정부터 구분을 정확하게 전달한다. DB 변경 없음이나 특정 데이터
  구조를 확정하지 않는다. 구현은 저장된 결과와의 호환을 지켜야 한다.
- 미룬 제품 결정은 없다. 이번 확정은 명세와 프로토타입에 한하며 실제 프롬프트,
  서버 검사, UI와 eval 구현 및 실제 모델 검증은 남아 있다.
