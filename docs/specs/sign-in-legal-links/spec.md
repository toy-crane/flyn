# 로그인 전 법적 고지 링크

## 사용자에게 보이는 결과

- 로그인하지 않은 사람도 로그인 방법 선택 화면에서 `이용약관`과 `개인정보 처리방침`을 열 수 있다.
- 두 링크는 로그인 버튼 묶음 바로 아래에 각각 독립된 누르기 영역으로 보인다. 링크를 열고 돌아와도 로그인 방법을 고를 수 있다.
- 링크만 보여 준다. 약관 동의나 개인정보 처리 동의를 받는다는 안내, 체크박스, 새 동의 단계는 없다.

## 범위

- iOS와 Android의 로그인 방법 선택 화면에 같은 두 링크를 둔다. iOS에는 Apple, Google, 이메일 버튼이, Android에는 Google, 이메일 버튼이 유지된다.
- 각 링크는 설정 화면에서 쓰는 문서와 같은 공개 웹 페이지를 시스템 브라우저로 연다.
- 밝은 화면과 어두운 화면에서 링크가 읽히고, 시스템 글자 크기를 키운 뒤 앱을 다시 시작해도 버튼이나 링크가 겹치거나 화면 밖으로 사라지지 않는다.

## 완료 기준

- 로그인 방법 선택 화면에서 버튼 아래에 `이용약관`과 `개인정보 처리방침`이 이 순서로 보이며, 각각 따로 누를 수 있다.
- `이용약관`은 공개 `/terms`, `개인정보 처리방침`은 공개 `/privacy`를 연다. 문서에서 앱으로 돌아오면 로그인 방법 선택 화면을 그대로 쓸 수 있다.
- 두 플랫폼 모두 로그인 방법 버튼의 순서와 동작이 바뀌지 않는다.
- 화면은 두 링크를 동의 표시나 동의 기록으로 취급하지 않는다.

## 제약과 근거

- [모바일 인증](../../decisions/mobile-authentication.md)은 플랫폼별 로그인 방법과 버튼을 정한다. 이 작업은 그 흐름을 바꾸지 않는다.
- [모바일 설정 구조](../../decisions/mobile-settings-structure.md)는 문서를 시스템 브라우저로 여는 방식을 정한다. 로그인 전 링크도 같은 결과를 따른다.
- [웹 표면 소유권](../../decisions/web-surface-ownership.md)은 두 문서의 공개 경로와 자리표시자 상태를 정한다. 링크를 추가해도 실제 법적 문안이 확정되었다는 뜻은 아니다.
- [UX 라이팅 원칙](../../decisions/ux-writing.md)과 `GLOSSARY.md`의 문서 이름을 그대로 쓴다.
- [모바일 타이포그래피](../../decisions/mobile-typography.md)가 정한 최대 시스템 글자 크기와 앱 재시작 절차로 확대 화면을 확인한다.
- 사용자가 비교 시안 A의 독립된 링크 두 개 배치를 선택했다. 비교 시안은 배치를 판단하기 위한 임시 자료였으므로 제품 화면 참고 파일로 보존하지 않는다.

## 가정

- 에이전트 가정: 두 링크 사이의 구분점과 작은 글자 크기는 비교 시안의 표현이다. 실제 기기에서 읽기와 누르기 영역을 지키기 위해 간격과 크기를 조정할 수 있다.

## 손대지 않는 것

- `/terms`와 `/privacy`의 실제 문안. 현재 자리표시자이며 사람이 따로 확정해야 한다.
- 동의 수집, 기록, 가입과 로그인 분리. 링크 노출만 승인되었다.
- 로그인 후 설정 화면의 기존 링크와 다른 인증 화면의 구성.

## 남은 위험

- 공개 웹 페이지가 자리표시자인 동안에는 이 링크만으로 스토어 배포 준비가 끝나지 않는다.
