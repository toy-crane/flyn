# 01 — 결함과 공용 컴포넌트 정리

## Outcome

다크 모드에서 메시지 메뉴와 인증 코드 칸의 표면 색이 카드와 같아진다. 인증 코드
칸이 HeroUI 기본 크기로 왼쪽에 모이고 틀린 코드의 표시가 HeroUI 무효 상태
외곽선으로 바뀌며, 이메일·닉네임·아이디·코드 화면의 오류 문구가 입력 칸에 붙은
필드 오류로 보인다. 채팅의 재시도 칩, 프로필 편집 알약, 교정 카드의 접기 버튼,
채팅의 보내기·중지·최신 메시지 버튼과 상태 줄의 재시도 아이콘이 HeroUI
컴포넌트의 눌림 반응과 비활성 표현을 갖는다. 공용 버튼의 가로 여백이 HeroUI
기본값으로 돌아가고, 소비자가 없는 토스트 설정이 사라지며, 로그인 버튼이 앱에서
고른 화면 모드를 테마 브리지에서 읽는다.

## Blockers

None.

## Acceptance criteria

- [ ] 저장소의 React Native UI에 `!important`로 HeroUI 클래스를 덮는 코드와 `opacity-40` 비활성 표현이 없다.
- [ ] 인증 코드를 틀렸을 때 칸의 무효 외곽선이 보이고, 칸은 HeroUI 기본 크기(44×48pt)로 왼쪽에 모인다.
- [ ] 이메일, 닉네임, 아이디, 코드 화면의 오류 문구가 입력 칸 아래 필드 오류로 보이고 화면 읽기에 알림으로 읽힌다.
- [ ] 재시도 칩, 프로필 편집 알약, 접기 버튼, 채팅 아이콘 버튼 네 개, 상태 줄 재시도 아이콘을 누르면 HeroUI의 눌림 반응이 있고, 비활성일 때 컴포넌트의 비활성 표현을 쓴다.
- [ ] iOS 다크 모드에서 메시지 메뉴, 인증 코드 칸, 카드의 표면 색이 같다. 밝은 모드에서도 이음새가 없다.
- [ ] 하단 행동 버튼과 인증 버튼의 너비와 자리가 달라지지 않는다.
- [ ] 앱에서 `다크`를 고르고 운영체제가 라이트여도 로그인 버튼 셋이 다크 모양이다.
- [ ] 로그인, 대화, 프로필 편집 화면을 기본 글자 크기와 최대 시스템 글자 크기로 앱을 완전히 닫고 다시 시작해 버튼과 칩이 잘리거나 겹치지 않는다.

## Constraints

- [모바일 컴포넌트 선택](../../../decisions/mobile-component-selection.md)의 예외 목록에 새 예외를 더하지 않는다. 공용 아이콘 버튼은 목록에 이미 있는 채팅 버튼과 아이콘 줄 자리를 모으는 것이다.
- 다크 모드 `overlay`와 `field-background`의 등재 자리와 값은 [모바일 색상 시맨틱](../../../decisions/mobile-color-semantics.md)을 따른다.
- 로그인 버튼의 브랜드 모양과 진행 표시는 [모바일 작업 진행 표시](../../../decisions/mobile-action-progress.md)가 소유한다. 색을 읽는 경로만 바꾼다.

## Verification

- 저장소 grep: React Native UI에서 `!` 접미 HeroUI 크기 클래스와 `opacity-40`이 0건.
- `bun run test`(모바일)가 통과하고, 공용 아이콘 버튼과 필드 오류의 접근성 역할·이름·상태를 검사하는 테스트가 있다.
- iOS 시뮬레이터 다크 모드에서 메시지 메뉴, 인증 코드 칸, 카드를 각각 찍어 표면 색이 같다.
- 인증 코드 화면에서 틀린 코드를 넣어 무효 외곽선과 필드 오류가 보인다.
