# 화면을 HeroUI 컴포넌트와 Typography에 맞춘다

## 배경

2026-09-13 디자인 시스템 감사에서 세 가지가 나왔다. RN `Text` 78곳이 저마다
className을 조립해 같은 역할이 서너 갈래로 갈려 있고, HeroUI Native를 근거 없이
우회한 자리가 12곳이며, 실제 결함이 3건이다. 사용자가
[모바일 컴포넌트 선택](../../decisions/mobile-component-selection.md) 규칙과
HeroUI `Typography` 채택을 확정했고, 시안 비교에서 HeroUI 기본값을 쓰는 안을
골랐다. 역할 대응표는 [모바일 타이포그래피](../../decisions/mobile-typography.md)가
소유한다.

이 스펙은 그 결정을 앱에 적용하는 한 작업이다. 크기가 커서 tasks로 나눠 낸다.
계약, 코드, HeroUI 1.0.8 소스에 대한 세 갈래 검토를 반영해 처음 안에서 다음을
고쳤다. 대화 중 배울 표현의 한 줄과 카드는 HeroUI `Accordion`으로 표현할 수 없어
예외로 남기고, 카드 밖 아이콘 줄과 손으로 조립하는 접근성 이름은 계약대로
유지하며, 누르는 알약은 `Chip` 대신 `Button`의 작은 크기를 쓰고, 버튼 높이와
펼침 카드 트리거 정렬은 global.css의 재정의 둘로 남긴다.

## 사용자에게 보이는 결과

- 같은 역할의 글자가 모든 화면에서 같은 크기, 행간, 굵기로 보인다. 본문과
  카드 설명의 행간이 지금보다 조금 넓어지고 제목에 HeroUI 기본 자간이 붙는다.
  대화 기록의 `최근 대화`처럼 목록 위 작은 소제목은 계약대로 보조색·중간 굵기·작은
  글자로 통일된다.
- 탐색의 스토리 목록, 스토리 상세와 대화 기록의 화 목록, 온보딩의 추천 아이디
  목록이 같은 모양의 목록이 된다. 행 사이 구분선은 HeroUI `Separator`다.
- 기억해 둘 표현과 표현 노트의 펼침 카드, 대화 기록의 회차 카드가 같은 모양의
  펼침 카드가 되고, 누르면 살짝 작아지는 눌림 반응이 있다. 인물 대사 카드는
  펼쳐지지 않는 카드로 같은 배경, 모서리, 그림자를 쓴다. 카드 아래 오른쪽의
  아이콘 줄은 접든 펼치든 같은 자리에 남는다.
- 펼친 카드는 제목 줄을 눌러 접는다. 펼친 내용을 눌러 접는 동작은 없어진다.
- 채팅의 재시도 알약, 편집 취소 버튼, 프로필 편집 알약, 채팅의 전송·중지·최신
  메시지 버튼이 HeroUI 컴포넌트의 눌림 반응과 비활성 표현을 갖는다. 프로필 편집
  알약은 HeroUI `Button`의 작은 크기라 지금보다 높이가 커진다.
- 인증 코드 칸이 HeroUI 기본 크기로 왼쪽에 모이고, 틀렸을 때의 빨간 테두리가
  HeroUI의 무효 상태 외곽선으로 바뀐다. 이메일, 닉네임, 아이디, 코드 화면의 오류
  문구가 입력 칸에 붙은 필드 오류로 보이고, 아이디 화면에서 확인 실패 뒤 다시
  시도하는 동작은 오류 문구 옆의 작은 버튼이 맡는다.
- 다크 모드에서 메시지 메뉴와 인증 코드 칸의 표면 색이 카드와 같아진다.
- 공용 버튼의 가로 여백이 HeroUI 기본값으로 돌아가고 진행 표시와 앞 아이콘은
  라벨 옆 줄 안에 선다. 큰 시스템 글자 크기에서 버튼이 라벨만큼 자라는 것은
  지금과 같다.
- 화면 안 제목과 섹션 소제목이 화면 읽기에 헤더로 읽힌다. 펼침 카드는 펼침
  상태를 가진 버튼으로, 행은 제목과 설명을 잇는 이름의 버튼으로 읽힌다.
- 문구, 색, 화면 구성, 그 밖의 동작(복사, 담기, 화 열기, 이어서 하기)은
  달라지지 않는다.

## 범위

### 결함과 시안 없이 되돌릴 수 있는 것

- 다크 모드 `overlay`와 `field-background`를 색상 계약의 표대로 전역 CSS에
  Light와 Dark 함께 등재한다.
- 소비자가 없는 HeroUI 토스트 설정과 반대 방향을 설명하는 주석을 지운다.
  화면 안 토스트의 규칙은 [모바일 토스트 자리](../../decisions/mobile-toast-placement.md)가
  소유하고 달라지지 않는다.
- 인증 코드 화면이 무효 상태를 HeroUI `isInvalid`로 넘기고, 직접 그린 테두리와
  칸 폭 조정을 없애 HeroUI 기본 칸을 쓴다. 코드 화면에는 `TextField`가 없으므로
  `FieldError`에 무효 상태를 직접 넘긴다.
- 인증 오류 문구를 HeroUI `FieldError`로 옮긴다. 이메일, 닉네임, 아이디 화면은
  `TextField` 안에, 코드 화면은 `InputOTP` 아래에 둔다. 화면 읽기의 알림 역할은
  `FieldError`가 붙이지 않으므로 직접 넘긴다. 입력이 없는 로그인 방법 화면의
  오류 문구는 대응표의 오류 역할(`body-sm`, `text-danger`)로 그린다.
- 아이디 화면에서 오류 문구 전체를 눌러 다시 시도하던 것을, `FieldError` 옆의
  HeroUI `Button` 작은 크기 삼차 변형 `다시 시도`로 바꾼다. 접근성 이름은
  지금 값을 유지한다.
- 인증 화면의 `또는` 구분선을 HeroUI `Separator`로 바꾼다.
- 채팅의 재시도 알약을 HeroUI `Button` 작은 크기 외곽선 변형으로, 프로필 편집
  알약을 작은 크기 삼차 변형으로 바꾼다.
- 채팅의 전송·중지·최신 메시지 버튼(44pt 원)과 편집 취소 버튼(28pt)을 저장소
  공용 아이콘 버튼 하나로 모은다. 눌림 반응은 `PressableFeedback`의 축소만,
  비활성은 HeroUI `element-disabled` 유틸리티를 쓴다. 자체 비활성 표현
  (`opacity-40`)을 없앤다. 전송이 진행 표시로 바뀌는 규칙은
  [모바일 채팅 메시지 동작](../../decisions/mobile-chat-message-actions.md)을 따른다.
- 공용 `Button`에서 `!important`로 HeroUI 클래스를 덮는 여백과 높이 재정의를
  걷어낸다. 큰 글자에서 버튼이 자라는 것은 global.css에서 버튼 높이를 최소
  높이로 바꾸는 재정의 하나로 유지한다. 선행 슬롯은 절대 위치 대신 HeroUI가 주는
  줄 안 슬롯을 쓰고, 진행 중 상태에서 크기를 고정하는 처리는 남긴다.
- 로그인 버튼이 `useColorScheme` 대신 테마 브리지의 `useAppTheme`를 읽는다.
  보이는 동작은 지금과 같다.

### 텍스트 역할 이전

- React Native UI의 모든 `Text`를 `Typography.Heading` 또는
  `Typography.Paragraph`로 바꾸고, 계약의 대응표에 따라 `type`을 고른다.
- `Text`에 붙어 있던 `text-*`, `leading-*`, `font-*` 클래스와 인라인 크기를
  없앤다. 색 className, `numberOfLines`, `selectable`, `testID`는 남긴다. 강조는
  `weight`로 옮긴다.
- 부분 강조 구간의 중첩 `Text`에는 색과 배경 클래스만 남긴다. 배울 표현의
  바뀐 부분은 계약대로 색으로만 강조하므로 굵기 클래스를 없앤다.
- AI 답변 Markdown 렌더러에는 대응표 `body`의 크기와 행간을 숫자로 넘긴다.
  진행 표시와 실패 줄의 줄 높이 계산도 대응표 값에 맞춘다. 표시 영역과 간격
  규칙 자체는 바꾸지 않는다.
- 토스트와 제공자 로그인 버튼은 확대 상한 때문에 인라인 줄 높이와 크기를
  갖는다. 계약의 예외대로 두되 그 기준값을 대응표의 값으로 맞춘다.

### 카드와 목록 행 이전

- 스토리 행, 스토리 상세와 대화 기록의 화 행, 추천 아이디 행을 HeroUI
  `ListGroup`으로 바꾼다. 표지, 화 번호, 쉐브론은 행의 앞뒤 슬롯에 둔다. 항목
  사이에 `Separator`를 넣고 손으로 그린 구분선을 없앤다. 눌리는 행은
  `PressableFeedback`으로 감싸고 `ListGroup.Item`은 `disabled`로 두며 버튼
  역할과 이름을 감싼 쪽에 준다. 대화가 없는 화 행과 스토리 상세의 화 행은
  눌리지 않는 행으로 둔다.
- 대화 기록의 소개와 카드 사이 구분선을 `Separator`로 바꾼다.
- 기억해 둘 표현과 표현 노트의 펼침 카드, 대화 기록의 회차 카드를 HeroUI
  `Accordion`의 표면 변형으로 바꾼다. 카드마다 독립 `Accordion`이며
  `selectionMode="single"`과 접기 허용을 명시한다. 제목 줄이 트리거이고 펼친
  내용은 내용 슬롯이다. 인물 대사 카드는 HeroUI `Card`로 그린다.
- 카드 아래 오른쪽 아이콘 줄과 회차 카드의 이어서 하기 버튼은 접힌 상태에서도
  보여야 하므로 `Accordion` 내용 슬롯이 아니라 카드 밖 아래에 둔다.
- 카드의 접근성 이름은 계약대로 출처, 영어, 한국어를 이어 붙여 직접 넘기고,
  옆으로 민 뒤 뗀 것을 누름으로 치지 않는 판정은 트리거의 누름 속성으로
  유지한다. 카드의 배율 재생성 처치는 없앤다. 그 제거는
  [글자 크기 스펙](../text-size-after-relaunch/spec.md)과 겹치며 먼저 끝난 쪽이
  없앤다.
- 펼침 애니메이션은 HeroUI 기본을 쓰되, 동작 줄이기가 켜지면 애니메이션을 끈다.

## 완료 기준

- 원시 `Pressable`이 남는 자리가 결정 계약의 예외 목록뿐이다. 스토리 행, 화 행
  두 화면, 추천 아이디 행, 기억해 둘 표현·표현 노트 카드, 회차 카드, 인증 구분선,
  대화 기록 헤더 아래에 손으로 그린 구분선(`border-b`, `border-t`, `h-px`)이
  없다. 상황 줄과 스토리 카드의 구분선은 이 스펙의 대상이 아니다.
- 저장소에 `!important`로 HeroUI 클래스를 덮는 코드와 `opacity-40` 비활성
  표현이 없다. global.css의 HeroUI 재정의는 계약이 적은 둘뿐이다.
- React Native UI에 `text-[Npx]`, `leading-[Npx]`가 없고, `Text`에 `text-*`
  (색 제외), `leading-*`, `font-*` 클래스가 없다. 인라인 크기는 계약이 적은
  예외(Markdown 렌더러, 토스트, 제공자 로그인 버튼, 코드 표시 monospace)뿐이다.
  쓰인 `type` 조합이 모두 대응표에 있다.
- 카드의 제목 줄을 누르면 펼쳐지고 다시 누르면 접힌다. 아이콘 줄을 눌러도, 카드를
  옆으로 밀다 떼도 카드가 열리지 않는다. 접힌 카드에도 아이콘 줄과 이어서 하기
  버튼이 보인다.
- 인증 코드를 틀렸을 때 칸의 무효 외곽선이 보이고, 이메일·닉네임·아이디·코드
  화면의 오류 문구가 입력 아래에 보이며 화면 읽기에 알림으로 읽힌다.
- 다크 모드에서 메시지 메뉴, 인증 코드 칸, 카드의 표면 색이 같다. 전역 CSS에
  `overlay`와 `field-background`가 Light·Dark 모두 `surface`와 같은 값으로 있다.
- 글자 크기 검증은 [모바일 타이포그래피](../../decisions/mobile-typography.md)의
  절차(각 플랫폼 최대 시스템 글자 크기로 바꾼 뒤 앱을 완전히 닫고 다시 시작)로
  한다. 인증, 온보딩, 탐색, 대화(종료 카드 포함), 표현 돌아보기, 표현 노트,
  스토리 상세, 대화 기록, 프로필 편집 화면을 기본 크기와 최대 크기, 밝은 화면과
  어두운 화면으로 열어 잘림과 겹침이 없다.
- 화면 읽기로 화면 안 제목과 섹션 소제목이 헤더로, 펼침 카드는 `expanded`
  상태를 가진 버튼으로, 눌리는 행은 제목과 설명을 잇는 이름의 버튼으로 읽힌다.
- 기존 자동 테스트가 모두 통과한다. 크기 클래스를 검사하던 테스트는 역할
  `type`을, 공용 아이콘 버튼과 `FieldError`와 카드와 행은 접근성 역할과 상태를,
  공용 `Button`은 새 선행 슬롯 배치를 검사한다.
- 각 task의 변경은 읽기 전용 `mobile-ui-consistency-reviewer` 검토를 거치고,
  실행 증거가 없는 항목은 `UNVERIFIED`로 남긴다.

## 제약과 근거

- 컴포넌트 선택, 예외 목록, 기본값 유지와 global.css 재정의 둘은
  [모바일 컴포넌트 선택](../../decisions/mobile-component-selection.md)이
  소유한다. 이 스펙은 예외 목록에 새 예외를 더하지 않는다.
- 역할 대응표, 인라인 숫자 예외, 글자 크기 검증 절차는
  [모바일 타이포그래피](../../decisions/mobile-typography.md)가 소유한다.
- 색 등재 자리와 값은 [모바일 색상 시맨틱](../../decisions/mobile-color-semantics.md)이
  소유한다.
- 로그인 버튼의 브랜드 모양과 진행 표시, 실패 줄의 표시 영역과 간격은
  [모바일 작업 진행 표시](../../decisions/mobile-action-progress.md)가 소유한다.
- 하단 행동 버튼의 여백과 배치는 [모바일 하단 CTA](../../decisions/mobile-bottom-cta.md)가
  소유한다. 버튼 여백 재정의를 걷어내도 이 배치는 달라지지 않아야 한다.
- 아이콘 줄의 크기, 간격, 반응은
  [모바일 채팅 메시지 동작](../../decisions/mobile-chat-message-actions.md)이 소유한다.
- 카드의 구성, 아이콘 줄 자리, 접근성 이름, 옆으로 민 판정은
  [표현 노트](../../decisions/expression-note.md)와
  [에피소드 종료와 표현 돌아보기](../../decisions/episode-ending-and-review.md)가,
  대화 중 배울 표현의 한 줄과 카드는
  [모바일 대화 중 교정](../../decisions/mobile-episode-correction.md)이, 회차
  카드와 화 행과 `최근 대화` 소제목은
  [모바일 스토리 탐색](../../decisions/mobile-story-browsing.md)이 소유한다. 이
  스펙은 그리는 수단만 바꾼다.
- HeroUI 아이콘 슬롯이 있는 자리(`Accordion` 인디케이터, `ListGroup` 접미
  쉐브론)는 HeroUI가 그리고, 그 밖의 아이콘은
  [모바일 아이콘 렌더링](../../decisions/mobile-icon-rendering.md)대로 프로젝트
  `Icon`이 그린다.
- 동작 줄이기 처리는 [에피소드 종료와 표현 돌아보기](../../decisions/episode-ending-and-review.md)의
  규칙을 따른다.

## 가정

- HeroUI `Accordion.Trigger`가 `PressableProps`를 받으므로 옆으로 민 판정을
  `onPressIn`과 `onPress`로 유지할 수 있다. 되지 않으면 그 카드만 되돌리고
  이유를 [표현 노트](../../decisions/expression-note.md)의 보존할 근거에 적는다.
- 공용 `Button`의 선행 슬롯을 줄 안으로 옮기고 여백을 HeroUI 기본으로 되돌려도
  하단 행동 버튼과 인증 버튼의 너비는 부모가 정하므로 보이는 차이가 없다.
- `ListGroup` 행의 제목 굵기가 HeroUI 기본(500)으로 내려간다. 사용자가 시안에서
  봤다.
- `PressableFeedback`으로 감싼 `ListGroup.Item`은 감싼 쪽 하나만 접근성 요소로
  읽힌다. 둘 다 읽히면 행 쪽의 접근성을 끈다.
- 아이디 화면의 `다시 시도` 버튼은 사용자가 시안에서 보지 않은 새 요소다.
  [프로필 정체성과 온보딩](../../decisions/mobile-profile-identity-and-onboarding.md)은
  같은 화면에서 다시 시도할 수 있어야 한다고만 정하고 방법은 정하지 않는다.
  오류 문구를 눌러 다시 시도하는 지금 방식을 남기라고 하면 `FieldError`는 그대로
  두고 그 행만 눌리게 한다.
- 프로필 편집 알약은 [모바일 프로필 설정](../../decisions/mobile-profile-settings.md)이
  이름(`사진 편집`)만 정하고 모양은 정하지 않는다. React Native 화면이라 HeroUI
  `Button` 작은 크기로 바꿀 수 있다.
- HeroUI `Card`의 안쪽 여백은 16pt, `Accordion` 표면 변형의 트리거 여백은
  20pt다. 인물 대사 카드와 펼침 카드의 안쪽 여백이 4pt 다르지만 재정의하지
  않는다.

## 손대지 않는 것

- 네이티브 헤더 제목과 탭 라벨. 운영체제가 소유한다.
- `@expo/ui`가 소유하는 설정 화면의 글자, 행, 오류 문구.
- 대화 중 배울 표현의 접힌 한 줄, 펼친 카드, 접기 쉐브론. 계약의 예외다. 그 안의
  글자 역할만 바꾼다.
- 실패 줄의 재시도 아이콘. 표시 크기와 터치 영역을 따로 정하는 계약의 예외다.
  그 안의 글자 역할만 바꾼다.
- 메시지 아래 아이콘 줄의 구조. 이미 계약대로다. 비활성 표현만 HeroUI
  `element-disabled`로 바꾼다.
- 탐색의 필터 칩. HeroUI `TagGroup` 기본 패턴이다.
- 채팅 말풍선, 장면 서술, 상황 줄, 결말 카드, 스토리 카드(스토리 만들기)의
  구조와 구분선. 각 계약이 모양을 소유한다. 글자 역할만 바꾼다.
- 문구와 색.

## 남은 위험

- 78곳을 바꾸므로 화면마다 줄바꿈 위치가 달라진다. 완료 기준의 화면 확인이
  이를 잡는다.
- 본문 행간 28과 제목 자간이 한글에서 어색해 보일 수 있다. 계약의 재검토
  조건에 따라 사용 증거가 쌓이면 global.css 한 곳에서 다시 본다.
- 카드 제목이 쓰는 `h6`의 Dynamic Type 램프는 HeroUI가 정한 `subheadline`이라,
  최대 글자 크기에서 본문보다 덜 커진다. 위계가 뒤집혀 보이는지 최대 크기
  확인에서 본다.
- `Accordion`의 펼침 애니메이션이 종료 카드의 축하 연출과 겹칠 수 있다. 종료
  카드가 있는 대화 화면에서 확인한다.
- `FieldError`의 문구 굵기가 지금 인증 오류 문구보다 가늘다. 대응표를 따르므로
  그대로 받아들인다.
- 펼친 내용을 눌러 접는 동작이 사라진다. 사용 중 불편이 보고되면 표현 노트
  계약에서 다시 본다.
