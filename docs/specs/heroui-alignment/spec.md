# 화면을 HeroUI 컴포넌트와 Typography에 맞춘다

## 배경

2026-09-13 디자인 시스템 감사에서 세 가지가 나왔다. RN `Text` 78곳이 저마다
className을 조립해 같은 역할이 서너 갈래로 갈려 있고, HeroUI Native를 근거 없이
우회한 자리가 12곳이며, 실제 결함이 3건이다. 사용자가
[모바일 컴포넌트 선택](../../decisions/mobile-component-selection.md) 규칙과
HeroUI `Typography` 채택을 확정했고, 시안 비교에서 HeroUI 기본값을 재정의 없이
쓰는 안을 골랐다. 역할 대응표는
[모바일 타이포그래피](../../decisions/mobile-typography.md)가 소유한다.

이 스펙은 그 결정을 앱에 적용하는 한 작업이다. 크기가 커서 tasks로 나눠 낸다.

## 사용자에게 보이는 결과

- 같은 역할의 글자가 모든 화면에서 같은 크기, 행간, 굵기로 보인다. 본문과
  카드 설명의 행간이 지금보다 조금 넓어지고 제목에 HeroUI 기본 자간이 붙는다.
- 탐색의 스토리 목록, 대화 기록의 회차 목록, 온보딩의 추천 아이디 목록이 같은
  모양의 목록이 된다. 둥글기 24, 행 안쪽 여백 16, hairline 구분선이다.
- 표현 카드, 교정 카드, 회차 카드가 같은 모양의 펼침 카드가 된다. 둥글기 24,
  안쪽 여백 20이고, 누르면 살짝 작아지는 눌림 반응이 있다.
- 채팅의 재시도 칩, 프로필 편집 알약, 교정 카드의 접기 버튼, 채팅의 보내기와
  중지와 최신 메시지 버튼이 HeroUI 컴포넌트의 눌림 반응과 비활성 표현을 갖는다.
- 인증 코드 칸이 HeroUI 기본 크기(44×48pt)로 왼쪽에 모이고, 틀렸을 때의 빨간
  테두리가 HeroUI의 무효 상태 외곽선으로 바뀐다. 인증 화면의 오류 문구가 입력
  칸에 붙은 필드 오류로 보인다.
- 다크 모드에서 메시지 메뉴와 인증 코드 칸의 표면 색이 카드와 같아진다.
- 공용 버튼의 가로 여백이 HeroUI 기본값으로 돌아간다. 너비를 부모가 정하는
  하단 행동 버튼은 달라지지 않는다.
- 화면 안 제목, 섹션 헤딩, 카드 제목이 화면 읽기에 헤더로 읽힌다. 카드는
  펼침 상태를 가진 버튼으로, 행은 버튼으로 읽힌다.
- 문구, 색, 화면 구성, 동작(펼침, 복사, 담기, 회차 열기, 이어서 하기)은
  달라지지 않는다.

## 범위

### 결함과 시안 없이 되돌릴 수 있는 것

- 다크 모드 `overlay`와 `field-background`를 `surface`와 같은 값으로 전역
  CSS에 등재한다.
- 소비자가 없는 HeroUI 토스트 설정과 반대 방향을 설명하는 주석을 지운다.
- 인증 코드 화면이 무효 상태를 HeroUI `isInvalid`로 넘기고 직접 그린 테두리와
  칸 폭 조정을 없애 HeroUI 기본 칸을 쓴다.
- 인증 오류 문구를 `TextField` 안의 HeroUI `FieldError`로 옮긴다. 접근성 알림
  역할은 유지한다.
- 채팅의 재시도 칩은 HeroUI `Chip`으로, 프로필 편집 알약은 공용 `Button`의
  작은 크기와 삼차 변형으로, 교정 카드의 접기 버튼은 HeroUI `CloseButton`으로
  바꾼다.
- 채팅의 보내기, 중지, 최신 메시지 버튼과 상태 줄의 재시도 아이콘을 공용 아이콘
  버튼 하나로 모은다. 44pt 원과 28pt 두 크기를 갖고 눌림 반응은 HeroUI
  `PressableFeedback`을 쓴다. 자체 비활성 표현(`opacity-40`)을 없앤다.
- 공용 `Button`에서 `!important`로 HeroUI 크기 클래스를 덮는 여백과 높이
  재정의를 걷어낸다. 진행 중 상태에서 크기를 고정하는 처리는 남긴다.
- 로그인 버튼이 `useColorScheme` 대신 테마 브리지의 `useAppTheme`를 읽는다.

### 텍스트 역할 이전

- React Native UI의 모든 `Text`를 `Typography`로 바꾸고, 계약의 대응표에 따라
  `type`을 고른다. 헤딩 역할은 `Typography.Heading`으로 쓴다.
- `Text`에 붙어 있던 `text-*`, `leading-*`, `font-*` 클래스와 인라인 크기를
  모두 없앤다. 색 className과 `numberOfLines`는 남긴다. 강조는 `weight`로
  옮긴다.
- 부분 강조가 필요한 문장(표현 카드의 표시 구간)은 `Typography` 안에 중첩한
  `Text`로 표현한다. 중첩 `Text`에도 크기 클래스를 두지 않는다.
- 상태 줄의 역할별 크기 상수와 진행 표시의 줄 높이 계산은 대응표의 값으로
  맞춘다. 진행 표시 크기 규칙 자체는 바꾸지 않는다.
- 토스트의 확대 상한과 로그인 버튼의 확대 상한은 그대로 둔다.

### 카드와 목록 행 이전

- 스토리 행, 회차 행, 추천 아이디 행을 HeroUI `ListGroup`으로 바꾼다. 표지,
  회차 번호, 쉐브론은 행의 앞뒤 슬롯에 둔다. 손으로 그린 구분선을 없앤다.
  행의 눌림 반응은 HeroUI 문서가 안내하는 대로 `PressableFeedback`으로 행을
  감싸고 `onPress`를 그쪽에 둔다. `ListGroup.Item` 혼자서는 눌림 반응이 없다.
- 표현 카드, 교정 카드, 회차 카드를 HeroUI `Accordion`의 표면 변형으로
  바꾼다. 아이콘 줄과 이어서 하기 버튼은 카드 내용 슬롯에 둔다.
- 표현 카드가 스와이프와 탭을 가르는 판정, 접근성 이름을 손으로 조립하는
  처리, 카드마다 있는 배율 재생성 처치를 없앤다. 재생성 처치 제거는
  [글자 크기 스펙](../text-size-after-relaunch/spec.md)과 겹치며 먼저 끝난
  쪽이 없앤다.

## 완료 기준

- 원시 `Pressable`이 남는 자리가 결정 계약의 예외 목록뿐이다. 손으로 그린
  구분선(`border-b`, `h-px`)이 없다.
- 저장소에 `!important`로 HeroUI 클래스를 덮는 코드와 `opacity-40` 비활성
  표현이 없다.
- React Native UI에 `text-[Npx]`, `leading-[Npx]`, 인라인 `fontSize`가 없고,
  `Text`에 `text-*`(색 제외), `leading-*`, `font-*` 클래스가 없다. 코드 표시의
  monospace 지정은 예외다. 계약의 대응표에 없는 `type` 조합이 없다.
- 카드를 누르면 펼쳐지고 다시 누르면 접힌다. 아이콘 줄을 눌러도 카드가 열리지
  않는다. 목록을 스크롤하다 손을 떼도 카드가 열리지 않는다.
- 인증 코드를 틀렸을 때 칸의 무효 표시가 보이고, 이메일과 닉네임과 아이디
  화면의 오류 문구가 입력 아래에 보인다.
- iOS 시뮬레이터와 Android 에뮬레이터에서 인증, 온보딩, 탐색, 대화, 종료,
  표현 돌아보기, 표현 노트, 대화 기록, 프로필 편집 화면을 기본 글자 크기와
  최대 시스템 글자 크기(앱을 완전히 닫고 다시 시작)로 열어 잘림과 겹침이 없다.
  밝은 화면과 어두운 화면 모두 확인하고, 다크 모드에서 메시지 메뉴, 인증 코드
  칸, 카드의 표면 색이 같다.
- 화면 읽기로 화면 안 제목, 섹션 헤딩, 카드 제목이 헤더로, 카드는 `expanded`
  상태를 가진 버튼으로, 행은 제목과 설명을 잇는 이름의 버튼으로 읽힌다.
- 기존 자동 테스트가 모두 통과한다. 크기 클래스를 검사하던 테스트는 역할
  `type`을, 공용 아이콘 버튼과 `FieldError`와 카드는 접근성 역할과 상태를
  검사한다.

## 제약과 근거

- 컴포넌트 선택, 예외 목록, 기본값 유지 규칙은
  [모바일 컴포넌트 선택](../../decisions/mobile-component-selection.md)이
  소유한다. 이 스펙은 예외 목록에 새 예외를 더하지 않는다.
- 역할 대응표, 재정의 금지, 글자 크기 검증 절차는
  [모바일 타이포그래피](../../decisions/mobile-typography.md)가 소유한다.
- 색 등재 위치와 `overlay`, `field-background` 규칙은
  [모바일 색상 시맨틱](../../decisions/mobile-color-semantics.md)이 소유한다.
- 로그인 버튼의 브랜드 모양과 진행 표시는
  [모바일 작업 진행 표시](../../decisions/mobile-action-progress.md)가 소유한다.
- 표현 카드의 구성과 아이콘 줄은 [표현 노트](../../decisions/expression-note.md)와
  [에피소드 종료와 표현 돌아보기](../../decisions/episode-ending-and-review.md)가,
  교정 카드의 제목·색·접기는
  [모바일 대화 중 교정](../../decisions/mobile-episode-correction.md)이, 회차
  카드와 행의 내용은 [모바일 스토리 탐색](../../decisions/mobile-story-browsing.md)이
  소유한다. 이 스펙은 그리는 수단만 바꾼다.

## 가정

- HeroUI `Typography`가 `numberOfLines`, `selectable`, `testID` 같은 RN `Text`
  속성을 그대로 받는다. 받지 못하는 속성이 있으면 그 자리만 RN `Text`로 남기고
  대응표의 값을 className으로 쓴 뒤 이유를 주석에 적는다.
- HeroUI `Accordion`이 스크롤 중 손을 뗀 것을 탭으로 오인하지 않는다. 지금
  카드가 직접 하던 12pt 이동 판정은 그래서 없앤다. 오인이 확인되면 그 판정만
  다시 넣고 이유를 예외 목록에 적는다.
- 공용 `Button`의 여백을 HeroUI 기본값으로 되돌려도 하단 행동 버튼과 인증
  버튼의 너비는 부모가 정하므로 보이는 차이가 없다.
- HeroUI `Chip`과 `CloseButton`이 지금 자리의 크기 안에 들어간다. 들어가지
  않으면 그 자리만 되돌리고 이유를 예외 목록에 적는다.
- `ListGroup` 행의 제목 굵기가 HeroUI 기본(500)으로 내려간다. 사용자가
  시안에서 봤다.

## 손대지 않는 것

- 네이티브 헤더 제목과 탭 라벨. 운영체제가 소유한다.
- `@expo/ui`가 소유하는 설정 화면의 글자와 행.
- 채팅 말풍선과 장면 서술의 구조. 카드가 아니라 메시지다. 글자 역할만 바꾼다.
- 상황 줄, 결말 카드, 스토리 카드(스토리 만들기)의 구조. 각 계약이 모양을
  소유하고 누를 수 있는 것이 아니다. 글자 역할만 바꾼다.
- AI 답변 Markdown 렌더러. 네이티브 렌더러가 숫자만 받으므로 대응표의 `body`
  값을 숫자로 넘기되 컴포넌트는 바꾸지 않는다.
- 문구와 색.

## 남은 위험

- 78곳을 바꾸므로 화면마다 줄바꿈 위치가 달라진다. 완료 기준의 화면 확인이
  이를 잡는다.
- 본문 행간 28과 제목 자간이 한글에서 어색해 보일 수 있다. 확인되면
  global.css 한 곳에서 재정의하고 계약에 적는다.
- 섹션 헤딩과 카드 제목이 쓰는 `h6`의 Dynamic Type 램프는 HeroUI가 정한
  `subheadline`이라, 최대 글자 크기에서 본문보다 덜 커진다. 위계가 뒤집혀
  보이는지 최대 크기 확인에서 본다.
- `Accordion`의 펼침 애니메이션이 지금의 즉시 펼침과 달라 종료 화면의 축하
  연출과 겹칠 수 있다. 종료 화면에서 확인한다.
- HeroUI `FieldError`의 기본 문구 스타일이 지금 인증 오류 문구와 조금 다를 수
  있다. 역할 대응표를 따르므로 그대로 받아들인다.
