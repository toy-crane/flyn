# 에피소드 대화 화면 개선

## 상태

2026-09-14 사용자가 시안 검토를 마치고 이 범위의 명세 확정을 요청했다. 구현 가능한 계약으로 확정한다. 제품 코드는 아직 변경하지 않았다.

## 사용자에게 필요한 변화

- 영어 대사 바로 아래에서 같은 크기의 한국어 뜻을 읽는다.
- 배울 표현과 대사 뜻에서 같은 모양의 링크로 AI에게 질문한다.
- 대사 뜻과 배울 표현이 나타나거나 펼쳐져도 읽던 대화가 갑자기 밀리지 않는다.
- 종료 축하는 충분히 알아볼 수 있는 속도로 보여 주고, 파티클은 카드 밖으로 퍼진다.
- 끝난 대화에 다시 들어오면 큰 완료 카드 대신 대화와 `표현 돌아보기` CTA를 본다.

영어 대화와 그 자리의 도움을 함께 제공한다는 제품의 전제는 [PRODUCT.md](../../../PRODUCT.md)가 정한다. 이 작업은 학습 내용과 사건 진행을 바꾸지 않고 읽기와 전환을 다룬다.

## 승인한 시안과 필수 결정

[에피소드 대화 시안](prototype.html)은 이 명세에서 바꾸는 배치, 질문 링크, CTA와 애니메이션의 느낌을 정한다. 에피소드의 `Default`, `대화 종료`, `다시 읽기`, `긴 대사`를 살펴볼 수 있다. 준비된 문장을 한 번 보내면 배울 표현이 나타나고, 한 번 더 보내면 종료 축하가 나온다.

시안은 더미 문장을 쓰는 HTML이다. 질문 시트와 표현 돌아보기는 변경한 입구의 연결 확인용이다. 시연용 답변, 두 번 보내면 끝나는 진행, 예시 시각과 문장, 입력창 형태와 실제 데이터 처리 방식은 구현 계약이 아니다. 제품 전체의 기존 화면을 시안에 맞춰 다시 만들지 않는다.

- [인물 대사 번역](../../decisions/mobile-utterance-translation.md): 대사 뜻의 표시 순서와 아이콘, 번역 요청·보관·복원·실패를 정한다.
- [모바일 대화 중 교정](../../decisions/mobile-episode-correction.md): 배울 표현의 내용, 확인 중·성공·실패 상태와 펼침을 정한다.
- [모바일 컴포넌트 선택](../../decisions/mobile-component-selection.md): 두 질문 링크의 공통 컴포넌트와 누름 반응을 정한다.
- [모바일 타이포그래피](../../decisions/mobile-typography.md): 대사와 대사 뜻의 같은 본문 역할, 시스템 글자 크기 지원을 정한다. 시안의 고정 글자 수치를 앱에 복사하지 않는다.
- [에피소드 종료와 표현 돌아보기](../../decisions/episode-ending-and-review.md): 종료 직후와 다시 읽기의 구분, CTA 대기 상태, 결말별 축하와 한 번만 재생하는 규칙을 정한다.
- [모바일 아이콘 렌더링](../../decisions/mobile-icon-rendering.md): 앱의 축하 그래픽 자산을 정한다. 시안의 SVG와 CSS는 Lottie를 대체하라는 결정이 아니다.
- [모바일 채팅 스크롤](../../decisions/mobile-chat-scrolling.md): 보낸 메시지의 위치, 최신 메시지 추적과 이전 대화를 읽는 위치를 정한다.
- [모바일 AI에게 물어보기](../../decisions/mobile-ask-ai.md): 질문 출처, 시트와 대화의 수명을 정한다.
- [UX 라이팅 원칙](../../decisions/ux-writing.md): 앱 문구를 정한다.

## 확정한 범위

### 대사 뜻과 질문 링크

인물 대사에 붙는 대사 뜻을 말풍선 바로 아래로 옮기고 아이콘 줄은 그 아래에 둔다. 카드 안의 반복된 번역 아이콘을 없앤다. 대사 뜻 본문은 영어 말풍선과 같은 글자 크기와 행간으로 읽힌다. 한국어 안내를 비롯한 배울 표현의 질문 링크도 대사 뜻과 같은 모양과 동작을 쓴다. 자세한 표시와 저장 규칙은 위 결정 계약을 따른다.

### 대화 안의 움직임

- 대사 뜻을 켜고 끌 때 글과 공간이 함께 부드럽게 나타나고 사라진다.
- 보낸 메시지의 배울 표현이 준비되면 카드 공간이 부드럽게 늘어나며 내용이 나타난다. 영어 교정과 한국어 입력 안내에 같은 방식을 쓴다.
- 배울 표현을 펼치거나 접을 때 설명 영역의 높이와 접기 표시가 함께 전환한다.
- 이 효과를 위해 별도의 로딩 표시나 인위적인 응답 대기 시간을 추가하지 않는다. 교정할 것이 없는 경우와 확인 실패에는 빈 카드를 만들지 않는다. 기존 상태 표시는 각 결정 계약을 따른다.
- 카드를 읽거나 번역을 여는 동작이 기존 스크롤 규칙을 덮어쓰지 않는다. 사용자가 위쪽을 읽는 중이면 맨 아래로 보내지 않으며, 자동 추적 중에는 카드 높이 변화도 따른다. 손으로 스크롤하면 자동 이동을 중단한다.
- 기존 말풍선 자체에 별도의 진입 이동을 추가하지 않는다. 스트리밍 글자마다 애니메이션을 반복하지 않는다.
- 재진입으로 복원된 카드와 대사 뜻은 처음부터 보인다. 새 카드가 생기는 효과를 다시 재생하지 않는다. 복원 뒤 사용자가 직접 펼치고 접는 동작에는 전환 효과를 쓴다.

### 종료 직후와 다시 읽기

종료 직후에는 실제 결말 카드와 축하를 보여 준다. 파티클은 카드의 모서리에 잘리지 않고 위와 양옆으로 퍼진다. 카드 내용과 축하 장식을 분리해 이 동작이 가능해야 한다. 효과가 끝나도 카드와 CTA는 자동으로 사라지지 않는다.

끝난 대화에 다시 들어오거나 표현 돌아보기에서 돌아오면 하단에는 `표현 돌아보기` CTA만 둔다. `대화가 끝났어요`, 결과 요약과 큰 완료 카드를 반복하지 않는다. 실제 결말의 저장과 대화 전문은 바꾸지 않는다. CTA 대기 상태와 결말별 연출 차이는 종료 결정 계약을 따른다.

## 관찰 가능한 완료 조건

1. 진행 중인 대화와 끝난 대화 모두에서 대사 뜻을 켜면 영어 말풍선, 아이콘 없는 한국어 뜻, 아이콘 줄 순서로 읽힌다. 복사와 담기는 계속 영어 대사를 대상으로 한다.
2. 짧은 뜻과 여러 줄의 뜻 모두 말풍선과 같은 본문 역할로 표시된다. 시스템 글자 크기를 키우고 앱을 다시 시작해도 뜻과 질문 링크가 잘리지 않는다.
3. 영어 교정, 한국어 입력 안내, 대사 뜻의 `AI에게 물어보기`가 같은 링크로 보이며, 누르면 해당 내용을 출처로 질문 시트가 열린다. 닫으면 원래 카드의 펼침 상태를 유지한다.
4. 배울 표현의 등장, 설명 펼침·접기, 대사 뜻의 표시·숨김을 반복해도 빈 공간, 겹친 글, 누를 수 없는 링크가 남지 않는다. 효과 도중 다시 눌러도 마지막 선택에 맞는 상태로 끝난다.
5. 이전 대사를 읽다가 다른 메시지의 카드가 준비되어도 읽던 위치를 강제로 바꾸지 않는다. 최신 대화를 따라가는 중이면 새 내용이 입력창이나 하단 CTA에 가리지 않는다.
6. 종료 축하 중 파티클 일부가 카드의 위쪽과 양옆 바깥에서 실제로 보인다. 화면 안에 머물며 대화 스크롤과 CTA 누름을 막지 않는다. 밝은 화면과 어두운 화면 모두에서 확인한다.
7. 축하 효과가 끝나도 종료 직후 카드와 CTA가 남는다. 효과 재생 중에도 준비된 CTA로 이동할 수 있고, 이동한 화면에 파티클이나 지연된 축하가 나타나지 않는다.
8. 종료 직후 표현 확인이 남아 있으면 결말 카드는 바로 보이고 CTA만 기존 대기 상태를 따른다. 실패가 끝난 뒤에는 이동할 수 있다. 버튼 활성화가 축하를 다시 시작시키지 않는다.
9. 기록에서 다시 열기, 앱 재진입, 표현 돌아보기에서 복귀할 때는 종료 문구·결과 요약·완료 마크 없이 하단 CTA만 보인다. 이때 번역과 배울 표현을 계속 열 수 있다.
10. 동작 줄이기에서는 이동·확산·크기 전환 없이 필요한 내용을 바로 보여 준다. 종료 직후의 정지된 완료 표시와 다시 읽기의 CTA를 구분한다. 큰 시스템 글자 크기와 화면 높이가 작은 경우에도 마지막 대사와 CTA에 접근할 수 있다.

## 조정 가능한 가정

- 시안의 카드 공간 전환은 약 480ms다. 실제 기기에서 느리거나 읽기를 방해하면 같은 동작 안에서 조정한다.
- 종료 카드 진입은 약 600ms, 파티클 확산은 250ms 뒤 시작해 약 2.1초 동안 이어진다. 정확한 수치보다 사용자가 효과를 알아보고 결과를 읽을 여유를 확보하는 것이 기준이다.
- 실제 기기의 키보드, 안전 영역, 글자 크기에 따른 간격은 기존 네이티브 화면 규칙 안에서 조정한다.

## 제외 범위

- 번역·교정 모델, 요청 프로토콜, 저장 구조, 결말 판정과 에피소드 진행은 바꾸지 않는다. 이번 문제는 표시와 움직임이다.
- 표현 노트, 표현 돌아보기 본문, AI 질문 답변과 시트 자체를 새로 설계하지 않는다. 질문 링크와 돌아보기 CTA의 연결만 다룬다.
- 새 애니메이션 라이브러리와 축하 소리, 마스코트, 운영 배포는 범위에 넣지 않는다.

## 검증한 내용과 남은 위험

- HTML 시안에서 390·768 너비, 밝은 화면·어두운 화면, 긴 대사, 배울 표현 펼침, 질문 시트, 종료와 재진입을 확인했다. 독립 리뷰에서 발견한 종료 문구 줄바꿈을 고쳤다.
- 파티클 분리 후 브라우저의 축하 중간 프레임에서 카드 밖 확산을 확인했다. 하단 CTA와 질문 링크 변경도 직접 확인했다. 마지막 수정의 독립 검토는 코드로 진행했다.
- 실제 iOS·Android의 Lottie 재생, 스크롤과 키보드 전환, 최대 시스템 글자 크기는 아직 확인하지 않았다. 구현 완료 판단에는 두 플랫폼의 실제 화면 증거가 필요하다.
- 시안의 영어 본문은 16px·24px 행간이다. 앱은 최신 타이포그래피 계약의 공통 역할을 적용해야 하므로 두 언어의 실제 줄바꿈은 시안과 달라질 수 있다.
- 이 범위에서 미정인 제품 동작은 없다. 위 시간과 간격은 조정 가능한 가정이며 새 제품 선택을 요구하지 않는다.
