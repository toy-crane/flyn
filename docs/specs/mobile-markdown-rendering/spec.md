# 모바일 Markdown 답변 표시 명세

## 목표

- 사용자가 AI 답변의 여러 문단을 끊김 없이 읽고, 필요한 구절을 문단 경계를
  넘어 선택해 복사하거나 AI에게 다시 물어볼 수 있게 한다.
- 한국어를 쓰는 학습자가 VoiceOver와 TalkBack으로 목록과 인용문을 읽을 때
  구조 안내도 한국어로 듣게 한다.
- 문서 편집기보다 짧은 대화가 중심인 플린에서 표나 할 일 목록보다 답변
  선택과 읽기 흐름을 우선한다.

## 확정 범위

- AI 답변과 에피소드의 등장인물 대사는 `EnrichedMarkdownText`가
  CommonMark로 직접 표시한다.
- 한 답변의 Markdown 본문은 하나의 네이티브 텍스트 선택 범위로 유지한다.
  문단, 제목, 일반 목록과 인용문 사이를 렌더러 구간이 가로막지 않는다.
- 문단, 제목, 강조, 인용문, 순서 있는 목록과 순서 없는 목록, 링크, 인라인
  코드와 코드 블록을 지원한다.
- 표와 할 일 목록처럼 GFM에서만 제공하는 표현은 제품 지원 범위에서 뺀다.
  해당 문법이 들어오더라도 표나 누를 수 있는 체크 상자로 표시한다고 보장하지
  않는다.
- 답변은 도착한 부분부터 표시하고 새로 붙은 글자의 스트리밍 표시를 유지한다.
  코드 블록도 같은 답변 안에서 도착한 만큼 이어서 보인다.
- 순서 있는 목록, 순서 없는 목록, 하위 목록, 인용문과 하위 인용문의 화면 읽기
  안내를 한국어로 제공한다. 순서 있는 목록은 항목 번호를 함께 읽는다.
- 링크를 누르면 운영체제가 처리할 수 있는 주소로 연다. 답변의 네이티브 텍스트
  선택과 앱이 더한 선택 메뉴 동작을 유지한다.
- 답변 전체 복사는 화면에 그려진 모양이 아니라 서버에서 받은 Markdown 원문을
  사용한다.

## 확정 제약과 이유

- Markdown 형식은 CommonMark다. 사용자가 확정했다. 현재 앱은 설명 문서보다
  짧은 대화와 학습 도움을 보여 주므로 GFM의 표와 할 일 목록보다 여러 문단에
  걸친 선택이 더 자주 필요하다.
- 렌더러는 `EnrichedMarkdownText` 하나만 사용한다. 현재 네이티브 선택, 링크와
  사용자 정의 선택 메뉴를 유지하면서 렌더러 사이의 표시 차이를 만들지 않기
  위해서다.
- `react-native-streamdown`, `remend`와 별도 Markdown 렌더러를 추가하지 않는다.
  불완전한 인라인 Markdown을 잠시 다듬는 이점보다 Worklets Bundle Mode와 별도
  Babel·Metro 경로가 만드는 운영 부담이 크고, 플린의 짧은 답변에서는 실제 읽기
  문제가 아직 반복되지 않았다.
- 닫히지 않은 강조, 링크와 인라인 코드는 별도 계층이 완성하지 않는다. 문법이
  닫힐 때까지 원문 기호가 잠시 보일 수 있다.
- CommonMark 코드 블록은 답변과 같은 선택 범위에 남는다. 긴 줄은 줄바꿈하며,
  GFM 전용 코드 머리글, 가로 스크롤과 블록별 복사 버튼은 제공하지 않는다.
  답변 전체 복사는 계속 제공한다.

## 수용 기준

- 두 문단 이상인 답변에서 첫 문단부터 다음 문단까지 하나의 선택 범위로 고를 수
  있다.
- 제목, 목록이나 인용문이 문단 사이에 있어도 그 앞뒤 글을 렌더러 구간 때문에
  따로 선택하지 않아도 된다.
- Markdown 링크를 누르면 해당 주소가 열리고, 고른 글에는 앱이 정한 선택 메뉴가
  나타난다.
- 스트리밍 답변의 일반 글과 코드 블록 내용이 도착한 만큼 보이며, 답변이 끝난
  뒤에도 같은 본문에서 선택할 수 있다.
- GFM 표가 가로 스크롤 표로 표시되지 않고, 할 일 목록이 누를 수 있는 체크
  상자로 표시되지 않는다.
- iOS VoiceOver와 Android TalkBack이 목록 항목과 인용문 안내를 영어가 아닌
  한국어로 읽는다. 하위 목록과 하위 인용문도 상위 항목과 구분해 읽는다.
- 답변 복사 결과가 서버에서 받은 Markdown 원문과 같다.
- 모바일의 기존 자동 검사와 타입 검사가 통과한다.

## 가정

아래 문구는 에이전트가 정한 값이라 실제 기기에서 듣고 더 자연스러운 표현으로
바꿀 수 있다.

- 순서 없는 목록은 "글머리표", 하위 항목은 "하위 글머리표"로 읽는다.
- 순서 있는 목록은 "목록 항목 {n}", 하위 항목은 "하위 목록 항목 {n}"으로
  읽는다.
- 인용문은 "인용문", 하위 인용문은 "하위 인용문"으로 읽는다.

## 제외

- GFM 표, 할 일 목록과 독립된 코드 블록 도구 모음. 문서형 답변이나 도구 결과가
  제품 범위에 들어와 실제 필요가 확인될 때 다시 본다.
- `react-native-streamdown`, `remend`, `markdown-to-jsx/native`, WebView나 다른
  Markdown 렌더러.
- Markdown 문법을 고치거나 완성하는 서버 후처리.
- AI 요청 경로, 모델, 프롬프트와 스트리밍 프로토콜 변경.
- 사용자 메시지와 에피소드 지문의 표시 방식 변경.

## 남은 위험

- CommonMark도 GFM과 같은 강조 규칙을 따르므로, 굵은 글씨 뒤에 한글 조사가 바로
  붙는 일부 문장은 원문 기호로 보일 수 있다.
- 긴 코드의 줄바꿈이 코드 열 정렬을 읽기 어렵게 만들 수 있다. 플린 답변에서 긴
  코드가 실제로 반복되면 선택 범위를 지키는 다른 표시 방식을 비교해야 한다.
- 불완전한 인라인 Markdown이 스트리밍 중 반복해서 읽기를 방해할 가능성은 남는다.
- 한국어 화면 읽기 안내의 실제 말투와 쉼은 iOS와 Android 기기에서 들어 봐야
  확정할 수 있다.
