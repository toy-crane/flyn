# 01 — 스토리 만들기부터 1화까지

## Outcome

사용자가 탐색 헤더의 + 버튼(접근성 이름 `스토리 만들기`)으로 `스토리 만들기` 대화를
열고, 플린이 먼저 제안하는 같이 다듬기 끝에 스토리 카드를 받아 고치고,
`대화 시작하기`로 각본을 만들어 저장한 뒤 1화를 바로 플레이한다. 만든 스토리는 만든
사람에게만 보이고, 탐색의 `전체`/`내 스토리` 칩과 `내 스토리` 빈 상태, 상세, 대화
기록, 계정 삭제, seed 재실행까지 [스펙](../spec.md)의 표지 이외 모든 동작이
들어간다. 표지 자리는 이 작업에서는 빈 색 상자다.

## Blockers

None.

## Acceptance criteria

- [x] 탐색 헤더의 + 버튼은 화면 읽기 기능에서 `스토리 만들기`로 읽히고, 누르면 탭
      없이 `스토리 만들기` 화면이 열린다. 뒤로 가면 탐색으로 돌아온다.
- [x] 화면을 열면 플린의 `어떤 상황을 만들고 싶어요?`가 입력 없이 먼저 보인다.
- [x] 상황 한 문장을 보내면 플린의 다음 말에 구체적인 사건이나 인물 제안이 있고,
      질문은 하나다. 화면에 선택지 버튼이 없다.
- [x] 두세 번 오간 뒤 스토리 카드가 나온다. 카드에 제목, 한 줄 소개, 인물, 화별
      제목과 상황 설명, `대화 시작하기`가 있고 입력창은 열려 있다. 인물은 4명, 한 화의
      인물은 3명을 넘지 않는다.
- [x] "2화는 빼 줘"를 보내면 새 카드의 화 수가 하나 줄고, 남은 화의 제목과
      인물은 이전 카드와 같다. `대화 시작하기`는 가장 최근 카드에만 붙는다.
- [x] "그냥 만들어 줘"를 보내면 더 묻지 않고 카드가 나온다.
- [x] `대화 시작하기`를 누르면 버튼이 진행 중을 보여 주고 두 번 눌리지 않으며, 끝나면
      1화가 첫 장면부터 열린다. 1화에서 뒤로 가면 탐색이고, `전체` 목록 맨 위와
      `내 스토리` 목록에 방금 만든 스토리가 있다.
- [x] 1화는 세 문장 이하의 한국어 장면 서술 뒤 영어 대사만으로 흐르고 지문이 없다.
      화자 이름은 카드의 인물 안에 있고 이름표 색은 카드의 인물 순서를 따른다. 결말은
      성공·타협·실패 중 하나로 난다.
- [x] `대화 시작하기`를 누르지 않고 화면을 나가면 `내 스토리`에 아무것도 생기지
      않는다. 만들기 실패 뒤에도 같다. 실패는 시작 실패와 같은 알림으로 보이고 닫으면
      카드와 대화가 남는다.
- [x] 다른 계정으로 로그인하면 그 스토리가 탐색, 스토리 탭, 상세, 대화 기록 어디에도
      없다.
- [x] 만든 스토리를 플레이한 뒤 계정을 삭제하면 그 스토리, 각본, 회차가 남지 않는다.
- [x] 공식 seed를 다시 실행한 뒤에도 만든 스토리와 그 회차가 그대로다.
- [x] 만든 스토리가 없을 때도 탐색에 `전체`와 `내 스토리` 칩이 보인다. `전체`에는
      기존 공식 스토리 다섯 개가 그대로 있고, `내 스토리`에는
      `아직 내 스토리가 없어요.`와 `스토리 만들기` 버튼이 보이며 그 버튼은
      `스토리 만들기` 화면을 연다.
- [x] 칩은 HeroUI의 `TagGroup` 기본 패턴을 그대로 쓴다.
- [x] 만든 스토리의 상세, `대화 시작하기`, 대화 기록, 회차, 이야기 기억, 교정,
      `AI에게 물어보기`, 표현 돌아보기, 결말과 완주 안내가 공식 스토리와 같이 동작한다.

## Constraints

- 스키마 변경은 [Supabase 스키마 작업 방식](../../../decisions/supabase-schema-workflow.md)에
  따라 선언형 스키마, 마이그레이션, seed, 생성 타입을 함께 바꾸고, 커밋 전에
  `supabase-reviewer`를 거친다. 공식 콘텐츠 seed는 사용자가 만든 스토리를 건드리지
  않아야 한다.
- 플레이 규칙은 [AI 에피소드 프로토콜](../../../decisions/ai-episode-protocol.md)을
  바꾸지 않는다. 첫 장면은 저장한 각본에서 읽고, 회차는 첫 사용자 메시지에 생긴다.
- 각본은 스펙의 "각본이 지켜야 할 것"을 따르고 공식 콘텐츠의 길이 한도 안에 든다.
  개요는 대화 중에만 만들고, 각본은 `대화 시작하기`에서 한 번 만든다. 인물은 스토리
  단위 인물 데이터로 저장하고 화는 그중 누가 나오는지를 가리킨다. 도입은 장면 서술 한
  덩어리 뒤 대사만이며 지문을 쓰지 않는다. 화당 인물 1–3명, 스토리당 4명 한도는
  데이터베이스가 거절하는 규칙이므로 카드 단계에서 먼저 지킨다.
- 대화 화면은 에피소드와 `AI에게 물어보기`가 쓰는 공통 대화 표현을 그대로 쓴다. 정리
  카드, 양자택일 선택지 버튼, 스토리 카드 밖의 새 컴포넌트를 더하지 않는다.
- 화면 문구는 [화면 문구 한국어 말투](../../../decisions/korean-ui-writing.md)와
  용어집의 `스토리 만들기`, `스토리 카드`, `내 스토리`를 따른다.
- 표지 생성은 이 작업에 넣지 않는다. 만든 스토리의 표지 경로는 비워 두어 표지
  자리가 빈 색 상자로 보이게 한다.

## Verification

- DB 테스트: 두 계정이 각각 스토리를 만들었을 때, 상대 계정의 조회에서 스토리, 에피소드,
  회차가 하나도 나오지 않는다.
- DB 테스트: 사용자가 스토리를 만들고 회차를 진행한 뒤 공식 seed를 다시 실행해도 그
  스토리, 에피소드, 회차의 행 수와 ID가 그대로다.
- DB 테스트: 만든 스토리를 플레이한 계정을 삭제하면 그 스토리, 에피소드, 회차, 메시지가
  모두 사라지고 공식 스토리는 남는다.
- API 테스트: `대화 시작하기` 요청은 카드 개요를 검증해 화 수 1–5, 인물 1–4명, 화당
  인물 1–3명을 요구하고, 생성한 각본이 길이 한도, 장면 서술 세 문장 이하, 세 결말
  기준을 갖췄을 때만 저장한다. 다른 계정의 스토리 ID로 1화를 열면 거절한다.
- 모바일 테스트: `전체`는 만든 스토리를 위에, 공식 스토리를 아래에 두고, `내 스토리`는
  만든 것만 보여 주며, 없으면 빈 안내와 `스토리 만들기` 버튼을 그린다.
- 모바일 테스트: 스토리 카드는 제목, 한 줄 소개, 인물, 화 목록을 그리고
  `대화 시작하기`는 가장 최근 카드에만 붙는다.
- 실행 검증: iOS 시뮬레이터에서 `agent-device`로 + 버튼 → 대화 세 번 → 카드 →
  "2화는 빼 줘" → `대화 시작하기` → 1화 첫 장면 → 뒤로 → 탐색 `내 스토리`에 스토리
  표시까지 한 세션으로 지나가고, 두 번째 계정으로 로그인해 그 스토리가 없는 것을 본다.

## Review checkpoint

One review pass after this task. 범위는 만든 스토리의 소유자 전용 저장과 모든 조회
경로의 제한, 마이그레이션과 seed 재실행 규칙, 계정 삭제의 삭제 순서다. 위험은 남의
스토리가 탐색이나 상세에 새거나, seed 재실행이 사용자 스토리를 덮거나, 계정 삭제가
참조 제약에 막혀 절반만 지워지는 것으로, 자동 검사만으로는 정책 누락을 다 잡기
어렵다.
