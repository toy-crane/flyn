# 구현 플랜 — AI 스토리 롤플레잉 영어 학습 앱 MVP

> The code is the terrain and this plan is a map: where they disagree, the
> terrain wins. A divergence at the decision level flows back to spec.md
> instead of being worked around.

## Approach

**목(mock) 우선 기반 세션 + 배치 병렬 스트림.** 기반 세션(S0)이 디자인 토큰·공유
컴포넌트·전체 라우트 스켈레톤·도메인 타입·**데이터 접근 심(인터페이스 + 프로토타입
픽스처 목 구현)**·AI 라우트 계약 스키마를 깐다. 이후 스트림들은 2개씩 배치로 병렬
실행하며, 화면은 목 심에, 백엔드·AI는 같은 계약의 반대편에 각각 구현한다. 마지막
배선 세션이 목을 실구현으로 교체한다. AI는 Vercel AI Gateway 경유 **Claude Sonnet 5**
를 기본 모델로 쓴다.

기각한 대안: 백엔드 우선(외부 설정에 전체가 블로킹), 화면별 수직 슬라이스(디자인·
계약 드리프트), 단일 순차 세션(컨텍스트 한계, 병렬성 없음).

## Order (세션 단위, 각 세션 = 워크트리 → PR, 배치 사이엔 전부 머지)

**사전 준비**(코드 밖, 사용자 작업 — 배치 1 전까지): AI Gateway 키·Supabase URL/anon
키를 `.env.local`로, Supabase 대시보드에서 Apple 공급자 활성화 + 번들 ID
`com.toycrane.flyn` 등록, Xcode 준비.

- **S0 기반** (선행, 단독): 토큰·폰트, 프로토타입에서 추출한 공유 컴포넌트, IA 전체
  라우트 스켈레톤(NativeTabs + 인증/몰입 그룹), 글로서리 기반 도메인 타입, 데이터
  심 + 픽스처, AI 계약 스키마, 이후 스트림이 쓸 의존성 일괄 추가, 앱 설정(이름·
  아이콘·번들 ID).
- **배치 1 — 계약 검증**: **S1 계정·데이터**(Supabase 스키마·RLS·마이그레이션,
  Sign in with Apple, 로그인 화면, 심 실구현, dev build 확립) + **S2 AI 엔진**(상황
  생성 / 스토리 턴: 내레이션·대사·교정·달성 판정·결말 / 교정 스레드 라우트 + 판정
  평가 하니스).
- **배치 2 — 핵심 루프 화면**: **S4 홈 + 상황 만들기** + **S5 스토리 세션 + 교정**.
- **배치 3 — 주변 화면**: **S3 온보딩 + 프로필** + **S6 결과 + 서재 + 책 상세**.
- **Wave 2** (순차): **S7 배선** — 화면↔실데이터/AI 스트리밍 연결, 로딩 상태 완성,
  스트릭·통계 계산. **S8 마감** — 세션 이어하기, Dynamic Type·터치 타깃·대비 점검,
  실기기 설치 + E2E.

## Acceptance criteria

- [ ] 시뮬레이터/실기기에서 전체 루프 완주: 로그인 → 온보딩 → 홈 → 상황 만들기 →
      세션(스트리밍) → 교정 패널/스레드 → 결말 → 결과 → 서재 → 책 상세 → 대화 다시 읽기
- [ ] 각 화면이 프로토타입의 화면·상태(빈 서재, 교정 없음, 결말 3종 등)를 재현
- [ ] 교정 3단 동선(밑줄 → 패널 → 스레드) 작동, 오류 없는 버블엔 밑줄 없음,
      초기 강도는 명백한 오류만
- [ ] 성공/실패/강제(30턴 상한) 3갈래 결말 모두 완결 연출로 종료
- [ ] 프로필 5개 항목 수정이 저장되고 이후 상황 생성에 반영
- [ ] 앱 재시작 후에도 서재·프로필·스트릭 유지
- [ ] 상황 생성 대기·AI 응답 대기 로딩 상태 존재
- [ ] 세션 중단 후 복귀 시 이어하기 제공
- [ ] 판정 평가 하니스가 고정 대화록에 대해 일관된 판정 출력

## Verification and seams

- **데이터 접근 심**: 화면은 인터페이스에만 의존 — 목/Supabase 교체 지점이자 화면
  검증 지점.
- **AI 라우트 계약**: 클라이언트·서버 공유 스키마. 라우트는 UI 없이 직접 요청으로
  검증(bun test).
- **판정 평가 하니스**: 고정 대화록 → 기대 판정 스크립트. 스펙의 "판정 프롬프트
  별도 검증" 이행.
- 순수 헬퍼(스트릭·턴 계산)는 콜로케이션 테스트, UI는 시뮬레이터에서 프로토타입 대조.

## Off-limits

- 스펙 Deferred 목록의 선반영·자리 만들기 금지. API 라우트 호스팅(EAS Hosting)도
  보류 — dev 서버로 충분.
- 기존 프리미티브·라우트 재배치 금지, barrel 금지, 레이어 import 방향 준수(CLAUDE.md).
- 화면 스트림은 공유 컴포넌트·토큰·심 계약을 수정하지 않는다 — 부족하면 보고로
  남기고 자기 화면 폴더 안에서 해결.
- 스펙·프로토타입 수정 금지 — 결정 차원의 어긋남은 스펙으로 역류.

## Risks and open questions

- **판정 일관성**(스펙 리스크): 하니스로 완화, Sonnet 5로 부족하면 판정만 상위 모델
  분리 검토.
- **dev 서버 종속**: 설치된 앱의 AI 호출은 Mac dev 서버 필요(같은 Wi-Fi). 단독
  구동이 필요해지면 API 라우트만 EAS Hosting에.
- NativeTabs unstable API(스펙 지정 사항) / 공유 컴포넌트 드리프트(off-limits로
  완화) / 교정 강도·턴 상한은 실사용 데이터로 조정.
