# AI 스토리 롤플레잉 영어 학습 앱 — MVP 스펙

AI가 즉석 생성하는 상황 기반 자유 스토리 속에서, 학습자가 캐릭터로 참여해 영어로
대화하며 배우는 롤플레잉 학습 앱. 정해진 시나리오 암기형 회화 앱과 달리 매번 새로운
스토리가 생성되는 것, 그리고 교정이 일회성 피드백이 아니라 대화의 시작점이라는 것이
차별점이다.

- 용어는 루트의 [GLOSSARY.md](../../../GLOSSARY.md)를 따른다.
- 승인된 전체 화면은 [prototype.html](./prototype.html)에 있다 (10개 화면, 상태 포함).
  구현 세션은 스펙(무엇을)과 프로토타입(어떻게 보이는지)을 함께 참조한다.
- 앱 아이콘 마스터: [app-icon.svg](./app-icon.svg).

## 타깃 학습자

한국인 중급(B1~B2) 성인. 읽기·듣기는 되지만 말하기·작문 산출이 약하다.
스토리를 즐길 독해력이 있어 자유 스토리 컨셉과 궁합이 가장 좋고, 개발자 본인이
첫 사용자가 되어 검증한다.

## 핵심 루프 (확정 결정)

1. **상황 시작** — 홈에서 AI가 학습자 프로필 기반 상황 카드 2~3개를 제안한다.
   카드에는 장르·제목·소개·목표·내 역할/AI 역할이 표기된다(카드 자체가 미리보기라
   탭하면 바로 시작). "나만의 상황 만들기"로 상황 만들기 화면에 진입할 수도 있다.
2. **상황 만들기** — 들어오자마자 AI가 무작위 상황(장면/목표/내 역할/AI 역할)을
   보여주고, 필드별 ✎로 수정한다(편집 시트에서 직접 고치기 또는 "AI가 다시 쓰기").
   전체 재생성은 "다른 상황 보기". 직접 아이디어 입력은 헤더 우측 "직접 만들기"
   (시트, 한국어 입력 허용). 정합성 규칙: 역할·장면이 바뀌면 목표는 항상 내 역할
   시점으로 AI가 다시 쓴다.
3. **스토리 세션** — 내레이션+대사 혼합의 텍스트 어드벤처. AI는 내레이터 겸 상대
   캐릭터, 학습자는 대사와 행동 묘사(`*I hold the case tighter*`)를 영어로 입력.
   - 근거: 순수 대화만으로는 장면 전환·사건 전개가 안 되고, 내레이션은 중급
     학습자에게 리딩 입력을 준다.
   - 화면: 상단에 목표 + 턴 카운터(예: 12/30) 상시 노출, 그 아래 역할 라인
     (`나 · 승객  AI · 회색 코트의 여자(내레이션 포함)`). 버블에는 발신자 라벨을
     달지 않는다 — 정렬(상대 왼쪽·회색 / 나 오른쪽·파랑)과 말꼬리가 화자를 구분.
4. **목표와 저항** — 목표는 서사적 과제(단서 알아내기, 마음 돌리기 등)로 시작부터
   공개되며 종료 트리거다. AI 상대는 목표를 쉽게 내주지 않는다(저항 = 발화 유도).
   과제형(주문·면접)으로 수렴시키지 않는다.
5. **진척 판정과 결말** — 상황 생성 시 구조화된 달성 조건을 함께 생성하고 매 턴
   평가한다. 결말은 성공 / 실패 / 강제 결말(하드 턴 상한) 세 갈래, 어느 쪽이든
   완결된 이야기로 연출한다. 턴 상한은 비용 통제 장치다(컨텍스트 재전송 비용).
6. **교정 패널** — 오류가 있는 학습자 버블은 틀린 부분에 물결 밑줄만 표시(몰입
   유지). 버블을 탭하면 패널이 펼쳐진다: 교정문(바뀐 부분만 파란 볼드) + 한 줄
   이유 + "더 물어보기"(교정 스레드 진입). 3단 동선: 밑줄(인지) → 패널(교정문·이유)
   → 스레드(심화 Q&A).
7. **교정 스레드** — 특정 교정 하나를 붙잡고 AI와 한국어 중심 Q&A. 스토리
   타임라인과 분리된 별도 채팅 화면. 추천 질문 칩 제공.
8. **결과 (세션 직후)** — 방금 완성된 책의 표지가 히어로(결말 배지는 표지 위),
   세리프 이탤릭 "The End" 헤드라인(결말 종류 무관하게 성립), 스트릭 한 줄,
   스토리 요약문, 통계 3종(턴/교정/교정 대화), 교정 리뷰, 하단 고정 "완료" CTA
   (→ 홈). `‹`는 끝난 대화로. "새 이야기 시작" 버튼은 두지 않는다 — 다음 세션
   유도는 홈의 역할.
9. **서재와 책 상세** — 완성한 세션은 장르색 표지의 책이 되어 서재(2열 북커버
   그리드)에 쌓인다. 책을 탭하면 책 상세: 미니 표지 + 완성 시점 메타 + 대화 다시
   읽기 + 그때의 교정 목록. 결과와 데이터는 같지만 맥락(성취 마무리 vs 회고)이
   다르므로 별도 화면이다.

## 화면 구성 (IA)

로그인 → 온보딩(5스텝) → **3탭: 홈 / 서재 / 프로필**
- 홈 → 상황 만들기 → 세션 → 결과 → (완료) 홈
- 서재 → 책 상세 → 교정 스레드 / 대화 다시 읽기
- 세션·결과·책 상세의 교정 → 교정 스레드

**탭 바 규칙**: 탭 루트(홈·서재·프로필)와 탭 내 푸시 상세(책 상세)는 탭 바 표시.
인증·온보딩 플로우와 몰입 플로우(상황 만들기·세션·결과·교정 스레드)는 숨김.
모든 화면은 고정 높이 + 내부 세로 스크롤이며, 상단 바는 위에, 탭 바·입력바·CTA
바·시트는 아래에 고정된다.

## 온보딩과 학습자 프로필

한 화면 한 질문, 5스텝. 전부 선택지 기반(자유 텍스트 없음)이라 민감정보 유입
통로가 없다. 나이·성별·직업·위치는 의도적으로 수집하지 않는다.

1. 영어 수준 — 자가 진단 3단계(체감 문장으로 표현). AI 출력 난이도·교정 강도 조절.
   ("B1~B2 고정" 초기 가정을 대체)
2. 학습 목적 — 여행/해외 생활·취업/일·비즈니스/시험/영화·드라마/재미. 소재 가중치.
3. 장르 취향 — 상황 생성의 장르 가중치(엄격한 필터 아님).
4. 관심사 — 일반 카테고리 12종. 스토리 소재.
5. 닉네임(선택, 건너뛰기 가능) — 스토리 속 내 이름. "실명이 아니어도 좋아요".

프로필 탭에서 5개 항목 모두 수정 가능.

## 계정·백엔드

## 구현 시 필수 (HIG 검토 결과)

- Sign in with Apple은 공식 컴포넌트 사용(커스텀 재현 금지).
- expo-router 네이티브 스택(스와이프 백 자동) + `NativeTabs`(iOS 26 Liquid Glass
  탭 바), 세이프 에어리어는 네이티브 컴포넌트에 위임.
- **상단 바는 네이티브 스택 헤더**를 쓴다(커스텀 재현 금지). 뒤로가기·스와이프
  백·세이프 에어리어·Dynamic Type이 전부 딸려 온다. 타이틀은 가운데 정렬이 되며,
  이는 프로토타입의 왼쪽 정렬을 대체하는 결정이다.
- **바 버튼은 SF Symbol 글리프**(`expo-symbols` / `Stack.Toolbar.Button`).
  긴 한글 라벨은 내비게이션 바에서 타이틀을 밀어낸다 — 문구는 접근성 라벨로
  남긴다(예: 상황 만들기의 "직접 만들기" → `square.and.pencil`).
- Dynamic Type 대응.
- 터치 타깃 44×44pt 이상(✎, 칩, 텍스트 버튼 포함 — 프로토타입에 반영됨).
- **교정 밑줄은 점선**: React Native의 `textDecorationStyle`에 wavy가 없다.
  물결이 꼭 필요하면 커스텀 렌더링이 따로 필요하다.
- 의미 있는 텍스트에는 #4e5968 이상의 대비 사용(#8b95a1은 장식적 캡션만).
- **로딩 상태 설계 필요**: 상황 생성 대기, AI 응답 대기(타이핑 인디케이터·스트리밍)
  — 프로토타입에 없는 상태이며 구현 시 반드시 설계한다.

## 남은 리스크

- **판정 일관성**: 목표 달성·실패 판정은 LLM 판단이라 구조화된 조건을 줘도 흔들릴
  수 있다. 판정 프롬프트를 별도 검증해야 한다.
- **학습량 게이밍**: 저항 설계에도 최소 발화로 목표를 찍는 경로가 남을 수 있다.
  세션당 학습자 발화량을 관찰한다.
- **자유 스토리의 중력**: 상황 생성이 과제형 시나리오로 수렴하지 않는지 지속 점검.
- **턴 상한 값**: 초기값을 정하고 데이터로 튜닝한다.
- **교정 품질·강도**: 어색함까지 지적할지 명백한 오류만 다룰지는 실사용으로 조정.
- **밑줄만으로 교정 인지가 충분한가**: 교정 패널 기본 접힘(B안)이라 탭하지 않고
  지나치는 학습자가 있을 수 있다. 열람률을 관찰하고 필요시 인라인(A안)으로 전환.
- **중도 이탈·이어하기**: 세션 중단 시 복귀 흐름이 미설계다(모바일 사용 특성상
  반드시 발생). 구현 시 세션 상태 저장·이어하기를 설계해야 한다.
- **온보딩 이탈**: 5스텝 필수 응답이 첫 실행 이탈을 만들 수 있다.
