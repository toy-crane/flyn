# S1 — 계정·데이터 (배치 1, S2와 병렬)

`kickoff/README.md`의 공통 규약을 따른다. 프로토타입 화면: ⓪ 로그인.
`.env.local` 필요 (Supabase URL·anon key).

## 스코프

1. **Supabase 스키마 + 마이그레이션** — supabase CLI 마이그레이션으로 관리
   (`supabase/` 디렉토리). 도메인: 학습자 프로필(온보딩 5항목), 스토리 세션(상황
   스냅샷·달성 조건·상태·결말·턴 수), 세션 메시지, 교정, 교정 스레드 메시지.
   스트릭·통계는 세션 완료 기록에서 계산 가능해야 한다(별도 테이블 여부는 세션
   판단). supabase-postgres-best-practices 스킬 참조.
2. **RLS** — 전 테이블, 본인 데이터만 접근.
3. **Sign in with Apple** — 공식 컴포넌트(커스텀 재현 금지, 스펙 HIG 절),
   `signInWithIdToken` 네이티브 플로우. Supabase 클라이언트 셋업(`src/lib/`).
4. **로그인 화면**(⓪) + 인증 가드 — 미로그인 → 로그인, 온보딩 미완 → 온보딩,
   완료 → 홈. 로그아웃 동작(프로필 화면 자체는 S3 소관, 가드만 여기서).
5. **데이터 심의 Supabase 구현** — S0 인터페이스의 실구현. 화면 연결은 S7 소관.
6. **dev build 확립** — `expo run:ios`로 SIWA 엔타이틀먼트 포함 빌드가 되는 상태.

## 주의

- 시뮬레이터에서 Apple 로그인을 실제 테스트하려면 시뮬레이터 설정 앱에 Apple ID
  로그인이 되어 있어야 한다. 안 되면 실기기 검증은 S8로 넘기고 보고에 남긴다.
- 심 인터페이스·계약을 바꾸고 싶으면 구현으로 우회하지 말고 보고에 "계약 변경
  제안"으로 남긴다 (배치 1의 존재 이유다 — 정당하면 머지 시 반영한다).
