# S0 구현 플랜 — 기반 세션

> The code is the terrain and this plan is a map: where they disagree, the
> terrain wins. A divergence at the decision level flows back to spec.md
> instead of being worked around.

## Approach

**계약 먼저, 시각 층은 그 위에.** 의존성·앱 설정 → 토큰·폰트 → 도메인 타입·
픽스처·데이터 심·AI 계약 스키마(테스트 가능한 코어) → 공유 컴포넌트 → 라우트
스켈레톤 순서로, `tsc`·`bun test`로 굳힐 수 있는 하부를 먼저 확정하고 눈으로
검증하는 층을 얹는다. 이름은 라우트·타입·심 메서드 전부 글로서리 영문 명칭을
그대로 쓴다 — 이 세션의 이름이 곧 프로젝트 표준이므로 표준의 원천을 글로서리
하나로 고정한다.

주요 결정:

- **탭 바 규칙을 구조로 강제** — 인증·온보딩 그룹과 몰입 플로우(상황 만들기·
  세션·결과·교정 스레드)는 탭 밖 루트 스택에, 책 상세는 서재 탭 안 푸시로
  배치한다. 화면별 토글 없이 노출 규칙이 내비게이션 구조에서 저절로 나온다.
- **토큰은 프로토타입 `:root` 어휘를 1:1 이관** — surface·fill·sub2·muted·
  accent·accent-soft·danger 등 프로토타입 변수명을 Tailwind 4 `@theme` 색
  이름으로 그대로 옮겨, 프로토타입 CSS와 앱 클래스가 같은 어휘를 쓰게 한다.
- **타이포그래피는 전부 시스템 폰트** — 본문은 San Francisco + Apple SD Gothic
  Neo, '책의 목소리'(내레이션·북커버·The End)는 시스템 세리프 New York
  (`ui-serif`). 번들 폰트 없음, `expo-font` 불필요, Dynamic Type 대응이
  시스템에서 나온다. 한글은 세리프 컨텍스트에서 고딕 폴백 — 세리프 노출
  지점이 영문 중심이라 수용.
- **AI 계약 스키마는 완성 페이로드 형태만 확정** — 스토리 턴 응답을 내레이션·
  대사·교정·달성 판정·결말이 표현되는 구조로 정의하되, 스트리밍 운반 방식은
  S2에 위임한다(스키마가 스트리밍을 막지 않는 형태인지만 여기서 점검).

기각한 대안: 컴포넌트 먼저(토큰 없이는 재작업), 화면 단위 수직 진행(마스터
플랜에서 기각됨), Pretendard 번들(스펙 초안 — 시스템 폰트로 대체 결정),
한글 세리프 번들(노출 지점 대비 비용 과다).

## Order

1. **의존성 + 앱 설정** — AI SDK(게이트웨이)·zod·supabase-js·auth 스토리지·
   expo-apple-authentication을 SDK 57 호환 버전으로 일괄 추가. app.json에
   이름·번들 ID·`usesAppleSignIn`·아이콘(마스터 SVG → 1024 풀블리드 PNG 생성
   후 커밋)·스플래시·`web.output: "server"`·스킴 정리. → `expo start` 부팅이
   첫 검증점.
2. **토큰·폰트** — `@theme` 이관 + 세리프(`ui-serif`) 유틸리티. 폰트 로딩
   코드는 없다.
3. **도메인 타입 → 픽스처 → 데이터 심 → AI 계약 스키마** — 여기서 `tsc`·
   `bun test` 그립 확보. 심 계약 테스트는 S1의 Supabase 구현이 재사용한다.
4. **공유 컴포넌트** — 프로토타입(proto 서버 렌더)과 시각 대조하며 킥오프
   목록 소화.
5. **라우트 스켈레톤 + 플레이스홀더 화면** — 픽스처 표시, 시뮬레이터에서 전
   화면 내비게이션 완주.

한 세션을 넘치면 3↔4 사이에서 끊는다 — 계약 코어까지가 첫 세션이고, 테스트
통과 상태로 경계가 깨끗하다.

## Acceptance criteria

- [ ] S0 킥오프 완료 기준 4항 전부: 시뮬레이터 전 화면 완주(탭 바 규칙 포함) ·
      공유 컴포넌트 시각 대응 · `tsc --noEmit`/`bun test` 통과 · 경고 없는
      `expo start` 부팅
- [ ] 탭 바 규칙이 구조로 검증됨 — 탭 루트 3개·책 상세만 탭 바 노출, 인증·
      온보딩·몰입 플로우는 숨김
- [ ] 라우트·타입·심 메서드 이름이 글로서리 영문 명칭과 일치
- [ ] 스토리 턴 응답 스키마에 내레이션·대사·교정·달성 판정·결말이 모두 표현됨
- [ ] 픽스처가 프로토타입 내용과 상태 변형(빈 서재·교정 없음·결말 3종)을
      그대로 담음

## Verification and seams

- **데이터 심 인터페이스** — 목 구현에 대한 계약 테스트(`bun test`)가 시금석.
  S1이 같은 테스트를 Supabase 구현에 돌리는 것이 이 심의 존재 이유다. 화면은
  인터페이스만 본다.
- **AI 계약 스키마** — zod parse 왕복 테스트. 라우트 구현은 없다(S2 소관).
- **시각 층** — 시뮬레이터 ↔ proto 서버 렌더 눈 대조. 자동화하지 않는다.
- 플레이스홀더 화면에는 테스트를 두지 않는다 — S3–S6이 갈아끼울 임시물이다.

## Off-limits

- 실제 Supabase·AI 호출 없음 — S0은 키 없이 완결된다. 마이그레이션(S1)·API
  라우트 구현(S2) 선점 금지.
- 스펙 Deferred 선반영·스펙·프로토타입 수정 금지 (마스터 플랜 공통 금지선).
- 기존 프리미티브(`src/tw`) 재배치 금지. 기존 라우트 파일은 위치를 유지하고
  내용만 실앱으로 교체한다 — ACME 템플릿 제거는 S0의 일이다.
- barrel 금지, 레이어 import 방향 준수 (CLAUDE.md).

## Risks and open questions

- **NativeTabs unstable API** — 스펙 지정 사항. SDK 57 시점 API를 확인해 쓰고,
  문제가 생기면 마무리 보고에 남긴다.
- **계약 스키마의 수명** — S1·S2가 "계약 변경 제안"을 내는 것은 배치 1의
  설계된 역할이다. S0 스키마는 최선의 초안이지 최종이 아니다.
- **`web.output: "server"` 전환** — 정적 웹 출력이 사라진다. 네이티브 우선
  앱이라 수용.
- **아이콘 래스터화** — SVG→PNG 변환이 1회 필요. 생성물 PNG를 커밋해 재현성
  문제를 피한다.
- **auth 스토리지 선택** — supabase 스킬 권고를 따르되(세션 토큰 크기와
  secure-store 한계 등), 의존성 추가 시점에 확정하고 근거를 커밋에 남긴다.
