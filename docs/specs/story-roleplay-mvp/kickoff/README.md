# 킥오프 공통 규약

모든 구현 세션(S0–S8)에 적용된다. 각 세션은 자기 킥오프 문서(S*.md)와 이 문서를
함께 따른다.

## 시작 절차

1. 다음을 먼저 읽는다: `GLOSSARY.md`, `docs/specs/story-roleplay-mvp/spec.md`,
   `docs/specs/story-roleplay-mvp/plan.md`, 자기 킥오프의 프로토타입 화면
   (`prototype.html` — launch.json의 `proto` 서버로 렌더해 볼 수 있다).
2. **플랜 모드로 계획을 세우고 승인받은 뒤 구현한다.** 계획은 그 시점의 실제
   코드(S0이 깔아둔 타입·심·컴포넌트)를 근거로 세운다.

## 경계

- plan.md의 Off-limits 절이 전 세션 공통 금지선이다.
- 자기 킥오프의 스코프 밖 파일은 수정하지 않는다. 공유 컴포넌트·토큰·심 계약이
  부족하면 **수정하지 말고** 자기 화면 폴더 안에서 해결한 뒤 마무리 보고에 남긴다.
- 스펙·프로토타입과 어긋나는 결정 차원의 발견은 구현으로 우회하지 말고 마무리
  보고에 "스펙 역류 제안"으로 남긴다.

키가 필요한 세션(S1, S2, S7)은 메인 체크아웃의 `/Users/toycrane/code/flyn/.env.local`

## 실행 (S0에서 확인된 것)

- S0의 화면들은 **픽스처를 표시하는 플레이스홀더**다. ✎·칩·시트 같은 조작은
  아직 붙어 있지 않다 — 반응이 없다고 고장 난 것이 아니라 각 화면 세션의 몫이다.
- `expo run:ios`는 실기기가 연결돼 있으면 그쪽 코드 서명 경로를 타다 실패한다.
  시뮬레이터로 빌드하려면 대상을 명시하거나 xcodebuild를 직접 쓴다.
- `pod install`은 로케일이 UTF-8이 아니면 죽는다. `LANG=en_US.UTF-8`을 준다.
- 파일을 옮기거나 이름을 바꾼 뒤에는 Metro를 `--clear`로 다시 띄운다.
- `lightningcss`는 `overrides`로 1.30.1에 고정돼 있고 `react-native-css`는
  nativewind가 선언한 `^3.0.1` 범위 안에 있어야 한다. 둘 중 하나라도 벗어나면
  번들러가 죽는다 — 올리려면 시뮬레이터 부팅까지 확인하고 올린다.

## 검증

- 화면 세션은 iOS 시뮬레이터에서 프로토타입과 대조한다. 병렬 세션과 Metro 포트가
  겹치지 않게 자기 킥오프에 지정된 포트를 쓴다 (`expo start --port <포트>`).
- 순수 헬퍼는 `*.test.ts` 콜로케이션 + `bun test`.
- 타입 체크(`tsc --noEmit`)가 통과해야 한다.
