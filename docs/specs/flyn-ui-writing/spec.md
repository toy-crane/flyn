# UX 라이팅 원칙 적용

상태: 완료. 사용자가 2026-09-12에 외부 디자인 시스템의 글쓰기 기준을 더는 참조하지
않고 Flyn 자체 기준을 쓰기로 했다. 한 문장으로 끝나는 한국어 고정 UI 문구에는
마침표를 붙이지 않고, 두 문장 이상이 이어지는 글에는 마지막 문장까지 마침표를
붙이기로 했다.

2026-09-13에 이름을 `UX 라이팅 원칙`으로 정하고, 세부 지침을 세 가지 큰 방향으로
줄이기로 했다. 2026-09-13에 앱 문구 적용, 자동 검사와 코드 검토를 마쳤다.

## 배경

기존 화면 문구 계약은 외부 디자인 시스템을 판정 기준으로 삼았다. 그 기준은 평서문과
명령문이면 한 문장뿐인 짧은 상태, 오류, 빈 화면 안내에도 마침표를 붙인다. Flyn의
화면에서는 이런 짧은 문구가 글보다 화면 요소에 가깝고, 마침표가 붙으면 필요 이상으로
무겁게 보인다. 문구의 역할을 상태, 오류, 보조 설명처럼 나누는 방식도 같은 문구가 놓인
자리에 따라 다르게 불릴 수 있어 일관되게 적용하기 어렵다.

이 작업은 화면 문구를 Flyn 자체 기준으로 판단하게 만들고, 문장 수로 마침표 규칙을
나눈다. 저장소에 남은 외부 디자인 시스템 참조도 함께 없앤다.

## 사용자에게 보이는 결과

- 상태, 오류, 빈 화면 안내, 토스트와 입력 안내가 한 문장이면 마침표 없이 짧게 끝난다.
- 두 문장 이상을 이어 읽는 안내는 각 문장의 경계와 글의 끝이 보이도록 마지막 문장까지
  마침표를 쓴다.
- 질문에는 물음표를 쓰고, 꼭 필요한 감탄에는 느낌표를 쓴다.
- 버튼, 메뉴, 제목, 라벨처럼 문장이 아닌 문구에는 지금처럼 문장 부호를 붙이지 않는다.
- 같은 역할과 뜻을 가진 문구는 화면이 달라도 같은 말투와 문장 부호를 쓴다.

## 확정한 기준

### Flyn이 직접 정하는 말투

- [UX 라이팅 원칙](../../decisions/ux-writing.md)이 내용, 길이와 말투를 판단하는 큰
  방향을 정한다. 문구별 세부 규칙을 늘리지 않고 이 원칙을 사용자 상황에 맞춰 적용한다.
- 이번 작업은 기존 말투의 방향을 바꾸지 않는다. 판정 기준의 소유권을 Flyn으로 옮기고
  마침표 기준을 문구의 역할 대신 한 텍스트 덩어리의 문장 수로 바꾼다.

### 문장 부호

- 한 텍스트 덩어리가 한국어 평서문이나 명령문 한 문장으로 끝나면 마침표를 붙이지
  않는다. 글자 크기나 상태, 오류, 보조 설명 같은 역할은 이 판단을 바꾸지 않는다.
- 두 문장 이상을 이어 하나의 글로 보여 줄 때는 마지막 문장을 포함한 각 평서문과
  명령문에 마침표를 붙인다.
- 질문에는 문장 수와 관계없이 물음표를 붙인다. 느낌표는 꼭 필요한 감탄에만 붙인다.
- 버튼, 메뉴, 제목, 라벨처럼 문장이 아닌 문구에는 문장 부호를 붙이지 않는다.
- 한 텍스트 덩어리는 한 화면 요소가 한 번에 보여 주고 함께 읽히는 글을 뜻한다. 같은
  화면에 떨어져 있는 두 문구는 각각 따로 판단한다.

예시는 아래와 같다.

- `표현을 확인하고 있어요.`는 `표현을 확인하고 있어요`로 바뀐다.
- `아직 저장한 표현이 없어요.`는 `아직 저장한 표현이 없어요`로 바뀐다.
- `메일 앱을 열지 못했습니다.`는 `메일 앱을 열지 못했습니다`로 바뀐다.
- `아이디는 30일에 한 번 바꿀 수 있어요. 이전 아이디는 30일 동안 다른 사람이 사용할
  수 없어요.`는 그대로 둔다.
- `표현을 삭제할까요?`는 그대로 둔다.

### 외부 기준과 참조

- 화면 문구를 판단할 때 외부 디자인 시스템의 글쓰기와 말투 기준을 불러오지 않는다.
- 저장소의 에이전트 지침, 결정 계약과 명세에서 외부 디자인 시스템의 글쓰기 및 로딩
  지침 참조를 없앤다. 데이터베이스의 초기 데이터를 뜻하는 `seed`는 이름만 같고 이
  작업과 관계없다.
- [UX 라이팅 원칙](../../decisions/ux-writing.md)이 Flyn 화면 문구의 유일한
  프로젝트 결정 계약이다.

## 완료 기준

1. 한국어 고정 UI 문구가 한 문장인 상태, 오류, 빈 화면 안내, 토스트와 입력 안내는
   마침표 없이 보인다.
2. 두 문장 이상인 안내는 문장 사이와 마지막 문장에 알맞은 문장 부호가 보인다.
3. 한 문장 질문의 물음표와 꼭 필요한 느낌표는 사라지지 않는다.
4. 버튼, 메뉴, 제목과 라벨에는 새 문장 부호가 생기지 않는다.
5. 같은 고정 문구를 화면 표시와 화면 읽기가 함께 쓰면 두 곳에서 같은 문구로 읽힌다.
6. 영어 대사와 학습 예문, 사용자가 쓴 글, 서버가 만든 스토리 콘텐츠의 문장 부호는
   바뀌지 않는다.
7. 저장소의 문서와 에이전트 지침에서 졸업한 외부 디자인 시스템을 화면 문구나 로딩
   판단의 근거로 참조하지 않는다.
8. 화면 문구를 확인하는 자동 검사가 새 문장 부호와 기존 질문, 여러 문장 안내를 함께
   확인한다.

## 가정

- 마침표 규칙은 한국어 고정 UI 문구에 적용한다. 영어는 문장 부호가 학습 내용의 일부라
  같은 규칙을 적용하지 않는다.
- 서버가 만든 한국어 스토리 소개, 장면 서술, 결말과 학습 설명은 콘텐츠다. 앱이 받은
  문장 부호를 고치지 않는다.
- 화면 읽기 전용 이름이 버튼이나 메뉴의 이름이면 지금처럼 문장 부호를 붙이지 않는다.
  화면에 보이는 상태 문구를 그대로 읽는 경우에는 보이는 문구와 같은 형태를 쓴다.
- 기존에 저장된 사용자 글과 서버 콘텐츠를 다시 쓰거나 옮기지 않는다.

## 범위 밖

- 영어 대사, 고친 영어 문장과 영어 예문의 문장 부호 변경
- 사용자가 입력한 글이나 이미 저장된 대화 내용 변경
- 서버 프롬프트가 만드는 스토리와 학습 콘텐츠의 말투 변경
- 랜딩 페이지, 이용약관과 개인정보 처리방침 본문 변경
- 색상, 타이포그래피, 간격, 아이콘과 컴포넌트 모양 변경
- 해요체와 합쇼체를 쓰는 현재 경계 변경

## 남은 위험

- 서버 콘텐츠에는 한 문장이어도 마침표가 남으므로 고정 UI 문구와 나란히 놓이면 표기가
  달라 보일 수 있다. 콘텐츠의 문장 부호는 의미와 영어 학습에 영향을 줄 수 있어 이번
  작업에서는 그대로 둔다.
- 한 화면 요소 안에서 문장을 줄바꿈해 보여 주거나 목록으로 나누면 하나의 글인지 판단이
  애매할 수 있다. 함께 이어 읽는 문장이면 여러 문장 규칙을 적용하고, 각 항목이 독립된
  선택지나 이름이면 문장이 아닌 문구로 판단한다.
- 짧은 합쇼체 오류에서 마침표를 빼면 기존보다 덜 공식적으로 보일 수 있다. Flyn은 짧은
  화면 문구의 가벼움과 일관성을 우선한다.

## 이 작업이 따르는 계약

- [UX 라이팅 원칙](../../decisions/ux-writing.md): 문구를 판단하는 세 가지 큰 방향과
  문장 부호 기준을 정한다.
- [PRODUCT.md](../../../PRODUCT.md): 사용자가 영어를 계속 쓰게 해야 한다는 제품 원칙을
  따른다. 화면 문구는 학습 흐름을 가로막지 않고 다음 행동을 바로 알 수 있게 한다.

## 구현과 검증

2026-09-13 기준:

- 인증, 프로필, 대화, 교정, 표현 노트와 스토리의 한 문장 고정 UI 문구에서 마침표를
  뺐다. 표시 문구와 화면 읽기 이름, 이를 확인하는 테스트와 현재 결정 계약의 예시를
  함께 맞췄다.
- 여러 문장인 프로필 안내와 계정 삭제 안내, 질문의 물음표는 유지했다. 영어 학습
  예문, 서버 콘텐츠, 사용자 글과 외부 제공자가 반환한 오류 원문은 바꾸지 않았다.
- 외부 디자인 시스템 참조 제거와 Flyn 자체 계약 작성은 앞선 문서 커밋에서 마쳤다.
  에이전트 지침, 결정 계약, 명세와 검토 지침에 해당 참조가 남지 않았음을 확인했다.
- 인증 오류의 기존 테스트에서 마침표 없는 문구를 기대하도록 먼저 바꿔 실패를
  확인했다. 구현을 바꾼 뒤 해당 테스트 12개를 모두 통과했다.
- 모바일 전체 테스트는 87개 묶음, 614개 테스트를 모두 통과했다.
- 나머지 패키지 테스트는 `bunx turbo run test --filter='!@repo/mobile'`로 통과했다.
  API는 캐시 결과를 재사용했고, 스크립트 테스트는 330개 통과, 별도 환경이 필요한
  7개는 건너뛰었다.
- 루트의 `bun run check-types`, `bun run check`와 `git diff --check`를 통과했다.
- 모바일 테스트 중 React `act` 경고가 출력됐으나 실패한 테스트는 없었다.
- 사용자가 2026-09-13에 문구만 바뀐 부분은 실제 화면에서 확인하지 않아도 된다고
  했다. 이번 변경은 문구와 관련 테스트·문서뿐이므로 실제 화면 확인과 개발 서버
  실행은 생략했다. iOS나 Android의 실제 렌더링을 검증했다는 뜻은 아니다.
- OpenAI Codex의 별도 검토 에이전트가 `cf358ee` 대비 전체 구현 diff 40개 파일을
  명세, UX 라이팅 원칙과 관련 결정 계약에 따라 한 차례 검토했다. 수정이 필요한
  finding은 없었다. 검토 에이전트는 테스트를 재실행하지 않았으며 위 실행 결과를
  검증 근거로 읽었다.
