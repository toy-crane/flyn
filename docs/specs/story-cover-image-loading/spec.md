# 스토리 표지 이미지 로딩

상태: 승인. 사용자가 2026-09-09에 BlurHash 미리보기와 짧은 전환, 이모지 제거를 확인하고 표준 결정 문서와 명세 확정을 요청했다. 구현과 기기 검증은 남아 있다.

## 사용자가 얻는 것

표지 원본을 받는 동안 원본의 색과 형태를 흐릿하게 본다. 원본이 준비되면 같은 자리에서 부드럽게 선명해진다. 로딩 전후에 이모지가 나타나거나 주변 내용이 밀리지 않는다.

## 범위와 동작

- 탐색 목록, 스토리 목록, 스토리 상세와 대화 기록 등 현재 스토리 표지를 보여 주는 모든 곳에 같은 기준을 적용한다.
- [모바일 이미지 로딩](../../decisions/mobile-image-loading.md)을 따른다. 각 표지의 BlurHash를 미리 제공하고 원본과 짧은 전환으로 연결한다.
- 기존에 등록한 표지에도 해당 원본의 해시를 준비한다. 새 표지를 등록하거나 교체할 때도 원본과 해시가 함께 갱신된다. 해시가 없다는 이유로 기존 스토리를 열지 못하게 하지 않는다.
- 스토리 표지의 이모지를 모든 상태에서 제거한다. 표지가 없거나 원본을 받지 못했을 때도 이모지를 대신 보여 주지 않는다.
- 표지 크기와 모서리, 원본의 잘림 기준은 기존 화면을 유지한다. 미리보기도 같은 영역을 채운다.
- 표지를 기다리는 동안 제목, 소개와 화면 행동을 사용할 수 있다. 이미지 실패를 스토리 정보 전체의 조회 실패로 취급하지 않는다.
- 목록을 빠르게 스크롤하거나 다른 스토리를 열어도 이전 스토리의 원본이나 해시를 잠깐 보여 주지 않는다.
- 표지를 교체하면 새 원본과 새 해시가 짝을 이룬다. 이전 캐시 때문에 교체 전 표지를 계속 보여 주지 않는다.
- 표지는 기존처럼 장식 이미지로 취급한다. 화면 읽기 기능에 로딩 상태나 미리보기를 별도로 반복해서 읽히지 않는다.

## 상태별 표시

| 조건 | 표지 영역 |
| --- | --- |
| 원본 로딩 중, 해시 있음 | 해당 원본의 BlurHash 미리보기 |
| 원본 표시 가능 | 원본 이미지 |
| 원본 로딩 중, 해시 없음 또는 유효하지 않음 | 배경색을 유지하고 원본 로딩 계속 |
| 표지 없음 | 배경색만 표시 |
| 원본 로딩 실패 | 유효한 미리보기가 있으면 유지하고, 없으면 배경색만 표시 |

배경색과 실패 시 표시는 아래의 바꿀 수 있는 기본값이다. 모든 경우에 표지 이모지는 표시하지 않는다.

## 완료 기준

- iOS와 Android에서 캐시가 없는 느린 네트워크로 표지를 열면 원본보다 먼저 해당 표지의 미리보기를 본다.
- 원본이 나타날 때 표지 영역의 크기나 잘림 기준이 바뀌지 않고 주변 내용이 밀리지 않는다.
- 탐색 목록, 스토리 목록, 스토리 상세와 대화 기록에서 같은 스토리의 표지와 미리보기가 일치한다.
- 표지 없음, 해시 없음, 잘못된 해시와 원본 로딩 실패를 각각 확인한다. 앱이 중단되지 않고 제목과 행동을 계속 사용할 수 있다.
- 위 모든 상태에서 표지 이모지가 나타나지 않는다.
- 캐시된 표지를 다시 열 때 불필요하게 원본을 가리고 로딩 시간을 만들지 않는다.
- 빠른 목록 스크롤과 연속 화면 이동에서 다른 스토리의 원본이나 해시가 나타나지 않는다.
- 기존 표지의 해시가 준비되어 있으며, 표지 교체 후 새 원본과 새 해시가 함께 보인다.
- 밝은 화면과 어두운 화면에서 배경색과 전환을 확인한다. 화면 읽기 기능은 표지를 별도 로딩 항목으로 읽지 않는다.

## 확정한 제약과 이유

- 사용자는 프로필 사진을 기존 HeroUI Avatar 방식으로 유지하고 스토리 표지에만 이번 변경을 적용하도록 확인했다. 프로필 사진 업로드와 대체 표시는 바꾸지 않는다.

- Expo Image, BlurHash, 짧은 전환과 표지 이모지 제거는 사용자 승인 사항이다. 재사용할 기준은 모바일 이미지 로딩 결정 계약이 소유한다.
- 표지는 기존 스토리를 알아보는 역할을 유지한다. [모바일 스토리 탐색](../../decisions/mobile-story-browsing.md)의 목록과 상세 행동은 바꾸지 않는다.
- 사용자가 조사 결과를 승인했으므로 별도 시안 검토는 반복하지 않는다. 실제 기기에서 전환을 확인하는 일은 구현 완료 기준에 포함한다.

## 바꿀 수 있는 기본값

- 전환 시간은 200ms로 시작한다. Expo의 강제값이 아닌 제안값이며 기기 검증에서 조정할 수 있다.
- 해시나 이미지가 없으면 기존 표지 배경색을 유지한다. 원본 로딩 실패 시 유효한 미리보기는 유지한다. 별도 회전 진행 표시나 이미지 전용 재시도 버튼은 추가하지 않는다.
- 화면 표시를 없애는 데 필요하지 않은 기존 이모지 저장 필드 삭제는 하지 않는다. 기존 데이터와 다른 사용처를 보존한다.

## 제외와 남은 위험

- 프로필 사진 등 다른 이미지의 일괄 교체, 표지 그림 재제작, 표지 크기 변경과 새 이미지 등록 화면은 범위 밖이다.
- 에피소드 상황 줄 등 표지와 관계없는 이모지는 유지한다.
- 표지 해시를 준비하고 전달하는 데 필요한 변경은 범위에 포함한다. 인증, 대화 저장과 스토리 진행 규칙은 바꾸지 않는다.
- 패키지 호환성과 API는 배포 소스로 확인했지만 실제 기기의 로딩 전환은 아직 검증하지 않았다.
- 기존 표지의 해시 준비와 교체 시 캐시 갱신을 빠뜨리면 배경색만 오래 보이거나 이전 표지가 남을 수 있다. 완료 기준에서 각각 확인한다.
- 필수 제품 결정은 남아 있지 않다. 데이터 전환 중 해시가 없는 표지는 위 상태별 표시로 처리한다.
