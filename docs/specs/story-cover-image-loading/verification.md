# 스토리 표지 검증

2026-09-09에 `4891/flyn`에서 검증했다. 구현 범위는 탐색, 최근 스토리, 상세와 대화 기록의 공통 `StoryCover`, 표지 API, 원본·BlurHash 준비와 등록이다. 프로필 사진과 에피소드 이모지는 유지했다.

## 자동 검사

- `bun run check`, `bun run check-types`, `bun run test` 통과. 모바일 72개 suite의 511개 테스트를 포함한다.
- 별도 Supabase 스택에서 전체 마이그레이션과 seed 초기화 후 DB 테스트 271개 통과. 보안 advisor는 문제를 보고하지 않았다.
- 실제 Storage 등록·교체·같은 원본 재등록 테스트의 assertion 8개 통과. 새 경로와 해시를 DB에 함께 저장하고 내려받은 이미지의 픽셀도 확인했다.
- 기본 표지 5개의 해시와 파일 경로 일치 검사 통과. 이름 변경 전후 PNG를 디코딩한 픽셀은 모두 같다.
- 임시 DB에서 타입을 다시 생성해 저장소 파일과 같은지 비교했다. 임시 폴더에 복사한 다른 세션의 DCL 파일 `20260909053318`은 테스트 DB에 적용하지 않았다. 마이그레이션 이력으로 확인했다.

## 실제 앱

`bun run dev ios android`로 현재 워크트리의 네이티브 빌드를 다시 설치했다. iOS `flyn-slot-1`, Android `flyn_dev_1`을 사용했다. 앱에서 이메일 코드를 요청하고 로그인했다.

원본이 캐시되지 않은 새 요청 주소를 이 워크트리 전용 임시 프록시로 연결했다. 원본 응답을 보류한 상태에서 네 화면의 같은 표지가 같은 BlurHash를 보여 주는지 확인했다. 응답을 풀었을 때 원본으로 전환되는 두 플랫폼의 동영상을 녹화하고 전환 프레임을 비교했다. 크기, 잘림, 모서리와 주변 내용의 위치를 유지했다.

| 입력 | 두 플랫폼에서 관찰한 결과 |
| --- | --- |
| 유효한 해시, 원본 지연 | 해당 표지의 흐릿한 미리보기 표시 |
| 유효한 해시, 원본 404 | 미리보기 유지 |
| 해시 없음, 원본 404 | 배경색 유지 |
| 잘못된 해시, 원본 지연 후 성공 | 배경색 뒤에 원본 표시, 앱 중단 없음 |
| 이미지 경로 없음 | 배경색만 표시 |

밝은 화면과 어두운 화면에서 위 상태를 각각 확인했다. 표지 이모지는 나타나지 않았으며 제목과 화면 이동을 계속 사용할 수 있었다. 접근성 트리에는 표지나 미리보기를 별도 항목으로 노출하지 않았다. VoiceOver와 TalkBack의 음성 출력 자체는 별도로 검증하지 않았다.

검증용 입력과 프록시 연결 코드를 제거한 뒤 실제 표지로 다시 확인했다. 목록 스크롤, 다른 스토리 상세 열기, 최근 스토리와 대화 기록 이동에서 표지가 해당 스토리와 일치했다. 캐시된 원본을 다시 열 때 인위적인 로딩 대기는 없었다. 같은 원본의 새 주소로 전환했을 때도 해당 원본과 미리보기가 연결됐다. 다른 원본으로 교체하는 DB·Storage 흐름은 위 통합 테스트에서 검증했다.

두 플랫폼에서 탐색 → 상세 → 대화 시작 → 메시지 전송 → 답변과 표현 피드백 → 대화 기록 → 이어서 하기를 실행했다. 저장한 메시지와 답변을 다시 읽었다. Metro 로그에 새 오류가 없었다.

## 검토와 경계

- `supabase-reviewer`: DB·등록 도구 범위 1회 완료. 수정할 결함 없음. 검토 당시 직접 확인하지 못했던 타입 생성과 추가 DCL 적용 여부는 위 검사로 확인했다.
- Codex 전체 코드 리뷰: 이미지 구현 diff와 명세·관련 결정 계약을 대상으로 1회 완료. 수정할 결함 없음. 오래된 문서 상태 설명을 현재 결과로 갱신했다.
- 다른 세션이 남긴 내비게이션 변경은 이미지 변경 커밋에 포함하지 않는다.
- 로컬 Simulator·Emulator의 Development Build 결과다. 운영 배포와 실제 휴대전화 검증은 포함하지 않는다.
