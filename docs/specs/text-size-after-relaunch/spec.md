# 시스템 글자 크기는 앱 시작 시점 값만 따른다

## 배경

큰 시스템 글자 크기를 확인할 때마다 화면 여기저기에 손을 대야 했다. 원인을 가르니
"얼마나 크게까지 지원하느냐"가 아니라 "앱을 연 채 글자 크기를 바꾸는 경우"였다.
그 경우만 빼면 상한 없이도 최대 크기에서 화면이 손질 없이 통과한다. 사용자가 그
경우를 지원하지 않기로 정했고, 근거와 검증 절차는
[모바일 타이포그래피](../../decisions/mobile-typography.md)가 소유한다.

이 스펙은 그 결정에 따라 남아 있는 임시 처치를 걷어내고, 검증 절차를 결정에
맞추는 작은 정리 작업이다.

## 사용자에게 보이는 결과

- 앱을 시작할 때의 시스템 글자 크기로 모든 화면이 잘림과 겹침 없이 그려진다.
  최대 크기(iOS `accessibility-extra-extra-extra-large`, Android 200%)도 같다.
- 앱을 연 채 시스템 글자 크기를 바꾼 뒤의 화면은 보장하지 않는다. 앱을 완전히
  닫고 다시 시작하면 새 크기로 맞게 그려진다. 설정에서 앱으로 돌아오는 것만으로는
  다시 시작되지 않는다.
- 사용자가 보는 글자 크기, 위계, 간격은 이 작업 전후로 달라지지 않는다.

## 범위

- 글자 배율이 바뀔 때 뷰를 강제로 다시 만드는 처치를 모두 없앤다. 현재는 채팅
  메시지, 장면 서술, 상황 줄, 배울 표현의 카드와 출처, 종료와 표현 돌아보기 화면, 배울 표현
  카드, 화면 상태와 상태 줄에 있다.
- 처치를 없앤 뒤에도 앱을 시작할 때의 배율에 맞춘 크기 계산(예: 진행 표시와
  줄 높이, 입력창 높이)은 그대로 둔다. 이 값들은 시작 시점의 배율만 읽으면 된다.
- 처치의 존재를 전제한 테스트는 없애거나 시작 시점 배율만 검사하도록 고친다.

## 완료 기준

- 저장소에서 글자 배율을 키로 삼아 뷰를 다시 만드는 코드가 사라진다.
- iOS 시뮬레이터를 최대 글자 크기로 설정하고 앱을 완전히 닫고 다시 시작해 홈, 탐색, 대화,
  종료, 표현 돌아보기, 표현 노트, 설정 화면이 잘림과 겹침 없이 그려진다.
  기본 크기에서도 같다.
- Android 에뮬레이터를 200%로 설정하고 앱을 완전히 닫고 다시 시작해 같은 화면을 확인한다.
- 기존 자동 테스트가 모두 통과한다.

## 제약과 근거

- 검증은 각 플랫폼의 최대 시스템 글자 크기로 바꾼 뒤 앱을 완전히 닫고 다시
  시작해서 한다. 앱을 연 채 바꿔 가며 본 결과는 증거로 삼지 않는다. 크기와 절차의
  근거는 결정 계약에 있다.
- 글자 확대 상한을 새로 두지 않는다. 좁은 크롬의 예외는 결정 계약이 이미 정한
  대로 유지한다.

## 가정

- 지금의 재생성 처치는 앱을 연 채 바꾸는 경우 외에는 화면에 영향을 주지 않는다.
  없앤 뒤 시작 시점 화면이 달라지면 그 화면의 배치 문제로 따로 본다.

## 손대지 않는 것

- 줄 높이나 글자 크기 토큰. 잘림의 원인이 아니었고 디자인 시스템 점검에서
  따로 본다.
- Android가 글자 크기 변경 때 Activity를 다시 만드는 네이티브 설정. 지원하지
  않는 경우에만 드러나므로 손대지 않는다.

## 남은 위험

- 실제 사용자가 앱을 연 채 크기를 바꾸고 돌아와 잘린 화면을 보면 앱을 완전히 닫고 다시 시작해야
  한다. 이 보고가 반복되면 결정 계약의 재검토 조건에 해당한다.
