# 첫 에피소드 완주 명세

## 목표

- 로그인한 사용자가 앱에서 에피소드 하나를 사건 시작부터 결말까지 영어로
  진행한다.
- 에피소드의 결론이 "몇 개를 틀렸다"가 아니라 사건의 결과로 남는다. 결말은
  성공, 타협, 실패 중 하나다.
- 플린의 가장 큰 베팅인 "사건이 있는 이야기 속에서 영어를 쓰는 경험"을 실제
  기기에서 플레이로 검증할 수 있게 만든다. 제품 전제는 루트 `PRODUCT.md`를
  따른다.

## 확정 범위

- 홈에서 에피소드를 시작한다. 레벨 테스트나 장면 선택 없이 바로 장면이 열린다.
- 에피소드는 이미 문제가 벌어진 장면에서 시작하고, 사용자가 입력하기 전에
  상대가 먼저 말한다.
- 첫 에피소드 장면은 카페다. 주문과 다른 커피가 나왔는데 직원은 벌써 다음
  손님을 부른다.
- 장면은 화자별 대사와 지문으로 흐른다. 대사는 영어로, 지문은 한국어로 쓴다.
- 상대는 사용자의 문법이 아니라 말의 내용에 반응한다. 강하게 항의하면 물러서고,
  애매하게 말하면 되묻는다.
- 모델이 사건이 마무리됐다고 판단하면 결말을 정하고 에피소드를 닫는다. 사용자가
  종료 버튼을 누르는 방식이 아니다.
- 마무리 화면에서 결말이 보이고 입력이 닫힌다. 사용자는 홈으로 돌아가거나
  처음부터 다시 시작할 수 있다.
- 에피소드 화면에서는 템플릿 Side chat 진입을 보이지 않게 한다.

## 확정 제약과 이유

- 대사는 영어, 지문은 한국어다. 사용자가 확정했다. 상황이 영어 없이도 이해된다는
  첫 에피소드 조건을 글에서 보장하고, 연습 대상인 대사에만 영어를 남긴다.
- 결말은 사용자의 말이 만든다. 정해진 턴 수, 시간, 종료 버튼으로 끝내지 않는다.
  "서툰 영어로도 원하는 것을 얻어냈다"는 결론은 결말이 대화 내용에서 나올 때만
  성립한다.
- 상대의 영어는 중급보다 조금 낮게 시작한다. 쉬우면 시시한 정도로 그치지만,
  어려우면 첫 화면에서 이탈한다.
- 이 단위는 교정이 전혀 없어도 성립하는 경험으로 만든다. 교정을 반영하지 않아도
  이야기는 계속된다는 제품 원칙과 같은 방향이고, 교정은 다음 단위에서 이 그릇
  위에 얹는다.
- 장면이 화자별 대사와 지문으로 스트리밍되는 형식은 한국어 시험 세계 스파이크로
  이미 검증했다. 이 단위는 그 형식을 영어 대사와 한국어 지문의 혼합으로 옮긴다.

## 수용 기준

- 로그인한 사용자가 홈에서 에피소드를 시작하면, 입력하기 전에 상대가 먼저 카페
  장면을 연다.
- 상대의 대사는 영어로 보이고, 지문은 한국어로 보인다.
- 짧게 답해도 길게 답해도 장면이 진행된다.
- 사용자의 태도에 따라 상대의 전개가 달라진다. 같은 장면에서 강하게 항의할 때와
  애매하게 말할 때 다른 반응이 관찰된다.
- 사건이 풀리거나 무산되면 에피소드가 성공, 타협, 실패 중 하나로 끝나고, 결말이
  화면에 보이며 입력이 닫힌다.
- 에피소드를 나갔다 다시 들어오면 새 에피소드가 처음부터 시작한다.
- 에피소드 화면에 Side chat 진입이 보이지 않는다.
- 저장소 루트에서 `bun run check`와 `bun run check-types`가 통과한다.

## 가정

아래는 에이전트가 정한 값이라 사용자가 뒤집을 수 있다.

- 첫 에피소드의 고정 인물은 직원 한 명이다. 주변 상황(다음 손님 등)은 지문이
  전한다.
- 마무리 화면은 결말 종류와 사건 결과 한 줄을 보여 준다. 오늘 배운 표현 자리는
  만들지 않는다.
- 사용자가 한국어로 입력해도 에피소드는 끊기지 않고, 상대는 영어 대사로
  반응한다.
- 다시 시작하면 같은 카페 장면이 처음부터 새로 열린다.
- 상대는 에피소드 안에서 사용자가 쓰는 문장에 맞춰 말의 난이도를 고르되, 수준을
  어디에도 저장하지 않는다.

## 제외

- 교정, 오늘 배운 표현, 고쳐서 다시 보내기. 다음 단위다.
- 잠깐 물어보기.
- 다음 이야기 예고, 이어 하기, 에피소드 사이의 기억, 시즌. 첫 에피소드는 시즌에
  묶지 않은 독립 완결로 두기로 사용자가 확정했다. 다음 화가 없는 상태에서 결말이
  새 질문을 남기면 지키지 못할 약속이 되고, 아무것도 저장하지 않으므로 나중에
  시즌 1화로 올려도 재작업이 없다.
- 사용자 언어 수준의 저장과 재사용.
- 에피소드 저장과 복구. 나가면 사라진다. 사건은 한 세션 안에 마무리한다는 제품
  정의와 맞는다.
- 템플릿 Side chat 기능 자체의 제거나 개편. 이번에는 에피소드 화면에서 진입만
  숨긴다. 이름과 동작 정리는
  [기존 follow-up](../../follow-ups/side-chat-name-still-in-screens-and-docs.md)이
  이미 담고 있다.
- 새 에피소드 콘텐츠 추가. 카페 장면 하나만 만든다.

## 보류

- 결말 이후 다음 에피소드로 잇는 방식. 예고와 기억 설계는 다음 단위에서 다룬다.
- 지문을 한국어로 두는 규칙을 첫 에피소드 너머 모든 에피소드에 적용할지. 수준이
  높은 사용자에게는 다시 볼 수 있어, 에피소드가 늘 때 결정 계약으로 올릴지
  판단한다.
- 사용자가 영어 대신 한국어만 계속 쓸 때 제품이 어떻게 유도할지. 이번에는
  끊기지 않는 것까지만 보장한다.

## 남은 위험

- 모델이 결말 판정을 안정적으로 하지 못하면 에피소드가 끝나지 않거나 너무 일찍
  끝날 수 있다. 실제 기기 플레이로 확인해야 한다.
- 영어 대사와 한국어 지문의 혼합 출력을 모델이 어길 수 있다. 스파이크에서 영어
  메타 텍스트가 대사로 샌 사례가 있어, 같은 검증이 이 혼합 형식에도 필요하다.
- 중급보다 조금 낮은 난이도가 실제 사용자에게 맞는지는 써 봐야 안다.
