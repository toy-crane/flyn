# 화면 글자를 HeroUI Typography 역할로 옮긴다

## 배경

2026-09-13 감사에서 RN `Text` 78곳이 저마다 className을 조립해 같은 역할이
서너 갈래로 갈려 있었다. 사용자가 HeroUI `Typography`를 텍스트 역할 층으로
채택하고, 시안 비교에서 HeroUI 기본값을 재정의 없이 쓰기로 정했다. 역할 대응표와
근거는 [모바일 타이포그래피](../../decisions/mobile-typography.md)가 소유한다.

## 사용자에게 보이는 결과

- 같은 역할의 글자가 모든 화면에서 같은 크기, 행간, 굵기로 보인다. 화면 안
  제목은 한 크기, 카드 제목과 섹션 헤딩은 한 크기다.
- 본문과 카드 설명의 행간이 지금보다 조금 넓어진다. 카드가 그만큼 길어진다.
- 제목에 HeroUI 기본 자간이 붙는다.
- 화면 제목, 섹션 헤딩, 카드 제목이 화면 읽기에 헤더로 읽힌다.
- 큰 시스템 글자 크기에서 모든 역할이 Dynamic Type 램프를 따라 커진다.
- 문구, 색, 배치, 동작은 달라지지 않는다.

## 범위

- React Native UI의 모든 `Text`를 `Typography`로 바꾸고, 계약의 대응표에
  따라 `type`을 고른다. 헤딩 역할은 `Typography.Heading`으로 쓴다.
- `Text`에 붙어 있던 `text-*`, `leading-*`, `font-*` 클래스와 인라인 크기를
  모두 없앤다. 색 className과 `numberOfLines`는 남긴다. 강조는 `weight`로
  옮긴다.
- 부분 강조가 필요한 문장(표현 카드의 표시 구간)은 `Typography` 안에 중첩한
  `Text`로 표현한다. 중첩 `Text`에도 크기 클래스를 두지 않는다.
- 상태 줄의 역할별 크기 상수와 진행 표시의 줄 높이 계산은 대응표의 값으로
  맞춘다. 진행 표시 크기 규칙 자체는 바꾸지 않는다.
- 토스트의 확대 상한과 로그인 버튼의 확대 상한은 그대로 둔다.
- `@expo/ui`가 소유하는 설정 화면의 글자는 바꾸지 않는다.

## 완료 기준

- 저장소의 React Native UI에 `text-[Npx]`, `leading-[Npx]`, 인라인
  `fontSize`가 없다. 코드 표시의 monospace 지정은 예외다.
- `Text`에 `text-*`(색 제외), `leading-*`, `font-*` 클래스가 없다.
- 계약의 대응표에 없는 `type` 조합이 없다.
- iOS 시뮬레이터와 Android 에뮬레이터에서 탐색, 대화, 종료, 표현 돌아보기,
  대화 기록, 표현 노트, 인증, 온보딩 화면을 기본 글자 크기와 최대 시스템 글자
  크기(앱을 완전히 닫고 다시 시작)로 열어 잘림과 겹침이 없다. 밝은 화면과
  어두운 화면 모두 확인한다.
- 화면 읽기로 화면 안 제목, 섹션 헤딩, 카드 제목이 헤더로 읽힌다.
- 기존 자동 테스트가 모두 통과한다. 크기 클래스를 검사하던 테스트는 역할
  `type`을 검사하도록 바꾼다.

## 제약과 근거

- 역할 대응표, 재정의 금지, 검증 절차는
  [모바일 타이포그래피](../../decisions/mobile-typography.md)가 소유한다.
- 컴포넌트가 소유하는 라벨(버튼, 칩, 목록 행)은
  [모바일 컴포넌트 선택](../../decisions/mobile-component-selection.md)에
  따라 앱이 글자를 지정하지 않는다.
- 이 스펙은 카드와 행의 컴포넌트 교체를 하지 않는다. 그 화면의 글자는 지금
  구조 안에서 역할만 바꾼다. 카드와 행 이전은
  [카드와 행 이전 스펙](../heroui-cards-and-rows/spec.md)이 맡는다.

## 가정

- HeroUI `Typography`가 `numberOfLines`, `selectable`, `testID` 같은 RN
  `Text` 속성을 그대로 받는다. 받지 못하는 속성이 있으면 그 자리만 RN `Text`로
  남기고 대응표의 값을 className으로 쓴 뒤 이유를 주석에 적는다.
- 대화 말풍선의 행간 28은 사용자가 시안으로 보고 받아들였다. 실제 대화에서
  읽기가 나빠지면 계약의 재검토 조건에 따라 global.css에서 다시 본다.

## 손대지 않는 것

- 네이티브 헤더 제목과 탭 라벨. 운영체제가 소유한다.
- AI 답변 Markdown 렌더러의 본문 크기. 네이티브 렌더러가 숫자만 받으므로
  대응표의 `body` 값을 숫자로 넘기되 컴포넌트는 바꾸지 않는다.
- 문구와 색.

## 남은 위험

- 78곳을 한 번에 바꾸므로 화면마다 줄바꿈 위치가 달라진다. 완료 기준의 화면
  확인이 이를 잡는다.
- 제목 자간이 한글에서 어색해 보일 수 있다. 확인되면 global.css 한 곳에서
  재정의하고 계약에 적는다.
- 섹션 헤딩과 카드 제목이 쓰는 `h6`의 Dynamic Type 램프는 HeroUI가 정한
  `subheadline`이라, 최대 글자 크기에서 본문(`body` 램프)보다 덜 커진다. 위계가
  뒤집혀 보이는지 최대 크기 확인에서 본다.
