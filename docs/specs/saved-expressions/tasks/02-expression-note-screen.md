# 02 — 담아 둔 표현을 한곳에서 본다

## Outcome

사용자가 하단의 `노트` 탭에서 담아 둔 표현을 최근순으로 보고, 필요 없는 것을 밀어서 지운다. 카드는 출처에 따라 다르게 그려져서 인물의 대사와 내가 고쳐 받은 표현을 한눈에 구분한다.

## Blockers

작업 01. 담긴 항목이 있어야 목록을 그리고 지울 수 있다.

## Acceptance criteria

- [x] 하단 탭이 홈, 탐색, 스토리, 노트 넷이 된다. `노트` 탭을 열면 화면 제목이 `표현 노트`다. 표현 노트는 [모바일 탭 배치](../../../decisions/mobile-tab-navigation.md)에 따라 NativeTabs 안에 둔다.
- [x] 최근 담은 것이 맨 위에 온다. 스토리별 묶음, 검색, 필터는 없다.
- [x] 카드 맨 위에 출처 표시가 있다. 인물 대사면 인물 이름, 그 밖에는 `내 표현`이고 뒤에 스토리 제목과 화 번호가 붙는다.
- [x] 영어 교정과 한국어 안내 카드는 띠 안의 원문, 고친 문장, 이유 세 덩어리다. 원문의 어긋난 자리는 밑줄, 고친 문장의 달라진 자리는 형광펜으로 짚는다. 형광펜은 조각에 붙는 문장부호까지 감싼다.
- [x] 인물 대사 카드는 영어 문장과 한국어 뜻 두 줄이고 띠가 없다. 세 카드를 한 화면에 놓으면 모양으로 구분된다.
- [x] 구역에 라벨과 구분선이 없다.
- [x] 카드를 왼쪽으로 밀면 `삭제`가 드러나고, 확인 없이 사라지며 목록이 당겨진다. 접근성 이름은 `삭제`다.
- [x] 빈 화면과 불러오기 실패가 모두 본문 정중앙에 선다. 담은 것이 없으면 본문 정중앙에 책갈피 아이콘과 `아직 저장한 표현이 없어요.`가 보조색 보통 굵기로 보이고 버튼은 없다.
- [x] 불러오지 못하면 본문 정중앙에 연결 끊김 아이콘, 굵은 제목 `표현 노트를 불러오지 못했어요.`, 보조 버튼 `다시 시도하기`가 보인다. 다시 부르는 동안 버튼에 진행 표시가 있고 중복으로 눌리지 않는다. 불러오는 중이나 오류를 빈 목록으로 표시하지 않는다.
- [x] iOS 기본 글자 크기와 큰 접근성 글자 크기에서 카드의 세 덩어리와 출처 표시가 겹치거나 잘리지 않는다. 밝은 화면과 어두운 화면에서 같은 위계를 유지한다.
- [x] [모바일 스토리 탐색](../../../decisions/mobile-story-browsing.md)이 탭 넷을 반영한다.

## Constraints

- 화면 모양은 [프로토타입](../prototype.html)의 표현 노트 화면과 같다. 이름과 문구는 [스펙](../spec.md)과 [용어집](../../../../GLOSSARY.md)을 따른다.
- 카드를 눌러 대화의 그 자리로 이동하는 동작은 만들지 않는다.

## Verification

- `bun run test`가 카드가 출처 종류에 따라 다르게 그려지는 것을 확인하는 테스트를 포함해 통과한다.
- `bun run check`가 통과한다.
- `agent-device` 한 세션에서 세 종류를 담은 뒤 `노트` 탭을 열어 세 카드를 확인하고, 밀어서 모두 지웠을 때 빈 화면으로 바뀌는 것까지 확인한다.

## Execution

- Verification: `bun run db:test` 309개, `bun run test`(모바일 537개, API 134개,
  스크립트 185개), `bun run check`와 `bun run check-types`가 모두 통과했다. iOS
  Simulator의 `agent-device` 한 세션에서 인물 대사, 영어 교정, 한국어 안내 셋을
  담고 `노트` 탭을 열어 세 카드가 모양으로 갈리는 것을 확인했다. 카드를 왼쪽으로
  밀자 `삭제`가 드러났고, 누르자 확인 없이 사라지며 목록이 당겨졌다. 둘을 다
  지우자 본문 정중앙에 책갈피와 `아직 저장한 표현이 없어요.`가 버튼 없이 섰다.
  API를 내리고 앱을 다시 열자 같은 자리에 연결 끊김 아이콘과 굵은 제목,
  `다시 시도하기`가 섰다. 큰 접근성 글자 크기와 어두운 화면에서도 세 덩어리와
  출처 표시가 겹치거나 잘리지 않았다.
- Verification: 핵심 루프를 기기에서 다시 밟았다. 회차를 이어 열어 한국어와
  영어로 각각 말하고, 한국어 안내와 영어 교정을 받고, 사건이 결말과 다음 화
  예고로 끝나는 것까지 확인했다. 그 사이 담은 표현이 탭을 옮길 때마다 노트에
  최근순으로 쌓였다.
- Blocker: —
- Revision: 탭 아이콘은 스펙이 이름을 정하지 않아 프로토타입의 책갈피를 따라
  iOS `bookmark`/`bookmark.fill`, Android `bookmark_border`/`bookmark`을 골랐다.
- Revision: 삭제가 실패했을 때의 화면은 스펙에 없어서, 목록에서 먼저 빼고 실패하면
  그 자리로 되돌리는 쪽을 골랐다. 확인을 묻지 않는 동작이라 사라지는 것이 먼저
  보여야 하고, 되돌아온 카드가 아직 남아 있다는 것을 화면이 그대로 말한다. 담기
  실패가 그 자리에 한 줄을 남기는 것과 달리 여기에는 매달릴 자리가 없다.
- Revision: 대화에서 담고 취소하는 일이 이 목록을 무효로 만들 자리를 갖지 않아서
  탭으로 돌아올 때마다 다시 묻게 두었는데, NativeTabs의 탭 전환에서는 화면
  포커스가 오지 않아 실제로는 앱을 다시 켤 때까지 낡은 목록이 남았다. 기기에서
  보고 바꿨다. 이제 담기와 취소가 끝날 때 그쪽이 노트 쿼리를 무효로 만들고, 붙어
  있는 목록이 그 자리에서 다시 읽는다.
- Revision: 토스트 문구 `표현을 저장했어요`는 스펙이 인용한 그대로 두었다.
  [화면 문구 한국어 말투](../../../decisions/korean-ui-writing.md)는 평서문에
  마침표를 붙이라고 하고, 이 문구는 타이틀도 버튼도 라벨도 아니다. 승인된 두
  자리가 한 글자에서 어긋나므로 어느 쪽을 고칠지는 사용자가 정한다.
