# 다시 받기가 같은 메시지를 두 번 판정해 교정을 겹쳐 쌓는다

**Symptom**: 다시 받기 요청은 사용자 메시지를 새로 싣지 않고 기준 메시지만
가리킨다. 그러면 서버가 남은 대화의 마지막(= 그 사용자 메시지)을 다시 판정해,
이미 교정이 붙어 있는 메시지에 새 교정 행을 더한다. 세션을 다시 열면 그 메시지의
카드에 항목이 두 벌로 나타난다.

**Observed evidence**: 코드 검토가 2026-08-29에 짚었다.
`apps/api/src/features/episode/route.ts`의 `POST /`는 `sent`가 없어도
`correctionFor(play.messages, ...)`를 부르고, 그 함수는 `messages.at(-1)`이
`user`이면 판정한다. 다시 받기는 그 자리에 사용자 메시지를 남기므로 조건이
맞는다. 같은 패턴은 `readSeenPatterns`가 거르지만, 판정이 다른 패턴을 내면 새
행이 들어간다. 지금 재현하지는 못했다.

**Suspected cause**: 판정 대상을 "이번 턴에 새로 받은 메시지"가 아니라 "대화의
마지막 사용자 메시지"로 정했다. 교정을 저장하지 않던 때는 화면 상태가 덮어써져
드러나지 않았다.

**What was tried**: 아무것도 바꾸지 않았다. 에피소드 화면이
`hasMessageActions={false}`라 다시 받기 버튼이 없어, 지금 사용자가 이 경로에
닿지 못한다.

**Proposed next step**: 다시 받기 버튼을 여는 단위에서 함께 고친다. 판정을
`asked.message`가 있을 때만 부르거나, 저장 전에 그 메시지의 기존 교정을 지운다.
앞의 것이 단순하고, 다시 받기에서는 사용자가 쓴 말이 그대로라 새 판정이 필요
없다는 뜻과도 맞는다.
