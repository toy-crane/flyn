# 앞 타임스탬프 마이그레이션 세 개를 db push가 건너뛴다

**Symptom**: `20260828*` 마이그레이션 세 개가 `20260829*` 세 개보다 앞 이름인데
뒤에 커밋됐다. `20260829*`를 이미 적용한 데이터베이스가 생기면
`supabase db push`가 기본값으로 앞 세 개를 건너뛰어, 그 환경만
`episode_runs` 시절 스키마에 남는다.

**Observed evidence**: 데이터베이스 검토가 2026-08-29에 짚었다. 브랜치가 더한
`20260828145912`, `20260828151746`, `20260828162001`이 main의
`20260829052530`, `20260829060000`, `20260829060931`보다 앞 이름이다. 로컬은
이름순 재생이라 문제가 없고, `bun run db:reset`이 아홉 개를 모두 적용해
`supabase_migrations.schema_migrations`에 남는다. 세 브랜치 파일은 `episode_*`
테이블과 함수만, main의 세 파일은 `public.stories`와 `storage.buckets`만
건드려 서로 참조가 없다.

**Suspected cause**: 원격 프로젝트에 연결한 적이 없어 리베이스할 때 타임스탬프를
다시 매기지 않았다. `supabase/.temp`에 `project-ref`가 없고 배포 워크플로도
없어 지금은 그런 환경이 존재하지 않는다.

**What was tried**: 그대로 두었다. 지금 적용 대상이 로컬 하나뿐이라 이름순
재생으로 충분하다.

**Proposed next step**: 원격 프로젝트를 붙이기 전에 세 파일의 타임스탬프를
`20260829060931` 뒤로 다시 매기거나, 첫 `db push`에 `--include-all`을 쓴다.
