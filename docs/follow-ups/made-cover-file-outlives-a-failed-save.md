# 각본이 실패하면 이미 올라간 표지 파일이 주인 없이 남는다

**Symptom**: `대화 시작하기`가 각본에서 실패하면 스토리는 만들어지지 않는다. 그런데 표지 그림은 각본과 나란히 만들어 저장소에 먼저 올라가므로, 그 파일만 `made/<사용자 id>/` 아래에 남는다. 어느 스토리도 그 파일을 가리키지 않는다.

**Observed evidence**: 2026-09-10 코드를 읽어 확인했다. `apps/api/src/features/episode/route.ts`의 `POST /ai/episode/stories`는 `madeCover`를 먼저 시작하고, `madeCover`는 그림을 받는 즉시 `bucket.upload`로 올린다. 각본이 형식을 어기거나 모델이 실패하면 그 뒤의 `create_story`에 닿지 못하고 502로 끝난다. 표지는 이미 올라간 뒤다. 기기에서 실제로 이 조합을 만들어 보지는 않았다. 각본 실패는 드물고 강제로 만들려면 모델을 함께 망가뜨려야 한다.

**Suspected cause**: 기다림을 늘리지 않으려고 그림과 각본을 나란히 만든다. 그림을 손에 쥐고 각본이 끝나기를 기다렸다가 올리면 이 문제는 없지만, 각본이 먼저 끝나는 보통의 경우에 표지가 붙는 시점이 그만큼 늦어진다.

**What was tried**: 지금은 그대로 둔다. 파일 이름이 내용의 해시라 같은 그림을 다시 만들면 같은 파일로 모이고, 계정을 지우면 `made/<사용자 id>/` 폴더를 통째로 비우므로 영원히 쌓이지는 않는다. 저장소 정책이 이 폴더의 깊이를 한 단계로 묶어 두어 나중에 훑기도 쉽다.

**Proposed next step**: 남은 파일이 실제로 얼마나 되는지 먼저 센다. `storage.objects`에서 `made/`로 시작하는 이름 중 `stories.cover_image_path`가 가리키지 않는 것을 세면 된다. 눈에 띄게 쌓이면 그때 정리하는 길을 만든다. 올리는 시점을 저장 뒤로 미루는 것은 마지막에 본다. 그러면 표지가 붙는 시점이 늦어진다.
