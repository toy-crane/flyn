# 홈의 최근 스토리가 마지막 대화 시각을 반영하지 않는다

**Symptom**: 진행 중인 스토리가 둘 이상일 때, 사용자가 가장 최근에 대화한
스토리가 홈의 이어 하기 카드로 올라오지 않을 수 있다. 먼저 시작한 스토리를 오래
플레이한 뒤 다른 스토리를 시작하면 시작 시각이 더 늦은 쪽이 앞선다.

**Observed evidence**: 2026-08-29 구현 기록과 현재
`apps/api/src/features/episode/catalog.ts`를 대조했다. 홈은 결말이 난 스토리는
`finished_at`, 진행 중인 스토리는 `started_at`으로 정렬한다. 마지막 메시지의
`created_at`은 읽지 않는다. 코드 주석도 이 값이 정확한 마지막 활동 시각이 아니라
근사값이라고 밝힌다.

**Suspected cause**: 마지막 활동 시각을 정확히 구하려면 지금 조회 모양에서는 이
계정의 메시지 행을 함께 읽어야 한다. 목록 하나를 정렬하려고 대화 행 전체를 읽지
않으려 시작 시각으로 줄였다.

**What was tried**: 결말이 있으면 `finished_at`, 없으면 `started_at`을 쓰는 현재
근사값을 유지했다. 스토리를 하나만 진행하거나 새 스토리를 시작한 직후에는 기대한
순서가 나온다.

**Proposed next step**: 플레이나 스토리별 마지막 메시지 시각을 집계해 한 번에 읽을
수 있게 만든 뒤, 홈 정렬이 `finished_at`, 마지막 메시지 시각과 `started_at` 중
가장 최근 값을 쓰게 한다. 대화 행 전체를 앱 응답에 싣지는 않는다.
