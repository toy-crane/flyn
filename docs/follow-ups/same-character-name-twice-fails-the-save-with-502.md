# 카드에 같은 인물 이름이 둘이면 저장이 502로 끝난다

**Symptom**: `대화 시작하기`를 눌렀을 때 스토리 카드에 이름이 같은 인물이 둘 있으면 저장이 502로 끝나고 앱은 `스토리를 만들지 못했어요.`만 보여 준다. 카드와 대화는 그대로 남지만 다시 시도해도 같은 자리에서 같은 실패가 반복되고, 어느 이름이 문제인지 화면에 드러나지 않는다.

**Observed evidence**: 2026-09-10 전체 diff 리뷰에서 코드를 읽어 확인했다. `apps/api/src/features/episode/story-creation.ts`의 `readStoryOutline`은 인물 수, 화 수, 화의 인물 수, 화의 인물이 카드에 있는 이름인지를 모두 미리 검사해 400과 문구로 돌려준다. 그런데 인물 이름끼리 겹치는지는 검사하지 않는다. `named`는 Set이라 겹치는 이름을 조용히 합친다. `supabase/schemas/30-tables.sql`의 `public.characters`에는 `unique (story_id, name)`이 있고 이 제약은 deferrable이 아니므로, `create_story`가 두 행을 넣는 문장에서 바로 터지고 함수 전체가 되돌아간다. 실제로 모델이 같은 이름을 둘 내놓는 것은 보지 못했다. 만들기 프롬프트에 이름이 서로 달라야 한다는 규칙이 없어 가능한 출력이다.

**Suspected cause**: 저장 전 검사가 데이터베이스 제약을 하나씩 따라가며 만들어졌는데, 이름의 유일성만 목록에서 빠졌다. `position`은 API가 `index + 1`로 다시 매겨 겹칠 수 없게 만들었지만 `name`은 카드가 준 값을 그대로 쓴다.

**What was tried**: 고치지 않았다. 실패해도 스토리가 절반만 남지는 않아 스펙이 요구하는 "실패한 시도는 아무것도 남기지 않는다"는 지켜지고, 수용 기준을 깨지 않는다. 모델이 실제로 같은 이름을 내놓는 것을 아직 보지 못해 일반 경로에서 재현한 결함으로 세지 않았다.

**Proposed next step**: `readStoryOutline`에 이름이 겹치는지 보는 줄을 더한다. 형제 검사와 같은 자리에 두고 400과 문구로 돌려주면, 502 대신 무엇이 잘못됐는지가 드러난다. 만들기 프롬프트의 `개요가 지켜야 할 것`에 이름이 서로 달라야 한다는 한 줄을 함께 넣는다. 길이도 같은 종류다. `characters_name_usable`은 60자까지인데 API는 비어 있지 않은지만 본다.
